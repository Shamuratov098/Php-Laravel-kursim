SQL 2: yozish, o'zgartirish va ikki jadvalni bog'lash

21-darsda faqat o'qidik. Bugun yozamiz — INSERT, UPDATE, DELETE — va eng muhimi JOIN: ikki jadvalni bir-biriga ulash. JOIN Modul C ning qolgan qismi (Eloquent bog'lanishlari) uchun poydevor.

📱 O'qish ≈ 13 daqiqa 💻 Amaliyot ≈ 20 daqiqa Kerak: Dars 21

Bu darsda nimalar bor
  1. Yozish uchta buyruq INSERT · UPDATE · DELETE — hammasi parametr bilan.
  2. Qaytgan son DB::update/delete nechta qator o'zgarganini aytadi.
  3. ⚠️ WHERE ni unutish Ataylab bajarib ko'rasiz: bitta unutilgan so'z butun jadvalni buzadi.
  4. Ikkinchi jadval va tashqi kalit ALTER TABLE · kompaniya_id · ma'lumot takrorlanmasligi.
  5. JOIN va LEFT JOIN Alias · ON sharti · juftsiz qatorlarning taqdiri.
  6. GROUP BY va HAVING Guruhlab hisoblash; WHERE bilan farqi.
  7. COUNT(*) va COUNT(ustun) Ikkinchisi NULL larni sanamaydi.
Nega bir jadval yetmaydi

21-darsdagi vakansiyalar jadvalida shahar ustuni bor edi. Endi har vakansiyaga kompaniya qo'shmoqchimiz. Eng oson yo'l — yana bitta ustun qo'shish: kompaniya_nomi, kompaniya_shahri, kompaniya_telefoni…

Va shu yerda muammo boshlanadi. «Uzum» kompaniyasida 10 ta vakansiya bo'lsa, kompaniya nomi 10 marta takrorlanadi. Kompaniya nomini o'zgartirsangiz — 10 joyda o'zgartirish kerak. Bittasini unutsangiz, bazada bir vaqtning o'zida ikki xil haqiqat paydo bo'ladi.

Yechim: kompaniyani alohida jadvalga chiqarish va vakansiyada faqat uning raqamini saqlash. Keyin ikkalasini JOIN bilan birlashtirib o'qish. Bu — bazaning eng asosiy g'oyasi va intervyuda eng ko'p so'raladigan SQL mavzusi.

Yozish: INSERT, UPDATE, DELETE

Uchalasi ham 21-darsdagi parametr qoidasiga bo'ysunadi — qiymat SQL satriga qo'shilmaydi, ? orqali alohida beriladi:

sql/03-yozish.php
DB::insert( 'INSERT INTO vakansiyalar (nom, maosh, shahar, faol) VALUES (?, ?, ?, ?)', ['PHP dasturchi', 950, 'Buxoro', 1] ); $soni = DB::update('UPDATE vakansiyalar SET maosh = ? WHERE nom = ?', [1000, 'PHP dasturchi']); $soni = DB::delete('DELETE FROM vakansiyalar WHERE faol = ?', [0]);
MetodNima qaytaradi
DB::insert(...)true/false. Yangi id uchun — DB::getPdo()->lastInsertId()
DB::update(...)Nechta qator o'zgardi — sonini qaytaradi
DB::delete(...)Nechta qator o'chdi
DB::select(...)Qatorlar massivi (21-dars)
DB::statement(...)Natija qaytarmaydigan SQL: CREATE, ALTER, DROP

UPDATE va DELETE qaytargan son juda foydali: agar 1 kutayotgan bo'lsangiz-u 0 kelsa — demak WHERE hech kimga to'g'ri kelmadi.

⚠️ WHERE ni unutish — eng qimmat xato

UPDATE va DELETE da WHERE ixtiyoriy. Yozmasangiz SQL xato bermaydi — u butun jadvalga qo'llanadi:

// ❌ WHERE yo'q UPDATE vakansiyalar SET shahar = 'Toshkent' → 5 qator o'zgardi (hammasi!) // ❌ Bu esa jadvalni bo'shatadi DELETE FROM vakansiyalar

Amaliyotda buni ataylab bajarasiz va natijasini ko'rasiz — qo'rqinchli narsani xavfsiz joyda bir marta ko'rish, uni real serverda birinchi marta ko'rishdan yaxshiroq.

Odat qiling: avval SELECT bilan WHERE ni sinang («aynan shu qatorlarmi?»), keyin uni UPDATE ga ko'chiring.

Ikkinchi jadval va tashqi kalit

sql/04-join.php
CREATE TABLE kompaniyalar ( id INTEGER PRIMARY KEY AUTOINCREMENT, nom TEXT NOT NULL, shahar TEXT ) ALTER TABLE vakansiyalar ADD COLUMN kompaniya_id INTEGER
  • ALTER TABLE — mavjud jadvalni o'zgartirish. Jadvalni qaytadan yasash shart emas (va ma'lumot yo'qolmaydi).
  • kompaniya_id — tashqi kalit (foreign key): boshqa jadvaldagi qatorning id si. Nomi odatda <jadval>_id shaklida bo'ladi.
  • Bu ustun bo'sh (NULL) ham bo'lishi mumkin — «kompaniyasi ko'rsatilmagan». Bu holat pastda muhim bo'ladi.

Natijada ma'lumot shunday joylashadi — takrorlanishsiz:

kompaniyalar vakansiyalar ┌────┬─────────────┐ ┌────┬────────────────────┬──────────────┐ │ id │ nom │ │ id │ nom │ kompaniya_id │ ├────┼─────────────┤ ├────┼────────────────────┼──────────────┤ │ 1 │ Uzum │ ←────── │ 1 │ Backend dasturchi │ 1 │ │ 2 │ EPAM │ ←──┐ │ 2 │ Frontend dasturchi │ 1 │ │ 3 │ Startup XYZ │ ←┐ │ │ 3 │ Laravel dasturchi │ 3 │ └────┴─────────────┘ │ └─── │ 4 │ QA muhandis │ 2 │ └───── │ 5 │ DevOps injener │ (bo'sh) │ └────┴────────────────────┴──────────────┘

JOIN — ikkalasini birga o'qish

JOIN
SELECT v.nom, k.nom AS kompaniya FROM vakansiyalar v JOIN kompaniyalar k ON k.id = v.kompaniya_id
  • vakansiyalar v — jadvalga qisqa nom (alias) berildi. Ikki jadvalda ham nom ustuni bor, shuning uchun v.nom va k.nom deb aniq ko'rsatish kerak.
  • ON k.id = v.kompaniya_id — qanday bog'lash sharti. Bu JOIN ning yuragi: «chapdagi qatorning kompaniya_id si o'ngdagi qatorning id siga teng bo'lsa — ularni bitta qator qilib ber».
  • AS kompaniya — natijadagi ustunga nom (21-dars).
Backend dasturchi | Uzum Frontend dasturchi | Uzum Laravel dasturchi | Startup XYZ QA muhandis | EPAM (4 qator)

5 ta vakansiya bor edi, natijada 4 ta. «DevOps injener» yo'qoldi — chunki uning kompaniya_id si bo'sh, ya'ni ON sharti unga to'g'ri kelmadi. Bu 21-darsdagi NULL qoidasining aynan o'zi.

LEFT JOIN — juftsizlarni ham qoldirish

LEFT JOIN
SELECT v.nom, k.nom AS kompaniya FROM vakansiyalar v LEFT JOIN kompaniyalar k ON k.id = v.kompaniya_id
Backend dasturchi | Uzum Frontend dasturchi | Uzum Laravel dasturchi | Startup XYZ QA muhandis | EPAM DevOps injener | (5 qator)

Endi 5 ta. «DevOps injener» qoldi, kompaniya ustuni esa bo'sh.

TuriMa'nosi
JOIN (= INNER JOIN)Faqat juftligi topilgan qatorlar. Juftsizlar tushib qoladi
LEFT JOINChapdagi (FROM dan keyingi) jadvalning hamma qatori qoladi; juftlik yo'q bo'lsa o'ng tomon NULL

Qaysi birini tanlash? Savolni shunday qo'ying: «juftligi yo'q qatorlar menga kerakmi?» «Kompaniyasi ko'rsatilmagan vakansiyalar ham ro'yxatda tursinmi?» — ha bo'lsa LEFT JOIN. Ish joyidagi eng ko'p uchraydigan bug': JOIN yozib qo'yib, hisobotdan qatorlar jimgina yo'qolgani.

GROUP BY — guruhlab hisoblash

«Har kompaniyada nechta vakansiya bor?» degan savol bitta qatorga sig'maydi — ma'lumotni guruhlarga bo'lib, har guruh uchun hisoblash kerak:

GROUP BY
SELECT k.nom, COUNT(*) AS soni, AVG(v.maosh) AS ort_maosh FROM vakansiyalar v JOIN kompaniyalar k ON k.id = v.kompaniya_id GROUP BY k.id
Uzum | 2 | 750 EPAM | 1 | 500 Startup XYZ | 1 | 1200

Har kompaniya uchun bitta qator qaytdi. COUNT(*), AVG(), SUM(), MIN(), MAX() — bular guruh funksiyalari: butun guruhni bitta songa aylantiradi.

WHERE va HAVING farqi

Ikkalasi ham «filtrlaydi», lekin qachonligi boshqa:

  • WHERE — guruhlashdan oldin, alohida qatorlarni filtrlaydi.
  • HAVING — guruhlashdan keyin, guruhlarni filtrlaydi.

Shuning uchun COUNT(*) > 1 ni WHERE ga yozib bo'lmaydi — o'sha paytda hali guruh yo'q:

GROUP BY k.id HAVING COUNT(*) > 1 → Uzum | 2

To'liq tartib endi shunday:

SELECT → FROM → JOIN → WHERE → GROUP BY → HAVING → ORDER BY → LIMIT

Sinab ko'ramiz

Natijani taxmin qiling

Quyidagi LEFT JOIN 5 qator qaytaradi (biz buni ko'rdik). Endi unga «faqat Toshkentdagi kompaniyalar» sharti qo'shildi. Nechta qator qaytadi?

so'rov
SELECT v.nom, k.nom AS kompaniya FROM vakansiyalar v LEFT JOIN kompaniyalar k ON k.id = v.kompaniya_id WHERE k.shahar = 'Toshkent'

Eslatma: Uzum va EPAM — Toshkentda, Startup XYZ — Samarqandda, «DevOps injener» esa kompaniyasiz.

Javobni ko'rish
3 qator Backend dasturchi | Uzum Frontend dasturchi | Uzum QA muhandis | EPAM

Ko'pchilik 4 deb o'ylaydi: «Samarqanddagi Startup XYZ tushib qoldi, kompaniyasiz DevOps esa LEFT JOIN tufayli qoladi».

Lekin DevOps ham yo'qoldi. Sababi 21-darsdagi qoida: LEFT JOIN unga bo'sh kompaniya berdi, ya'ni k.shahar — NULL. Va NULL = 'Toshkent' hech qachon rost bo'lmaydi. Demak WHERE uni chiqarib tashladi.

🔑 Klassik tuzoq: WHERE da o'ng jadvalning ustunini ishlatsangiz, LEFT JOIN jimgina oddiy JOIN ga aylanadi. Shart ON ga yozilsa esa LEFT xususiyati saqlanadi:

LEFT JOIN kompaniyalar k ON k.id = v.kompaniya_id AND k.shahar = 'Toshkent' → 5 qator

Farqi: ON — qanday bog'lash, WHERE — qaysi qatorni qoldirish. LEFT JOIN da bu ikkisi bir xil emas.

SAVOL 1 UPDATE da WHERE unutilsa nima bo'ladi?

SQL bu holatni xato deb hisoblamaydi — buyruq butun jadvalga qo'llanadi. Shuning uchun avval SELECT bilan WHERE ni sinash odat bo'lishi kerak.

SAVOL 2 JOIN va LEFT JOIN farqi nimada?

Oddiy JOIN juftligi topilmagan qatorni tushirib qoldiradi; LEFT JOIN uni qoldirib, o'ng tomonni NULL qilib qo'yadi.

SAVOL 3 COUNT(*) va COUNT(kompaniya_id) farqi nimada?

Bizning jadvalda COUNT(*) → 5, lekin COUNT(kompaniya_id) → 4, chunki «DevOps injener» ning kompaniya_id si bo'sh.

Eslab ayting

Avval o'zingiz javob bering, keyin ochib tekshiring. Oxirgi ikkitasi — 21-darsni takrorlash.

Nega kompaniya alohida jadvalda saqlanadi?

Takrorlanmasligi uchun. Bir jadvalda saqlansa, kompaniya nomi har vakansiyada qaytariladi va uni o'zgartirish kerak bo'lganda hamma joyda o'zgartirish kerak — bittasi unutilsa bazada ikki xil haqiqat paydo bo'ladi.

ON nima uchun kerak?

U qanday bog'lash shartini aytadi: ON k.id = v.kompaniya_id — «chapdagi qatorning tashqi kaliti o'ngdagi qatorning id siga teng bo'lsa, ularni bitta qator qil».

WHERE va HAVING qachon ishlaydi?

WHERE — guruhlashdan oldin (alohida qatorlarni), HAVING — guruhlashdan keyin (guruhlarni). Shuning uchun COUNT(*) > 1 faqat HAVING da yoziladi.

↩︎ Takrorlash: foydalanuvchi qiymati SQL'ga qanday qo'shiladi?

Faqat parametr bilan: DB::select('... WHERE nom = ?', [$nom]). Satrga qo'shib yozish — SQL injection.

↩︎ Takrorlash: NULL ni qanday tekshiriladi?

IS NULL / IS NOT NULL bilan. = NULL hech qachon rost bo'lmaydi.

Cho'ntak xulosasi
  • DB::insert · DB::update · DB::delete — oxirgi ikkitasi nechta qator o'zgarganini qaytaradi.
  • ⚠️ UPDATE/DELETE da WHERE ixtiyoriy — unutilsa butun jadval. Avval SELECT bilan sinang.
  • ALTER TABLE ... ADD COLUMN — mavjud jadvalga ustun qo'shish.
  • Tashqi kalit (kompaniya_id) — boshqa jadvaldagi qatorning id si. Ma'lumot takrorlanmaydi.
  • JOIN ... ON k.id = v.kompaniya_id — ikki jadvalni bitta qator qilib beradi. Alias (v, k) bir xil nomli ustunlarni ajratadi.
  • 🔑 JOIN juftsizni tushiradi, LEFT JOIN qoldiradi (o'ng tomon NULL).
  • 🔑 LEFT JOIN dan keyin WHERE da o'ng jadval ustunini ishlatsangiz — u jimgina oddiy JOIN ga aylanadi. Shartni ON ga yozing.
  • GROUP BY + COUNT/AVG/SUM/MIN/MAX — guruhlab hisoblash. Guruhlarni filtrlash — HAVING.
  • COUNT(*) qatorlarni, COUNT(ustun) esa NULL bo'lmaganlarni sanaydi.
  • Tartib: SELECT → FROM → JOIN → WHERE → GROUP BY → HAVING → ORDER BY → LIMIT.
