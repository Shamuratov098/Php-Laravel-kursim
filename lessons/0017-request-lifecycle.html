DARS 17 · MODUL B — LARAVEL

⭐ Request Lifecycle: so'rovning Laravel ichidagi sayohati

Bu kursning eng katta bog'lanish darsi. Laravel'ning public/index.php faylini o'zingiz yozgan fayl bilan yonma-yon qo'yamiz — va ular qator-baqator mos kelishini ko'rasiz. Bundan tashqari bitta yangi tushuncha keladi: middleware.

📱 O'qish ≈ 12 daqiqa 💻 Amaliyot ≈ 16 daqiqa Kerak: Dars 16

Nega bu muhim

«So'rov Laravel ichida qanday sayohat qiladi?» — bu intervyudagi eng ko'p beriladigan savollardan biri. Missiyangizdagi muvaffaqiyat mezoni ham shuni o'z ichiga oladi.

Lekin intervyudan muhimroq sabab bor: xatoni topish. Sahifa ishlamayapti — muammo route'dami, middleware'dami, controllerdami? Yo'lni bilmagan odam tasodifiy joylarga dd() tashlab ko'radi. Yo'lni bilgan odam qaysi bosqichda uzilganini aniqlab, to'g'ridan-to'g'ri o'sha yerga boradi.

Va bugun bu dars siz uchun oson bo'ladi — chunki mexanizmning yarmini o'zingiz yozgansiz.

Yonma-yon: sizning kodingiz va Laravel

SIZNING mini-framework'ingiz — public/index.php (14–15-darslar)
require __DIR__ . '/../vendor/autoload.php'; $container = new Container(); $container->bind(VakansiyaRepo::class, XotiraRepo::class); $router = new Router($container); $router->add('GET', '/vakansiyalar', Vakansiyalar::class); $metod = $_SERVER['REQUEST_METHOD']; $yol = parse_url($_SERVER['REQUEST_URI'], PHP_URL_PATH); echo $router->dispatch($metod, $yol);
LARAVEL — public/index.php (haqiqiy fayl, to'liq)
<?php use Illuminate\Foundation\Application; use Illuminate\Http\Request; define('LARAVEL_START', microtime(true)); // Determine if the application is in maintenance mode... if (file_exists($maintenance = __DIR__.'/../storage/framework/maintenance.php')) { require $maintenance; } // Register the Composer autoloader... require __DIR__.'/../vendor/autoload.php'; // Bootstrap Laravel and handle the request... $app = require_once __DIR__.'/../bootstrap/app.php'; $app->handleRequest(Request::capture());

Laravel'ning kirish nuqtasi — 20 qator. Va uch ajratilgan qator sizning kodingizga to'g'ridan-to'g'ri mos keladi:

SizdaLaravel'daMa'nosi

Qolgan qatorlar — qo'shimchalar: LARAVEL_START (tezlikni o'lchash uchun vaqt belgisi) va maintenance mode tekshiruvi («sayt ta'mirlanmoqda» rejimi). Ular yadroga tegishli emas.

Request::capture() nima

Siz $_SERVER['REQUEST_METHOD'] va $_SERVER['REQUEST_URI'] ni qo'lda o'qidingiz. Request::capture() xuddi shu ishni qiladi — faqat hammasini: metod, yo'l, $_GET, $_POST, sarlavhalar, cookie'lar, yuklangan fayllar — va bularni bitta obyektga soladi.

Shuning uchun Laravel'da $request->input('ism') deb yozasiz, $_POST['ism'] deb emas. Ostida esa aynan $_POST turadi (13-dars).

bootstrap/app.php — ilovaning sozlash nuqtasi

bootstrap/app.php (haqiqiy fayl, to'liq)
return Application::configure(basePath: dirname(__DIR__)) ->withRouting( web: __DIR__.'/../routes/web.php', commands: __DIR__.'/../routes/console.php', health: '/up', ) ->withMiddleware(function (Middleware $middleware): void { // }) ->withExceptions(function (Exceptions $exceptions): void { ... })->create();

Bu fayl Application obyektini yasab qaytaradi — ya'ni Laravel'ning container'i. Sizning new Container() qatoringizning o'rni shu. Uch sozlash bloki bor:

  • withRouting(...) — «route'lar qaysi faylda». Sizda $router->add(...) chaqiruvlari index.php ichida edi; Laravel'da ular alohida faylda (routes/web.php) va bu yerda faqat yo'li ko'rsatiladi. health: '/up' — 16-darsda ko'rgan «ilova tirikmi?» route'i shu yerdan keladi.
  • withMiddleware(...) — yangi tushuncha, pastda batafsil.
  • withExceptions(...) — xatolar qanday ko'rsatilishi. 11-darsdagi try/catch — bu uning markazlashgan shakli: Laravel butun ilovani o'rab oladi va tutilmagan exception'ni chiroyli xato sahifasiga aylantiradi. Sizda esa index.php da try/catch bor edi — bir xil g'oya.

->withRouting(...)->withMiddleware(...)->create() — har metod o'zini qaytaradi, shuning uchun zanjir qilib yozish mumkin. Bu fluent interface deb ataladi va Laravel'da juda ko'p uchraydi.

🆕 Middleware — so'rov yo'lidagi qatlamlar

Bu sizning mini-framework'ingizda yo'q edi. Middleware — so'rov controllerga yetib borguncha o'tadigan qatlam. Har qatlam so'rovni ko'radi va qaror qiladi: o'tkazish yoki to'xtatish.

middleware tuzilishi
public function handle(Request $request, Closure $next): Response { // 1) controllerga KIRISHDAN oldin $response = $next($request); // ← keyingi qatlamga uzatadi // 3) controllerdan QAYTGANDAN keyin return $response; }

$next($request) — «davom et». Shu chaqiruvdan oldingi kod controllerdan oldin ishlaydi, keyingi kod esa controller javob qaytargandan keyin. Ya'ni middleware controllerni o'rab oladi — sandvich kabi.

1 · Middleware (kirish)

$next dan oldin
Auth tekshiruvi, log, tilni aniqlash

2 · Controller

handle / index
Asosiy ish — javob hosil qilinadi

3 · Middleware (chiqish)

$next dan keyin
Javobga sarlavha qo'shish, vaqtni o'lchash

4 · Javob ketadi

response
Brauzerga yuboriladi (1-dars!)

Amaliyotda buni log orqali o'z ko'zingiz bilan tasdiqlaysiz: uchta yozuv 1 → 2 → 3 tartibida chiqadi.

Middleware nima uchun kerak — 14-darsdagi muammoning yechimi

14-darsda front controller'ning foydalaridan birini aytgandim: «markaziy nazorat — har so'rovni logga yozish yoki kirmagan odamni to'sib qo'yish qoidasini bitta joyda yozish». Middleware — aynan shuning quroli.

Laravel'da auth middleware kirmagan foydalanuvchini login sahifasiga yuboradi — controllerga umuman yetib bormaydi. Bu Modul D da (middleware darsi) batafsil.

To'liq yo'l — yetti qadam

Ettitadan beshtasini o'zingiz yozgansiz. Qolgan ikkitasi — Request obyekti va middleware — bugungi darsning yangiligi.

💻 Amaliy qism kompyuterda

Amaliyotda IshTop ichidagi public/index.php va bootstrap/app.php ni to'liq o'qib chiqasiz, keyin o'z middleware'ingizni yozasiz. Uchta joyga log qo'yib, so'rov yuborasiz va logni o'qiysiz — tartib 1 → 2 → 3 bo'lishini, ya'ni middleware controllerni o'rab olishini o'z ko'zingiz bilan tasdiqlaysiz.

Amaliyot

  1. IshTop'ga o'ting va kirish nuqtasini to'liq o'qing

    20 qator — o'qib chiqishga arziydi. Bu butun Laravel ilovasining boshlanishi.

    cd ~/Projects/Learn/ishtop cat -n public/index.php

    Kutilgan natija: 20 qator. Uchtasini toping: require ... vendor/autoload.php (12-dars), require_once ... bootstrap/app.php (container), $app->handleRequest(...) (dispatch). Qolganlari — vaqt belgisi va maintenance tekshiruvi.

  2. bootstrap/app.php ni o'qing

    cat -n bootstrap/app.php

    Kutilgan natija: ~21 qator. withRouting ichida routes/web.php yo'li va health: '/up' — 16-darsda route:list da ko'rgan up route'i shu yerdan kelgan. withMiddleware hozircha bo'sh (//).

  3. O'z middleware'ingizni yarating

    php artisan make:middleware IzniKuzat INFO Middleware [app/Http/Middleware/IzniKuzat.php] created successfully.

    Kutilgan natija: fayl yaratildi. Ochib ko'rsangiz ichida return $next($request); bitta qator turadi — «shunchaki o'tkazib yubor».

  4. Middleware'ga iz qoldiruvchi kod yozing

    $next() dan oldin va keyin — ikki joyga log.

    cat > app/Http/Middleware/IzniKuzat.php <<'EOF' <?php namespace App\Http\Middleware; use Closure; use Illuminate\Http\Request; use Symfony\Component\HttpFoundation\Response; class IzniKuzat { public function handle(Request $request, Closure $next): Response { logger()->info('1. MIDDLEWARE: controllerga KIRISHDAN oldin'); $response = $next($request); logger()->info('3. MIDDLEWARE: controllerdan QAYTGANDAN keyin'); return $response; } } EOF

    Kutilgan natija: jimlik. logger()->info(...) — Laravel'ning log yozuvchisi; yozuvlar storage/logs/laravel.log ga tushadi (4-darsdagi log fayli!).

  5. Controller'ga ham iz qo'ying

    cat > app/Http/Controllers/VakansiyaController.php <<'EOF' <?php namespace App\Http\Controllers; class VakansiyaController extends Controller { public function index(): string { logger()->info('2. CONTROLLER: index ishlayapti'); return '<h1>Vakansiyalar</h1>'; } } EOF

    Kutilgan natija: jimlik.

  6. Middleware'ni route'ga ulang

    Middleware butun ilovaga ham, bitta route'ga ham ulanishi mumkin. Biz bitta route'ga ulaymiz — natija aniqroq ko'rinadi.

    cat > routes/web.php <<'EOF' <?php use App\Http\Controllers\VakansiyaController; use App\Http\Middleware\IzniKuzat; use Illuminate\Support\Facades\Route; Route::get('/', function () { return view('welcome'); }); Route::get('/vakansiyalar', [VakansiyaController::class, 'index']) ->middleware(IzniKuzat::class); EOF

    Kutilgan natija: jimlik. ->middleware(...) — route'ga qatlam qo'shish.

  7. Logni tozalab, so'rov yuboring

    Bu darsning asosiy tajribasi.

    php artisan serve > /dev/null 2>&1 & sleep 2 > storage/logs/laravel.log curl -s http://localhost:8000/vakansiyalar; echo <h1>Vakansiyalar</h1>

    Kutilgan natija: sahifa javobi.
    Bu yerda serverni fonda ishga tushirdik (& bilan), shuning uchun terminal band bo'lmaydi. Keyinroq to'xtatish uchun: pkill -f "artisan serve" — yoki oddiygina yangi terminal oynasidan foydalanaversangiz ham bo'ladi.

  8. Logni o'qing — tartibni ko'ring

    grep -oE '[123]\. (MIDDLEWARE|CONTROLLER): .*' storage/logs/laravel.log 1. MIDDLEWARE: controllerga KIRISHDAN oldin 2. CONTROLLER: index ishlayapti 3. MIDDLEWARE: controllerdan QAYTGANDAN keyin

    Kutilgan natija: aynan shu tartib. 🎉
    Isbot bo'ldi: middleware controllerni o'rab oladi — bir marta oldin, bir marta keyin ishlaydi. Bitta handle() metodi ichida, lekin $next($request) ning ikki tomonida.

  9. To'liq logni ham ko'rib chiqing

    tail -5 storage/logs/laravel.log [2026-08-12 12:12:07] local.INFO: 1. MIDDLEWARE: controllerga KIRISHDAN oldin [2026-08-12 12:12:07] local.INFO: 2. CONTROLLER: index ishlayapti [2026-08-12 12:12:07] local.INFO: 3. MIDDLEWARE: controllerdan QAYTGANDAN keyin

    Kutilgan natija: vaqt belgisi va daraja (local.INFO) bilan. Sana-vaqt sizda boshqacha bo'ladi.
    Bu 4-darsdagi bilimning davomi: «oq sahifa ko'rsangiz — logga qara». Laravel'da o'sha log aynan shu fayl.

  10. Ishni saqlang

    git add -A git commit -m "17-dars: request lifecycle va birinchi middleware"

    Kutilgan natija: commit haqida xabar. Diqqat: storage/logs/laravel.log Git'ga tushmaydi — Laravel uni ham ignore qilgan.

Sinab ko'ramiz

Natijani taxmin qiling

Ikkita middleware ulangan — A va B shu tartibda. Har biri $next() ning ikki tomonida log yozadi. Controller ham bitta log yozadi. Logda nechta yozuv va qanday tartibda chiqadi?

routes/web.php
Route::get('/test', [C::class, 'index']) ->middleware([A::class, B::class]); // A: log('A-kirish') ... $next() ... log('A-chiqish') // B: log('B-kirish') ... $next() ... log('B-chiqish') // C: log('CONTROLLER')
Javobni ko'rish
A-kirish B-kirish CONTROLLER B-chiqish A-chiqish

Besh yozuv, va tartib simmetrik — A birinchi kiradi, oxirgi chiqadi.

Sabab: middleware'lar bir-birini o'rab oladi, ketma-ket turmaydi. Ya'ni A ichida B, B ichida controller:

A ( B ( CONTROLLER ) )

Bu tuzilma piyoz yoki matryoshka ga o'xshatiladi. Har qatlamdan kirasiz, markazga yetasiz, keyin teskari tartibda chiqasiz.

Nega bu muhim: tartib real ta'sir qiladi. Masalan auth middleware'i «tilni aniqlash» middleware'idan oldin turishi kerak — chunki foydalanuvchi kirmagan bo'lsa, tilni aniqlashning hojati yo'q. Va javobga sarlavha qo'shadigan middleware tashqi qatlamda turishi kerak, aks holda uning «chiqish» qismi ishlamay qolishi mumkin.

SAVOL 1 Laravel'ning $app->handleRequest(...) qatori sizning kodingizdagi nimaga to'g'ri keladi?

Uchtasi mos keladi: autoload → autoload, bootstrap/app.php → container yasash, handleRequest() → dispatch().

SAVOL 2 Middleware'da $next($request) nima qiladi?

$next() — «davom et». Undan oldingi kod controllerdan oldin, keyingi kod controllerdan keyin ishlaydi. Chaqirmasangiz — so'rov to'xtaydi (masalan auth shunday qiladi).

SAVOL 3 Request::capture() nimani qiladi?

Metod, yo'l, $_GET, $_POST, sarlavhalar, cookie, fayllar — hammasi bitta Request obyektiga yig'iladi. Shuning uchun $request->input('ism') deb yozasiz.

Eslab ayting

Avval o'zingiz javob bering, keyin ochib tekshiring. Oxirgi ikkitasi — 16-darsni takrorlash.

So'rovning yo'lini yetti qadamda ayting

1) public/index.php ga keladi → 2) autoload ulanadi → 3) bootstrap/app.php container yasaydi → 4) Request::capture() → 5) middleware qatlamlari → 6) router topadi, container controllerni yasaydi → 7) javob middleware'lardan teskari qaytib brauzerga ketadi.

Middleware nima uchun «sandvich» deb ataladi?

Chunki u controllerni o'rab oladi: $next() dan oldin va keyin kod ishlaydi. Bir necha middleware bo'lsa — piyoz kabi ichma-ich: A(B(CONTROLLER)), chiqish teskari tartibda.

bootstrap/app.php nima qaytaradi?

Application obyektini — ya'ni Laravel'ning container'i. Sizning new Container() qatoringizning o'rni shu. Uch sozlash: withRouting, withMiddleware, withExceptions.

↩︎ Takrorlash: Laravel'da standart baza qaysi va u qayerda?

SQLite — bitta fayl: database/database.sqlite. create-project uni o'zi yaratib, migration'larni ham bajaradi.

↩︎ Takrorlash: nega .env Git'ga tushmaydi?

Ichida parollar, API kalitlari va APP_KEY bor. Repoda uning o'rniga .env.example turadi — kalitlar ro'yxati, qiymatlarsiz.

Cho'ntak xulosasi
  • Laravel'ning public/index.php — 20 qator, va uchtasi sizning kodingizga mos: autoload · bootstrap/app.php · handleRequest().
  • bootstrap/app.php — Application (container) ni yasaydi. withRouting · withMiddleware · withExceptions.
  • Request::capture() — $_SERVER, $_GET, $_POST, sarlavhalar, cookie — hammasi bitta obyektga.
  • 🆕 Middleware — so'rov yo'lidagi qatlam. $next($request) dan oldin va keyin kod ishlaydi.
  • Bir necha middleware — ichma-ich: A(B(CONTROLLER)). Kirish tartibda, chiqish teskari.
  • $next() chaqirilmasa — so'rov to'xtaydi (auth shunday ishlaydi).
  • Yo'lning 7 qadamidan 5 tasini Modul A da o'zingiz yozgansiz.
  • logger()->info(...) → storage/logs/laravel.log (4-darsdagi log).
