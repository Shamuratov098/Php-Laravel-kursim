DARS 52 · MODUL G — LARAVEL ICHKI MEXANIZMI

Collections

Modelni get() qilganingizda massiv emas, kolleksiya qaytadi. 28-darsdan beri uni ishlatib kelyapmiz, lekin nima ekanini so'ramadik. Bugun ochamiz — va yo'lda API javobini jimgina buzadigan bitta xatoni tutamiz.

📱 O'qish ≈ 17 daqiqa 💻 Amaliyot ≈ 28 daqiqa Kerak: Dars 51

Bu darsda nimalar bor
  1. Kolleksiya nima 🔍 O'lchandi: get() → Eloquent\Collection, u esa Support\Collection dan meros oladi.
  2. foreach va zanjir Bir xil ishning ikki yozilishi — va nega ikkinchisi tezroq o'qiladi.
  3. ⚠️ Darsning eng qimmat xatosi filter() kalitlarni saqlaydi → JSON massiv o'rniga obyekt bo'lib qoladi. Haqiqiy API javobida o'lchandi.
  4. values() — bir so'zlik yechim Va nega u groupBy dan keyin kerak emas.
  5. O'zgarmaslik Har bir metod yangi kolleksiya qaytaradi. Asl ma'lumot tegilmaydi — o'lchandi.
  6. pluck va nuqta pluck('kompaniya.nom') — bog'lanish ichiga kirish. Ikkinchi argument bilan kalit ham beriladi.
  7. groupBy, reduce, sum Haqiqiy statistika endpointi yozamiz — sikl yozmasdan.
  8. ⚠️ avg() va null 🔍 O'lchandi: avg 1900, sum/count esa 1583.3. Ikkalasi ham «o'rtacha» deyiladi.
  9. Yuqori tartibli proksi $v->sum->maosh va $v->filter->faol — closure'siz yozuv.
  10. LazyCollection va xotira 🔍 20 006 yozuvda o'lchandi: get() 54 MB, cursor() 24 MB.
  11. Yalqov zanjir erta to'xtaydi 🔍 take(3) uchun 20 006 dan atigi 2510 yozuv o'qildi.
  12. Har xil holatlar (7 ta) Kolleksiyada where va SQL'dagi where · each va map · cursor ni qayta ishlatish · qachon massiv afzal.
Massiv emas ekan

28-darsdan beri shunday yozamiz:

$vakansiyalar = Vakansiya::get(); foreach ($vakansiyalar as $v) { ... }

Massivdek ishlaydi. Lekin turini so'rasak:

get_class(Vakansiya::get()) → Illuminate\Database\Eloquent\Collection get_parent_class(...) → Illuminate\Support\Collection

Bu obyekt, va unda yuzdan ortiq metod bor. Ularning ba'zilarini bilmasdan ishlatgansiz ham: 46-darsda $javob->json('data.*.maosh'), 43-darsda VakansiyaResource::collection(...), 51-darsda Facade::defaultAliases()->merge(...).

Bugun ularni ataylab ishlatamiz. Va bitta jimgina xatoni ham tutamiz — u aynan API javobida ko'rinadi.

foreach va zanjir

Vazifa: Toshkentdagi faol vakansiyalarning nomlarini maosh bo'yicha kamayish tartibida olish.

foreach bilan
$natija = []; foreach ($vakansiyalar as $v) { if ($v->shahar === 'Toshkent' && $v->faol) { $natija[] = $v; } } usort($natija, fn ($a, $b) => $b->maosh <=> $a->maosh); $nomlar = []; foreach ($natija as $v) { $nomlar[] = $v->nom; }
kolleksiya bilan
$nomlar = $vakansiyalar ->where('shahar', 'Toshkent') ->where('faol', true) ->sortByDesc('maosh') ->pluck('nom') ->values();

Ikkalasi ham bir xil natija beradi. Farq — o'qishda: ikkinchisi nima qilinayotganini aytadi, birinchisi qanday qilinayotganini.

🔑 Bu «qisqaroq» degani emas

foreach yomon emas — u tushunarli va tez. Kolleksiyaning foydasi bosqichlarni ajratishda: har bir qator bitta ish qiladi va uni alohida o'qish mumkin.

⚠️ Uzun zanjir esa aksincha — 8 ta metod ketma-ket kelsa, foreach dan ham qiyin bo'lib ketadi. Chegara oddiy: zanjirni ovoz chiqarib o'qib ko'ring. Gapga o'xshamasa, bo'lib yuboring.

⚠️ filter() kalitlarni saqlaydi

Bu darsning eng qimmat qismi. Oddiy misoldan boshlaymiz:

$sonlar = collect([1, 2, 3, 4, 5, 6]); $juft = $sonlar->filter(fn ($n) => $n % 2 === 0); $juft->toJson() → {"1":2,"3":4,"5":6} ⚠️ OBYEKT

Kutgan narsamiz [2,4,6] edi. Chiqqani esa JSON obyekt — chunki filter asl kalitlarni (1, 3, 5) saqlab qoladi, va nol'dan boshlanmagan ketma-ketlik JSON'da massiv bo'la olmaydi.

sort() ham xuddi shunday:

collect([3, 1, 2])->sort()->toJson() → {"1":1,"2":2,"0":3}

Endi buni haqiqiy API'da ko'ramiz

Statistika endpointi yozdik. Unda «eng yuqori maoshli uchta vakansiya» bor:

$vakansiyalar->sortByDesc('maosh')->take(3)->map(fn ($v) => [...])
// javobda: "top_uchta": { "2": { "nom": "DevOps muhandis", "maosh": 3000 }, "0": { "nom": "Backend dasturchi", "maosh": 2500 }, "4": { "nom": "Mobil dasturchi", "maosh": 2000 } } ⚠️ massiv emas, OBYEKT — va kalitlar 2, 0, 4

Ikkita muammo birdan. Mijoz massiv kutgan edi — obyekt oldi. Va kalitlar tartibsiz: 2, 0, 4. JavaScript'da obyekt kalitlarining tartibi kafolatlanmaydi, ya'ni mobil ilova «eng yuqori maoshli» ro'yxatni boshqa tartibda ko'rsatishi mumkin.

✅ Yechim bitta so'z:

->map(fn ($v) => [...]) ->values() ← qo'shildi "top_uchta": [ { "nom": "DevOps muhandis", "maosh": 3000 }, { "nom": "Backend dasturchi", "maosh": 2500 }, { "nom": "Mobil dasturchi", "maosh": 2000 } ] ✅ massiv, to'g'ri tartibda
⚠️ Qoida

Kalitni o'zgartiradigan yoki yo'qotadigan har bir metoddan keyin, agar natija JSON'ga ketayotgan bo'lsa, values() qo'ying:

filter · reject · where · sortBy · sortByDesc · sort unique · skip · take (filterdan keyin) · shuffle

🔑 Bu 46-darsdagi ?sort=moash va 47-darsdagi o'lik handler bilan bir oiladan: status 200, javob noto'g'ri.

🔍 Testda tutish oson: expect(array_keys($javob->json('top_uchta')))->toBe([0, 1, 2]).

Qachon values() KERAK EMAS

Statistikaning ikkinchi qismida groupBy bor — va u ataylab values() siz qoldirilgan:

"shaharlar": { "Toshkent": { "soni": 4, "eng_yuqori_maosh": 2500 }, "Samarqand": { "soni": 1, "eng_yuqori_maosh": 3000 }, "Buxoro": { "soni": 1, "eng_yuqori_maosh": 800 } } ✅ obyekt — va bu TO'G'RI

Bu yerda kalitlar ma'noli: ular shahar nomlari. Mijoz shaharlar.Toshkent.soni deb bemalol o'qiy oladi.

Mezon oddiy: kalit ma'lumotmi yoki tasodifmi? Ma'noli bo'lsa — obyekt qoldiring. Tasodifiy raqam bo'lsa — values().

O'zgarmaslik

Kolleksiyaning har bir metodi yangi kolleksiya qaytaradi. Asl ma'lumot tegilmaydi:

$asl = collect([3, 1, 2]); $saralangan = $asl->sort(); $asl->toJson() → [3,1,2] ← o'zgarmadi $saralangan->toJson() → {"1":1,"2":2,"0":3} $asl === $saralangan → YO'Q

Bu usort() dan farq qiladi — u massivni joyida o'zgartiradi.

🔑 Nega bu muhim

Bitta kolleksiyani bir necha marta ishlatsangiz, har bir zanjir mustaqil:

$v = Vakansiya::get(); $faollar = $v->where('faol', true); // $v tegilmadi $qimmatlar = $v->sortByDesc('maosh'); // $v yana tegilmadi

⚠️ Istisno: transform() — u joyida o'zgartiradi. Nomi ham shuni aytadi (map emas).

Kundalik metodlar

$v = Vakansiya::with('kompaniya')->get(); pluck('nom') → ["Backend dasturchi","Frontend dasturchi",...] pluck('nom', 'id') → {"10":"Backend dasturchi","11":"Frontend dasturchi"} pluck('kompaniya.nom') → ["Uzum Tech","Alif Lab"] ← nuqta bilan! groupBy('shahar')->keys() → ["Toshkent","Samarqand","Buxoro"] groupBy('shahar')->map->count() → {"Toshkent":4,"Samarqand":1,"Buxoro":1} sum('maosh') → 9500 max('maosh') → 3000 reduce(fn ($jami, $x) => $jami + (int) $x->maosh, 0) → 9500

pluck('kompaniya.nom') ga alohida e'tibor bering: nuqta orqali bog'lanishga kiradi. Bu 46-darsdagi assertJsonPath('meta.total', 1) bilan bir xil yozuv.

reduce — eng umumiy metod

Qolgan hamma narsani reduce bilan yozsa bo'ladi: u kolleksiyani bitta qiymatga yig'adi.

reduce(fn ($yigilgan, $element) => ..., $boshlangich)

sum(), count(), max() — hammasi shuning maxsus holatlari. Amalda esa aksincha: reduce ni faqat tayyor metod yo'q bo'lganda ishlating — u o'qish uchun eng qiyini.

⚠️ avg() va null

Bazamizda 6 ta vakansiya bor, bittasining maoshi null («Kelishuv asosida»). O'rtacha maoshni ikki xil yo'l bilan hisoblaymiz:

jami yozuv: 6 maoshi bor yozuv: 5 sum('maosh'): 9500 avg('maosh'): 1900 ← 9500 / 5 sum / count: 1583.3 ← 9500 / 6

Ikkalasi ham «o'rtacha maosh» deb ataladi, lekin boshqa son. avg() null qiymatlarni hisobga olmaydi — bo'luvchi 6 emas, 5.

Qaysi biri to'g'ri? Savolga bog'liq:

«Maosh ko'rsatilgan vakansiyalarda o'rtacha qancha?» → 1900 (avg) «Bir vakansiyaga o'rtacha qancha maosh to'g'ri keladi?» → 1583 (sum/count)

Muammo shundaki, kod ikkalasida ham bir xil ko'rinadi. Yana ikkita o'lchangan holat:

collect([1, 2])->avg() → 1.5 (float) collect([2500, 1200, null])->avg() → 1850 (int — bo'linish butun chiqdi) collect([])->avg() → NULL ⚠️

Oxirgisi eng xavflisi: bo'sh kolleksiyada avg() null qaytaradi. Uni to'g'ridan-to'g'ri round() ga bersangiz 0 chiqadi va «o'rtacha maosh 0» degan ma'lumot ko'rsatiladi.

✅ round((float) $v->avg('maosh')) // ochiq aytilgan ✅ $v->isEmpty() ? null : round($v->avg('maosh')) // yoki ochiq tekshiruv

Haqiqiy misol: statistika endpointi

app/Http/Controllers/Api/StatistikaController.php
<?php namespace App\Http\Controllers\Api; use App\Http\Controllers\Controller; use App\Models\Vakansiya; class StatistikaController extends Controller { public function __invoke() { $vakansiyalar = Vakansiya::with('kompaniya')->get(); return [ 'jami' => $vakansiyalar->count(), 'faol' => $vakansiyalar->where('faol', true)->count(), 'ortacha_maosh' => round((float) $vakansiyalar->avg('maosh')), 'shaharlar' => $vakansiyalar ->groupBy('shahar') ->map(fn ($guruh) => [ 'soni' => $guruh->count(), 'eng_yuqori_maosh' => $guruh->max('maosh'), ]) ->sortByDesc('soni'), 'top_uchta' => $vakansiyalar ->sortByDesc('maosh') ->take(3) ->map(fn ($v) => [ 'nom' => $v->nom, 'maosh' => $v->maosh, 'kompaniya' => $v->kompaniya?->nom, ]) ->values(), ]; } }

Marshrutga ulash bir qator (48-darsdagi v1 guruhi ichida):

routes/api.php
Route::get('/statistika', StatistikaController::class)->name('statistika');

__invoke() — bitta ishni qiladigan controller. Marshrutda metod nomini yozish kerak emas.

Bitta foreach ham yo'q. Va e'tibor bering: where('faol', true) bu yerda SQL emas — ma'lumot allaqachon xotirada, bu kolleksiya filtri.

Yuqori tartibli proksi

Ba'zi metodlarni closure'siz yozsa bo'ladi:

$v->sum(fn ($x) => $x->maosh) ≡ $v->sum->maosh $v->filter(fn ($x) => $x->faol) ≡ $v->filter->faol $v->map(fn ($x) => $x->count()) ≡ $v->map->count() // o'lchandi: $v->sum->maosh → 9500 $v->filter->faol->count() → 5

Bu ham 51-darsdagi mexanizm: ->sum xossa emas, u __get orqali proksi obyekt qaytaradi va keyingi ->maosh ni ushlaydi.

⚠️ Faqat bir nechta metodda ishlaydi (map, filter, sum, each, every, reject, sortBy va boshqalar) — va IDE bularni ham bilmaydi.

LazyCollection va xotira

Kolleksiyaning bitta kamchiligi bor: u hamma narsani xotiraga oladi. 20 006 ta yozuv bilan o'lchadik:

usul xotira cho'qqisi ────────────────────────────── get() 54 MB ⚠️ cursor() 24 MB chunk(500) 24 MB lazy() 26 MB (bo'sh ilova: 22 MB)

Ya'ni get() ~32 MB qo'shimcha oldi, yalqov usullar esa 2–4 MB. Farq yozuv soniga qarab o'sadi: 200 000 yozuvda get() ilovani yiqitadi.

Vakansiya::get() → Illuminate\Database\Eloquent\Collection Vakansiya::cursor() → Illuminate\Support\LazyCollection Vakansiya::lazy() → Illuminate\Support\LazyCollection

LazyCollection bir xil metodlarni beradi — map, filter, take — lekin yozuvlarni bittalab o'qiydi.

Yalqov zanjir erta to'xtaydi

Eng chiroyli tomoni shu. 20 006 yozuvdan «maoshi 3000 dan yuqori birinchi 3 tasi» ni so'raymiz va nechta yozuv o'qilganini sanaymiz:

Vakansiya::cursor() ->map(...) ← bu yerda sanadik ->filter(fn ($v) => $v->maosh > 3000) ->take(3) ->pluck('nom') ko'rilgan yozuv: 2510 ta (jami 20 006 dan)

Uchtasini topgach zanjir to'xtadi. Oddiy kolleksiyada bunday bo'lmaydi: get() avval 20 006 tasini o'qiydi, keyin filtrlaydi.

🔑 Qachon nima
get() → yuzlab yozuv, bir necha marta ishlatiladi, JSON'ga ketadi cursor() → minglab yozuv, BIR MARTA yuriladi (eksport, hisobot) chunk() → minglab yozuv, har qismda YOZISH bor (yangilash, o'chirish) lazy() → cursor kabi, lekin qismlab o'qiydi (katta jadval uchun xavfsizroq)

🔍 chunk() va lazy() bazadan qismlab oladi (limit/offset), cursor() esa bitta so'rov ochib qoldiradi.

Har xil holatlar

Yetti holat. Bu bo'lim ma'lumotnoma — hozir bir marta o'qib chiqing, keyin kerak bo'lganda qaytib qarang.

HOLAT 1

Kolleksiyadagi where — SQL emas

❌ Vakansiya::get()->where('shahar', 'Toshkent') → 20 006 yozuv BAZADAN olinadi, keyin xotirada filtrlanadi ✅ Vakansiya::where('shahar', 'Toshkent')->get() → baza faqat keraklisini qaytaradi

Yozilishi deyarli bir xil, o'rni boshqa. Qaysi tomonda get() turganiga qarang.

🔑 Statistika controllerida where ataylab kolleksiyada: ma'lumot allaqachon olingan va u bir necha marta ishlatiladi. Ikkinchi so'rov yuborish behuda bo'lardi.

⚠️ Kolleksiya where i SQL'nikidan farq qiladi: u qat'iy solishtirmaydi (where('faol', 1) va where('faol', true) bir xil ishlaydi). Qat'iylik kerak bo'lsa — whereStrict().

HOLAT 2

each va map farqi

map(fn ($x) => ...) → YANGI kolleksiya qaytaradi each(fn ($x) => ...) → o'sha kolleksiyani qaytaradi (yon ta'sir uchun)

each — foreach ning kolleksiyadagi ko'rinishi. Natija kerak bo'lmasa ishlatiladi (log yozish, email yuborish).

⚠️ each ichida false qaytarsangiz sikl to'xtaydi — kam ma'lum, lekin foydali.

⚠️ Yalqov kolleksiyada each hammasini yuradi va erta to'xtash foydasini yo'qotadi. Zanjirda map ishlating.

HOLAT 3

cursor() ni ikki marta ishlatish

$k = Vakansiya::cursor(); $k->take(5)->count(); → 5 $k->take(5)->count(); → 5 ← ishladi // lekin so'rovlar soni: DB::getQueryLog() → 2 ta so'rov ⚠️

Ishlaydi, lekin bazaga qayta boradi. Oddiy kolleksiya esa ma'lumotni xotirada saqlaydi — uni necha marta ishlatsangiz ham qo'shimcha so'rov yo'q.

🔑 Farq shu: kolleksiya — ma'lumot, yalqov kolleksiya — retsept.

✅ Bir necha marta kerak bo'lsa ->collect() bilan oddiy kolleksiyaga aylantiring (lekin unda xotira foydasi yo'qoladi).

HOLAT 4

Qachon oddiy massiv afzal

✅ massiv: 2-3 elementli sozlama, tez qaytariladigan qiymat ✅ kolleksiya: ustida ish qilinadi (filtr, saralash, guruh)

collect([...])->first() yozish uchun kolleksiya yasash — ortiqcha. Massivning o'z funksiyalari (array_map, array_filter) ham yomon emas.

🔑 Kolleksiya zanjir kerak bo'lganda foyda beradi. Bitta amal uchun massiv soddaroq.

🔍 Arr:: yordamchisi ham bor — Arr::pluck(), Arr::only() — obyekt yasamasdan.

HOLAT 5

Foydali kam ma'lum metodlar

partition(fn ($x) => ...) → [mos kelganlar, kelmaganlar] tap(fn ($k) => dump($k)) → zanjirni buzmasdan qarash whenNotEmpty(fn ($k) => ...) → bo'sh bo'lmasa bajar sole(fn ($x) => ...) → aynan bitta bo'lishi kerak, aks holda xato countBy(fn ($x) => ...) → {"qiymat": nechta} flatMap · flatten · zip · pad

tap() — nosozlikni topishda eng foydalisi: uzun zanjirning o'rtasiga qo'yib, o'sha joydagi holatni ko'rasiz.

sole() — «bitta bo'lishi shart» holatlarida first() dan xavfsizroq: ikkita bo'lsa xato beradi, jimgina birinchisini olmaydi.

HOLAT 6

Zanjir ichida baza so'rovi

❌ $vakansiyalar->map(fn ($v) => $v->kompaniya->nom) → har bir element uchun BAZAGA so'rov (N+1) ✅ Vakansiya::with('kompaniya')->get()->map(fn ($v) => $v->kompaniya->nom)

Kolleksiya metodlari «xotirada ishlaydi» degan taassurot beradi — lekin ichidagi $v->kompaniya bazaga boradi.

🔑 29 va 46-darsdagi N+1 muammosi shu yerda yangi kiyimda qaytadi: with() ni unutmang.

🔍 Model::preventLazyLoading() buni testda xatoga aylantiradi.

HOLAT 7

Resource va kolleksiya

VakansiyaResource::collection($vakansiyalar)

43-darsdagi bu yozuv ham kolleksiya ustida ishlaydi: har bir modelni Resource'ga o'raydi.

⚠️ Agar unga filter() dan chiqqan kolleksiya bersangiz, o'sha kalit muammosi qaytadi: data massiv o'rniga obyekt bo'ladi.

✅ Resource'ga berishdan oldin values().

💻 Quyida amaliyot bor. Hozir o'qish rejimidasiz — kompyuter yoningizda bo'lganda 💻 Amaliyot rejimiga o'ting va shu bo'limdan davom eting.

Sinab ko'ramiz

Natijani taxmin qiling

Dasturchi «faqat faol vakansiyalar» endpointini yozdi:

app/Http/Controllers/Api/FaolController.php
public function __invoke() { return Vakansiya::get() ->filter(fn ($v) => $v->faol) ->map(fn ($v) => ['nom' => $v->nom, 'maosh' => $v->maosh]); }

Testini ham yozdi va u yashil:

$javob = $this->getJson('/api/v1/faol'); $javob->assertOk() ->assertJsonCount(3); ← YASHIL

Ertasi kuni mobil ilova dasturchisi yozdi: «ro'yxat ba'zan bo'sh ko'rinadi, ba'zan tartibi o'zgaradi». Serverda xato yo'q. Nima bo'lyapti?

Javobni ko'rish

filter() kalitlarni saqlaydi. Agar birinchi vakansiya faol bo'lmasa, kalitlar 0 dan boshlanmaydi — va JSON massiv o'rniga obyekt bo'lib chiqadi:

// hamma faol bo'lsa: [ {...}, {...}, {...} ] ✅ massiv // birinchisi faol bo'lmasa: { "1": {...}, "2": {...}, "3": {...} } ⚠️ obyekt

⚠️ Mobil ilova javob.map(...) yozgan bo'lsa, obyektda u ishlamaydi — ro'yxat bo'sh ko'rinadi. Va obyekt kalitlarining tartibi kafolatlanmagani uchun tartib ham o'zgaradi.

🔑 Nega test tutmadi? assertJsonCount(3) massivda ham, obyektda ham 3 beradi. Test sonini tekshirgan, shaklini emas.

✅ shaklni tekshiradigan test: expect(array_keys($javob->json()))->toBe([0, 1, 2]); // yoki expect($javob->json())->toBeArray();

✅ Yechim bitta so'z: zanjir oxiriga ->values().

🔍 Umumiy saboq: «ba'zan ishlaydi» degan shikoyat deyarli har doim ma'lumotga bog'liq xatoni bildiradi. Bu yerda: birinchi yozuv faol bo'lsa ishlaydi, bo'lmasa yo'q.

SAVOL 1 filter() dan keyin JSON'da nima bo'ladi?

🔍 O'lchandi: collect([1..6])->filter(juft)->toJson() → {"1":2,"3":4,"5":6}. Xuddi shu narsa sort, where, unique dan keyin ham. ✅ JSON'ga ketayotgan bo'lsa — values(). 🔑 groupBy dan keyin esa kerak emas: u yerda kalitlar ma'noli.

SAVOL 2 avg('maosh') va sum/count nega farq qiladi?

🔍 O'lchandi: 6 yozuv, 1 tasining maoshi null. avg → 1900 (9500/5), sum/count → 1583.3 (9500/6). ⚠️ Bo'sh kolleksiyada avg() → NULL. 🔑 Ikkalasi ham to'g'ri — savolga bog'liq.

SAVOL 3 cursor() ning get() dan farqi nimada?

🔍 20 006 yozuvda o'lchandi: get() 54 MB, cursor() 24 MB. Yalqov zanjir erta ham to'xtaydi: take(3) uchun atigi 2510 yozuv o'qildi. ⚠️ Uchinchi variant teskarisi: qayta yurilganda cursor() bazaga yana so'rov yuboradi.

Eslab ayting

Javobni ovoz chiqarib ayting, keyin ochib solishtiring.

Qaysi metodlardan keyin values() kerak va nega?
Kalitni o'zgartiradigan yoki yo'qotadiganlardan keyin: filter, reject, where, sortBy, sortByDesc, sort, unique, skip. Sabab: kalitlar saqlanadi, nol'dan boshlanmagan ketma-ketlik esa JSON'da massiv bo'la olmaydi — obyekt bo'lib chiqadi. 🔑 groupBy dan keyin kerak emas: u yerda kalitlar ma'lumotning o'zi.
avg() ning tuzog'i nima?
U null qiymatlarni hisobga olmaydi — bo'luvchi jami yozuv soni emas, faqat qiymati bor yozuvlar soni. 🔍 O'lchandi: avg 1900, sum/count 1583.3. ⚠️ Bo'sh kolleksiyada NULL qaytaradi, round() esa uni 0 qiladi. ✅ round((float) $v->avg(...)) yoki ochiq isEmpty() tekshiruvi.
Kolleksiyadagi where va Eloquent'dagi where farqi?
Vakansiya::where(...)->get() — SQL: baza faqat keraklisini qaytaradi. Vakansiya::get()->where(...) — xotirada: hamma yozuv olinadi, keyin filtrlanadi. 🔑 get() qaysi tomonda turganiga qarang. ⚠️ Kolleksiya where i qat'iy solishtirmaydi — qat'iylik uchun whereStrict().
cursor(), chunk() va get() qachon ishlatiladi?
get() — yuzlab yozuv, bir necha marta ishlatiladi, JSON'ga ketadi. cursor() — minglab yozuv, bir marta yuriladi (eksport, hisobot). chunk() — minglab yozuv va har qismda yozish bor. 🔍 O'lchandi (20 006 yozuv): 54 · 24 · 24 · 26 MB.
Yalqov zanjirning eng katta foydasi nima?
Erta to'xtash. 🔍 O'lchandi: 20 006 yozuvdan «maoshi 3000 dan yuqori birinchi 3 tasi» uchun atigi 2510 yozuv o'qildi. Oddiy kolleksiyada bunday bo'lmaydi: get() avval hammasini o'qiydi. ⚠️ Lekin each() ishlatsangiz bu foyda yo'qoladi — u hammasini yuradi.
Xulosa
  • get() massiv emas — Eloquent\Collection, u Support\Collection dan meros oladi.
  • Zanjir foreach dan qisqa emas — bosqichlarga ajratilgan. Ovoz chiqarib o'qib bo'lmasa, bo'lib yuboring.
  • ⚠️ filter() kalitlarni saqlaydi → JSON massiv emas, obyekt. O'lchandi: {"1":2,"3":4,"5":6}.
  • ✅ JSON'ga ketayotgan bo'lsa — values(). groupBy dan keyin esa kerak emas.
  • ⚠️ Haqiqiy API'da bu «ba'zan bo'sh ro'yxat» va «tartib o'zgaradi» bo'lib ko'rinadi — kalitlar 2, 0, 4 bo'lib chiqdi.
  • Kolleksiya o'zgarmas: har metod yangi obyekt qaytaradi. Istisno — transform().
  • pluck('kompaniya.nom') — nuqta bilan bog'lanishga kirish.
  • ⚠️ avg() null larni hisobga olmaydi: 1900 va 1583.3. Bo'sh kolleksiyada NULL.
  • $v->sum->maosh — yuqori tartibli proksi, 51-darsdagi sehrli metodlar mexanizmida.
  • ⚠️ get()->where(...) — SQL emas, xotirada. get() qaysi tomonda turganiga qarang.
  • cursor()/lazy() → LazyCollection. 🔍 20 006 yozuvda 54 MB va 24 MB.
  • Yalqov zanjir erta to'xtaydi: take(3) uchun 20 006 dan 2510 yozuv.
  • ⚠️ Zanjir ichida $v->kompaniya yozsangiz N+1 qaytadi — with() ni unutmang.
🌱 Keyingi dars

Bugungi statistika controlleri bitta ish qildi: ma'lumotni shakllantirdi. Lekin ilovada ko'pincha bitta voqea bir nechta ishni boshlaydi.

Vakansiya yaratilganda: xabar yuborish (49-darsda qo'shdik) · statistikani yangilash · qidiruv indeksiga qo'shish · adminga bildirish. Hozir bularning hammasi store() metodiga yig'ilib boradi.

53-darsda Events va Listeners bilan bu zanjirni uzamiz: controller «vakansiya yaratildi» deb e'lon qiladi, kim eshitishi esa uning ishi emas.
