DARS 26 · MODUL C — MA'LUMOTLAR

Bog'lanish: $v->kompaniya->nom

25-darsda kod qisqardi, lekin bitta narsa yo'qoldi: ro'yxatdagi kompaniya nomi. Bugun uni qaytaramiz — va shu bilan birga 22-darsdagi JOIN ni kodga aylantiramiz. Modelga bir marta ikki qator yozasiz, keyin butun ilovada $v->kompaniya->nom deb yozish kifoya.

📱 O'qish ≈ 16 daqiqa 💻 Amaliyot ≈ 24 daqiqa Kerak: Dars 25

Bu darsda nimalar bor
  1. belongsTo — «kimga tegishli» Vakansiya → kompaniya. Tashqi kalitni ushlab turgan tomon. $v->kompaniya bitta obyekt qaytaradi.
  2. hasMany — «kimlarga ega» Kompaniya → vakansiyalar. Teskari tomon. $k->vakansiyalar to'plam (Collection) qaytaradi.
  3. Laravel ustun nomini qanday taxmin qiladi belongsTo — metod nomidan, hasMany — klass nomidan. Ikkalasi ham _id qo'shadi.
  4. Xossa va metod farqi $k->vakansiyalar — tayyor natija; $k->vakansiyalar() — so'rov, ustiga where/orderBy qo'shish mumkin.
  5. Har xil holatlar (7 ta) Nom mos kelmaganda · bog'lanish NULL bo'lganda (3 xil yozish) · bog'lanish orqali yaratish · filtrlash (whereHas) · sanash (withCount) · keyin biriktirish (associate) · uzoq bog'lanish.
  6. N+1 muammosi va with() So'rovlar sonini o'lchab ko'rasiz: 5 → 2 → 1. Bu Modul H dagi tezlik darsining poydevori.
  7. IshTop'da natija Ro'yxatga kompaniya ustuni qaytadi; vakansiya sahifasida «shu kompaniyaning boshqa vakansiyalari» bo'limi paydo bo'ladi.
  8. Nullsafe operator ?-> Bo'sh bog'lanishni xatosiz o'qish usuli — va u ?? bilan qanday birga ishlatiladi.
Nega bu muhim

Real ilovada hech bir ma'lumot yolg'iz turmaydi. Vakansiya kompaniyaga tegishli, ariza nomzodga, izoh maqolaga. IshTop'ning qolgan qismi (ariza, ko'nikma, ish beruvchi) butunlay shu tushunchaga tayanadi.

22-darsda buni JOIN bilan yechgandik — lekin har safar SELECT ... LEFT JOIN ... ON ... yozish kerak edi. Eloquent bog'lanishi esa bir marta e'lon qilinadi va butun ilovada ishlaydi. Ya'ni bilim modelda saqlanadi, controllerlarda takrorlanmaydi.

Bu intervyuning ham asosiy savoli: «hasMany va belongsTo ni tushuntirib bering», «N+1 nima?» Ikkinchi savolga javobni bugun o'lchab olasiz — taxmin qilib emas.

Ikki tomon: belongsTo va hasMany

Bazada bog'lanishni bitta ustun ushlab turadi — vakansiyalar.kompaniya_id (22-dars). Lekin unga ikki tomondan qarash mumkin, va Eloquent'da har tomon o'z metodiga ega:

kompaniyalar vakansiyalar ┌────┬─────────────┐ ┌────┬────────────────────┬──────────────┐ │ id │ nom │ │ id │ nom │ kompaniya_id │ ├────┼─────────────┤ ├────┼────────────────────┼──────────────┤ │ 1 │ Uzum │◄───────────────│ 1 │ Backend dasturchi │ 1 │ │ │ │◄───────────────│ 2 │ Frontend dasturchi │ 1 │ └────┴─────────────┘ └────┴────────────────────┴──────────────┘ hasMany ─────────────────────► «Uzum'ning vakansiyalari» (ko'plik) belongsTo ◄───────────────────── «bu vakansiya kimga tegishli» (birlik)
TomoniMetodQaytaradi
Tashqi kalit uning ichida (vakansiya)belongsToBitta obyekt yoki NULL
Tashqi kalit boshqada (kompaniya)hasManyCollection (bo'sh bo'lishi mumkin)

Qaysi birini qo'yishni qanday bilish? Savol bitta: «_id ustuni qaysi jadvalda?» Qaysi jadvalda bo'lsa, o'sha modelda belongsTo, ikkinchisida hasMany.

app/Models/Vakansiya.php
use Illuminate\Database\Eloquent\Relations\BelongsTo; class Vakansiya extends Model { protected $table = 'vakansiyalar'; public function kompaniya(): BelongsTo { return $this->belongsTo(Kompaniya::class); } }
app/Models/Kompaniya.php
use Illuminate\Database\Eloquent\Relations\HasMany; class Kompaniya extends Model { protected $table = 'kompaniyalar'; public function vakansiyalar(): HasMany { return $this->hasMany(Vakansiya::class); } }

Shundan keyin ishlatish — xossa kabi, qavssiz:

$v = Vakansiya::find(3); $v->kompaniya->nom → "Startup XYZ" get_class($v->kompaniya) → App\Models\Kompaniya $k = Kompaniya::find(1); $k->vakansiyalar->count() → 2 $k->vakansiyalar->pluck('nom')->implode(', ') → "Backend dasturchi, Frontend dasturchi"

E'tibor bering — kompaniya() metod deb e'lon qilindi, lekin $v->kompaniya deb qavssiz ishlatildi. Bu tasodif emas va keyingi bo'limning mavzusi.

Laravel ustun nomini qanday taxmin qiladi

Biz hech qayerda kompaniya_id deb yozmadik. Laravel uni o'zi topdi — lekin ikki metod ikki xil joydan taxmin qiladi:

MetodNimadan taxmin qiladiNatija
belongsToMetod nomidan: kompaniya()kompaniya + _id = kompaniya_id ✅
hasManyKlass nomidan: Kompaniyakompaniya + _id = kompaniya_id ✅
Nega bu safar o'zbekcha nom muammo bermadi

25-darsda $table ni qo'lda yozishga majbur bo'ldik, chunki Laravel ko'plik yasashga urinadi (Vakansiya → vakansiyas). Bog'lanishda esa u ko'plik yasamaydi — shunchaki _id qo'shadi. Bizning ustun aynan kompaniya_id bo'lgani uchun taxmin to'g'ri chiqdi.

🔑 Xulosa: ustunni model nomiga qarab nomlash — Kompaniya modeli → kompaniya_id ustuni — Laravel bilan urishmaslikning eng oson yo'li. Nom mos kelmasa nima bo'lishini pastda HOLAT 2 da ko'rasiz.

Tekshirish usuli (25-darsdagi getTable() ning ukasi):

(new Vakansiya)->kompaniya()->getForeignKeyName() → kompaniya_id (new Kompaniya)->vakansiyalar()->getForeignKeyName() → kompaniya_id

Xossa va metod: $k->vakansiyalar va $k->vakansiyalar()

Bu darsning eng ko'p chalkashtiradigan joyi, lekin qoida bitta:

YozilishiNima bo'ladi
$k->vakansiyalar (qavssiz)So'rov bajariladi → Collection. Tayyor natija
$k->vakansiyalar() (qavs bilan)So'rov bajarilmaydi → HasMany. Ustiga qo'shish mumkin
farqi amalda
// Tayyor natija — hammasi $k->vakansiyalar; // So'rov — ustiga shart qo'shamiz $k->vakansiyalar() ->where('faol', 1) ->orderBy('maosh', 'desc') ->get();

Va bu yerda ham sehr yo'q — 25-darsdagi toSql() ishlaydi:

$k->vakansiyalar()->toSql() select * from "vakansiyalar" where "vakansiyalar"."kompaniya_id" = ? and "vakansiyalar"."kompaniya_id" is not null

Ikki narsaga qarang: ? — parametr (21-dars), va is not null — 21-darsdagi NULL qoidasi Eloquent'ning o'z SQL'ida. Ya'ni siz o'rgangan narsa Laravel ichida ham xuddi shunday ishlaydi.

Har xil holatlar

Bog'lanish yozilishining yetti holati. Bu bo'lim ma'lumotnoma — hozir bir marta o'qib chiqing, keyin kerak bo'lganda qaytib qarang.

HOLAT 1

Nomlar mos kelganda — hech narsa yozmaymiz

Ustun kompaniya_id, metod kompaniya(), model Kompaniya. Taxmin to'g'ri, ikkinchi argument shart emas.

public function kompaniya(): BelongsTo { return $this->belongsTo(Kompaniya::class); }

Bu eng ko'p uchraydigan holat — loyihani shunday nomlashga harakat qiling.

HOLAT 2

Metod nomi ustunga mos kelmaganda — ⚠️ jimgina buziladi

Aytaylik metodni o'zbekcha ma'noliroq nomlamoqchi bo'ldik:

public function ishBeruvchi(): BelongsTo { return $this->belongsTo(Kompaniya::class); }

Laravel metod nomidan taxmin qiladi: ishBeruvchi → ish_beruvchi_id. Bunday ustun yo'q. Va endi eng xatarli qismi:

$v->ishBeruvchi → NULL Xato: yo'q Bazaga so'rov: yuborilmaydi ham

❌ Hech qanday xato yo'q. Sahifada shunchaki bo'sh joy chiqadi va siz «ma'lumot yo'q shekilli» deb o'ylaysiz. Bu ish joyida soatlab vaqt yeydigan bug'.

✅ Yechim — ikkinchi argument:

return $this->belongsTo(Kompaniya::class, 'kompaniya_id'); ↑ tashqi kalit aniq ko'rsatildi $v->ishBeruvchi->nom → "Startup XYZ" ✅

🔑 Qoida: bog'lanish NULL qaytarsa, birinchi tekshiradigan narsa — getForeignKeyName(). U sizga Laravel qaysi ustunni izlayotganini aytadi.

HOLAT 3

Bog'lanish bo'sh bo'lganda — uch xil yozish

«DevOps injener» ning kompaniya_id si NULL, demak $v->kompaniya ham NULL. To'g'ridan-to'g'ri $v->kompaniya->nom yozsangiz — xato:

Attempt to read property "nom" on null

Uchta to'g'ri yechim bor, uchalasi ham ishlaydi:

1) @if — eng ko'rinadigan, ichida boshqa narsa ham bo'lsa qulay @if ($v->kompaniya) {{ $v->kompaniya->nom }} @else — @endif 2) ?-> (nullsafe) + ?? — eng qisqasi, bitta qiymat uchun {{ $v->kompaniya?->nom ?? '—' }} 3) optional() yordamchisi — eski kodlarda uchraydi {{ optional($v->kompaniya)->nom ?? '—' }}

?-> — nullsafe operator (PHP 8): «chapdagisi null bo'lsa, davom etma, null qaytar». Ya'ni $v->kompaniya?->nom xato bermaydi, null beradi — keyin ?? uni — ga almashtiradi.

Biz 2-shaklni ishlatamiz: bitta qiymat chiqarish uchun eng toza. Bir necha qator kerak bo'lsa — @if.

HOLAT 4

Bog'lanish orqali yaratish — kompaniya_id ni yozmaymiz

Yangi vakansiyani kompaniyadan boshlab yaratsangiz, Laravel tashqi kalitni o'zi to'ldiradi:

$k = Kompaniya::where('nom', 'EPAM')->first(); $yangi = $k->vakansiyalar()->create([ 'nom' => 'Scala dasturchi', 'maosh' => 1700, ]); $yangi->kompaniya_id → 2 ← qo'lda yozmadik!

Diqqat: vakansiyalar() — qavs bilan, chunki bu so'rov (yuqoridagi qoida). Va create ishlashi uchun $fillable da nom, maosh bo'lishi kerak (25-dars).

Nima uchun bu yaxshi: kompaniya_id ni qo'lda yozganda xato raqam yozish mumkin. Bunday yozganda mumkin emas.

HOLAT 5

Bog'lanish bo'yicha filtrlash — whereHas

«Toshkentdagi kompaniyalarning vakansiyalari» kerak. Shart vakansiyada emas, bog'langan jadvalda:

Vakansiya::whereHas('kompaniya', function ($q) { $q->where('shahar', 'Toshkent'); })->count() → 4 Vakansiya::doesntHave('kompaniya')->count() → 1 Vakansiya::has('kompaniya')->count() → 4

whereHas — «bog'langan yozuvi bor va u shu shartga mos»; has — «bog'langan yozuvi bor»; doesntHave — «yo'q». Ichidagi function ($q) — 16-darsdagi closure.

Bu 22-darsdagi JOIN ... WHERE ning o'rnini bosadi, lekin takroriy qatorlar muammosi yo'q.

HOLAT 6

Sanash — withCount va nega ->count() yetmaydi

«Har kompaniyada nechta vakansiya bor?» — 22-darsda bu GROUP BY edi. Eloquent'da ikki yo'l bor, lekin bir xil emas:

❌ Kompaniya::all() ichida $k->vakansiyalar->count() → 4 so'rov (har kompaniya uchun BARCHA qatorlarni tortadi, keyin sanaydi) ✅ Kompaniya::withCount('vakansiyalar') → 1 so'rov, natija $k->vakansiyalar_count da

withCount yasagan SQL:

select "kompaniyalar".*, (select count(*) from "vakansiyalar" where "kompaniyalar"."id" = "vakansiyalar"."kompaniya_id") as "vakansiyalar_count" from "kompaniyalar"

Ustun nomi qolipi — <bog'lanish>_count. Ya'ni vakansiyalar → vakansiyalar_count.

HOLAT 7

Keyin biriktirish va ajratish — associate

Vakansiya avval kompaniyasiz yaratilgan, keyin biriktirish kerak:

$v = Vakansiya::find(5); $v->kompaniya → NULL $v->kompaniya()->associate($k); $v->save(); $v->fresh()->kompaniya->nom → "EPAM"

associate() — obyektni bog'laydi (aslida kompaniya_id ni qo'yadi), dissociate() — ajratadi (NULL qiladi). save() shart — bo'lmasa bazaga yozilmaydi.

fresh() — obyektni bazadan qaytadan o'qish. Bog'lanish bir marta o'qilgach xotirada saqlanadi, shuning uchun o'zgarishdan keyin yangilash kerak.

Muqobil yo'l — $v->kompaniya_id = $k->id; keyin save(). Natija bir xil; associate esa niyatni ko'rsatadi.

⚡ N+1 muammosi — o'lchab ko'ramiz

Bog'lanish shunchalik oson ishlaydiki, ortida nima bo'layotgani ko'rinmaydi. Ro'yxat sahifasini eslang: 5 vakansiya, har biri uchun $v->kompaniya->nom.

── with() SIZ SO'ROVLAR SONI: 5 select * from "vakansiyalar" select * from "kompaniyalar" where "kompaniyalar"."id" = ? limit 1 select * from "kompaniyalar" where "kompaniyalar"."id" = ? limit 1 select * from "kompaniyalar" where "kompaniyalar"."id" = ? limit 1 ... (yana 1 ta)

Bitta so'rov ro'yxat uchun, keyin har qator uchun bittadan. Nomi shundan: 1 + N. 5 vakansiyada bu sezilmaydi. 500 vakansiyada — 501 so'rov, va sahifa sekinlashadi.

Yechim — with(): «bularni oldindan yuklab qo'y».

── with() BILAN SO'ROVLAR SONI: 2 select * from "vakansiyalar" select * from "kompaniyalar" where "kompaniyalar"."id" in (1, 2, 3)

Ikkinchi so'rovga qarang: in (1, 2, 3) — Laravel kerakli id larni yig'ib, hammasini bitta so'rovda oldi. Va u 3 ta, chunki takrorlanganlarini tashlab yubordi. Ro'yxat 500 qator bo'lsa ham — 2 so'rov.

controller
Vakansiya::with('kompaniya') ->orderBy('maosh', 'desc') ->get();
Atamalar: lazy va eager

Lazy loading («dangasa yuklash») — bog'lanish kerak bo'lganda o'qiladi. Standart holat, va aynan u N+1 ni keltiradi.

Eager loading («intiluvchan yuklash») — with() bilan oldindan o'qiladi. Bu ikki atama intervyuda ham, hujjatlarda ham shu nomda uchraydi.

Qoida oddiy: sikl ichida bog'lanishga murojaat qilsangiz — with() yozing. Bitta yozuv uchun (masalan show sahifasi) kerak emas.

Sinab ko'ramiz

Natijani taxmin qiling

Hamkasbingiz bog'lanish metodini ma'noliroq nomlamoqchi bo'ldi va shunday yozdi (ustun nomi esa o'zgarmagan — kompaniya_id):

app/Models/Vakansiya.php
public function ishBeruvchi(): BelongsTo { return $this->belongsTo(Kompaniya::class); }

Keyin viewda {{ $v->ishBeruvchi->nom }} yozdi. Uch savol: (a) nima chiqadi? (b) xato xabari bo'ladimi? (c) bazaga nechta so'rov ketadi?

Javobni ko'rish
(a) Sahifa buziladi: Attempt to read property "nom" on null (b) Bog'lanishning o'zi xato BERMAYDI — u jimgina NULL qaytaradi (c) Kompaniyalar jadvaliga so'rov UMUMAN yuborilmaydi

Sabab: belongsTo tashqi kalit nomini metod nomidan taxmin qiladi — ishBeruvchi → ish_beruvchi_id. Bunday ustun yo'q, demak modelda bunday xossa ham yo'q → qiymat null → Laravel «bog'langan yozuv yo'q» deb hisoblaydi va so'rov yubormaydi.

Jonli o'lchandi: $v->ishBeruvchi → NULL, so'rovlar soni — faqat 1 (vakansiyaning o'zi uchun).

🔑 Nega bu xatarli: agar viewda ?-> ishlatgan bo'lsangiz, sahifa buzilmaydi ham — shunchaki bo'sh joy chiqadi. Siz esa «bazada kompaniya yo'q shekilli» deb o'ylab, bazani tekshirib vaqt yo'qotasiz.

Ikkita yechim:

1) Metodni ustun nomiga moslash (afzal): public function kompaniya() → kompaniya_id ✅ 2) Tashqi kalitni aniq ko'rsatish: return $this->belongsTo(Kompaniya::class, 'kompaniya_id');

Tashxis qo'yish usuli: bog'lanish NULL qaytarsa — getForeignKeyName() ni chaqirib, Laravel qaysi ustunni izlayotganini so'rang. Taxmin qilib emas, o'lchab.

SAVOL 1 $k->vakansiyalar va $k->vakansiyalar() farqi nimada?

Qavssiz — so'rov bajarilib Collection qaytadi. Qavs bilan — HasMany so'rovi qaytadi, ustiga where, orderBy, hatto create qo'shish mumkin.

SAVOL 2 belongsTo metodining nomi ustun nomiga mos kelmasa nima bo'ladi?

Eng xatarli xato turi — ovoz chiqarmaydigan. Tashxis: getForeignKeyName(). Yechim: metodni ustunga moslash yoki ikkinchi argument bilan aniq ko'rsatish.

SAVOL 3 with('kompaniya') nima uchun yoziladi?

Biz o'lchadik: 5 → 2. 500 qatorli ro'yxatda bu 501 → 2 bo'ladi. Qoida: sikl ichida bog'lanishga murojaat qilsangiz — with().

Eslab ayting

Avval o'zingiz javob bering, keyin ochib tekshiring. Oxirgi ikkitasi — 25-darsni takrorlash.

belongsTo ni qaysi modelga yozish kerak?

Tashqi kalit ustuni (kompaniya_id) qaysi jadvalda bo'lsa, o'sha modelga. Ikkinchisiga — hasMany.

Ikki metod tashqi kalit nomini qayerdan taxmin qiladi?

belongsTo — metod nomidan (kompaniya() → kompaniya_id); hasMany — klass nomidan (Kompaniya → kompaniya_id). Tekshirish — getForeignKeyName().

N+1 nima va qanday yechiladi?

Ro'yxat uchun 1 so'rov + har qator uchun bittadan (1 + N). Yechim — with('bog\'lanish'): Laravel kerakli id larni yig'ib bitta in (...) so'rovi yuboradi. Biz o'lchadik: 5 → 2.

↩︎ Takrorlash: $table nima uchun kerak edi?

Laravel klass nomini inglizcha ko'plikka aylantiradi: Vakansiya → vakansiyas. O'zbekcha nomlarda bu xato, shuning uchun jadval nomi qo'lda yoziladi.

↩︎ Takrorlash: $fillable da yo'q maydon nima bo'ladi?

Jimgina tashlanadi, xato yo'q. $fillable butunlay yo'q bo'lsa esa — MassAssignmentException.

Cho'ntak xulosasi
  • Tashqi kalit qaysi jadvalda — o'sha modelda belongsTo, ikkinchisida hasMany.
  • belongsTo → bitta obyekt yoki NULL · hasMany → Collection.
  • Taxmin: belongsTo metod nomidan, hasMany klass nomidan, ikkalasi ham _id qo'shadi. Tekshirish — getForeignKeyName().
  • 🔑 Qavssiz — natija, qavs bilan — so'rov. $k->vakansiyalar vs $k->vakansiyalar()->where(...)->get().
  • ⚠️ Metod nomi ustunga mos kelmasa — jimgina NULL, xato ham, so'rov ham yo'q. Yechim: nomni moslash yoki ikkinchi argument.
  • Bo'sh bog'lanish uchun uch shakl: @if · ?-> + ?? · optional().
  • Bog'lanish orqali yaratish: $k->vakansiyalar()->create([...]) — kompaniya_id o'zi qo'yiladi.
  • Filtrlash: whereHas · has · doesntHave. Sanash: withCount → <nom>_count.
  • Biriktirish: associate() / dissociate() + save(); fresh() — bazadan qayta o'qish.
  • ⚡ N+1: sikl ichida bog'lanish → 1 + N so'rov. Yechim with(): 5 → 2. Atamalar: lazy va eager loading.
🌱 Keyingi dars

Bugungi bog'lanish bir tomonlama ko'plik edi: bitta kompaniyada ko'p vakansiya, lekin bitta vakansiyada bitta kompaniya.
