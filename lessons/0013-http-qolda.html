DARS 13 · MODUL A — POYDEVOR

HTTP qo'lda: forma, GET/POST va session

Bu darsdan keyin forma yuborasiz, kelgan ma'lumotni xavfsiz chiqarasiz va foydalanuvchini so'rovlar orasida eslab qolasiz. Bu Modul A ning oxirgi «tushuncha» darsi — keyingi ikkitasida hammasini birlashtirib mini-framework yozasiz.

📱 O'qish ≈ 10 daqiqa 💻 Amaliyot ≈ 14 daqiqa Kerak: Dars 12

Nega bu muhim

1-darsda so'rov–javob aylanasini tashqaridan ko'rdik. Bugun uning ichiga kiramiz: so'rov qanday qismlardan iborat, forma ma'lumoti qayerdan keladi, va server qanday qilib «bu — o'sha foydalanuvchi» deb bilib oladi.

Laravel'da bularning hammasi tayyor: $request->input('ism'), session(), redirect(). Lekin ular ustiga qurilgan poydevor aynan bugungi narsa. Va bir narsa Laravel'da ham sizning mas'uliyatingizda qoladi: foydalanuvchi kiritgan matnni xavfsiz chiqarish. Bu — intervyuda so'raladigan XSS mavzusi.

So'rov nimadan iborat

QismPHP'daNima
Metod$_SERVER['REQUEST_METHOD']GET (o'qish) yoki POST (yuborish)
Manzil$_SERVER['REQUEST_URI']/sahifa.php?ism=Ali
Query$_GETManzildagi ? dan keyingi qism
Tana$_POSTForma yuborgan ma'lumot — manzilda ko'rinmaydi

$_GET va $_POST — oddiy assotsiativ massivlar (5-dars!). Ular PHP tomonidan avtomatik to'ldiriladi. Ya'ni yangi tushuncha emas — faqat yangi manba.

GET va POST — qachon qaysi biri

GET — o'qish uchun: qidiruv, filtr, sahifalash. Manzilda ko'rinadi, demak havolani nusxalab yuborish mumkin.
POST — o'zgartirish uchun: yaratish, tahrirlash, o'chirish. Manzilda ko'rinmaydi, brauzer uni «qayta yuborilsinmi?» deb so'raydi.
Qoida: ma'lumotni o'zgartiradigan amal hech qachon GET bo'lmasin. Aks holda havolani ochishning o'zi ma'lumotni o'chirib qo'yishi mumkin.

Forma va uni qabul qilish

tushuncha
<?php $xabar = ''; if ($_SERVER['REQUEST_METHOD'] === 'POST') { $ism = trim($_POST['ism'] ?? ''); $xabar = $ism === '' ? 'Ism kiritilmadi' : 'Salom, ' . htmlspecialchars($ism, ENT_QUOTES) . '!'; } ?> <form method="post"> <input type="text" name="ism"> <button type="submit">Yuborish</button> </form>

Bir necha yangi detal:

  • Bitta fayl ikki ish qiladi: GET da formani ko'rsatadi, POST da uni qabul qiladi. Shuning uchun REQUEST_METHOD ni tekshiramiz.
  • name="ism" → $_POST['ism']. Forma maydonining nomi massiv kalitiga aylanadi.
  • ?? '' — null coalescing: «agar kalit yo'q bo'lsa, bo'sh matn ol». 5-darsdagi Warning: Undefined array key ning toza yechimi.
  • trim() — chetdagi bo'sh joylarni olib tashlaydi. Foydalanuvchi faqat probel yuborsa, u bo'sh deb hisoblansin.
  • ?: — ternary: shart ? rost : yolg'on. Qisqa if/else (3-dars).

🔒 XSS: kiritilgan matnni xom holda chiqarmang

Bu darsning eng muhim qismi. Tasavvur qiling htmlspecialchars yozilmagan:

xavfli.php — SHUNDAY YOZMANG
$ism = $_POST['ism'] ?? ''; echo "Salom, {$ism}!"; // xom holda javobga tushdi

Foydalanuvchi ismi o'rniga <script>alert(1)</script> yozsa, natija:

Salom, <script>alert(1)</script>!

Bu haqiqiy HTML teg bo'lib javobga tushdi — brauzer uni kod sifatida bajaradi. Bu XSS (cross-site scripting): tajovuzkor sizning sahifangizda o'z kodini ishlatadi — cookie o'g'irlashi, forma yuborishi mumkin.

htmlspecialchars bilan esa:

Salom, &lt;script&gt;alert(1)&lt;/script&gt;!

Teg belgilar zararsiz matnga aylandi — ekranda <script> deb ko'rinadi, lekin bajarilmaydi.

Qoida — hech qachon buzmang

Tashqaridan kelgan har qanday ma'lumot HTML'ga chiqarilishidan oldin htmlspecialchars dan o'tadi. «Tashqaridan» = forma, query, baza, API — ya'ni siz yozmagan hamma narsa.

Yaxshi xabar: Blade buni o'zi qiladi. {{ $ism }} yozganingizda Laravel avtomatik htmlspecialchars qo'llaydi. Lekin buni bilib ishlating — chunki Blade'da himoyani o'chirish usuli ham bor ({!! $ism !!}), va uni bilmasdan ishlatish aynan shu teshikni ochadi.

Session: server sizni eslab qoladi

1-darsda ko'rgan muhim fakt: PHP har so'rovda noldan ishga tushadi. O'zgaruvchilar so'rov tugagach yo'qoladi. Unda sayt qanday qilib «siz kirgansiz» deb biladi?

tushuncha
session_start(); // 1) sessiyani ochadi $_SESSION['tashrif'] = ($_SESSION['tashrif'] ?? 0) + 1; // 2) yozadi/o'qiydi echo $_SESSION['tashrif']; // keyingi so'rovda ham saqlanadi

$_SESSION — yana bir assotsiativ massiv, lekin u so'rovlar orasida yashaydi. Ishlash mexanizmi ikki qismdan:

1 · Server yozadi

server-side
Ma'lumot serverda saqlanadi (odatda faylda). Brauzer uni ko'rmaydi

2 · Kalit beriladi

cookie
Brauzerga faqat session ID — cookie'da. Bu «shkaf raqami»

3 · Brauzer qaytaradi

har so'rovda
Keyingi so'rovda cookie avtomatik yuboriladi

4 · Server topadi

$_SESSION
ID bo'yicha o'sha ma'lumotni topib, massivga soladi

Ya'ni ma'lumot serverda, kaliti brauzerda. Amaliyotda buni isbotlaysiz: cookie bilan hisoblagich 1, 2, 3 bo'lib o'sadi; cookie'siz esa har doim 1 — chunki server «siz kim ekanligingizni» bilmaydi.

session_start() chiqishdan oldin

Session cookie sarlavha (header) orqali yuboriladi, sarlavhalar esa javob tanasidan oldin ketadi. Shuning uchun session_start() hech qanday echo yoki HTML'dan oldin chaqirilishi kerak. Aks holda: Warning: session_start(): Session cannot be started after headers have already been sent. Bu 1-darsdagi qoidaning davomi: ?> dan keyin adashib qoldirilgan bo'sh qator ham javobga tushadi — va aynan shu xatoni keltiradi.

Redirect: «boshqa manzilga bor»

tushuncha
header('Location: /29-session.php'); exit; // exit SHART

header() javobga sarlavha qo'shadi; Location sarlavhasi brauzerga «boshqa manzilga o't» deydi (status 302 Found). exit shart — aks holda PHP qolgan kodni bajarishda davom etadi va siz kutmagan ish sodir bo'ladi.

Nega redirect kerak: POST → redirect → GET naqshi. Forma qabul qilingandan keyin foydalanuvchini GET sahifasiga yuborasiz, shunda u sahifani yangilaganda forma qayta yuborilmaydi. Laravel'da bu return redirect() bo'ladi.

💻 Amaliy qism kompyuterda

Amaliyotda 28-forma.php (forma + xavfsiz chiqarish) va 29-session.php (tashrif hisoblagichi + redirect) yozasiz. Ikki muhim isbot: (1) <script> yuborib, himoyali va himoyasiz kod farqini ko'rasiz; (2) cookie bilan va cookie'siz so'rov yuborib, session qanday ishlashini tasdiqlaysiz.

Amaliyot

  1. Papkaga o'ting va formani yozing

    Bitta fayl ikki ish qiladi: GET da ko'rsatadi, POST da qabul qiladi.

    cd ~/Projects/Learn/php-poydevor cat > 28-forma.php <<'EOF' <?php declare(strict_types=1); $xabar = ''; if ($_SERVER['REQUEST_METHOD'] === 'POST') { $ism = trim($_POST['ism'] ?? ''); $xabar = $ism === '' ? 'Ism kiritilmadi' : 'Salom, ' . htmlspecialchars($ism, ENT_QUOTES) . '!'; } ?> <!doctype html> <h1>Ariza formasi</h1> <?php if ($xabar !== ''): ?> <p><b><?= $xabar ?></b></p> <?php endif; ?> <form method="post"> <input type="text" name="ism" placeholder="Ismingiz"> <button type="submit">Yuborish</button> </form> <p>Metod: <?= $_SERVER['REQUEST_METHOD'] ?></p> EOF

    Kutilgan natija: jimlik.
    Yangi yozuvlar: <?= $x ?> — bu <?php echo $x; ?> ning qisqasi. if (...): ... endif; — HTML orasida qavs o'rniga ishlatiladigan shakl (o'qish osonroq).

  2. Serverni ko'tarib, formani sinab ko'ring

    php -S localhost:8000 [...] PHP 8.3.32 Development Server (http://localhost:8000) started

    Kutilgan natija: server ishlab turadi. Brauzerda http://localhost:8000/28-forma.php ni ochib, ismingizni yozib yuboring. «Metod:» qatori GET dan POST ga o'zgaradi.
    Terminal band bo'ladi — yangi oyna oching yoki keyingi qadamlarni brauzerda bajaring.

  3. 🔒 XSS'ni sinab ko'ring — himoyali kod

    Bu darsning eng muhim tajribasi. Formaga oddiy ism emas, kod yozamiz.

    Formaga aynan shuni kiritib yuboring:

    <script>alert(1)</script>

    Kutilgan natija: sahifada hech qanday oyna chiqmaydi. Matn shunchaki ko'rinadi: Salom, <script>alert(1)</script>!
    Brauzerda Ctrl+U bilan manbani ko'rsangiz — &lt;script&gt; deb yozilgan. Ya'ni teg matnga aylangan.

  4. 🔒 Endi himoyasiz kod bilan solishtiring

    Farqni o'z ko'zingiz bilan ko'rish — «har doim htmlspecialchars» qoidasini yodlashdan ishonchli.

    cat > xavfli.php <<'EOF' <?php $ism = $_POST['ism'] ?? ''; echo "Salom, {$ism}!"; EOF curl -s -X POST --data-urlencode 'ism=<script>alert(1)</script>' http://localhost:8000/xavfli.php Salom, <script>alert(1)</script>!

    Kutilgan natija: teg xom holda javobga tushdi — ya'ni brauzer uni bajaradi. Farqni ko'rdingiz: bitta funksiya bor-yo'qligi xavfsizlik teshigini ochadi yoki yopadi.
    curl ishlatdik, chunki brauzerda bu haqiqatan oyna chiqaradi. Bu faylni o'chirib tashlashni unutmang: rm xavfli.php

  5. Session bilan hisoblagich yozing

    cat > 29-session.php <<'EOF' <?php declare(strict_types=1); session_start(); $_SESSION['tashrif'] = ($_SESSION['tashrif'] ?? 0) + 1; if (($_POST['chiqish'] ?? '') !== '') { session_destroy(); header('Location: /29-session.php'); exit; } ?> <!doctype html> <p>Siz bu sahifaga <b><?= $_SESSION['tashrif'] ?></b> marta kirdingiz.</p> <form method="post"> <button type="submit" name="chiqish" value="1">Hisobni tozalash</button> </form> EOF

    Kutilgan natija: jimlik. Brauzerda http://localhost:8000/29-session.php ni ochib, sahifani bir necha marta yangilang — raqam o'sib boradi. «Hisobni tozalash» bosilsa 1 ga qaytadi.

  6. Session cookie'ga bog'liqligini isbotlang

    Ma'lumot serverda, lekin kaliti brauzerda. Cookie bo'lmasa server sizni tanimaydi.

    echo '--- cookie BILAN (3 marta) ---' for i in 1 2 3; do curl -s -c /tmp/c.txt -b /tmp/c.txt http://localhost:8000/29-session.php | grep -oE '<b>[0-9]+</b>'; done echo '--- cookie SIZ (2 marta) ---' for i in 1 2; do curl -s http://localhost:8000/29-session.php | grep -oE '<b>[0-9]+</b>'; done --- cookie BILAN (3 marta) --- <b>1</b> <b>2</b> <b>3</b> --- cookie SIZ (2 marta) --- <b>1</b> <b>1</b>

    Kutilgan natija: cookie bilan 1, 2, 3; cookie'siz har doim 1. 🎉 Mana isbot: session serverda yashaydi, lekin uni topish uchun cookie'dagi kalit kerak.
    -c = cookie'ni saqla, -b = saqlanganini yubor.

  7. Redirect'ni ko'ring

    curl -s -D - -o /dev/null -c /tmp/c.txt -b /tmp/c.txt -X POST -d 'chiqish=1' http://localhost:8000/29-session.php | grep -iE 'HTTP/|location' HTTP/1.1 302 Found Location: /29-session.php

    Kutilgan natija: 302 Found va Location sarlavhasi. Javob tanasi yo'q — brauzerga faqat «boshqa yerga bor» deyilgan.

  8. Tozalang va ishni saqlang

    rm -f xavfli.php git add -A git commit -m "13-dars: HTTP qo'lda — forma, XSS, session"

    Kutilgan natija: commit haqida xabar. Serverni Ctrl+C bilan to'xtatishni unutmang.

Sinab ko'ramiz

Natijani taxmin qiling

Bir xil sahifa ikki marta so'raladi — bir marta cookie saqlanadi, bir marta yo'q. Hisoblagich nima ko'rsatadi?

terminal
# A — cookie saqlanadi curl -c /tmp/c.txt -b /tmp/c.txt .../29-session.php curl -c /tmp/c.txt -b /tmp/c.txt .../29-session.php # B — cookie saqlanmaydi curl .../29-session.php curl .../29-session.php
Javobni ko'rish
A: 1 keyin 2 B: 1 keyin 1

B da hisoblagich o'smaydi — har so'rov yangi session boshlaydi.

Sabab: $_SESSION ma'lumoti serverda saqlanadi, lekin u session ID bo'yicha topiladi. ID esa brauzerga cookie orqali beriladi. Cookie saqlanmasa, keyingi so'rovda ID kelmaydi → server «bu yangi mehmon» deb o'ylab, yangi bo'sh session yasaydi.

Nega bu muhim: bu «foydalanuvchi tizimga kirgan» degan holatning ham mexanizmi. Login qilganda server sessionga «bu foydalanuvchi №5» deb yozadi, va keyingi har so'rovda cookie'dagi ID orqali sizni tanib oladi. Cookie o'chirilsa — tizimdan chiqib ketasiz.

Va shu yerda XSS nega xavfli ekani ham ochiladi: tajovuzkorning JavaScript kodi cookie'ni o'qiy oladi — ya'ni session ID'ni o'g'irlab, sizning nomingizdan kirishi mumkin. Mana nega htmlspecialchars shunchaki «chiroyli chiqarish» emas, xavfsizlik chorasi.

SAVOL 1 Ma'lumotni o'zgartiradigan amal qaysi metod bilan yuborilishi kerak?

GET — o'qish uchun (qidiruv, filtr). O'zgartirish GET bo'lsa, havolani ochishning o'zi ma'lumotni o'chirib qo'yishi mumkin.

SAVOL 2 htmlspecialchars nima qiladi?

< → &lt; ga aylanadi: teg ekranda ko'rinadi, lekin brauzer uni bajarmaydi. O'chirmaydi — zararsizlantiradi.

SAVOL 3 $_SESSION ma'lumoti qayerda saqlanadi?

Ma'lumot serverda, brauzerga faqat session ID beriladi. Shuning uchun cookie'siz so'rovda hisoblagich har doim 1 bo'ldi.

Eslab ayting

Avval o'zingiz javob bering, keyin ochib tekshiring. Oxirgi ikkitasi — 12-darsni takrorlash.

$_GET va $_POST — bu qanday narsalar?

Oddiy assotsiativ massivlar (5-dars), PHP tomonidan avtomatik to'ldiriladi. $_GET — manzildagi ? dan keyingi qism, $_POST — forma tanasi.

XSS qanday yuzaga keladi va qanday to'xtatiladi?

Tashqaridan kelgan matn xom holda HTML'ga chiqarilsa, undagi teglar bajariladi. To'xtatish: chiqarishdan oldin htmlspecialchars. Blade {{ }} buni o'zi qiladi.

Nega session_start() chiqishdan oldin turadi?

Chunki session cookie sarlavha orqali yuboriladi, va sarlavhalar javob tanasidan oldin ketadi. Chiqish boshlangandan keyin sarlavha qo'shib bo'lmaydi.

↩︎ Takrorlash: use klassni yuklaydimi?

Yo'q. use faqat nomni hal qiladi; yuklashni autoload qiladi (composer dump-autoload + bitta require 'vendor/autoload.php').

↩︎ Takrorlash: catch (Exception) nimani tutmaydi?

Error avlodlarini — TypeError, DivisionByZeroError. Hammasi uchun Throwable.

Cho'ntak xulosasi
  • So'rov qismlari: $_SERVER['REQUEST_METHOD'] · REQUEST_URI · $_GET · $_POST.
  • GET = o'qish, POST = o'zgartirish. O'zgartirish hech qachon GET bo'lmasin.
  • name="ism" → $_POST['ism']. Yo'q kalit uchun ?? ''.
  • 🔒 Tashqaridan kelgan matn HTML'ga chiqishdan oldin htmlspecialchars. Blade {{ }} buni o'zi qiladi; {!! !!} esa himoyani o'chiradi.
  • $_SESSION — ma'lumot serverda, kaliti cookie'da. session_start() har qanday chiqishdan oldin.
  • header('Location: ...') + exit; — redirect (302). POST → redirect → GET naqshi.
  • <?= $x ?> = <?php echo $x; ?> · if (...): endif; — HTML orasida qulay shakl.
🌱 Kelasi darslar uchun urug'

Endi sizda hamma bo'lak bor: klass, interface, autoload, va bugungi $_SERVER['REQUEST_URI'] bilan REQUEST_METHOD.

Keyingi ikki dars — kursning yuragi. 1-darsda «URL = fayl yo'li» degan modelni ko'rgandik va «Laravel bu qoidani buzadi» deb aytgandim. 14-darsda o'sha buzilishni o'z qo'lingiz bilan yasaysiz: bitta kirish nuqtasi (public/index.php) va router. 15-darsda esa container — obyektlarni o'zi yasaydigan mexanizm. Shundan keyin Laravel ochilganda har bir qismini allaqachon yozgan bo'lasiz.
