Mini-framework 2: container va dependency injection

Modul A ning cho'qqisi. Bugun obyektlarni o'zi yasaydigan va kerakli bog'liqliklarni o'zi topib qo'yadigan container yozasiz. Bu Laravel'ning eng markaziy mexanizmi — undan keyin Laravel'da controller konstruktoriga yozilgan har bir parametr sizga tushunarli bo'ladi.

📱 O'qish ≈ 12 daqiqa 💻 Amaliyot ≈ 18 daqiqa Kerak: Dars 14

Bu darsda nimalar bor
  1. Bog'liqlikni e'lon qilish Controller o'ziga nima kerakligini konstruktorda aytadi (dependency injection).
  2. Container Obyektlarni yasab beradigan 35 qatorli klass.
  3. 🔍 Reflection «Sehr»ning haqiqiy nomi: PHP klassdan «senga nima kerak?» deb so'ray oladi.
  4. Autowiring Container tiplarga qarab bog'liqlikni o'zi topadi.
  5. Rekursiya Bog'liqlikning bog'liqligi ham yasaladi.
  6. Router container'ni ishlatadi Ikki dars birlashib mini-framework bo'ladi.
Nega bu muhim

14-darsdagi router shunday qildi:

$controller = new $klass(); // hech qanday argument yo'q

Demak controller hech narsa qabul qila olmaydi. Lekin real controller'ga ma'lumot kerak — vakansiyalar ro'yxati bazadan, xabar yuboruvchi, sozlamalar.

Birinchi xayolga keladigan yechim — controller ularni o'zi yasasin:

class Vakansiyalar implements Controller { public function handle(): string { $repo = new MySqlRepo(); // ← muammo shu yerda ... } }

Bu qattiq bog'lanish: controller aynan MySqlRepo ga bog'lanib qoldi. Testda soxta ma'lumot berish mumkin emas, bazani almashtirish uchun controllerni tahrirlash kerak — ya'ni 10-darsda aytgan muammo qaytdi.

Yechim: controller nima kerakligini aytadi, yasashni esa boshqa narsa qiladi. O'sha boshqa narsa — container.

1-qadam: controller nima kerakligini e'lon qiladi

src/Controllers/Vakansiyalar.php
class Vakansiyalar implements Controller { public function __construct(private VakansiyaRepo $repo) {} public function handle(): string { foreach ($this->repo->hammasi() as $nom) { ... } } }

Bu dependency injection (bog'liqlikni tashqaridan berish). Diqqat qiling — tip interface (VakansiyaRepo), aniq klass emas. Controller «menga hammasi() ni biladigan narsa kerak» deydi, «menga aynan MySQL kerak» demaydi. 10-darsdagi g'oya — shartnomaga tayanish.

Foydasi darhol ko'rinadi: testda soxta VakansiyaRepo berasiz, ishlab chiqarishda haqiqiysini — controller farqini bilmaydi.

Lekin savol paydo bo'ldi: kim uni yasaydi? Router'da new $klass() bor, u argument bermaydi. Va agar bersa ham — router qayerdan bilsin qaysi controllerga nima kerakligini?

2-qadam: container

Container — bu obyekt yasovchi. Uning ikki vazifasi bor:

MetodNima qiladi
bind($nom, $klass)«VakansiyaRepo so'ralsa, XotiraRepo ni ber» — interface va uning bajarilishini bog'laydi
make($nom)Obyekt yasaydi — va kerakli bog'liqliklarni o'zi topib qo'yadi
src/Container.php
class Container { private array $bindings = []; public function bind(string $nom, string $klass): void { $this->bindings[$nom] = $klass; } public function make(string $nom): object { $klass = $this->bindings[$nom] ?? $nom; $reflector = new \ReflectionClass($klass); if (! $reflector->isInstantiable()) { throw new \Exception("Container yasay olmadi: {$klass} — bind() qilinganmi?"); } $konstruktor = $reflector->getConstructor(); if ($konstruktor === null) { return new $klass(); } $argumentlar = []; foreach ($konstruktor->getParameters() as $parametr) { $tip = $parametr->getType(); if ($tip === null || $tip->isBuiltin()) { throw new \Exception("Container yasay olmadi: {$klass} ning \${$parametr->getName()} parametri klass emas"); } $argumentlar[] = $this->make($tip->getName()); } return $reflector->newInstanceArgs($argumentlar); } }

🔍 Reflection — «sehr»ning haqiqiy nomi

Butun mexanizm bitta narsaga tayanadi: ReflectionClass. Bu PHP'ning o'z kodiga qarash qobiliyati. Ya'ni dastur ishlab turganda:

  • «Bu klassdan obyekt yasash mumkinmi?» → isInstantiable() (interface va abstract uchun yo'q — 9 va 10-darslar)
  • «Konstruktori bormi?» → getConstructor()
  • «Konstruktori qanday parametrlar kutadi?» → getParameters()
  • «Bu parametrning tipi nima?» → getType() (6-darsdagi type hint — mana u nima uchun ham kerak edi!)
Mana «sehr» nima edi

Laravel controller konstruktoriga Request $request deb yozsangiz, u obyektni «qandaydir tarzda» o'zi beradi. Endi bilasiz qanday: framework Reflection bilan konstruktoringizga qaraydi, tiplarni o'qiydi va har birini yasab beradi. Hech qanday sehr yo'q — type hint o'qiladi va shunga qarab obyekt yasaladi.

Bu autowiring deb ataladi: «simlarni o'zi ulash».

Rekursiya: bog'liqlikning bog'liqligi

Diqqat qiling — $this->make($tip->getName()) o'zini chaqiradi. Shuning uchun zanjir qanchalik uzun bo'lsa ham ishlaydi:

make(Vakansiyalar) → konstruktorda VakansiyaRepo kerak → bindings'da qaraydi → XotiraRepo → XotiraRepo ning konstruktori yo'q → new XotiraRepo() → new Vakansiyalar($xotiraRepo)

Agar XotiraRepo ga ham nimadir kerak bo'lsa, container yana pastga tushadi. Siz faqat «menga Vakansiyalar ber» deysiz — qolganini u hal qiladi.

Router endi container'ni ishlatadi

src/Router.php — ikki o'zgarish
class Router { public function __construct(private Container $container) {} public function dispatch(string $metod, string $yol): string { ... $controller = $this->container->make($klass); return $controller->handle(); } }

Router ham DI ishlatadi — unga container tashqaridan beriladi. Va new $klass() o'rniga $container->make($klass). Boshqa hech narsa o'zgarmadi.

public/index.php — sozlash joyi
$container = new Container(); $container->bind(VakansiyaRepo::class, XotiraRepo::class); $router = new Router($container); $router->add('GET', '/vakansiyalar', Vakansiyalar::class);

Mana butun ilovaning sozlash nuqtasi: bitta joyda «qaysi interface uchun qaysi bajarilish». Bazani almashtirmoqchi bo'lsangiz — bitta qatorni o'zgartirasiz, controllerlarga tegmaysiz.

Bizning container'ning cheklovi — halol aytaman

make() har chaqirilganda yangi obyekt yasaydi. Ya'ni bir so'rov ichida Container ikki marta so'ralsa, ikki xil obyekt chiqadi. Ba'zi narsalar uchun bu yaroqsiz — masalan bazaga ulanish bitta bo'lishi kerak.

Buning yechimi singleton deb ataladi: «bir marta yasa, keyin o'shani qaytar». Laravel'da bu $this->app->singleton(...). Biz uni bugun yozmaymiz — G modulida (Laravel ichki mexanizmi) Laravel'ning haqiqiy container'ini o'rganganda qaytamiz.

💻 Amaliy qism kompyuterda

Amaliyotda VakansiyaRepo interface'i va uning bajarilishini yozasiz, controller'ni DI qabul qiladigan qilib o'zgartirasiz, Container ni yozasiz va router'ni unga ulaysiz. Keyin uchta holatni sinaysiz: normal ishlash, bind() qilinmagan holat va oddiy tipli parametr — ikkalasi ham tushunarli xabar beradi.

Amaliyot

  1. Papkaga o'ting

    cd ~/Projects/Learn/php-poydevor

    Kutilgan natija: jimlik.

  2. Shartnoma va uning bajarilishini yozing

    Interface — «nima qila oladi», klass — «qanday qiladi» (10-dars).

    cat > src/VakansiyaRepo.php <<'EOF' <?php declare(strict_types=1); namespace App; interface VakansiyaRepo { public function hammasi(): array; } EOF cat > src/XotiraRepo.php <<'EOF' <?php declare(strict_types=1); namespace App; class XotiraRepo implements VakansiyaRepo { public function hammasi(): array { return ['Backend dasturchi', 'Frontend dasturchi']; } } EOF

    Kutilgan natija: jimlik. XotiraRepo — «xotiradagi» soxta ma'lumot. Keyinchalik uning o'rniga bazadan o'qiydiganini yozasiz, va controllerga tegmaysiz.

  3. Container'ni yozing — darsning yuragi

    cat > src/Container.php <<'EOF' <?php declare(strict_types=1); namespace App; class Container { private array $bindings = []; public function bind(string $nom, string $klass): void { $this->bindings[$nom] = $klass; } public function make(string $nom): object { $klass = $this->bindings[$nom] ?? $nom; $reflector = new \ReflectionClass($klass); if (! $reflector->isInstantiable()) { throw new \Exception("Container yasay olmadi: {$klass} — bind() qilinganmi?"); } $konstruktor = $reflector->getConstructor(); if ($konstruktor === null) { return new $klass(); } $argumentlar = []; foreach ($konstruktor->getParameters() as $parametr) { $tip = $parametr->getType(); if ($tip === null || $tip->isBuiltin()) { throw new \Exception("Container yasay olmadi: {$klass} ning \${$parametr->getName()} parametri klass emas"); } $argumentlar[] = $this->make($tip->getName()); } return $reflector->newInstanceArgs($argumentlar); } } EOF

    Kutilgan natija: jimlik. 35 qator — va shu 35 qator Laravel'ning eng markaziy g'oyasini o'z ichiga oladi.

  4. Controller'ni DI qabul qiladigan qiling

    cat > src/Controllers/Vakansiyalar.php <<'EOF' <?php declare(strict_types=1); namespace App\Controllers; use App\Controller; use App\VakansiyaRepo; class Vakansiyalar implements Controller { public function __construct(private VakansiyaRepo $repo) {} public function handle(): string { $qatorlar = ''; foreach ($this->repo->hammasi() as $nom) { $qatorlar .= "<li>{$nom}</li>"; } return "<h1>Vakansiyalar</h1><ul>{$qatorlar}</ul>"; } } EOF

    Kutilgan natija: jimlik. Diqqat: controller XotiraRepo haqida hech narsa bilmaydi — faqat VakansiyaRepo shartnomasini biladi.

  5. Container'ni to'g'ridan-to'g'ri sinab ko'ring

    Router'ga ulashdan oldin, mexanizm o'zi ishlashini tasdiqlaymiz.

    php -r ' require "vendor/autoload.php"; $c = new App\Container(); $c->bind(App\VakansiyaRepo::class, App\XotiraRepo::class); echo $c->make(App\Controllers\Vakansiyalar::class)->handle(), PHP_EOL; ' <h1>Vakansiyalar</h1><ul><li>Backend dasturchi</li><li>Frontend dasturchi</li></ul>

    Kutilgan natija: ro'yxat chiqdi. 🎉 Nima sodir bo'ldi: siz faqat «Vakansiyalar ber» dedingiz. Container uning konstruktoriga qaradi, VakansiyaRepo kerakligini o'qidi, bindings'da XotiraRepo ni topdi, uni yasadi va controllerga berdi. Siz XotiraRepo ni hech qayerda new qilmadingiz.

  6. Router'ni container'ga ulang

    cat > src/Router.php <<'EOF' <?php declare(strict_types=1); namespace App; class Router { private array $routes = []; public function __construct(private Container $container) {} public function add(string $metod, string $yol, string $controller): void { $this->routes[$metod][$yol] = $controller; } public function dispatch(string $metod, string $yol): string { $klass = $this->routes[$metod][$yol] ?? null; if ($klass === null) { throw new RouteTopilmadi("Route topilmadi: {$metod} {$yol}"); } $controller = $this->container->make($klass); return $controller->handle(); } } EOF

    Kutilgan natija: jimlik. Faqat ikki qator o'zgardi.

  7. Kirish nuqtasini yangilang

    cat > public/index.php <<'EOF' <?php declare(strict_types=1); require __DIR__ . '/../vendor/autoload.php'; use App\Container; use App\Router; use App\RouteTopilmadi; use App\VakansiyaRepo; use App\XotiraRepo; use App\Controllers\BoshSahifa; use App\Controllers\Vakansiyalar; $container = new Container(); $container->bind(VakansiyaRepo::class, XotiraRepo::class); $router = new Router($container); $router->add('GET', '/', BoshSahifa::class); $router->add('GET', '/vakansiyalar', Vakansiyalar::class); $metod = $_SERVER['REQUEST_METHOD']; $yol = parse_url($_SERVER['REQUEST_URI'], PHP_URL_PATH); try { echo $router->dispatch($metod, $yol); } catch (RouteTopilmadi $e) { http_response_code(404); echo "<h1>404</h1><p>", htmlspecialchars($e->getMessage()), "</p>"; } EOF

    Kutilgan natija: jimlik.

  8. Butun ilovani brauzerda sinang

    php -S localhost:8000 public/index.php

    Kutilgan natija: server ishlaydi. Boshqa oynada:

    curl -s http://localhost:8000/vakansiyalar; echo <h1>Vakansiyalar</h1><ul><li>Backend dasturchi</li><li>Frontend dasturchi</li></ul>

    🎉 Sizda ishlaydigan mini-framework bor: front controller, router, container va DI.

  9. bind() ni olib tashlab, xatoni ko'ring

    Bu xato Laravel'da ham eng ko'p uchraydiganlardan biri — uni tanib olish muhim.

    php -r ' require "vendor/autoload.php"; $c = new App\Container(); $c->make(App\Controllers\Vakansiyalar::class); ' 2>&1 | head -1 PHP Fatal error: Uncaught Exception: Container yasay olmadi: App\VakansiyaRepo — bind() qilinganmi?

    Kutilgan natija: xabar yechimni aytadi. Sababi: container VakansiyaRepo ni yasashga urindi, lekin u interface — undan obyekt yasab bo'lmaydi (10-dars).
    Laravel'da xuddi shu holatda: Target [App\VakansiyaRepo] is not instantiable. Endi bu xabar sizga tushunarli.

    git add -A git commit -m "15-dars: container va DI — Modul A tugadi"

Sinab ko'ramiz

Natijani taxmin qiling

Container'da hech qanday bind() yo'q. Uch chaqiruv nima qaytaradi?

taxmin.php
$c = new Container(); A) $c->make(XotiraRepo::class); B) $c->make(VakansiyaRepo::class); C) $c->make(Vakansiyalar::class);
Javobni ko'rish
A) ✅ ishlaydi — XotiraRepo obyekti B) ❌ Exception: ... App\VakansiyaRepo — bind() qilinganmi? C) ❌ Exception: ... App\VakansiyaRepo — bind() qilinganmi?

A ishlaydi — XotiraRepo oddiy klass, konstruktori yo'q. bind() kerak emas: bindings'da topilmasa, container nomni o'zini klass deb oladi ($this->bindings[$nom] ?? $nom).

B xato beradi — VakansiyaRepo bu interface, undan obyekt yasab bo'lmaydi (9 va 10-darslar). Container buni isInstantiable() bilan aniqlaydi va tushunarli xabar beradi.

C ham xato beradi — va sabab B bilan bir xil. Vakansiyalar ning o'zi yasalishi mumkin, lekin uning konstruktorida VakansiyaRepo kerak. Container rekursiv ravishda uni yasashga tushadi va shu yerda to'xtaydi. Xato xabari ham aynan o'sha interface'ni ko'rsatadi, Vakansiyalar ni emas — chunki muammo pastda.

Amaliy xulosa: Laravel'da Target [...] is not instantiable xatosini ko'rsangiz, javob deyarli har doim bitta: interface uchun bajarilish bog'lanmagan. Yechim — service provider'da bind() yozish. Bu G modulida (Service Provider) batafsil ko'riladi.

SAVOL 1 Container controller'ga nima kerakligini qanday biladi?

ReflectionClass bilan konstruktorga qaraydi va parametr tiplarini o'qiydi. Mana 6-darsdagi type hint nima uchun ham kerak edi — u shunchaki hujjat emas, mashina o'qiydigan ma'lumot.

SAVOL 2 bind() nima uchun kerak?

Interface'dan obyekt yasab bo'lmaydi, shuning uchun container'ga «VakansiyaRepo so'ralsa XotiraRepo ber» deb aytish kerak. Oddiy klasslar uchun bind() shart emas.

SAVOL 3 Nega controller XotiraRepo emas, VakansiyaRepo ni so'raydi?

Shartnomaga tayanish (10-dars): testda soxta repo, keyinroq bazadan o'qiydigan repo — controllerga tegilmaydi. O'zgartiriladigan joy bitta: index.php dagi bind().

Eslab ayting

Avval o'zingiz javob bering, keyin ochib tekshiring. Oxirgi ikkitasi — 14-darsni takrorlash.

Dependency injection nima — bir gapda?

Obyekt kerakli narsalarni o'zi yasamaydi, ularni tashqaridan (odatda konstruktor orqali) qabul qiladi. Shunda u aniq klasslarga bog'lanmaydi.

Reflection nima va container'da nima uchun kerak?

PHP'ning o'z kodiga qarash qobiliyati. Container u bilan konstruktorni topadi, parametr tiplarini o'qiydi va har birini yasab beradi. Bu autowiring.

Bizning container'ning asosiy cheklovi nima?

make() har chaqirilganda yangi obyekt yasaydi. Bazaga ulanish kabi narsalar uchun singleton kerak («bir marta yasa, keyin o'shani qaytar») — G modulida ko'ramiz.

↩︎ Takrorlash: front controller qanday muammolarni yechadi?

Takrorlanish (sozlash bir joyda), markaziy nazorat, chiroyli manzil, xavfsizlik (faqat public/ ochiq).

↩︎ Takrorlash: router controller'lar haqida nima biladi?

Faqat handle() metodi borligini — interface Controller shartnomasi orqali. Shuning uchun yangi sahifa qo'shilganda Router.php ga tegilmaydi.

Cho'ntak xulosasi
  • DI: obyekt kerakli narsani konstruktorda e'lon qiladi, o'zi yasamaydi. Tip — interface, aniq klass emas.
  • Container — obyekt yasovchi. bind(interface, klass) + make($nom).
  • 🔑 Reflection — PHP o'z kodiga qaraydi: isInstantiable() · getConstructor() · getParameters() · getType().
  • Bu autowiring: type hint o'qiladi va shunga qarab obyekt yasaladi. «Sehr»ning haqiqiy nomi shu.
  • make() rekursiv — bog'liqlikning bog'liqligi ham yasaladi.
  • Sozlash bitta joyda: index.php dagi bind(). Bazani almashtirish = bitta qator.
  • «bind() qilinganmi?» xatosi = Laravel'dagi Target [...] is not instantiable.
  • Cheklov: singleton yo'q — har make() yangi obyekt yasaydi.
🎓 MODUL A TUGADI — nima qildingiz

15 dars oldin PHP faylini brauzerda ochishdan boshladingiz. Bugun sizda ishlaydigan mini-framework bor:

  • Front controller — hamma so'rov bitta nuqtadan o'tadi, faqat public/ ochiq
  • Router — metod + yo'l → controller, 404 exception bilan
  • Container — Reflection bilan autowiring va interface bog'lanishi
  • Ustiga: namespace, autoload, Composer, OOP, exception, XSS himoyasi

Endi eng qiziq qismi. 16-darsdan Laravel ochiladi — va siz u yerda public/index.php, routes/web.php, controller konstruktoriga yozilgan tiplar, Target is not instantiable xatosini ko'rganda hech qanday sehr topmaysiz. Chunki har birini o'z qo'lingiz bilan yozgansiz.

Aynan shu — kursning butun maqsadi edi. Modul A ning eng qimmatli natijasi yozilgan kod emas, «bu narsa qanday ishlayotganini bilaman» degan holat.
