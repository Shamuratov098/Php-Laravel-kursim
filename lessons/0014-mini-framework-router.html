DARS 14 · MODUL A — POYDEVOR

Mini-framework 1: front controller va router

Bu kursning eng muhim ikki darsidan birinchisi. Bugun 1-darsda ko'rgan «URL = fayl yo'li» qoidasini o'z qo'lingiz bilan buzasiz: bitta kirish nuqtasi va router yozasiz. Shundan keyin Laravel'ning routes/web.php fayli sizga sehr emas, tanish mexanizm bo'lib ko'rinadi.

📱 O'qish ≈ 11 daqiqa 💻 Amaliyot ≈ 18 daqiqa Kerak: Dars 13

Nega bu muhim

Hozirgacha har sahifa alohida fayl edi: 28-forma.php, 29-session.php. Bu kichik mashqlar uchun yetadi, lekin real loyihada to'rtta muammo chiqadi:

  1. Takrorlanish. Har fayl o'zini o'zi sozlashi kerak: autoload, session_start(), sozlamalar. Aynan bir xil qatorlar 50 faylda.
  2. Markaziy nazorat yo'q. «Har so'rovni logga yoz» yoki «kirmagan odamni to'sib qo'y» degan qoidani bitta joyda yozib bo'lmaydi.
  3. Chiroyli manzil yo'q. /vakansiyalar/12 degan URL uchun shunday nomli fayl yo'q — demak bunday manzil ham bo'lmaydi.
  4. Xavfsizlik. Barcha PHP fayllari brauzerga ochiq. Kimdir /src/Router.php ni so'rasa nima bo'ladi?

Yechim bitta va u front controller deb ataladi: hamma so'rov bitta faylga keladi, va o'sha fayl nima qilish kerakligini hal qiladi. Laravel ham, Symfony ham, deyarli barcha zamonaviy framework ham shunday ishlaydi.

Front controller: bitta kirish nuqtasi

1 · Har so'rov

/ · /vakansiyalar · /yoq
Manzil qanday bo'lishidan qat'i nazar

2 · Bitta fayl

public/index.php
Hammasi shu yerga keladi. Sozlash bir marta

3 · Router qaraydi

jadval
Metod + yo'l → qaysi controller

4 · Controller javob beradi

handle()
Yoki topilmasa — 404

Papka tuzilishi va nega public/

php-poydevor/ tuzilishi
public/ index.php ← brauzerga OCHIQ bo'lgan yagona fayl src/ Controller.php ← shartnoma (interface) Router.php ← yo'l jadvali RouteTopilmadi.php ← 404 uchun exception Controllers/ BoshSahifa.php Vakansiyalar.php vendor/ ← yashirin composer.json ← yashirin

Server faqat public/ papkasini ko'rsatadi. Qolgan hamma narsa — kodingiz, kutubxonalar, sozlamalar — brauzer uchun mavjud emas. Bu jiddiy xavfsizlik chorasi: hujumchi .env yoki kod faylini so'rab ololmaydi.

Laravel'da xuddi shunday

Laravel loyihasida ham public/index.php bor va u ham yagona ochiq fayl. Uning ichidagi birinchi ishlardan biri — require __DIR__.'/../vendor/autoload.php'; — ya'ni 12-darsda yozgan qatoringiz. 16-darsda IshTop loyihasini yaratganda buni o'z ko'zingiz bilan ko'rasiz.

Router: yo'l jadvali

Router — bu shunchaki jadval (5-darsdagi massiv!) va uni o'qiydigan ikki metod:

src/Router.php
class Router { private array $routes = []; public function add(string $metod, string $yol, string $controller): void { $this->routes[$metod][$yol] = $controller; } public function dispatch(string $metod, string $yol): string { $klass = $this->routes[$metod][$yol] ?? null; if ($klass === null) { throw new RouteTopilmadi("Route topilmadi: {$metod} {$yol}"); } $controller = new $klass(); return $controller->handle(); } }

Butun router — 20 qator. Ichida sehr yo'q, faqat oldingi darslardagi narsalar:

  • $routes[$metod][$yol] — ichma-ich assotsiativ massiv (5-dars). Metod ham kalit, chunki GET / va POST / — ikki boshqa route.
  • ?? null — topilmasa null (13-dars).
  • throw new RouteTopilmadi(...) — 11-darsdagi o'z exception klassim. 404 ni shu bilan hal qilamiz.
  • new $klass() — yangi narsa: klass nomi o'zgaruvchida turishi mumkin. $klass ichida "App\Controllers\BoshSahifa" matni bor, va PHP shu nomli klassdan obyekt yasaydi. Autoload (12-dars) faylni o'zi topadi.
  • $controller->handle() — har controller shu metodga ega, chunki...

...chunki shartnoma bor

src/Controller.php
interface Controller { public function handle(): string; }

Mana 10-darsning foydasi amalda. Router controller'lar haqida hech narsa bilmaydi — u faqat «handle() ni biladigan narsa» kutadi. Yangi sahifa qo'shish uchun:

src/Controllers/BoshSahifa.php
namespace App\Controllers; use App\Controller; class BoshSahifa implements Controller { public function handle(): string { return "<h1>IshTop</h1><p>Bosh sahifa</p>"; } }

Va index.php da bitta qator qo'shasiz. Router'ga tegilmaydi.

Kirish nuqtasi

public/index.php
require __DIR__ . '/../vendor/autoload.php'; $router = new Router(); $router->add('GET', '/', BoshSahifa::class); $router->add('GET', '/vakansiyalar', Vakansiyalar::class); $metod = $_SERVER['REQUEST_METHOD']; $yol = parse_url($_SERVER['REQUEST_URI'], PHP_URL_PATH); try { echo $router->dispatch($metod, $yol); } catch (RouteTopilmadi $e) { http_response_code(404); echo "<h1>404</h1>"; }

Uch yangi detal:

  • __DIR__ — «shu fayl turgan papka». Nisbiy yo'l ('vendor/autoload.php') qaysi papkadan ishga tushirilganiga bog'liq bo'lardi; __DIR__ esa har doim to'g'ri.
  • BoshSahifa::class — klassning to'liq nomini matn sifatida beradi ("App\Controllers\BoshSahifa"). Qo'lda yozishdan yaxshi: nomni adashsangiz muharrir darhol ogohlantiradi.
  • parse_url(..., PHP_URL_PATH) — manzildan faqat yo'lni ajratadi. /vakansiyalar?sahifa=2 dan /vakansiyalar qoladi — aks holda query string route'ni buzardi.
Bu Laravel'da qanday ko'rinadi
// sizning kodingiz $router->add('GET', '/vakansiyalar', Vakansiyalar::class); // Laravel Route::get('/vakansiyalar', [VakansiyaController::class, 'index']);

Deyarli bir xil. Laravel'da metod nomi ham beriladi (bitta controllerda bir nechta sahifa bo'lishi uchun) va route'lar routes/web.php faylida turadi. G'oya esa aynan bugungi g'oya.

💻 Amaliy qism kompyuterda

Amaliyotda beshta fayl yozasiz: interface Controller, o'z exception klassingiz, Router, ikkita controller va public/index.php. Keyin serverni front controller rejimida ko'tarib, uchta manzilni sinaysiz — va oxirida yangi sahifani router'ga tegmasdan qo'shasiz.

Amaliyot

12-darsda composer.json va src/ tayyorlangan — App\ → src/ qoidasi allaqachon ishlaydi. Ustiga quramiz.

  1. Papkalarni tayyorlang

    cd ~/Projects/Learn/php-poydevor mkdir -p src/Controllers public

    Kutilgan natija: jimlik.

  2. Shartnoma va exception klassini yozing

    Ikkisi ham kichik, lekin router'ning poydevori: biri «controller nima qila olishi kerak», ikkinchisi «topilmadi» holati.

    cat > src/Controller.php <<'EOF' <?php declare(strict_types=1); namespace App; interface Controller { public function handle(): string; } EOF cat > src/RouteTopilmadi.php <<'EOF' <?php declare(strict_types=1); namespace App; class RouteTopilmadi extends \Exception {} EOF

    Kutilgan natija: jimlik.
    Diqqat: extends \Exception — oldidagi teskari chiziq muhim. App namespace ichida turganimiz uchun, usiz PHP App\Exception ni izlaydi. \ «eng yuqoridan (global'dan) ol» degani.

  3. Router'ni yozing

    Butun framework'ning yuragi — 20 qator.

    cat > src/Router.php <<'EOF' <?php declare(strict_types=1); namespace App; class Router { private array $routes = []; public function add(string $metod, string $yol, string $controller): void { $this->routes[$metod][$yol] = $controller; } public function dispatch(string $metod, string $yol): string { $klass = $this->routes[$metod][$yol] ?? null; if ($klass === null) { throw new RouteTopilmadi("Route topilmadi: {$metod} {$yol}"); } $controller = new $klass(); return $controller->handle(); } } EOF

    Kutilgan natija: jimlik.

  4. Ikkita controller yozing

    cat > src/Controllers/BoshSahifa.php <<'EOF' <?php declare(strict_types=1); namespace App\Controllers; use App\Controller; class BoshSahifa implements Controller { public function handle(): string { return "<h1>IshTop</h1><p>Bosh sahifa</p>"; } } EOF cat > src/Controllers/Vakansiyalar.php <<'EOF' <?php declare(strict_types=1); namespace App\Controllers; use App\Controller; class Vakansiyalar implements Controller { public function handle(): string { return "<h1>Vakansiyalar</h1><p>Ro'yxat</p>"; } } EOF

    Kutilgan natija: jimlik. Diqqat: fayl src/Controllers/ da, namespace esa App\Controllers — PSR-4 qoidasi bo'yicha papka = namespace (12-dars).

  5. Kirish nuqtasini yozing

    cat > public/index.php <<'EOF' <?php declare(strict_types=1); require __DIR__ . '/../vendor/autoload.php'; use App\Router; use App\RouteTopilmadi; use App\Controllers\BoshSahifa; use App\Controllers\Vakansiyalar; $router = new Router(); $router->add('GET', '/', BoshSahifa::class); $router->add('GET', '/vakansiyalar', Vakansiyalar::class); $metod = $_SERVER['REQUEST_METHOD']; $yol = parse_url($_SERVER['REQUEST_URI'], PHP_URL_PATH); try { echo $router->dispatch($metod, $yol); } catch (RouteTopilmadi $e) { http_response_code(404); echo "<h1>404</h1><p>", htmlspecialchars($e->getMessage()), "</p>"; } EOF

    Kutilgan natija: jimlik. Diqqat: 404 xabarida ham htmlspecialchars — chunki xabar ichida foydalanuvchi so'ragan manzil bor (13-dars qoidasi!).

  6. Serverni front controller rejimida ko'taring

    Manzil oxiriga fayl nomi berilsa, PHP har so'rovni shu fayldan o'tkazadi — aynan bizga kerak bo'lgani.

    php -S localhost:8000 public/index.php [...] PHP 8.3.32 Development Server (http://localhost:8000) started

    Kutilgan natija: server ishlaydi. Farqni sezdingizmi — oldin php -S localhost:8000 deb yozardik, endi oxirida public/index.php bor. Shu argument «hamma so'rovni bu fayldan o't» deydi.
    Yangi terminal oynasi oching yoki brauzerda sinang.

  7. Uchta manzilni sinang

    Bu darsning g'alabasi: .phpsiz, toza manzillar.

    curl -s http://localhost:8000/ ; echo curl -s http://localhost:8000/vakansiyalar ; echo curl -s -w '\n[status: %{http_code}]\n' http://localhost:8000/yoq <h1>IshTop</h1><p>Bosh sahifa</p> <h1>Vakansiyalar</h1><p>Ro'yxat</p> <h1>404</h1><p>Route topilmadi: GET /yoq</p> [status: 404]

    Kutilgan natija: ikki sahifa va bitta 404 — haqiqiy HTTP status 404 bilan. 🎉 Diqqat: manzillarda .php yo'q, va /vakansiyalar degan fayl ham yo'q. Router hal qildi.

  8. Metod ham muhimligini tekshiring

    curl -s -X POST -w '\n[status: %{http_code}]\n' http://localhost:8000/ <h1>404</h1><p>Route topilmadi: POST /</p> [status: 404]

    Kutilgan natija: GET / bor, lekin POST / yo'q → 404. Route jadvali metod + yo'l bo'yicha kalitlangan. Laravel'dagi Route::get va Route::post farqi aynan shu.

  9. Yangi sahifa qo'shing — router'ga tegmasdan

    Bu 10-darsdagi shartnomaning haqiqiy foydasi.

    cat > src/Controllers/Kompaniyalar.php <<'EOF' <?php declare(strict_types=1); namespace App\Controllers; use App\Controller; class Kompaniyalar implements Controller { public function handle(): string { return "<h1>Kompaniyalar</h1>"; } } EOF php -r ' require "vendor/autoload.php"; echo (new App\Controllers\Kompaniyalar())->handle(), PHP_EOL; ' <h1>Kompaniyalar</h1>

    Kutilgan natija: ishladi — va diqqat qiling, composer dump-autoload qilmadik! Nega ishladi: vendor/composer/autoload_psr4.php ichida faqat qoida turadi ('App\\' => src/), fayl ro'yxati emas. Ya'ni yangi klass darhol topiladi. dump-autoload faqat composer.json o'zgarganda kerak.

  10. Yangi controller'ni route'ga ulang

    Bitta qator — Router faylining ichiga tegilmaydi.

    public/index.php ni muharrirda ochib, ikkita qator qo'shing: use App\Controllers\Kompaniyalar; (yuqoriga) va $router->add('GET', '/kompaniyalar', Kompaniyalar::class); (route'lar yoniga). Keyin:

    curl -s http://localhost:8000/kompaniyalar <h1>Kompaniyalar</h1>

    Kutilgan natija: yangi sahifa ishlaydi. Router.php ga tegmadik — chunki u shartnomaga tayanadi, aniq klasslarga emas.

  11. Ishni saqlang

    git add -A git commit -m "14-dars: front controller va router"

    Kutilgan natija: commit haqida xabar. Serverni Ctrl+C bilan to'xtatishni unutmang.

Sinab ko'ramiz

Natijani taxmin qiling

Route'lar shunday e'lon qilingan:

public/index.php
$router->add('GET', '/vakansiyalar', Vakansiyalar::class);

Quyidagi uch so'rov nima qaytaradi?

so'rovlar
A) GET /vakansiyalar?sahifa=2 B) POST /vakansiyalar C) GET /vakansiyalar/
Javobni ko'rish
A) ✅ ishlaydi — Vakansiyalar sahifasi B) ❌ 404 — metod mos kelmadi C) ❌ 404 — yo'l mos kelmadi (oxirgi / qo'shimcha)

A ishlaydi, chunki parse_url(..., PHP_URL_PATH) query qismini ajratib tashlaydi: /vakansiyalar?sahifa=2 dan /vakansiyalar qoladi. Bu qator bo'lmasa, A ham 404 bergan bo'lardi — va bu juda chalkash bug' bo'lardi.

B — 404, chunki jadval $routes['GET']['/vakansiyalar'] deb saqlangan; POST uchun yozuv yo'q. Bu xato emas, xususiyat: bir manzilda GET (ko'rsatish) va POST (saqlash) har xil ish qilishi kerak.

C — 404, chunki "/vakansiyalar/" va "/vakansiyalar" — ikki boshqa matn (3-dars: === qat'iy solishtiradi). Bizning router'da oxirgi chiziqni normallashtiruvchi kod yo'q.

Mana real framework nima uchun kattaroq ekanining javobi: Laravel bunday holatlarni o'zi hal qiladi — oxirgi chiziq, HEAD metodi, katta-kichik harf, route parametrlari (/vakansiyalar/{id}), nomlangan route'lar. Yadro g'oyasi esa siz yozgan 20 qator.

SAVOL 1 Nega faqat public/ papkasi brauzerga ochiq bo'ladi?

Xavfsizlik: src/, vendor/, .env — brauzer uchun mavjud emas. Aks holda hujumchi kod yoki parollarni so'rab olishi mumkin edi.

SAVOL 2 Router controller'lar haqida nima biladi?

Router interface Controller shartnomasiga tayanadi. Shuning uchun yangi sahifa qo'shilganda Router.php ga tegilmaydi — 10-darsdagi g'oyaning amaliy foydasi.

SAVOL 3 Yangi klass qo'shganda composer dump-autoload kerakmi?

PSR-4 qoida saqlaydi (App\ → src/), fayl ro'yxatini emas. dump-autoload faqat composer.json o'zgarganda kerak.

Eslab ayting

Avval o'zingiz javob bering, keyin ochib tekshiring. Oxirgi ikkitasi — 13-darsni takrorlash.

Front controller qanday to'rtta muammoni yechadi?

1) Sozlash takrorlanmaydi (bir joyda). 2) Markaziy nazorat paydo bo'ladi (log, auth). 3) Chiroyli manzil mumkin (/vakansiyalar/12). 4) Xavfsizlik — faqat public/ ochiq.

new $klass() nima qiladi?

Klass nomi o'zgaruvchida matn sifatida turadi va PHP shu nomli klassdan obyekt yasaydi. Faylni autoload o'zi topadi. Shuning uchun router aniq klasslarni bilishi shart emas.

Nega parse_url(..., PHP_URL_PATH) kerak?

Manzildan faqat yo'lni ajratish uchun. /vakansiyalar?sahifa=2 → /vakansiyalar. Usiz query string route'ni buzardi.

↩︎ Takrorlash: nega 404 xabarida htmlspecialchars bor?

Chunki xabar ichida foydalanuvchi so'ragan manzil bor — ya'ni tashqaridan kelgan matn. Uni xom holda chiqarish XSS ochadi (13-dars).

↩︎ Takrorlash: $_SESSION ma'lumoti qayerda yashaydi?

Serverda, kaliti (session ID) esa brauzerdagi cookie da. Cookie bo'lmasa server foydalanuvchini tanimaydi.

Cho'ntak xulosasi
  • Front controller: hamma so'rov public/index.php ga keladi. Faqat public/ brauzerga ochiq.
  • Router — ichma-ich massiv: $routes[$metod][$yol] = KlassNomi. Metod ham kalit.
  • interface Controller { handle(): string; } — router shartnomaga tayanadi, aniq klasslarga emas.
  • new $klass() — klass nomi o'zgaruvchida bo'lishi mumkin; faylni autoload topadi.
  • Klass::class — to'liq nomni matn sifatida beradi (adashsangiz muharrir aytadi).
  • parse_url(..., PHP_URL_PATH) — query'ni ajratadi. __DIR__ — yo'lni ishonchli qiladi.
  • 404 — RouteTopilmadi exception + http_response_code(404).
  • php -S localhost:8000 public/index.php — front controller rejimi.
  • PSR-4 qoida saqlaydi → yangi klass uchun dump-autoload kerak emas.
🌱 Keyingi dars — Modul A ning cho'qqisi

Router ishlayapti, lekin bitta zaif joyi bor: new $klass() — controller'ga hech narsa berilmaydi. Agar Vakansiyalar controller'i bazaga ulanish yoki xabar yuboruvchi kerak bo'lsa, u ularni o'zi yasashga majbur bo'ladi. Va shu bilan controller aniq klasslarga qattiq bog'lanib qoladi — 10-darsda aytgan muammo qaytadi.

15-darsda buni container yechadi: obyektlarni u yasaydi, va kerakli bog'liqliklarni o'zi topib qo'yadi. Bu Laravel'ning eng markaziy mexanizmi — Service Container. Uni o'z qo'lingiz bilan yozgandan keyin, Laravel'da controller konstruktoriga yozilgan har bir parametr sizga tushunarli bo'ladi.
