Chiqarish — bu ko'chirish emas

Ko'p yangi dasturchi buni «fayllarni serverga nusxalash» deb tasavvur qiladi. Aslida kamida o'n bir ish bor va ularning tartibi muhim.

Noto'g'ri tartib: 1) migratsiya → yangi ustun qo'shildi 2) kod → eski kod hali ishlab turibdi va u ustunni bilmaydi ⚠️ To'g'ri tartib: 1) ta'mirlash rejimi 2) kod 3) bog'liqliklar 4) migratsiya 5) kesh 6) ta'mirlash rejimidan chiqish

🔑 Va eng muhimi: orqaga qaytish rejasi chiqarishdan oldin tayyor bo'lsin.

Bugun har qadamni o'lchaymiz va beshta eng ko'p uchraydigan xatoni ataylab chaqiramiz — shunda serverda ularni tanib olasiz.

Serverda nima ishlaydi

Brauzer ↓ HTTPS (443) nginx ← statik fayllar, sertifikat, marshrutlash ↓ fastcgi (9000 yoki soket) PHP-FPM ← PHP jarayonlari havzasi ↓ public/index.php ← Laravel shu yerdan boshlanadi ↓ MySQL · Redis ← alohida xizmatlar
⚠️ Hujjat ildizi — eng ko'p qilinadigan xato
❌ root /var/www/ishtop; ✅ root /var/www/ishtop/public;

Noto'g'ri qo'ysangiz, butun loyiha internetga ochiladi:

https://ishtop.uz/.env ← sirlaringiz https://ishtop.uz/composer.json ← paket versiyalari (66-dars: zaifliklar) https://ishtop.uz/storage/logs/laravel.log

🔑 Laravel ataylab shunday qurilgan: public/ dan tashqarida hech narsa veb orqali ko'rinmasligi kerak.

🔍 Va public/index.php ning birinchi ishi — ta'mirlash rejimini tekshirish:

if (file_exists($maintenance = __DIR__.'/../storage/framework/maintenance.php')) { require $maintenance; }

nginx sozlamasi

/etc/nginx/sites-available/ishtop
server { listen 80; server_name ishtop.uz www.ishtop.uz; root /var/www/ishtop/public; # ← public/ index index.php; charset utf-8; location / { try_files $uri $uri/ /index.php?$query_string; } location ~ \.php$ { fastcgi_pass unix:/var/run/php/php8.3-fpm.sock; fastcgi_param SCRIPT_FILENAME $realpath_root$fastcgi_script_name; include fastcgi_params; } location ~ /\.(?!well-known).* { # .env, .git — YOPIQ deny all; } client_max_body_size 20M; # fayl yuklash (66-dars) }

Ta'mirlash rejimi

O'lchadik:

oddiy so'rov → 503 javob sarlavhasida → Retry-After: 60 /sirli-kalit-123 ni ochish → 302 (cookie o'rnatib, / ga yo'naltiradi) keyin oddiy so'rov → 200 ✅ siz ko'rasiz, boshqalar yo'q php artisan up → 200
🔑 Maxfiy kalit nima uchun

Chiqarishdan keyin tekshirish kerak: sayt ishlayaptimi? Lekin foydalanuvchilarga hali ko'rsatmaslik kerak.

Maxfiy kalit aynan shuni beradi: siz ichkarida, qolganlar 503 ko'radi.

🔍 Retry-After: 60 — bu qidiruv tizimlariga «60 soniyadan keyin qayting» degan signal. Usiz Google sahifani o'chirilgan deb hisoblashi mumkin.

⚠️ Kalit .env da bo'lsin, deploy skriptida ochiq yozilmasin.

⚠️ Beshta eng ko'p uchraydigan xato

Har birini ataylab chaqirdik. Serverda ularni tanib olasiz.

⚠️ XATO 1: APP_KEY yo'q

Illuminate\Encryption\MissingAppKeyException No application encryption key has been specified.

Sabab: .env serverga yangi ko'chirilgan va APP_KEY bo'sh.

php artisan key:generate --force

⚠️ Lekin diqqat: kalitni o'zgartirsangiz, shifrlangan hamma narsa — sessiyalar, shifrlangan ustunlar — o'qib bo'lmaydigan bo'lib qoladi. Ishlayotgan saytda key:generate ni ishlatmang.

⭐ ⚠️ XATO 2: config:cache tuzog'i

54-darsda tilga olgandik. Endi o'lchaymiz:

php artisan config:cache config('app.name') → Laravel # .env ni o'zgartiramiz: APP_NAME=IshTopYangi config('app.name') → Laravel ⚠️ ESKISI! php artisan config:clear config('app.name') → IshTopYangi ✅
⚠️ Xato yo'q, qiymat eski

Bu 62 va 66-darslardagi bilan bir xil naqsh: xato yo'q, natija noto'g'ri.

Serverda bu shunday ko'rinadi: parolni o'zgartirdingiz, deploy qildingiz — ilova hamon eski parol bilan ulanmoqchi.

🔑 Sabab: config:cache dan keyin Laravel .env ni umuman o'qimaydi. Va env() funksiyasi null qaytaradi.

✅ Shuning uchun deploy skriptida optimize:clear keyin optimize — shu tartibda.

⚠️ Va shuning uchun env() ni faqat config/ fayllarida ishlating — controllerda yoki modelda hech qachon.

⚠️ XATO 3: migrate --force siz

APP_ENV=production php artisan migrate WARN Command cancelled.

Laravel ishlab chiqarish muhitida tasdiq so'raydi. Deploy skriptida klaviatura yo'q — javob kelmaydi va buyruq bekor qilinadi.

php artisan migrate --force → INFO Nothing to migrate. ✅

🔍 Xuddi shu himoya migrate:fresh, db:wipe, migrate:rollback da ham bor — va 66-darsdan eslang, --force himoyani o'chiradi.

Har xil holatlar

Yetti holat. Bu bo'lim ma'lumotnoma — hozir bir marta o'qing, keyin chiqarish paytida qaytib qarang.

HOLAT 1

HTTPS — Let's Encrypt

sudo apt install certbot python3-certbot-nginx sudo certbot --nginx -d ishtop.uz -d www.ishtop.uz sudo certbot renew --dry-run ← avtomatik yangilanishni sinash

Certbot nginx sozlamasini o'zi yangilaydi va 80 → 443 yo'naltirish qo'shadi.

✅ Laravel tomonida:

# .env APP_URL=https://ishtop.uz # AppServiceProvider::boot() if (app()->isProduction()) { URL::forceScheme('https'); }

⚠️ Usiz route() va asset() http:// qaytaradi — brauzer «aralash mazmun» ogohlantirishini beradi.

HOLAT 2

Nol to'xtashli chiqarish

/var/www/ishtop/ releases/ 2026-08-26-1200/ ← eski 2026-08-26-1430/ ← yangi shared/ .env ← BITTA nusxa storage/ ← BITTA nusxa current -> releases/2026-08-26-1430 ← SIMVOLIK HAVOLA

Yangi versiya yonida tayyorlanadi, so'ng current havolasi bir lahzada almashadi.

✅ Orqaga qaytish ham bir lahzada: havolani eski papkaga qaytarasiz.

🔑 Tayyor vositalar: Deployer, Laravel Envoy, Laravel Forge. Qo'lda yozish shart emas.

HOLAT 3

.env ni qanday boshqarmaslik

❌ git ga qo'shish (66-dars) ❌ Slack orqali yuborish ❌ har deploy da qo'lda tahrirlash ❌ .env.example ni eskirgan qoldirish (68-dars predict)

✅ Yo'llar:

1) Serverda BIR MARTA yaratiladi, shared/ da yashaydi 2) Sirlar boshqaruvchisi (Vault, AWS Secrets Manager) 3) CI/CD sirlar ombori (GitHub Secrets — Modul J'da)

🔑 Va .env.example ni har yangi o'zgaruvchi qo'shilganda yangilang — u hujjat.

Qo'lda ishlayapti, o'zi ishlamayapti. Nima bo'lgan?

Javobni ko'rish

Navbat ishchisi eski kod bilan ishlayapti — yoki umuman ishlamayapti.

Ikkita alohida sabab bo'lishi mumkin, ikkalasi ham deploy skriptidagi kamchilikdan:

1) queue:restart YO'Q edi → eski worker jarayoni HALI ISHLAYAPTI → u ESKI kodni xotirasida saqlaydi (55-dars) → yangi Job sinfini bilmaydi yoki eski mantiqni bajaradi 2) worker UMUMAN ishlamayapti → deploy paytida jarayon o'ldi va qayta ko'tarilmadi → supervisor sozlanmagan

🔑 Va nega log toza? Chunki xato ilovada emas. Ilova job'ni navbatga qo'ydi va bu muvaffaqiyatli bo'ldi. Job esa hech kim tomonidan olinmadi.

Buni ko'rish oson edi:

select count(*) from jobs; ← navbatda nechta kutyapti? php artisan queue:monitor default ← Laravel'ning o'z tekshiruvi ps aux | grep queue:work ← worker umuman bormi?

✅ Deploy skriptida ikkita qator yetishmayotgan edi:

php artisan queue:restart ← eski worker larga "tugating" signali sudo supervisorctl restart ishtop-worker:* ← yoki to'g'ridan-to'g'ri

⚠️ queue:restart worker'ni o'ldirmaydi — u «joriy job'ni tugatib, chiqing» degan signal qo'yadi. Qayta ko'tarish — supervisorning ishi.

🔑 Umumiy saboq: ilova ishlayotgani — hamma narsa ishlayapti degani emas. Fon jarayonlari alohida yashaydi va ular alohida tekshiriladi.

🔍 Va yana bir saboq: juma kuni chiqarmang. Muammo chiqsa, uni tuzatadigan odam bo'lmaydi.

SAVOL 1 ⭐ config:cache qilingandan keyin .env ni o'zgartirsangiz nima bo'ladi?

🔍 O'lchandi: config:cache → config('app.name') Laravel; .env da APP_NAME=IshTopYangi qilindi → config() hamon Laravel; config:clear dan keyin → IshTopYangi. ⚠️ Xato yo'q, natija noto'g'ri. 🔑 config:cache dan keyin Laravel .env ni umuman o'qimaydi — env() null qaytaradi. ✅ Deploy'da tartib: optimize:clear keyin optimize.

SAVOL 2 APP_ENV=production da php artisan migrate (--force siz) nima qiladi?

🔍 O'lchandi: WARN Command cancelled. — Laravel tasdiq so'raydi, deploy skriptida klaviatura yo'q. --force bilan → INFO Nothing to migrate. 🔑 Xuddi shu himoya migrate:fresh, db:wipe, migrate:rollback da ham bor. ⚠️ 66-darsdan: --force himoyani o'chiradi — skriptga yozishdan oldin o'ylang.

SAVOL 3 nginx'da hujjat ildizi (root) qayerga qaratiladi?

🔑 root /var/www/ishtop/public; ⚠️ Noto'g'ri qo'ysangiz butun loyiha internetga ochiladi: /.env, /composer.json, /storage/logs/laravel.log. ✅ Tekshirish bir buyruq: curl -I https://ishtop.uz/.env → 404 yoki 403 bo'lishi shart. ☠️ 200 qaytsa — darrov tuzating va sirlarni almashtiring (66-dars).

Eslab ayting

Javobni ovoz chiqarib ayting, keyin ochib solishtiring.

Chiqarish tartibini sanab bering
1) down --secret · 2) git pull --ff-only · 3) composer install --no-dev --optimize-autoloader · 4) migrate --force · 5) optimize:clear · 6) optimize · 7) storage:link · 8) PHP-FPM reload · 9) queue:restart · 10) up · 11) about. 🔑 Skript boshida set -e — usiz migratsiya yiqilsa ham up bajariladi va buzuq ilova ochiq qoladi. ⚠️ Tartib muhim: migratsiya koddan keyin, aks holda eski kod yangi ustunni bilmaydi.
🔍 optimize nima qiladi va qancha foyda beradi?
Config, events, routes va view'larni bitta tayyor faylga keshlaydi. 🔍 O'lchandi: config 26 642 bayt, routes 22 096, services 23 488; bajarilishi 0.14 s. 🔍 Tezlik: 13.23 → 8.65 ms (35%), lekin ⚠️ farq tebranadi — bir o'lchovda umuman ko'rinmadi. Bitta o'lchov yetarli emas. Sabab: keshsiz Laravel har so'rovda 15+ config faylini o'qiydi va marshrutlarni tahlil qiladi. ⚠️ Mahalliy ishda ishlatmang: .env o'zgarishini sezmaydi. ✅ Deploy'da: optimize:clear keyin optimize.
Ta'mirlash rejimi va maxfiy kalit
php artisan down --secret="X" --retry=60. 🔍 O'lchandi: oddiy so'rov 503 + Retry-After: 60; /X ni ochish 200 va cookie o'rnatiladi; keyin oddiy so'rov ham 200. 🔑 Foydasi: chiqarishdan keyin siz tekshirasiz, foydalanuvchilar hali ko'rmaydi. 🔍 Retry-After qidiruv tizimlariga «qayting» signali — usiz sahifa o'chirilgan deb hisoblanishi mumkin. ⚠️ Kalitni skriptga ochiq yozmang — .env da bo'lsin.
⚠️ Beshta xatoni va ularning ko'rinishini ayting
1) MissingAppKeyException: No application encryption key has been specified. → key:generate --force (⚠️ ishlayotgan saytda emas). 2) ⭐ config:cache tuzog'i — xato yo'q, qiymat eski. 3) WARN Command cancelled. → --force. 4) UnexpectedValueException ... could not be opened in append mode: Permission denied → chown -R www-data storage bootstrap/cache. 5) Hujjat ildizi noto'g'ri → /.env 200 qaytadi. 🔑 Faqat storage va bootstrap/cache yoziladigan bo'lsin.
Orqaga qaytish rejasi qanday bo'ladi?
Kod — oson: git checkout <commit> + composer install + optimize. Migratsiya — qiyin: migrate:rollback --force, lekin down() to'g'ri yozilganmi? Ustun o'chsa ma'lumot ham ketadi. Ma'lumot — faqat zaxira nusxadan (deploy'dan oldin olingan). ✅ Xavfsiz naqsh — kengaytir–ko'chir–toraytir: yangi ustun qo'sh → ma'lumotni ko'chir va kodni o'tkaz → eski ustunni o'chir. Uch alohida deploy. 🔑 Nol to'xtash uchun: releases/ + shared/ + current simvolik havolasi.

🌱 Keyingi dars

Sayt ishlab turibdi. Lekin 55, 57 va 58-darslarda yozgan narsalarimiz — navbat, bildirishnomalar va rejalashtirilgan buyruqlar — hozircha faqat mahalliy ishladi.

Serverda ular o'zi ishga tushmaydi. Kimdir ularni doim ishlatib turishi kerak.

70-darsda supervisor va cron ni sozlaymiz: worker o'lsa qayta ko'tarilsin, schedule:run har daqiqada ishlasin. Va bugungi predict'dagi muammoni — «xat kelmayapti» — ildizidan yechamiz.
