Task Scheduling

57-darsda savol qoldi: bildirishnomalar jadvali o'sib boradi, eskilarini kim tozalaydi? Va yangi talab bor: muddati o'tgan vakansiyalar har kecha o'zi yopilsin. Ikkalasi bitta narsani talab qiladi — belgilangan vaqtda o'zi ishlaydigan kod. Va yo'lda modelimizdagi yashirin xatoni topamiz.

📱 O'qish ≈ 16 daqiqa 💻 Amaliyot ≈ 26 daqiqa Kerak: Dars 57

Bu darsda nimalar bor

  2. make:command va atributlar Laravel 13'da #[Signature] va #[Description] — xossa emas.
  3. Buyruq parametrlari {--kun=0 : izoh} — imzoning o'zi yordam matnini ham beradi.
  4. routes/console.php da reja Laravel 11+ da Kernel.php yo'q — reja marshrutlar kabi yoziladi.
  5. Schedule::command va Schedule::call Artisan buyrug'i yoki to'g'ridan-to'g'ri closure.
  6. schedule:list 🔍 O'lchandi: cron ifodasi va «Next Due» — reja to'g'ri o'qilganini tekshirish.
  7. schedule:run va schedule:test Birinchisi vaqti kelganlarni, ikkinchisi istalgan vazifani darrov ishlatadi.
  8. withoutOverlapping va onOneServer Uzoq ish yoki bir necha server bo'lganda majburiy.
  9. ⚠️ Yashirin xato topildi Test qizardi va sabab rejada emas edi: modelda faol uchun cast yo'q ekan.
  10. Buyruqni test qilish $this->artisan(...), expectsOutputToContain, assertSuccessful.
  11. Rejaning o'zini test qilish Schedule::events() — vazifa ro'yxatda turganini tekshirish.
  12. Har xil holatlar (7 ta) Vaqt zonasi · chiqishni saqlash · xato bo'lsa xabar · runInBackground · cron sintaksisi.
Hech kim bosmaydigan tugma

Ikki talab yig'ilib qoldi:

57-dars: notifications jadvali o'sib boradi — eskilarini tozalash kerak yangi: muddati o'tgan vakansiya saytda turaverishi kerak emas

Ikkalasi ham hech kim so'ramaydigan ish. Foydalanuvchi «eski bildirishnomalarni tozala» tugmasini bosmaydi.

An'anaviy yechim — cron: serverda vaqt jadvali. Lekin har yangi vazifa uchun serverga kirib crontab tahrirlash kerak bo'ladi, va u kodda ko'rinmaydi.

Laravel boshqacha qiladi: serverga bitta qator yoziladi, qolgan hammasi kodda:

* * * * * cd /yol/loyihaga && php artisan schedule:run >> /dev/null 2>&1

Bu qator har daqiqada schedule:run ni chaqiradi, u esa vaqti kelgan vazifalarni topadi va ishlatadi.

Avval vakansiyaga muddat ustuni kerak:

index() — 25-darsdan tanish: biz bu ustun bo'yicha qidiramiz, demak indeks kerak.

<?php namespace App\Console\Commands; use App\Models\Vakansiya; use Illuminate\Console\Attributes\Description; use Illuminate\Console\Attributes\Signature; use Illuminate\Console\Command; #[Signature('ishtop:vakansiyalarni-yop {--kun=0 : Necha kun oldingi muddat}')] #[Description('Muddati o\'tgan vakansiyalarni yopadi')] class VakansiyalarniYop extends Command { public function handle(): int { $chegara = now()->subDays((int) $this->option('kun'))->toDateString(); $soni = Vakansiya::where('faol', true) ->whereNotNull('muddat') ->whereDate('muddat', '<', $chegara) ->update(['faol' => false]); $this->info("{$soni} ta vakansiya yopildi."); return self::SUCCESS; } }
🔑 Laravel 13'da atributlar

Eski Laravel'da protected $signature va protected $description xossa edi. Laravel 13'da ular atribut:

#[Signature('ishtop:vakansiyalarni-yop {--kun=0 : Necha kun oldingi muddat}')] #[Description('Muddati o\'tgan vakansiyalarni yopadi')]

Bu 29-darsdagi #[Scope] va 53-darsdagi #[ObservedBy] bilan bir oiladan — Laravel asta-sekin atributlarga o'tmoqda.

🔍 Imzo o'zi hujjat: {--kun=0 : izoh} dagi izoh --help da ko'rinadi.

🔑 Nom oldiga ishtop: qo'ydik — php artisan list da o'z buyruqlaringiz bir joyda turadi.

Sinab ko'ramiz. Uchta vakansiya: biri muddati o'tgan, biri kelasi, biri muddatsiz:

faol: 6 php artisan ishtop:vakansiyalarni-yop 1 ta vakansiya yopildi. faol: 5 yopiq: 1 ✅ faqat muddati o'tgani

Rejaga qo'yish

Laravel 11+ da app/Console/Kernel.php yo'q. Reja marshrutlar kabi yoziladi:

routes/console.php
use Illuminate\Support\Facades\DB; use Illuminate\Support\Facades\Schedule; Schedule::command('ishtop:vakansiyalarni-yop') ->dailyAt('03:00') ->withoutOverlapping() ->onOneServer() ->appendOutputTo(storage_path('logs/reja.log')); Schedule::call(function () { DB::table('notifications') ->whereNotNull('read_at') ->where('created_at', '<', now()->subMonths(3)) ->delete(); })->weeklyOn(1, '04:00')->name('eski-bildirishnomalarni-tozala');

Ikki xil usul:

Schedule::command('nom') → Artisan buyrug'i (alohida jarayonda) Schedule::call(fn () => ..) → closure (schedule:run jarayonida)

Kichik ish uchun call yetarli. Katta ish uchun command afzal: alohida jarayon, ya'ni xotira muammosi butun rejani buzmaydi.

Tekshiramiz:

php artisan schedule:list 0 3 * * * php artisan ishtop:vakansiyalarni-yop Next Due: 7 hours from now 0 4 * * 1 eski-bildirishnomalarni-tozala Next Due: 5 days from now

dailyAt('03:00') → 0 3 * * *, weeklyOn(1, '04:00') → 0 4 * * 1. Laravel odam o'qiy oladigan yozuvni cron ifodasiga o'zi o'giradi.

🔑 name() nega kerak?

Schedule::call da buyruq nomi yo'q — schedule:list da u anonim bo'lib ko'rinadi.

->name('...') unga nom beradi va withoutOverlapping() ham aynan shu nom bo'yicha qulflaydi.

schedule:run va schedule:test

php artisan schedule:run INFO No scheduled commands are ready to run.

To'g'ri — soat 03:00 emas. schedule:run faqat vaqti kelgan vazifalarni ishlatadi.

⚠️ Test qizardi — sabab rejada emas edi

Buyruq uchun test yozdim:

$otgan = Vakansiya::factory()->create(['faol' => true, 'muddat' => now()->subDay()]); $this->artisan('ishtop:vakansiyalarni-yop')->assertSuccessful(); expect($otgan->fresh()->faol)->toBeFalse(); → FAILED

Buyruq ishladi («1 ta vakansiya yopildi»), lekin tekshiruv qizardi. Nima xato?

dump(get_debug_type($v->faol)); → bool (yaratilganda) $this->artisan(...); dump(get_debug_type($v->faol)); → int (yangilangandan keyin) ⚠️ var_export($v->faol) → 0
⚠️ Xato buyruqda emas — modelda

Modelimizda faol uchun cast yo'q edi. SQLite boolean ustunni 0/1 qilib saqlaydi, va bazadan qayta o'qilganda u butun son bo'lib keladi.

Yaratilganda bool ko'ringani chalg'itdi: o'sha qiymat siz bergan holicha xotirada turgan edi.

✅ Yechim modelda:

protected function casts(): array { return ['muddat' => 'date', 'faol' => 'boolean']; }

🔑 Bu xato 29-darsdan beri koddagi turgan edi — faqat hech qachon toBeFalse() kabi qat'iy tekshiruv yozmaganmiz. 34-darsda rol uchun cast yozgandik, faol esa e'tibordan chetda qolgan.

🔍 Naqsh tanish: test yozish yashirin xatoni ochdi. 46-darsdagi ?q=0 ham shunday topilgandi.

Har xil holatlar

Yetti holat. Bu bo'lim ma'lumotnoma — hozir bir marta o'qib chiqing, keyin kerak bo'lganda qaytib qarang.

HOLAT 1

Vaqt oralig'i usullari

everyMinute() everyFiveMinutes() hourly() hourlyAt(17) daily() dailyAt('03:00') twiceDaily(1, 13) weekly() weeklyOn(1, '04:00') monthly() quarterly() yearly() cron('0 */6 * * *') → o'z ifodangiz

Qo'shimcha cheklovlar zanjirlanadi:

->weekdays() ->weekends() ->between('9:00', '18:00') ->unlessBetween('0:00', '6:00') ->when(fn () => config('ishtop.reja_yoqilgan'))

🔑 when() foydali: sozlama bilan rejani o'chirib qo'yish mumkin (54-dars).

HOLAT 2

Vaqt zonasi

config/app.php: 'timezone' => 'UTC' ← standart dailyAt('03:00') → UTC bo'yicha 03:00 → Toshkentda 08:00 ⚠️

✅ Ikki yo'l:

1) config/app.php da: 'timezone' => 'Asia/Tashkent' 2) vazifada: ->timezone('Asia/Tashkent')->dailyAt('03:00')

⚠️ Birinchisi butun ilovaga ta'sir qiladi (now(), sanalar). Ikkinchisi faqat o'sha vazifaga.

🔍 Tekshirish: schedule:list «Next Due» ni ko'rsatadi — u kutgan vaqtingizmi?

HOLAT 3

withoutOverlapping

->everyMinute()->withoutOverlapping()

Vazifa 3 daqiqa davom etsa, everyMinute bilan uchtasi birga ishlaydi. Natija: baza qulflari, ikki marta bajarilgan ish.

withoutOverlapping() qulf qo'yadi: oldingisi tugamaguncha yangisi ishlamaydi.

⚠️ Qulf standart holda 24 soat yashaydi. Vazifa qulab tushsa (server o'chsa) qulf qolib ketishi mumkin — withoutOverlapping(10) bilan daqiqasini bering.

HOLAT 4

onOneServer va runInBackground

->onOneServer() → bir necha serverda FAQAT bittasi ishlatsin ->runInBackground() → keyingi vazifani kutmasdan davom etsin

onOneServer — ilova uch serverda ishlayotgan bo'lsa majburiy: aks holda email uch marta ketadi.

⚠️ U umumiy kesh talab qiladi (redis yoki database) — file keshda serverlar bir-birini ko'rmaydi.

runInBackground — bir vaqtda boshlanadigan uzun vazifalar uchun.

HOLAT 5

Xato bo'lsa hech kim bilmaydi

⚠️ cron chiqishi >> /dev/null ga ketadi vazifa yiqilsa — hech qanday xabar YO'Q

✅ Uch qatlam:

->appendOutputTo(storage_path('logs/reja.log')) → chiqishni saqlash ->emailOutputOnFailure('admin@ishtop.uz') → xato bo'lsa xat ->onFailure(fn () => Log::error('...')) → o'z reaksiyangiz ->onSuccess(fn () => ...) → muvaffaqiyatda

🔑 Yoki tashqi kuzatuv: vazifa oxirida ma'lum manzilga so'rov yuboriladi (->pingOnSuccess($url)) — kelmasa xizmat sizni ogohlantiradi.

HOLAT 6

Cron sintaksisi

┌─ daqiqa (0-59) │ ┌─ soat (0-23) │ │ ┌─ oyning kuni (1-31) │ │ │ ┌─ oy (1-12) │ │ │ │ ┌─ hafta kuni (0-7, 0 va 7 = yakshanba) │ │ │ │ │ 0 3 * * * → har kuni 03:00 */15 * * * * → har 15 daqiqada 0 4 * * 1 → har dushanba 04:00 0 0 1 * * → har oyning 1-sanasi

Laravel'da buni yozish shart emas — lekin schedule:list ni o'qish uchun bilish kerak.

HOLAT 7

Rejadagi ish sekin bo'lsa

⚠️ Schedule::call(...) ichida 100 000 yozuvni yangilash → schedule:run JARAYONI band bo'ladi → boshqa vazifalar kechikadi

✅ Uch yechim:

1) Schedule::command(...) → alohida jarayon 2) ->runInBackground() → kutmasdan davom 3) Ish navbatga qo'yilsin: Schedule::call(fn () => EksportIsh::dispatch())->daily();

🔑 Uchinchisi eng yaxshisi: reja faqat boshlaydi, og'ir ishni navbat ishchisi bajaradi (55-dars).

🔍 Va ish ichida cursor() / chunk() (52-dars) — xotira uchun.

Javobni ko'rish

Uchta narsa birga ishlayapti.

2. withoutOverlapping yo'q. Vazifa 4 daqiqa davom etadi. Agar server band bo'lib 5 daqiqa cho'zilsa — keyingi schedule:run ikkinchi nusxani boshlaydi. Natija: ikki marta email.

Reja faqat boshlasin: Schedule::call(fn () => HisobotIsh::dispatch()). Og'ir ishni navbat ishchisi bajaradi (55-dars) — qayta urinish va failed_jobs bepul keladi. Muqobillar: Schedule::command (alohida jarayon) va runInBackground(). 🔍 Ish ichida cursor() (52-dars).
Buyruq uchun nechta xil test kerak?
Ikki xil. 1) Buyruqning mantiqi: $this->artisan(...), expectsOutputToContain, assertSuccessful. 2) Buyruq rejada turibdimi: Schedule::events() ichidan qidirish. 🔑 Ikkinchisi ko'pincha unutiladi — buyruq mukammal bo'lsa ham, rejaga qo'shilmagan bo'lsa hech qachon ishlamaydi va hech kim sezmaydi.
