DARS 38 · MODUL E — TEST (PEST)

Feature test: HTTP javobini so'roqqa tutish

37-darsda javobdan atigi ikki narsa so'radik: status va redirect. Aslida javobda ancha ko'p narsa bor — sahifada qanday matn chiqdi, sessiyaga qaysi xato tushdi, qaysi ko'rinish render qilindi. Bugun shu savollarni berishni o'rganamiz va IshTop'ning o'nta muhim xulqini qulflab qo'yamiz.

📱 O'qish ≈ 16 daqiqa 💻 Amaliyot ≈ 25 daqiqa Kerak: Dars 37

Bu darsda nimalar bor
  1. Javobda nima bor Status, sarlavhalar, HTML matni, sessiya, render qilingan ko'rinish — har biriga alohida savol bor.
  2. Status yordamchilari assertOk · assertForbidden · assertNotFound — assertStatus(200) dan o'qilishi yaxshiroq.
  3. assertRedirect va assertRedirectToRoute Manzil bo'yicha yoki route nomi bo'yicha — ikkinchisi manzil o'zgarsa ham ishlaydi.
  4. ⚠️ from() — qayerdan kelgani Unutilsa back() sayt ildiziga qaytaradi. O'lchangan.
  5. assertSessionHasErrors 35-darsdagi Form Request qoidalarini bittalab qulflash. Xatosiz holatdagi xabari ham ko'rsatiladi.
  6. assertSee / assertDontSee Sahifada matn bormi. Massiv bilan va assertSeeInOrder bilan.
  7. ⚠️ O'zbekcha apostrof tuzog'i Qo'shildi HTML'da Qo&#039;shildi bo'ladi. To'rt xil variant o'lchandi — qaysi biri ishlaydi.
  8. assertSeeText Teglarni tashlab, faqat matnni qidiradi — matn teglar bilan bo'lingan bo'lsa asqotadi.
  9. assertSessionHas Flash xabarni tekshirish: «Qo'shildi: …» sessiyaga yozildimi.
  10. assertViewIs / assertViewHas Qaysi Blade fayli render qilindi va unga qanday o'zgaruvchilar berildi.
  11. 🔍 withoutExceptionHandling() 403 yoki 500 ortidagi haqiqiy istisnoni ko'rsatadi — tashxis qo'yishning eng tez usuli.
  12. Har xil holatlar (7 ta) Apostrof · from() · xatosiz assertSessionHasErrors · assertDontSee yolg'oni · followingRedirects · status yordamchilari · sekin testlar.
Javob — bitta son emas

37-darsdagi test shunday edi:

$javob = $this->get('/vakansiyalar'); $javob->assertStatus(200);

Bu «sahifa ochildi» deganini bildiradi. Lekin nima ochildi? Bo'sh sahifa ham 200 qaytaradi. Xato ro'yxati bilan to'lgan sahifa ham. Nomzodga ish beruvchi formasi ko'rsatilgan sahifa ham.

Javob ichida bir necha qatlam bor va har biriga alohida savol bor:

status → assertOk() · assertForbidden() · assertNotFound() sarlavhalar → assertRedirect() · assertRedirectToRoute() HTML matni → assertSee() · assertDontSee() · assertSeeText() sessiya → assertSessionHas() · assertSessionHasErrors() ko'rinish → assertViewIs() · assertViewHas()

Bugungi maqsad — shu savollar bilan IshTop'ning o'nta muhim xulqini yozib qo'yish. Shundan keyin 29–35-darslarda qurgan narsalaringiz o'z-o'zini qo'riqlaydi.

Status: o'qiladigan shakl

assertStatus(200) → assertOk() assertStatus(403) → assertForbidden() assertStatus(404) → assertNotFound() assertStatus(401) → assertUnauthorized() assertStatus(422) → assertUnprocessable()

Ikkalasi bir xil ishlaydi. Farq — o'qilishida: son o'rniga ma'no yoziladi va testni o'qigan odam HTTP kodlarini yodlab o'tirmaydi.

tests/Feature/VakansiyaTest.php test('vakansiyalar sahifasi ochiladi', function () { $this->get('/vakansiyalar')->assertOk(); });

Diqqat: $javob o'zgaruvchisi yo'q. Assertion metodlari javobning o'zini qaytaradi, shuning uchun ularni zanjir qilib yozish mumkin — 29-darsdagi query builder bilan bir naqsh.

$this->get('/vakansiyalar') ->assertOk() ->assertSee('Vakansiyalar') ->assertDontSee('Yangi vakansiya');

Redirect va from()

$javob->assertRedirect('/vakansiyalar'); $javob->assertRedirectToRoute('vakansiyalar.index'); // route NOMI bilan

Ikkinchisi afzal: 24-darsdagi qoida bo'yicha manzil o'zgarishi mumkin, nom esa qolaveradi.

⚠️ from() unutilsa

Validatsiya xatosida controller back() qiladi — «kelgan joyingga qayt». Lekin test so'rovida «kelgan joy» yo'q: brauzer emassiz, Referer sarlavhasi yuborilmaydi.

O'lchandik:

from() SIZ → http://localhost:8000 ← sayt ILDIZI from() BILAN → http://localhost:8000/vakansiyalar

Ya'ni assertRedirect('/vakansiyalar') yiqiladi va siz controllerda xato qidira boshlaysiz — aslida xato testda.

$this->actingAs($u) ->from('/vakansiyalar') // ← «bu sahifadan yubordim» ->post('/vakansiyalar', [...]);

🔑 Qoida: orqaga qaytaradigan har bir so'rovda from() yozing. Bu odatda validatsiya testlari.

Validatsiyani qulflash: assertSessionHasErrors

35-darsda VakansiyaRequest yozdik. Uning qoidalari ishlayotganini yozib qo'yamiz:

tests/Feature/VakansiyaTest.php test('qoidalarga mos kelmagan ma\'lumot rad etiladi', function () { $ishBeruvchi = User::factory()->create(['rol' => Rol::IshBeruvchi]); $javob = $this->actingAs($ishBeruvchi) ->from('/vakansiyalar') ->post('/vakansiyalar', ['nom' => 'abc', 'maosh' => 'matn']); $javob->assertRedirect('/vakansiyalar'); $javob->assertSessionHasErrors(['nom', 'maosh']); $this->assertDatabaseMissing('vakansiyalar', ['nom' => 'abc']); });

Uch qatlam tekshirildi: qayerga qaytdi, qaysi maydonlarda xato bor, va eng muhimi — bazaga yozilmadi.

🔑 Uchinchisisiz test to'liq emas. Xato ro'yxatini ko'rsatib, ammo yozuvni saqlab qo'yadigan kod ham bo'lishi mumkin.

Xatosiz holatda bu assertion nima deydi — buni ham ko'rib qo'yaylik:

Session is missing expected key [errors]. Failed asserting that false is true.

Aniq va tushunarli: sessiyada errors kaliti umuman yo'q, ya'ni validatsiya o'tib ketgan.

Flash xabarni tekshirish

$javob->assertSessionHas('xabar', "Qo'shildi: Backend dasturchi");

19-darsdan beri ishlatib kelayotgan ->with('xabar', ...) aynan shu kalitni sessiyaga yozadi.

Sahifadagi matn: assertSee

$javob->assertSee('Backend dasturchi'); $javob->assertDontSee('Yangi vakansiya'); $javob->assertSee(['Vakansiyalar', 'Backend dasturchi']); // massiv $javob->assertSeeInOrder(['Vakansiyalar', 'Backend dasturchi']); // tartib bilan
⚠️ O'zbekcha apostrof — bu darsning tuzog'i

IshTop'dagi xabarlar apostrofga to'la: Qo'shildi, bo'lsin, o'chirildi. Blade esa {{ }} ichidagi hamma narsani ekranlaydi (18-dars):

Blade'da: {{ session('xabar') }} HTML'da: Qo&#039;shildi: Backend dasturchi

Ya'ni sahifaning HTML kodida Qo'shildi degan matn umuman yo'q. Unda assertSee("Qo'shildi: …") qanday ishlaydi? To'rtta variantni o'lchab ko'rdik:

A assertSee("Qo'shildi: Backend dasturchi") → ✓ o'tdi B assertSee("Qo'shildi: Backend dasturchi", false) → ⨯ YIQILDI C assertSee("Qo&#039;shildi: Backend dasturchi", false) → ✓ o'tdi D assertSeeText("Qo'shildi: Backend dasturchi") → ✓ o'tdi

Sabab: assertSee izlanayotgan matnni ham ekranlaydi — shuning uchun A ishlaydi. Ikkinchi argument false «ekranlama» degani, va o'shanda xom apostrof HTML'da topilmaydi.

🔑 Qoida: odatiy holda assertSee ni ikkinchi argumentsiz ishlating va matnni o'zbekcha yozavering. false ni faqat HTML teg qidirganda qo'ying (masalan assertSee('<form', false)).

assertSeeText — teglar aralashganda

Blade'da: <p>Vakansiya qo'shish uchun <b>ish beruvchi</b> sifatida kirishingiz kerak.</p> assertSee('ish beruvchi sifatida kirishingiz') → ⨯ YIQILDI assertSeeText('ish beruvchi sifatida kirishingiz') → ✓ o'tdi

Sabab ko'rinib turibdi: matn o'rtasida </b> turibdi, shuning uchun tutash qator sifatida u HTML'da yo'q.

assertSeeText avval barcha teglarni olib tashlaydi, keyin qidiradi. Matn <b> yoki <span> bilan bo'lingan bo'lsa — shu kerak.

Ko'rinish: assertViewIs va assertViewHas

$this->get('/vakansiyalar') ->assertViewIs('vakansiyalar.index') // qaysi Blade fayli ->assertViewHas('vakansiyalar') // controller shu nomni berdimi ->assertViewHas('shaharlar');

Bu tekshiruvlar HTML'ga qaramaydi — ular controller bilan Blade o'rtasidagi shartnomani tekshiradi. Dizayn o'zgarsa, bu testlar yiqilmaydi.

🔍 Qachon foydali: sahifa katta va murakkab bo'lganda assertSee mo'rt bo'lib qoladi (matn ozgina o'zgarsa yiqiladi). assertViewHas esa ma'lumot yetkazildimi degan savolga javob beradi.

🔍 withoutExceptionHandling() — 403 ortida nima bor

Test 403 qaytardi, siz esa 302 kutgan edingiz. Sabab qayerda — policy'dami, Form Request'dami, middleware'dami?

Odatda Laravel istisnolarni ushlab, chiroyli HTTP javobga aylantiradi. Bir qatorda buni o'chirib qo'yish mumkin:

$this->withoutExceptionHandling() ->actingAs($nomzod) ->post('/vakansiyalar', [...]);

Endi test yiqiladi — lekin foydali tarzda:

FAILED ... AuthorizationException This action is unauthorized. at vendor/laravel/framework/.../Foundation/Http/FormRequest.php:337 335▕ protected function failedAuthorization() 336▕ { ➜ 337▕ throw new AuthorizationException;

🔑 Javob aniq: taqiqni Form Requestning authorize() metodi qo'ygan (35-dars), policy emas. Endi qayerga qarash kerakligini bilasiz.

Ish tugagach bu qatorni olib tashlang — u faqat tashxis uchun. Aks holda testingiz 403 javobini emas, istisnoni kutadigan bo'lib qoladi.

Har xil holatlar

Yetti holat. Bu bo'lim ma'lumotnoma — hozir bir marta o'qib chiqing, keyin kerak bo'lganda qaytib qarang.

HOLAT 1

Apostrof va assertSee(..., false)

A assertSee("Qo'shildi: …") → ✓ B assertSee("Qo'shildi: …", false) → ⨯ Blade ekranlagan C assertSee("Qo&#039;shildi: …", false) → ✓ D assertSeeText("Qo'shildi: …") → ✓

Ikkinchi argument false — «izlanayotgan matnni ekranlama». Odatiy holda assertSee uni ekranlaydi va shuning uchun o'zbekcha matn bemalol ishlaydi.

✅ Qoida: false ni faqat HTML teg qidirganda ishlating (assertSee('<form', false)). Matn uchun — hech qachon.

🔍 Bu tuzoq inglizcha qo'llanmalarda deyarli uchramaydi, chunki inglizcha matnda apostrof kam. O'zbekchada esa u har qadamda.

HOLAT 2

from() unutilishi

from() SIZ → Location: http://localhost:8000 from() BILAN → Location: http://localhost:8000/vakansiyalar

Testda Referer sarlavhasi yo'q, shuning uchun back() sayt ildiziga qaytaradi.

✅ Orqaga qaytaradigan har bir so'rovdan oldin ->from('/qayerdan') yozing. Belgisi oddiy: agar controller back() ishlatsa — from() kerak.

🔍 Chalg'ituvchi tomoni — va bu o'lchandi. Redirect tekshiruvi yiqilganda sessiyada validatsiya xatolari bo'lsa, Pest sizga haqiqiy farqni ko'rsatmaydi:

sessiyada xato BOR → Error: Call to a member function all() on array sessiyada xato YO'Q → Failed asserting that two strings are equal.

Birinchi xabar butunlay boshqa tomonga olib ketadi: siz kodingizdan ->all() qidira boshlaysiz — holbuki u yerda hech qanday all() yo'q.

✅ Tashxis: shu xabarni ko'rsangiz, avval redirect manzilini o'z ko'zingiz bilan qarang:

dump($javob->headers->get('Location')); → "http://localhost:8000" ← from() unutilgan
HOLAT 3

Xatosiz holatda assertSessionHasErrors

Session is missing expected key [errors]. Failed asserting that false is true.

Sessiyada errors kaliti umuman yo'q — ya'ni validatsiya o'tib ketgan, so'rov muvaffaqiyatli bajarilgan.

✅ Ikki sabab bo'lishi mumkin: qoida haqiqatan ishlamayapti, yoki yuborgan ma'lumotingiz to'g'ri chiqib qolgan. Ikkinchisi ko'proq uchraydi — yuborayotgan qiymatlarni qayta o'qing.

HOLAT 4

assertDontSee yolg'on xotirjamlik beradi

->assertDontSee('Yangi vakansiya') // ✓ o'tdi // lekin sahifada: <h2>Yangi e'lon</h2> ← matn o'zgargan!

assertDontSee «yo'q»ni tasdiqlaydi. Matn o'zgartirilsa u baribir o'tadi — endi hech qanday himoya qolmagan bo'lsa ham.

✅ Har doim juftlab yozing: bir testda «ko'rinmaydi», boshqasida «ko'rinadi». Agar «ko'rinadi» testi ham yashil bo'lsa, matn haqiqatan o'zgarmagan.

🔑 Kuchliroq usul: ko'rinishni emas, huquqni tekshiring — assertForbidden(). Matn o'zgarishidan mustaqil.

HOLAT 5

followingRedirects()

$this->actingAs($u)->followingRedirects() ->post('/vakansiyalar', [...]) ->assertOk() ->assertSee("Qo'shildi: Backend dasturchi");

Odatda test redirect'ni kuzatmaydi — 302 javobda to'xtaydi. followingRedirects() uni oxirigacha olib boradi, natijada 200 va yakuniy sahifa keladi.

✅ Qulay, lekin ehtiyot bo'ling: endi assertRedirect ishlatib bo'lmaydi — redirect allaqachon bajarilgan. Ikki narsani tekshirish kerak bo'lsa, ikkita alohida test yozing.

HOLAT 6

Status yordamchilarini ishlatish

assertStatus(403) → assertForbidden() assertStatus(404) → assertNotFound() assertStatus(200) → assertOk()

Bir xil ishlaydi, lekin testni o'qish osonlashadi: son o'rniga ma'no turadi.

🔍 Yana bir foydasi: assertForbidden() deb yozilgan test nima himoya qilinayotganini aytadi. assertStatus(403) esa faqat sonni aytadi va o'quvchi HTTP jadvalini eslashi kerak bo'ladi.

HOLAT 7

Mo'rt testlar

->assertSee('Backend dasturchi — 9 000 000 so\'m/oy') // ⚠️ mo'rt ->assertSee('Backend dasturchi') // ✅ barqaror ->assertViewHas('vakansiyalar') // ✅ dizayndan mustaqil

Uzun, aniq matnga bog'langan test dizayn ozgina o'zgarsa yiqiladi — holbuki hech nima buzilmagan. Bunday testlar tez ishonchni yo'qotadi va odamlar ularni o'chira boshlaydi.

✅ Tekshiruvni eng qisqa ishonchli belgiga bog'lang: vakansiya nomi, xato xabarining o'zagi, yoki umuman assertViewHas.

🔑 Savol: «bu o'zgarsa, foydalanuvchi uchun nimadir buziladimi?» Yo'q bo'lsa — testda unga bog'lanmang.

Sinab ko'ramiz

Natijani taxmin qiling

Dasturchi nomzod formani ko'rmasligini test qildi:

tests/Feature/VakansiyaTest.php
test('nomzod qo\'shish formasini ko\'rmaydi', function () { $nomzod = User::factory()->create(['rol' => Rol::Nomzod]); $this->actingAs($nomzod)->get('/vakansiyalar') ->assertDontSee('Yangi vakansiya'); });

Oradan bir oy o'tdi. Dizayner sarlavhani «Yangi e'lon» ga o'zgartirdi, va yo'l-yo'lakay kimdir @can ni ham olib tashladi — endi formani hamma ko'radi.

Test nima deydi?

Javobni ko'rish
✓ nomzod qo'shish formasini ko'rmaydi Yashil. Holbuki nomzod formani KO'RIB TURIBDI.

Sabab: test 'Yangi vakansiya' matnini qidiryapti, sahifada esa endi 'Yangi e'lon'. Matn topilmadi — demak assertDontSee bajarildi.

⚠️ assertDontSee «yo'q»ni tasdiqlaydi, va «yo'q» bo'lishining ikki sababi bor: himoya ishlayapti yoki siz noto'g'ri narsani qidiryapsiz. Test ikkalasini ajrata olmaydi.

Birinchi yechim — juftlab yozish:

test('ish beruvchi formani ko\'radi', ...)->assertSee('Yangi vakansiya'); test('nomzod formani ko\'rmaydi', ...)->assertDontSee('Yangi vakansiya');

Matn o'zgarsa birinchisi darhol qiziradi va sizni ogohlantiradi.

Ikkinchi yechim — kuchliroq: ko'rinishni emas, huquqni tekshiring:

$this->actingAs($nomzod) ->post('/vakansiyalar', ['nom' => 'Test nomi', 'maosh' => 1]) ->assertForbidden();

Bu test dizaynga umuman bog'liq emas: sarlavha ham, tugma ham, tartib ham o'zgarishi mumkin — 403 qolaveradi.

🔑 Qoida: assertDontSee — ko'rinish uchun qo'shimcha tekshiruv. Asosiy himoya har doim status bilan tekshirilsin. Bu 33-darsdagi «yashirish — himoya emas» qoidasining testdagi ko'rinishi.

SAVOL 1 Nega assertSee("Qo'shildi") apostrof bilan ham ishlaydi?

Blade {{ }} ichini ekranlaydi, HTML'da Qo&#039;shildi turadi. assertSee esa izlanayotgan matnni ham ekranlaydi — shuning uchun mos keladi. ⚠️ Ikkinchi argument false qo'ysangiz ekranlash o'chadi va o'zbekcha matn topilmay qoladi.

SAVOL 2 Testda from() yozilmasa back() qayerga qaytaradi?

Testda Referer sarlavhasi yo'q — brauzer emassiz. O'lchandi: Location: http://localhost:8000. ⚠️ Va bunday holatda xato xabari chalg'itadi: Call to a member function all() on array. Yechim — ->from('/vakansiyalar').

SAVOL 3 withoutExceptionHandling() nima qiladi?

Odatda Laravel istisnoni ushlab, chiroyli HTTP javobga (403, 500) aylantiradi. Bu metod uni o'chiradi va siz AuthorizationException ni manba faylida ko'rasiz — 403 ni kim qo'yganini bilib olasiz. 🔍 Tashxis tugagach qatorni olib tashlang.

Eslab ayting

Avval o'zingiz javob bering, keyin ochib tekshiring. Oxirgi ikkitasi — 37-darsni takrorlash.

Validatsiya testida nechta narsa tekshiriladi?

Uchta: qayerga qaytdi (assertRedirect), qaysi maydonlarda xato bor (assertSessionHasErrors) va bazaga yozilmadi (assertDatabaseMissing). Oxirgisisiz test to'liq emas.

assertSee va assertSeeText farqi?

assertSee HTML kodida qidiradi (izlanayotgan matnni ekranlab). assertSeeText avval teglarni tashlaydi — matn <b> bilan bo'lingan bo'lsa shu kerak.

Nega assertDontSee yolg'on xotirjamlik beradi?

«Yo'q» bo'lishining ikki sababi bor: himoya ishlayapti yoki matn o'zgargan. Test ajrata olmaydi. Yechim — juftlab yozish yoki huquqni tekshirish (assertForbidden).

Cho'ntak xulosasi
  • Javobda bir necha qatlam bor: status, sarlavhalar, HTML, sessiya, ko'rinish — har biriga alohida savol.
  • Status: assertOk() · assertForbidden() · assertNotFound() — assertStatus(403) dan o'qilishi yaxshiroq.
  • Assertion metodlari javobning o'zini qaytaradi — zanjir qilib yozing.
  • assertRedirect('/manzil') · assertRedirectToRoute('nom') — ikkinchisi manzil o'zgarsa ham ishlaydi.
  • ⚠️ from(): testda Referer yo'q, shuning uchun back() sayt ildiziga qaytaradi (http://localhost:8000). back() ishlatadigan har bir so'rovda ->from('/qayerdan').
  • ⚠️ Redirect tekshiruvi yiqilganda sessiyada validatsiya xatosi bo'lsa, Pest chalg'ituvchi xabar beradi: Call to a member function all() on array. Manzilni dump() bilan qarang.
  • assertSessionHasErrors(['nom', 'maosh']) — 35-darsdagi qoidalarni qulflaydi. Xatosiz holatda: Session is missing expected key [errors].
  • assertSessionHas('xabar', '…') — flash xabar.
  • ⚠️ O'zbekcha apostrof: Blade ekranlaydi (Qo&#039;shildi), lekin assertSee izlanayotgan matnni ham ekranlaydi — shuning uchun assertSee("Qo'shildi") ishlaydi. Ikkinchi argument false qo'ysangiz — yiqiladi.
  • false ni faqat HTML teg qidirganda ishlating: assertSee('<form', false).
  • assertSeeText teglarni tashlab qidiradi — matn <b> bilan bo'lingan bo'lsa.
  • assertSee([...]) massiv bilan, assertSeeInOrder([...]) tartib bilan.
  • ⚠️ assertDontSee yolg'on xotirjamlik beradi: matn o'zgarsa ham o'tadi. Juftlab yozing yoki assertForbidden() bilan huquqni tekshiring.
  • assertViewIs('vakansiyalar.index') · assertViewHas('vakansiyalar') — dizayndan mustaqil.
  • followingRedirects() — redirect'ni oxirigacha kuzatadi (keyin assertRedirect ishlatib bo'lmaydi).
  • 🔍 withoutExceptionHandling() — 403/500 ortidagi haqiqiy istisno. Tashxis tugagach olib tashlang.
  • Mo'rt testdan qoching: uzun aniq matnga emas, eng qisqa ishonchli belgiga bog'laning.
  • Natija: 10 test, 27 tekshiruv, 0.22 soniya — 29–35-darslar qulflandi.
