DARS 27 · MODUL C — MA'LUMOTLAR

Ko'pdan-ko'pga: vakansiya ↔ ko'nikma

26-darsdagi bog'lanish bir tomonlama edi: bitta vakansiyada bitta kompaniya. Lekin vakansiya bir necha ko'nikma talab qiladi, va bitta ko'nikma bir necha vakansiyada uchraydi. Bunday holatni bitta ustun bilan yechib bo'lmaydi — uchinchi jadval kerak.

📱 O'qish ≈ 16 daqiqa 💻 Amaliyot ≈ 26 daqiqa Kerak: Dars 26

Bu darsda nimalar bor
  1. Nega bitta ustun yetmaydi Ko'pdan-ko'pga (many to many) bog'lanishning shakli va uni kompaniya_id kabi yechib bo'lmasligining sababi.
  2. Pivot jadval Uchinchi jadval — konikma_vakansiya. Faqat ikki tashqi kalitdan iborat bo'lishi mumkin, lekin qo'shimcha ustun ham qo'shiladi.
  3. Pivot jadvalni migration bilan yasash foreignId()->constrained() · cascadeOnDelete() · unique([...]) — takroriy juftlikni baza darajasida taqiqlash.
  4. belongsToMany — ikki tomondan Bu bog'lanishda ikki tomon ham bir xil metodni ishlatadi — 26-darsdagi belongsTo/hasMany juftligidan farqi shu.
  5. Laravel pivot nomini qanday taxmin qiladi Ikki model nomini alifbo tartibida qo'shadi: Konikma + Vakansiya → konikma_vakansiya. Ko'plik yasamaydi.
  6. Amallar: attach · detach · sync · toggle Qo'shish · olib tashlash · ro'yxatni aynan moslashtirish · almashtirish. Va syncWithoutDetaching nima uchun kerak.
  7. Pivot ustunidagi qo'shimcha ma'lumot withPivot('daraja') va $k->pivot->daraja. Yozilmasa — jimgina NULL.
  8. Har xil holatlar (7 ta) Nom mos kelmaganda · takroriy attach · withPivot siz · sync va uning hisoboti · filtrlash · ikki tomonlama sanash · pivotga vaqt muhri.
  9. N+1 va with() Yana o'lchaymiz: 6 → 2 → 1. Pivot bilan ishlaganda so'rov inner join ga aylanadi.
  10. IshTop'da natija Vakansiya sahifasida ko'nikmalar ro'yxati, ro'yxat sahifasida ko'nikma soni.
Nega bitta ustun yetmaydi

26-darsda kompaniyani vakansiyalar.kompaniya_id ustuni bilan bog'lagandik. Xuddi shu yo'lni ko'nikma uchun sinab ko'ramiz: vakansiyalar.konikma_id. Lekin vakansiya uchta ko'nikma talab qilsa-chi?

❌ konikma_id ustuniga uchta qiymat sig'maydi ❌ konikma_id_1, konikma_id_2, konikma_id_3 — nechta ustun kerak? Beshta? O'nta? Va «PHP talab qiladigan vakansiyalar» so'rovi qanday yoziladi?

Muammoning ildizi shunda: bog'lanish vakansiyaning xossasi ham emas, ko'nikmaning xossasi ham emas — u ikkisining orasidagi fakt. Shuning uchun uni o'z jadvalida saqlash kerak.

Bu naqsh hamma joyda uchraydi: maqola ↔ teg, o'quvchi ↔ kurs, film ↔ janr. Va IshTop uchun ham ikkinchi marta kerak bo'ladi — nomzod ↔ vakansiya (ariza).

Pivot jadval — bog'lanishning o'z jadvali

Pivot jadvalning har qatori — bitta juftlik. Vakansiyaga to'rtinchi ko'nikma kerak bo'lsa, jadvalga yana bitta qator qo'shiladi; ustun qo'shilmaydi. Shuning uchun cheklov yo'q.

Atama: pivot

Pivot jadval (pivot table) — faqat bog'lanishni saqlash uchun yasalgan jadval. Boshqa nomlari ham bor: junction table, join table, «oraliq jadval». Laravel hujjatlarida pivot deyiladi, shuning uchun kursda ham shu atamani ishlatamiz.

Odatda unda id ham shart emas — ikki tashqi kalit birgalikda qatorni ajratib turadi. Lekin biz id ni qoldiramiz: Laravel'ning standart $table->id() qatori zarar qilmaydi va keyinroq pivotga qo'shimcha ustun qo'shganda qulay bo'ladi.

belongsToMany — ikki tomon ham bir xil

26-darsda ikki tomon ikki xil metod ishlatgan edi (belongsTo va hasMany). Ko'pdan-ko'pgada esa simmetriya bor — ikkalasi ham belongsToMany:

app/Models/Vakansiya.php
public function konikmalar(): BelongsToMany { return $this->belongsToMany(Konikma::class)->withPivot('daraja'); }
app/Models/Konikma.php
public function vakansiyalar(): BelongsToMany { return $this->belongsToMany(Vakansiya::class); }

Ishlatish 26-darsdagidek — qavssiz natija, qavs bilan so'rov:

$v->konikmalar->pluck('nom')->implode(', ') → "PHP, Laravel, SQL" $k->vakansiyalar->pluck('nom')->implode(', ') → "Backend dasturchi, Laravel dasturchi" $v->konikmalar()->where('nom', 'PHP')->exists() → true

Pivot nomi qanday taxmin qilinadi

Biz hech qayerda konikma_vakansiya deb yozmadik. Qoida:

Ikki MODEL nomi → kichik harfga → ALIFBO tartibida → «_» bilan qo'shiladi Konikma + Vakansiya → konikma, vakansiya → konikma_vakansiya ✅ (k < v) Diqqat: ko'plik YASALMAYDI. «konikmalar_vakansiyalar» emas!

O'zbekcha nomlar bu safar ham muammo bermadi

25-darsda $table ni qo'lda yozishga majbur bo'ldik, chunki Laravel ko'plik yasashga urinardi. Bog'lanishlarda esa (26 va 27-darslar) u ko'plik yasamaydi — shunchaki _id qo'shadi yoki ikki nomni birlashtiradi.

Shuning uchun butun kursda faqat bitta qoidaga rioya qilsak yetadi: jadval nomlarini model nomiga qarab tanlash (Kompaniya → kompaniya_id, Konikma+Vakansiya → konikma_vakansiya). Migration'ni biz yozamiz, ya'ni nomni tanlash ham bizning qo'limizda.

Ochiq gap: professional Laravel loyihalarida kod nomlari odatda inglizcha bo'ladi (Vacancy, Skill) — hujjatlar, kutubxonalar va xalqaro jamoa shu tilda. Bu kursda o'zbekcha nom ongli tanlov: atamalar tushunarli bo'lishi uchun. Ish joyida jamoaning uslubiga qarab yozasiz.

Amallar: attach, detach, sync, toggle

Pivotdagi qo'shimcha ma'lumot

Pivot jadvalda daraja ustuni bor edi. Unga yetib borish uchun ikki narsa kerak:

1) Modelda: ->withPivot('daraja') 2) Ishlatishda: $k->pivot->daraja
foreach ($v->konikmalar as $k) { echo $k->nom, ' — ', $k->pivot->daraja; } PHP — kuchli Laravel — SQL —

$k->pivot — pivot qatorini ifodalovchi obyekt (Illuminate\Database\Eloquent\Relations\Pivot). Uning ichida faqat siz withPivot da sanab o'tgan ustunlar bo'ladi:

withPivot('daraja') BOR → {"vakansiya_id":1,"konikma_id":1,"daraja":"kuchli"} withPivot YO'Q → {"vakansiya_id":1,"konikma_id":1} va $k->pivot->daraja → NULL (xato yo'q!)
🔍 Sehr yo'q: pivot qayerdan keladi

26-darsdagi toSql() shu yerda ham javob beradi. Laravel pivot ustunlarini taxallus bilan tortadi:

select "konikmalar".*, "konikma_vakansiya"."vakansiya_id" as "pivot_vakansiya_id", "konikma_vakansiya"."konikma_id" as "pivot_konikma_id", "konikma_vakansiya"."daraja" as "pivot_daraja" from "konikmalar" inner join "konikma_vakansiya" on "konikmalar"."id" = "konikma_vakansiya"."konikma_id" where "konikma_vakansiya"."vakansiya_id" = ?

pivot_ prefiksiga qarang — $k->pivot obyekti aynan shu ustunlardan yasaladi. Va so'rovning o'zi — 22-darsdagi INNER JOIN. Ya'ni siz o'rgangan SQL Laravel ichida o'zgarmagan holda ishlaydi.

Har xil holatlar

Yetti holat. Bu bo'lim ma'lumotnoma — hozir bir marta o'qib chiqing, keyin kerak bo'lganda qaytib qarang.

HOLAT 1

Nomlar taxminga mos kelganda — hech narsa yozmaymiz

Pivot jadval konikma_vakansiya, kalitlar vakansiya_id va konikma_id. Hammasi taxminga mos:

return $this->belongsToMany(Konikma::class);

Migration'ni siz yozgani uchun bu holatga erishish mumkin — jadvalni shunchaki to'g'ri nomlash kifoya. Eng ko'p uchraydigan va eng oson holat.

HOLAT 2

Nom taxminga mos kelmaganda — barcha argumentlarni ko'rsatish

Aytaylik pivot jadvalni vakansiya_konikmalari deb nomlagansiz (yoki mavjud bazada shunday). Taxmin ishlamaydi va xato chiqadi:

SQLSTATE[HY000]: General error: 1 no such table: konikma_vakansiya

✅ Yechim — to'rt argument:

return $this->belongsToMany( Konikma::class, 'vakansiya_konikmalari', // pivot jadval nomi 'vakansiya_id', // bu modelning kaliti 'konikma_id', // u modelning kaliti );

Bu xato ovoz chiqaradi (26-darsdagi belongsTo dan farqli — u jimgina NULL qaytarardi). Sababi: pivotda so'rov albatta yuboriladi, jadval esa yo'q. Xatoni o'qish oson: xabar sizga Laravel qaysi nomni izlaganini aytadi.

HOLAT 3

Bir juftlikni ikki marta qo'shish

attach() mavjudini tekshirmaydi. Bizda unique indeks bor, shuning uchun baza rad etadi:

$v->konikmalar()->attach(1); // birinchi marta — OK $v->konikmalar()->attach(1); // ikkinchi marta: SQLSTATE[23000]: Integrity constraint violation: 19 UNIQUE constraint failed: konikma_vakansiya.vakansiya_id, konikma_vakansiya.konikma_id

⚠️ Agar unique indeks bo'lmasa — xato bo'lmaydi, pivotga ikkinchi qator qo'shiladi va sahifada «PHP» ikki marta ko'rinadi. Aynan shu sababdan biz uni migration'ga yozdik: bu ma'lumotning butunligini baza darajasida himoya qiladi.

✅ Xatoni try/catch bilan tutish emas, to'g'ri metodni tanlash kerak:

$v->konikmalar()->syncWithoutDetaching([1]); // bori bo'lsa — jim turadi
HOLAT 4

withPivot yozilmaganda — ⚠️ jimgina NULL

Pivotda daraja ustuni bor, ma'lumot ham bor, lekin modelda withPivot('daraja') yozilmagan:

$k->pivot->daraja → NULL Xato: yo'q Bazada qiymat: BOR ('kuchli')

Bu 26-darsdagi «jimgina buzilish»ning ukasi. Sahifada shunchaki bo'sh joy chiqadi va siz ma'lumotni bazada qidirib vaqt yo'qotasiz.

✅ Tashxis: $k->pivot->toArray() ni chiqarib ko'ring — unda faqat withPivot da sanalgan ustunlar bo'ladi. Ustun ro'yxatda yo'q bo'lsa, muammo modelda.

->withPivot('daraja', 'created_at') // bir nechta ustun ->withTimestamps() // pivotdagi vaqt muhrlarini boshqarish
HOLAT 5

sync · syncWithoutDetaching · toggle

Uchalasi ham ro'yxat qabul qiladi, lekin natijasi butunlay boshqacha. Boshlang'ich holat: PHP, SQL, Docker

sync([2, 4]) → Laravel, Git (2 va 4 qo'shildi, QOLGANLARI O'CHDI) syncWithoutDetaching([2, 4]) → PHP, SQL, Docker, Laravel, Git (qo'shildi, hech narsa o'chmadi) toggle([2, 4]) → PHP, SQL, Docker, Laravel, Git (yo'q edi — keldi; bori bo'lganda ketardi)

sync() hisobot qaytaradi — nima qilganini aniq ko'rsatadi:

{"attached":[2,4],"detached":[1,3,5],"updated":[]}

Bu hisobot juda foydali: shubha bo'lsa uni chiqarib ko'ring va detached ro'yxatiga qarang.

Qachon qaysi biri: forma butun ro'yxatni yuborsa (checkbox'lar) — sync; bitta narsa qo'shish kerak bo'lsa — syncWithoutDetaching; «yoqish/o'chirish» tugmasi — toggle.

HOLAT 6

Filtrlash — ikki tomondan ham

whereHas (26-dars) ko'pdan-ko'pgada ham xuddi shunday ishlaydi:

// PHP talab qiladigan vakansiyalar Vakansiya::whereHas('konikmalar', fn ($q) => $q->where('nom', 'PHP'))->pluck('nom') → "Backend dasturchi, Laravel dasturchi" (2 ta) // Hech qanday ko'nikma ko'rsatilmagan vakansiyalar Vakansiya::doesntHave('konikmalar')->count() → 1 // Bitta so'rovda ikkita shart: PHP VA SQL Vakansiya::whereHas('konikmalar', fn ($q) => $q->where('nom', 'PHP')) ->whereHas('konikmalar', fn ($q) => $q->where('nom', 'SQL')) ->pluck('nom')

Oxirgi misolga diqqat: «PHP va SQL» uchun ikkita whereHas yoziladi. Bitta whereHas ichida where('nom','PHP')->where('nom','SQL') yozsangiz — hech narsa topilmaydi, chunki bitta qator ikki xil nomga ega bo'lolmaydi.

HOLAT 7

Ikki tomonlama sanash — withCount

withCount (26-dars) pivot ustida ham ishlaydi, va ikki tomondan ham ma'noli:

// Har vakansiyada nechta ko'nikma Vakansiya::withCount('konikmalar')->get() → $v->konikmalar_count // Eng ko'p talab qilinadigan ko'nikma — bitta so'rovda Konikma::withCount('vakansiyalar')->orderByDesc('vakansiyalar_count')->get() PHP 2 Laravel 2 SQL 2 Git 2 Docker 1

Ikkinchisi — real hisobot: «bozorda qaysi ko'nikma ko'proq talab qilinadi». 22-darsda buni JOIN + GROUP BY bilan yozgan bo'lardik; endi bitta qator.

⚡ N+1 — pivot bilan ham

26-darsdagi muammo bu yerda ham bor, va yechim ham o'sha:

── with() SIZ SO'ROVLAR SONI: 6 ← 1 + 5 (har vakansiya uchun bittadan) ── with('konikmalar') BILAN SO'ROVLAR SONI: 2 ... where "konikma_vakansiya"."vakansiya_id" in (1, 2, 3, 4, 5) ── withCount('konikmalar') SO'ROVLAR SONI: 1

Ikkinchi so'rovdagi in (1, 2, 3, 4, 5) — Laravel barcha vakansiyalarning id larini yig'ib, pivotdan hammasini bitta so'rovda oldi.

bir necha bog'lanishni birga yuklash
Vakansiya::with(['kompaniya', 'konikmalar'])->findOrFail($id);

with() massiv ham qabul qiladi — bir necha bog'lanishni birga yuklash uchun. Har biri uchun bittadan qo'shimcha so'rov ketadi, ya'ni 3 so'rov jami — sikldagi o'nlab so'rovdan ancha yaxshi.

💻 Amaliy qism kompyuterda

Amaliyotda ikkita migration yozasiz (konikmalar va pivot), keyin barcha amallarni skriptda sinab ko'rasiz — shu qatorda sync() nimani o'chirganini hisobot bilan ko'rasiz. Oxirida vakansiya sahifasida ko'nikmalar ro'yxati, ro'yxat sahifasida esa ko'nikma soni paydo bo'ladi.

Amaliyot

  1. Ikkita migration yarating

    Tartib muhim: pivot ikkala jadvalga tayanadi, shuning uchun konikmalar oldin yaratilishi kerak.

  2. konikmalar migration'ini to'ldiring

    Ya'ni: bitta qator qo'shasiz. ->unique() — «PHP» ikki marta yozilmasin.

  3. Pivot migration'ini to'ldiring

    Darsning eng muhim migration'i: ikki tashqi kalit, cascade va takroriy juftlik taqiqi.

    Endi bajarishdan oldin SQL'ni ko'ring, keyin bajaring:

    php artisan migrate --pretend | tail -8 php artisan migrate 2026_…_create_konikmalar_table .. DONE 2026_…_create_konikma_vakansiya_table .. DONE

    Kutilgan natija: --pretend chiqishida on delete cascade va create unique index … qatorlarini ko'rasiz, keyin ikki migration bajariladi.

Sinab ko'ramiz

Natijani taxmin qiling

«Laravel dasturchi» vakansiyasida uchta ko'nikma bor: PHP, Laravel, Docker. Hamkasbingiz unga SQL ni ham qo'shmoqchi bo'ldi. Hujjatda sync metodini ko'rdi va shunday yozdi:

kod
$v = Vakansiya::find(3); // PHP, Laravel, Docker $sql = Konikma::where('nom', 'SQL')->first(); $v->konikmalar()->sync([$sql->id]); echo $v->konikmalar()->pluck('nom')->implode(', ');

Ekranda nima chiqadi? Va xato xabari bo'ladimi?

Javobni ko'rish
SQL Xato: yo'q Bazada: PHP, Laravel, Docker juftliklari O'CHIRILDI

Uchta ko'nikma yo'qoldi. Sababi: sync() «qo'sh» degani emas — u ro'yxatni aynan moslashtiradi. Siz bergan ro'yxatda faqat SQL bor edi, demak qolganlari ortiqcha hisoblandi va pivotdan o'chirildi.

Buni sync() qaytargan hisobot ochiq aytadi:

{"attached":[3],"detached":[1,2,5],"updated":[]} ↑ uchta juftlik o'chirildi

🔑 Nega bu xatarli: xato yo'q, ogohlantirish yo'q. Kod «ishlaydi» — faqat ma'lumot yo'qoladi. Va agar bu forma orqali bajarilsa, foydalanuvchi buni ancha keyin sezadi.

To'g'ri yechim — niyatga mos metod:

// «Qo'sh, boshqasiga tegma» $v->konikmalar()->syncWithoutDetaching([$sql->id]); → PHP, Laravel, Docker, SQL ✅ // attach() ham qo'shadi, lekin bori bo'lsa UNIQUE xatosi beradi $v->konikmalar()->attach($sql->id);

sync() o'z joyida to'g'ri: forma checkbox'lar bilan butun ro'yxatni yuborganda («shu vakansiyaning ko'nikmalari — aynan shular»). Ya'ni metod yomon emas, niyatga mos kelmagan.

SAVOL 1 Ko'pdan-ko'pga bog'lanish uchun nima kerak?

Bog'lanish ikki tomonning hech biriga tegishli emas — u ikkisining orasidagi fakt. Shuning uchun o'z jadvalida saqlanadi va har juftlik bitta qator bo'ladi.

SAVOL 2 sync([5]) nima qiladi?

sync ro'yxatni aynan moslashtiradi. Faqat qo'shish kerak bo'lsa — syncWithoutDetaching. Hisobotdagi detached ro'yxati nima o'chganini aytadi.

SAVOL 3 Modelda withPivot('daraja') yozilmasa nima bo'ladi?

Bazada qiymat bor, lekin so'rovga qo'shilmaydi — ya'ni yana jimgina buzilish. Tashxis: $k->pivot->toArray() da ustun bor-yo'qligini ko'rish.

Eslab ayting

Avval o'zingiz javob bering, keyin ochib tekshiring. Oxirgi ikkitasi — 26-darsni takrorlash.

Pivot jadval nomini Laravel qanday taxmin qiladi?

Ikki model nomini kichik harfga o'giradi, alifbo tartibida qo'yadi va _ bilan qo'shadi: Konikma + Vakansiya → konikma_vakansiya. Ko'plik yasamaydi.

attach, sync va syncWithoutDetaching farqi?

attach — qo'shadi, mavjudini tekshirmaydi (takroriy juftlik yoki UNIQUE xatosi); sync — ro'yxatni aynan moslashtiradi, ortiqchasini o'chiradi; syncWithoutDetaching — qo'shadi, hech narsa o'chirmaydi.

Pivotdagi qo'shimcha ustunga qanday yetib boriladi?

Modelda ->withPivot('daraja'), ishlatishda $k->pivot->daraja. Birinchisi yozilmasa — jimgina NULL.

↩︎ Takrorlash: qavssiz va qavs bilan farqi?

Qavssiz ($v->konikmalar) — so'rov bajariladi, Collection qaytadi. Qavs bilan ($v->konikmalar()) — so'rov, ustiga where, attach, sync qo'shiladi.

↩︎ Takrorlash: N+1 nima va qanday o'lchanadi?

Sikl ichida bog'lanishga murojaat → 1 + N so'rov. O'lchash: DB::enableQueryLog() + count(DB::getQueryLog()). Yechim — with() (o'lchandi: 6 → 2).

Cho'ntak xulosasi
  • Ko'pdan-ko'pga bog'lanish uchinchi jadvalda saqlanadi — pivot. Har qator = bitta juftlik.
  • Ikki tomon ham bir xil metod: belongsToMany.
  • 🔑 Pivot nomi taxmini: ikki model nomi → kichik harf → alifbo tartibida → _ bilan. konikma_vakansiya. Ko'plik yasalmaydi.
  • Migration'da: foreignId()->constrained() · cascadeOnDelete() · unique([...]) — oxirgisi takroriy juftlikni baza darajasida taqiqlaydi.
  • Amallar (hammasi qavs bilan): attach · detach · sync · syncWithoutDetaching · toggle · updateExistingPivot.
  • ⚠️ sync() ro'yxatdan tashqarisini o'chiradi. Faqat qo'shish uchun — syncWithoutDetaching. Hisobotdagi detached ga qarang.
  • ⚠️ detach() argumentsiz — hammasini olib tashlaydi.
  • Pivotdagi qo'shimcha ustun: modelda withPivot('daraja'), ishlatishda $k->pivot->daraja. Yozilmasa — jimgina NULL.
  • Nom taxminga mos kelmasa — to'rt argument: belongsToMany(Model::class, 'pivot', 'bu_id', 'u_id'). Bu xato ovoz chiqaradi («no such table»).
  • 🔍 Pivot ustunlari SQL'da pivot_ prefiksi bilan tortiladi, so'rov esa 22-darsdagi INNER JOIN.
  • ⚡ N+1 pivot bilan ham bor: 6 → 2 → 1 (with, withCount). with() massiv ham qabul qiladi.
