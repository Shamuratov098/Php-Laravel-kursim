DARS 64 · MODUL I — ISHLAB CHIQARISHGA TAYYORGARLIK

DTO va qatlamlar orasidagi chegara

62-darsda mantiqni Action ga ko'chirdik. Lekin ma'lumot hamon array $malumot bo'lib yuribdi — ichida nima borligini faqat kodni o'qib bilasiz. Bugun uni nomlangan va tipli obyektga solamiz. Va PHP haqida bir haqiqatni o'lchaymiz — ko'pchilik uni noto'g'ri biladi.

📱 O'qish ≈ 17 daqiqa 💻 Amaliyot ≈ 30 daqiqa Kerak: Dars 63

Bu darsda nimalar bor
  1. Massivning uchta muammosi 🔍 Kalitni xato yozsangiz — jimgina null.
  2. DTO nima Ma'lumot uchun sinf. Mantiq yo'q, faqat shakl.
  3. readonly va konstruktor xossalari 🔍 O'zgartirsangiz: Cannot modify readonly property.
  4. Nomlangan argumentlar Yettita parametr ham o'qiladigan bo'ladi.
  5. 🔍 Xato darrov chiqadi Undefined property · ArgumentCountError.
  6. ⭐ declare(strict_types=1) haqidagi haqiqat 🔍 O'lchandi: u chaqiruvchi faylda hal bo'ladi.
  7. 🔍 Strictsiz nima bo'ladi '900' jimgina int 900 ga aylandi.
  8. FormRequest bilan bog'lash soRovdan() — HTTP chegarasi shu yerda tugaydi.
  9. 🔍 Shartnomani o'zgartirish Tip tizimi hamma chaqiruv joyini ko'rsatdi.
  10. jadvalGa() DTO nomlari va ustun nomlari — alohida narsa.
  11. ⚠️ Qachon DTO kerak emas Har massivni sinfga aylantirish — xato.
  12. Har xil holatlar (7 ta) Enum · kolleksiya · with() · navbat · paketlar.
Massiv — qulay, lekin jim

62-darsdagi Action imizga qarang:

public function bajar(array $malumot, User $egasi): Vakansiya

Savol: $malumot ichida nima bor?

Javob: bilmaysiz. Buni aniqlash uchun metod ichini o'qish kerak, keyin Vakansiya::create() ni, keyin $fillable ni, keyin migratsiyani.

Va bu shunchaki noqulaylik emas — xatolarning manbai:

$malumot = ['nom' => 'PHP dasturchi', 'shahar' => 'Toshkent', 'maosh' => 900]; $malumot['maosh'] -> 900 $malumot['maoshi'] -> NULL ⚠️ jimgina. Xato YO'Q.

Bitta harf. Xato yo'q, ogohlantirish yo'q (?? bilan), test yashil. Va maosh null bo'lib bazaga tushadi.

Yana ikki muammo:

2) IDE yordam bermaydi → avtomatik to'ldirish yo'q 3) O'zgartirish oson → massiv har joyda o'zgartirilishi mumkin

DTO — ma'lumot uchun sinf

DTO — Data Transfer Object. Nomi qo'rqinchli, o'zi juda oddiy: faqat ma'lumot saqlaydigan sinf. Mantiq yo'q, baza yo'q, HTTP yo'q — faqat shakl.

app/Data/VakansiyaMalumoti.php
<?php declare(strict_types=1); namespace App\Data; final readonly class VakansiyaMalumoti { public function __construct( public string $nom, public string $shahar, public ?int $maosh = null, public ?int $kompaniyaId = null, public bool $faol = true, ) {} }

Bu 16 qatorda to'rt narsani aytadi, massiv esa hech birini aytmaydi:

1) QAYSI maydonlar bor (nom, shahar, maosh, kompaniyaId, faol) 2) Ularning TIPI qanday (string, ?int, bool) 3) Qaysilari MAJBURIY (nom, shahar) 4) Standart qiymat nima (faol = true)
🔑 Uchta kalit so'z
final → meros olinmasin (63-dars: LSP buzilishini oldini oladi) readonly → yaratilgach O'ZGARMASIN (62-dars: holatsizlik) public → konstruktorda xossa e'lon qilish (PHP 8.0+)

Oxirgisi eng ko'p vaqt tejaydi. PHP 8 dan oldin xuddi shu sinf 40 qatordan ortiq bo'lardi: xossalar, konstruktor, getterlar.

🔍 readonly class (PHP 8.2+) — har xossaga alohida yozish shart emas, butun sinf readonly.

🔍 Xato darrov chiqadi

Massiv bilan solishtiramiz. Har uchala holatni o'lchadik:

1) KALIT / XOSSA NOMIDA XATO $malumot['maoshi'] ?? null -> NULL ⚠️ jim $dto->maoshi -> ErrorException: Undefined property: VakansiyaMalumoti::$maoshi ✅ ovozli (tinker'da: WARNING) 2) O'ZGARTIRISHGA URINISH $malumot['maosh'] = 1000 -> o'zgardi ⚠️ $dto->maosh = 1000 -> Error: Cannot modify readonly property ✅ 3) MAJBURIY MAYDON TUSHIB QOLDI ['shahar' => 'T'] -> hech narsa ⚠️ new VakansiyaMalumoti(shahar: 'T') -> ArgumentCountError: Argument #1 ($nom) not passed ✅

Naqsh aniq: massiv jim, DTO ovozli. Va «ovozli» — bu yaxshi. Xato yozilayotgan paytda chiqadi, foydalanuvchi shikoyat qilganda emas.

Nomlangan argumentlar

DTO ning ikkinchi foydasi — chaqirish o'qiladigan bo'ladi:

❌ new VakansiyaMalumoti('PHP dasturchi', 'Toshkent', 900, 7, true); // ↑ ↑ ↑ qaysi biri qaysi? ✅ new VakansiyaMalumoti( nom: 'PHP dasturchi', shahar: 'Toshkent', maosh: 900, kompaniyaId: 7, );

🔑 Va nomlangan argumentlar tartibga bog'liq emas: ixtiyoriylarini o'tkazib yuborishingiz mumkin. faol ni yozmadik — standart qiymati ishlatildi:

$dto->faol = true <-- standart qiymat

⭐ declare(strict_types=1) haqidagi haqiqat

DTO da public ?int $maosh deb yozdik. Demak matn o'tkazsak xato beradi, to'g'rimi?

new VakansiyaMalumoti(nom: 'PHP', shahar: 'T', maosh: '900');

Sinab ko'ramiz. Testda yozdik:

it('noto\'g\'ri tipni qabul qilmaydi', function () { new VakansiyaMalumoti(nom: 'PHP dasturchi', shahar: 'Toshkent', maosh: '900'); })->throws(TypeError::class);
FAILED Tests\Feature\MalumotTest > it noto'g'ri tipni qabul qilmaydi Failed asserting that exception of type "TypeError" is thrown. ⚠️

Xato chiqmadi. Lekin DTO faylida declare(strict_types=1) bor edi-ku?

⚠️ strict_types chaqiruvchi faylda hal bo'ladi

Buni aniq o'lchash uchun ikkita fayl yozdik. Ikkalasi ham bir xil DTO ni chaqiradi — farq faqat o'z boshidagi e'londa:

chaqiruvchida strict BOR -> TypeError chaqiruvchida strict YO'Q -> xato YO'Q, maosh = 900 (int) ⚠️

Ya'ni '900' jimgina int 900 ga aylantirildi.

🔑 Bu PHP haqidagi eng ko'p noto'g'ri tushuniladigan narsalardan biri. declare(strict_types=1) — sinf e'lon qilingan faylga emas, sinf chaqirilgan faylga ta'sir qiladi.

Sabab mantiqan tushunarli: «men tiplarni qat'iy ishlataman» degan qaror — kod yozuvchining qarori. Kutubxona muallifi uni siz uchun hal qila olmaydi.

Test faylining boshiga bir qator qo'shdik:

<?php declare(strict_types=1);
Tests: 5 passed (9 assertions) ✅
✅ Amaliy xulosa
declare(strict_types=1) ni HAR FAYLGA yozing: app/ dagi sinflarga (o'z ichidagi chaqiruvlar uchun) tests/ dagi testlarga (tip xatolarini TUTISH uchun)

⚠️ Laravel'ning o'zi uni ishlatmaydi (moslik uchun), shuning uchun make: buyruqlari ham qo'shmaydi — o'zingiz yozasiz.

🔍 65-darsda ko'ramiz: buni har faylga avtomatik qo'yadigan vosita ham bor.

FormRequest bilan bog'lash

Endi savol: DTO qayerda yaratiladi?

Javob — HTTP chegarasida. Ya'ni tashqi dunyodan (so'rov) ichki dunyoga (mantiq) o'tayotgan joyda:

app/Data/VakansiyaMalumoti.php (davomi)
public static function soRovdan(VakansiyaRequest $request): self { $tekshirilgan = $request->validated(); return new self( nom: $tekshirilgan['nom'], shahar: $tekshirilgan['shahar'], maosh: isset($tekshirilgan['maosh']) ? (int) $tekshirilgan['maosh'] : null, kompaniyaId: isset($tekshirilgan['kompaniya_id']) ? (int) $tekshirilgan['kompaniya_id'] : null, ); }

⚠️ (int) castlariga e'tibor bering. HTTP dan hamma narsa matn bo'lib keladi — maosh=900 aslida '900'. Tekshiruv ('integer') uni qabul qiladi, lekin aylantirmaydi.

🔑 Ya'ni cast bu yerda shart — va aynan shuning uchun DTO chegarada turadi: tashqi tartibsizlikni ichkariga o'tkazmaydi.

Controller endi:

public function store(VakansiyaRequest $request, VakansiyaYarat $yarat) { $vakansiya = $yarat->bajar(VakansiyaMalumoti::soRovdan($request), $request->user()); return VakansiyaResource::make($vakansiya) ->response()->setStatusCode(201); }

Va Action:

public function bajar(VakansiyaMalumoti $malumot, User $egasi): Vakansiya { $vakansiya = Vakansiya::create($malumot->jadvalGa() + ['user_id' => $egasi->id]); VakansiyaYaratildi::dispatch($vakansiya); return $vakansiya->fresh(); }
🔑 jadvalGa() nega kerak?
DTO da: kompaniyaId (PHP uslubi — camelCase) Jadvalda: kompaniya_id (SQL uslubi — snake_case)

Bu ataylab ajratilgan. DTO — ilovangizning tili, jadval ustunlari — bazaning tili. Ular bir-biriga bog'lanib qolmasin.

✅ Foydasi: ertaga ustun nomi o'zgarsa, faqat jadvalGa() o'zgaradi — DTO ni ishlatgan hech qaysi kod tegilmaydi.

🔍 Shartnomani o'zgartirganda nima bo'ldi

Action imizning imzosini o'zgartirdik:

- public function bajar(array $malumot, User $egasi): Vakansiya + public function bajar(VakansiyaMalumoti $malumot, User $egasi): Vakansiya

Testlarni ishga tushirdik:

Tests: 2 failed, 98 passed (204 assertions) TypeError: App\Actions\VakansiyaYarat::bajar(): Argument #1 ($malumot) must be of type App\Data\VakansiyaMalumoti, array given, called in tests/Feature/AmalTest.php on line 14
🔑 Bu — foyda, muammo emas

Tip tizimi hamma chaqiruv joyini ko'rsatdi: fayl nomi, qator raqami, kutilgan tip, kelgan tip.

Massiv bilan bunday bo'lmasdi. Massivning «shakli» o'zgarsa — hech narsa sezilmaydi, kod ishlashda davom etadi va noto'g'ri natija beradi.

massiv shakli o'zgardi → jimgina null lar, xato YO'Q ⚠️ DTO tipi o'zgardi → TypeError, aniq manzil bilan ✅

🔍 Va bu refaktoringni xavfsiz qiladi: ikkita joyni tuzatdik va yana 105 ta test yashil bo'ldi.

Testlar ham tozalandi — endi ular o'qiladigan:

$vakansiya = (new VakansiyaYarat)->bajar( new VakansiyaMalumoti( nom: 'PHP dasturchi', shahar: 'Toshkent', maosh: 900, kompaniyaId: $kompaniya->id, ), $egasi, );

⚠️ Qachon DTO kerak emas

63-darsdagi ogohlantirish shu yerda ham amal qiladi: har massivni sinfga aylantirish — xato.

❌ KERAK EMAS: ['nom' => 'x'] → bitta maydon. Shunchaki parametr qiling. Resource ichidagi javob massivi → u JSON ga ketyapti, chegara emas config() qaytargan massiv → o'qish uchun, uzatish uchun emas Eloquent modelining o'zi → u allaqachon tipli obyekt
✅ KERAK: 1) QATLAM CHEGARASI → HTTP → mantiq, mantiq → navbat 2) UCHTA+ MAYDON → nomlangan argumentlar o'qishni osonlashtiradi 3) IXTIYORIY MAYDONLAR → qaysilari majburiyligi ko'rinib tursin 4) QAYTA ISHLATILADI → bir necha joydan bir xil shakl uzatiladi
⚠️ Eng ko'p uchraydigan haddan oshirish

«Har controller uchun Request DTO, har javob uchun Response DTO, har model uchun Model DTO».

Natija: bitta maydon qo'shish uchun to'rt fayl ochiladi, va ularning uchtasi bir xil narsani takrorlaydi.

🔑 Eloquent modeli DTO emas, lekin ko'p hollarda uning o'rnini bosadi. U tipli, nomlangan va IDE ko'radi. Chegara kesib o'tilmayotgan bo'lsa — modelning o'zi yetarli.

Har xil holatlar

Yetti holat. Bu bo'lim ma'lumotnoma — hozir bir marta o'qing, keyin kerak bo'lganda qaytib qarang.

HOLAT 1

DTO ichida Enum

final readonly class VakansiyaMalumoti { public function __construct( public string $nom, public Rol $kimUchun = Rol::Ishberuvchi, // matn emas, ENUM ) {} }

✅ Endi noto'g'ri qiymat umuman yozib bo'lmaydi — 'ishberuvci' deb xato yozsangiz, PHP darrov aytadi.

🔑 63-darsdagi match naqshi bilan birga: yangi rol qo'shilsa, UnhandledMatchError sizni tutadi.

HOLAT 2

Ro'yxat: tipli kolleksiya

public function __construct( /** @var array<int, KonikmaMalumoti> */ public array $konikmalar = [], ) {}

⚠️ PHP massiv ichidagi tipni tekshirmaydi — array deyish mumkin, KonikmaMalumoti[] deb yozib bo'lmaydi.

✅ Ikki yechim: PHPDoc (@var array<int, X>) — statik tahlil ko'radi; yoki konstruktorda tekshirish:

foreach ($konikmalar as $k) { if (! $k instanceof KonikmaMalumoti) { throw new InvalidArgumentException('Faqat KonikmaMalumoti'); } }
HOLAT 3

Nusxa olib o'zgartirish

public function maoshBilan(?int $maosh): self { return new self( nom: $this->nom, shahar: $this->shahar, maosh: $maosh, // faqat shu o'zgardi kompaniyaId: $this->kompaniyaId, faol: $this->faol, ); }

readonly obyektni o'zgartirib bo'lmaydi — lekin o'zgartirilgan nusxasini qaytarish mumkin.

✅ Bu naqsh (immutable with-er) Laravel'da ham bor: $date->addDay() yangi Carbon qaytaradi.

🔑 Maydonlar ko'payib ketsa, PHP 8.3 dan beri clone with muhokama qilinyapti — hozircha qo'lda yoziladi.

HOLAT 4

Navbatga uzatish (55-dars)

class VakansiyalarniEksport implements ShouldQueue { public function __construct(public VakansiyaMalumoti $malumot) {} }

⚠️ Job navbatga serializatsiya qilinadi. readonly sinflar buni normal ko'taradi, lekin ichida model bo'lsa — SerializesModels kerak.

✅ Shuning uchun DTO ichida model emas, id saqlash afzal (bizda kompaniyaId).

🔑 Yon foyda: DTO da model bo'lmasa, navbatdagi job eskirgan ma'lumot bilan ishlamaydi.

HOLAT 5

DTO ichiga mantiq qo'yish

❌ final readonly class VakansiyaMalumoti { public function saqla(): Vakansiya { return Vakansiya::create($this->jadvalGa()); // ⚠️ bazaga tegdi } public function soliqHisobla(): int { ... } // ⚠️ biznes mantiq }

DTO — ma'lumot, xizmat emas. Bazaga tegsa, u Action bo'lib qoladi; hisoblasa — Service.

✅ Ruxsat etilgani: shakl bilan bog'liq metodlar — jadvalGa(), soRovdan(), maoshBilan().

🔑 Sinov: «bu metod bazaga, tarmoqqa yoki vaqtga tegadimi?» Ha bo'lsa — DTO da emas.

HOLAT 6

Tayyor paketlar

spatie/laravel-data → DTO + tekshiruv + Resource, hammasi bitta sinfda cuyz/valinor → massivdan tipli obyektga xavfsiz aylantirish

Ular ko'p narsani avtomatlashtiradi: FormRequest qoidalari DTO dan chiqariladi, JSON javob ham o'sha sinfdan.

⚠️ Lekin ular o'z konventsiyalarini olib keladi va sehr qo'shadi. Kursimiz tamoyili — «sehr yo'q»: avval oddiy PHP bilan qiling.

🔑 Paketni og'riq paydo bo'lganda qo'shing (63-dars) — «zamonaviy» bo'lgani uchun emas.

HOLAT 7

Chegaralarni topish

HTTP so'rovi → mantiq ✅ DTO (VakansiyaMalumoti) mantiq → navbat/job ✅ DTO mantiq → tashqi API ✅ DTO tashqi API → mantiq ✅ DTO (javobni tipli qilish) controller → Resource ❌ model yetarli Service → Query ❌ oddiy parametrlar yetarli model → Blade ❌ model yetarli

🔑 Qoida: ma'lumot «begona» hududga o'tayotgan bo'lsa — DTO. Bir hudud ichida yursa — kerak emas.

«Begona hudud» — bu tarmoq, navbat, boshqa jamoa kodi, yoki shunchaki tekshirilmagan tashqi kirish.

💻 Quyida amaliyot bor. Hozir o'qish rejimidasiz — kompyuter yoningizda bo'lganda 💻 Amaliyot rejimiga o'ting va shu bo'limdan davom eting.

Eslab ayting

Javobni ovoz chiqarib ayting, keyin ochib solishtiring.

DTO nima va massivdan nimasi yaxshi?
Data Transfer Object — faqat ma'lumot saqlaydigan sinf. Mantiq yo'q, baza yo'q, HTTP yo'q — faqat shakl. 16 qatorda to'rt narsani aytadi: qaysi maydonlar · ularning tipi · qaysilari majburiy · standart qiymat. Massiv esa hech birini aytmaydi. 🔍 O'lchandi: massivda xato kalit → jimgina NULL; DTO'da → Undefined property. Uchta kalit so'z: final (63-dars, LSP) · readonly (62-dars, holatsizlik) · konstruktor xossalari (PHP 8.0+).
⭐ strict_types haqidagi haqiqat nima?
U chaqiruvchi faylda hal bo'ladi, sinf e'lon qilingan faylda emas. 🔍 O'lchandi (DTO faylida strict_types bor holda): chaqiruvchida bor → TypeError: Argument #3 ($maosh) must be of type ?int, string given; chaqiruvchida yo'q → xato yo'q, '900' → int 900. 🔑 Sabab mantiqiy: «tiplarni qat'iy ishlataman» — kod yozuvchining qarori, kutubxona muallifi uni hal qila olmaydi. ⚠️ Laravel uni ishlatmaydi, make: buyruqlari qo'shmaydi — o'zingiz yozasiz.
DTO qayerda yaratiladi va nega (int) cast kerak?
Qatlam chegarasida — tashqi dunyodan ichkariga o'tayotgan joyda (soRovdan()). ⚠️ HTTP dan hamma narsa matn bo'lib keladi: maosh=900 aslida '900'. Tekshiruv ('integer') uni qabul qiladi, lekin aylantirmaydi. ✅ Shuning uchun DTO chegarada turadi: tashqi tartibsizlikni ichkariga o'tkazmaydi. 🔑 jadvalGa() ham shu sabab: DTO'da kompaniyaId (PHP uslubi), jadvalda kompaniya_id (SQL uslubi) — ular bog'lanib qolmasin.
DTO qachon KERAK EMAS?
Ma'lumot bir hudud ichida yursa. ❌ Kerak emas: bitta maydonli massiv · Resource ichidagi javob massivi · config() qaytargani · Eloquent modelining o'zi (u allaqachon tipli va nomlangan). ✅ Kerak: qatlam chegarasi (HTTP → mantiq, mantiq → navbat, tashqi API) · uchta+ maydon · ixtiyoriy maydonlar bor · bir necha joydan bir xil shakl uzatiladi. ⚠️ Eng ko'p uchraydigan haddan oshirish: «har controllerga Request DTO, har javobga Response DTO» — bitta maydon uchun to'rt fayl ochiladi.
DTO nimani kafolatlamaydi?
Ma'noni. DTO int $summa ekanini kafolatlaydi, lekin u tiyindami yoki so'mdami — aytmaydi. 🔑 Agar qiymat haqida «bu qanday birlikda?» degan savol tug'ilsa — u int emas, o'z tipiga loyiq (Value Object): Pul::somdan(150). ✅ Konstruktorni private qiling — shunda faqat nomlangan yaratuvchilar orqali yaratiladi va birlik har chaqiruvda ko'rinadi. 🔍 Farqi: DTO ma'lumotni tashiydi, Value Object bitta qiymatning ma'nosini saqlaydi.
