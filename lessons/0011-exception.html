DARS 11 · MODUL A — POYDEVOR

Exception: xatoni tutib olish

4-darsda xatoni o'qishni o'rgandik. Bugun uni tutib olamiz: xato bo'lganda dastur to'xtamaydi, siz o'zingiz hal qilasiz. 4-darsdan qolgan qarz shu yerda to'lanadi — va endi buni tushunish uchun hamma narsa bor, chunki xato ham obyekt.

📱 O'qish ≈ 9 daqiqa 💻 Amaliyot ≈ 12 daqiqa Kerak: Dars 10

Bu darsda nimalar bor
  1. Nega bu dars 4-darsda emas Exception obyekt, shuning uchun OOP dan keyin turadi.
  2. throw «Bu yerda muammo bor» deb e'lon qilish; funksiya darhol to'xtaydi.
  3. try / catch / finally Tutib olish va har holatda bajariladigan qism.
  4. 🔑 Ierarxiya Throwable · Exception · Error — catch tur bo'yicha tutadi.
  5. Bir nechta catch Aniqdan umumiyga tartibi va nima uchun aksi ishlamaydi.
  6. O'z exception klassingiz Domenga mos xato turini yasash.
  7. Tuzoq: catch (Exception) U DivisionByZeroError ni tutmaydi — nega.
Nega bu muhim

Ba'zi xatolar — kutilgan xatolar. Foydalanuvchi manfiy maosh kiritdi, fayl topilmadi, tashqi API javob bermadi. Bularda dastur to'xtamasligi kerak — aksincha, xushmuomala javob berishi kerak: «Maosh manfiy bo'lolmaydi, iltimos tuzatib qayta yuboring».

Laravel'da bu mexanizm hamma joyda: har validatsiya xatosi, har «sahifa topilmadi» (404), har muvaffaqiyatsiz queue job — hammasi exception. Boshqaning kodini o'qiyotganda ham try/catch ni doim ko'rasiz. Ya'ni bu — o'qish uchun ham, yozish uchun ham majburiy ko'nikma.

Nega bu dars 4-darsda emas, hozir?

Sababi bitta va endi u ravshan: xato — obyekt. 4-darsda ko'rgan DivisionByZeroError — bu shunchaki xabar emas, klass nomi. Uni tutib olish uchun klass, meros va ierarxiya kerak bo'ladi — ya'ni 7–10-darslardagi bilim.

Endi hammasi joyida, davom etamiz.

throw — «bu yerda muammo bor»

tushuncha
function maoshniTekshir(int $maosh): int { if ($maosh < 0) { throw new InvalidArgumentException("Maosh manfiy bo'lolmaydi: {$maosh}"); } return $maosh; }

throw new ... — ikki ish qiladi:

  • new bilan xato obyektini yasaydi (7-darsdagi new — aynan o'sha).
  • throw bilan uni otadi: funksiya darhol to'xtaydi, return ga yetmaydi.

Diqqat qiling — 8-darsda validatsiyani «jimgina rad etish» bilan qilgandik (return;). U yechim ishlaydi, lekin bitta kamchiligi bor: chaqiruvchi rad etilganini bilmaydi. throw esa buni yashirmaydi.

try / catch — tutib olish

tushuncha
echo "Boshlandi"; try { $maosh = maoshniTekshir(-500); echo "Bu qator chiqmaydi"; } catch (InvalidArgumentException $e) { echo "Tutildi: ", $e->getMessage(); } echo "Dastur davom etdi";
Boshlandi Tutildi: Maosh manfiy bo'lolmaydi: -500 Dastur davom etdi

Ishlash tartibi:

  1. try { } — «shu blokni bajarishga urinib ko'r».
  2. Xato otilsa — try blokining qolgani tashlab ketiladi («Bu qator chiqmaydi» chindan chiqmadi).
  3. catch (Tur $e) — «shu turdagi xato bo'lsa, mana bu bilan hal qilaman». $e — o'sha xato obyekti.
  4. Undan keyin dastur normal davom etadi. Mana asosiy foyda.

$e->getMessage() — endi bu yozuv tanish: -> obyektga murojaat (7-dars), getMessage() — xato obyektining metodi. Boshqa foydali metodlari: getFile(), getLine(), getCode() — ya'ni 4-darsda o'qigan «to'rt bo'lak»ni kod orqali ham olish mumkin.

🔑 Ierarxiya: catch tur bo'yicha tutadi

Bu darsning eng muhim qismi va 9-darsdagi meros bilimining to'g'ridan-to'g'ri qo'llanishi. PHP'dagi xatolar daraxt shaklida tuzilgan:

Throwable

interface
Eng tepasi. Otiladigan hamma narsa shunga mos keladi

Exception

class
Kutilgan muammolar: validatsiya, fayl, tarmoq. Odatda siz shularni otasiz

Error

class
Dasturchi xatosi: TypeError, DivisionByZeroError

O'z klassim

extends Exception
MaoshXatosi — domenga xos, ma'noli nom

catch avlodlarni ham tutadi (9-darsdagi instanceof qoidasi): catch (Exception $e) deb yozsangiz, InvalidArgumentException ham, o'zingizning MaoshXatosi ham tutiladi — chunki ular Exception avlodlari.

⚠️ Eng ko'p adashtiradigan joy

Error — Exception emas! Ular aka-uka, biri ikkinchisining avlodi emas. Ya'ni:

catch (Exception $e) → DivisionByZeroError ni TUTMAYDI catch (Throwable $e) → tutadi (chunki Throwable eng tepada)

Bugungi taxmin mashqi aynan shu haqda. Yodda tuting: hammasini tutish kerak bo'lsa — Throwable.

Bir nechta catch — aniqdan umumiyga

tushuncha
try { $maosh = maoshniTekshir($kiritilgan); } catch (MaoshXatosi $e) { // 1) eng ANIQ tur echo "Maosh xatosi: ", $e->getMessage(); } catch (Exception $e) { // 2) umumiyroq — qolganlari echo "Boshqa xato: ", $e->getMessage(); } finally { echo "tekshiruv tugadi"; // 3) HAR HOLDA ishlaydi }

PHP catch bloklarini yuqoridan pastga tekshiradi va birinchi mos kelganini ishlatadi (3-darsdagi if/elseif kabi). Shuning uchun tartib muhim: aniq turlar yuqorida, umumiylari pastda. Aks holda catch (Exception) hammasini o'zi yutib yuboradi va pastdagi bloklar hech qachon ishlamaydi.

finally — xato bo'ldi yoki bo'lmadi, har holda ishlaydi. Odatda tozalash uchun: faylni yopish, ulanishni uzish.

O'z exception klassingiz

tushuncha
class MaoshXatosi extends Exception {}

Tanasi bo'sh — va bu yetarli. Nima uchun kerak: nom. Endi catch (MaoshXatosi $e) deb yozib, aynan shu muammoni boshqalaridan ajratib hal qila olasiz. Va kodni o'qigan odam nima bo'layotganini nomdan tushunadi. Laravel'da o'nlab shunday klasslar bor — masalan ValidationException, ModelNotFoundException.

Xatoni jimgina yutib yubormang

Eng yomon naqsh shu:

try { xavfliIsh(); } catch (Throwable $e) { // hech narsa }

Bunda muammo yo'qoladi: dastur ishlayotgandek ko'rinadi, lekin ish bajarilmagan. Keyinchalik sababini topish deyarli imkonsiz. Qoida: tutgan xatoni yoki hal qiling, yoki logga yozing, yoki qayta oting — lekin jim qolmang. Bu 4-darsdagi «Warning ni e'tiborsiz qoldirmang» qoidasining davomi.

💻 Amaliy qism kompyuterda

Amaliyotda 25-exception.php da o'z MaoshXatosi klassingizni yozasiz, uchta qiymatni siklda tekshirasiz va uch xil natijani ko'rasiz — qabul qilindi / maosh xatosi / boshqa xato. Oxirida eng muhim tajriba: catch (Exception) DivisionByZeroError ni tutmasligini isbotlaysiz va Throwable bilan tuzatasiz.

Amaliyot

  1. Papkaga o'ting

    cd ~/Projects/Learn/php-poydevor

    Kutilgan natija: jimlik.

  2. Exception bilan validatsiya yozing

    Uchta qiymat — uchta yo'l. Sikl ichida try/catch bo'lsa, bitta xato butun siklni to'xtatmaydi.

    cat > 25-exception.php <<'EOF' <?php declare(strict_types=1); class MaoshXatosi extends Exception {} function maoshniTekshir(int $maosh): int { if ($maosh < 0) { throw new MaoshXatosi("Maosh manfiy bo'lolmaydi: {$maosh}"); } if ($maosh > 100000) { throw new InvalidArgumentException("Maosh juda katta: {$maosh}"); } return $maosh; } foreach ([800, -500, 999999] as $kiritilgan) { try { $maosh = maoshniTekshir($kiritilgan); echo "✅ Qabul qilindi: {$maosh}", PHP_EOL; } catch (MaoshXatosi $e) { echo "❌ Maosh xatosi: ", $e->getMessage(), PHP_EOL; } catch (Exception $e) { echo "❌ Boshqa xato (", get_class($e), "): ", $e->getMessage(), PHP_EOL; } finally { echo " — tekshiruv tugadi", PHP_EOL; } } echo "Dastur oxirigacha ishladi", PHP_EOL; EOF php 25-exception.php ✅ Qabul qilindi: 800 — tekshiruv tugadi ❌ Maosh xatosi: Maosh manfiy bo'lolmaydi: -500 — tekshiruv tugadi ❌ Boshqa xato (InvalidArgumentException): Maosh juda katta: 999999 — tekshiruv tugadi Dastur oxirigacha ishladi

    Kutilgan natija: uch xil natija va oxirida «Dastur oxirigacha ishladi». Diqqat: finally uch marta ishladi — xato bor-yo'qligidan qat'i nazar. Va ikkita xato siklni to'xtatmadi.

  3. catch (Exception) ning chegarasini ko'ring

    Bu darsning eng muhim tajribasi. 4-darsdagi DivisionByZeroError ni tutishga urinamiz.

    php -r 'try { echo 10 / 0; } catch (Exception $e) { echo "tutildi"; }' 2>&1 | head -1 PHP Fatal error: Uncaught DivisionByZeroError: Division by zero in Command line code:1

    Kutilgan natija: try/catch yozgan bo'lsak ham dastur to'xtadi! «tutildi» chiqmadi. Sababi: DivisionByZeroError — Exception emas.

  4. Throwable bilan tuzating

    php -r 'try { echo 10 / 0; } catch (Throwable $e) { echo "Tutildi: ", get_class($e), PHP_EOL; }' Tutildi: DivisionByZeroError

    Kutilgan natija: endi tutildi. Bitta so'z o'zgardi — Exception → Throwable — va xatti-harakat butunlay boshqacha bo'ldi.

  5. Ierarxiyani o'z ko'zingiz bilan tekshiring

    Yodlashdan ko'ra bir marta ko'rish ishonchli.

    php -r 'foreach ([new Exception("x"), new DivisionByZeroError("x"), new TypeError("x")] as $e) { printf("%-22s Exception:%-6s Error:%s\n", get_class($e), var_export($e instanceof Exception, true), var_export($e instanceof Error, true)); }' Exception Exception:true Error:false DivisionByZeroError Exception:false Error:true TypeError Exception:false Error:true

    Kutilgan natija: DivisionByZeroError va 6-darsdagi TypeError — ikkalasi ham Error, Exception emas. Ular dasturchi xatosi — ya'ni odatda tutilmaydi, tuzatiladi.

  6. Ishni saqlang

    git add -A git commit -m "11-dars: exception"

    Kutilgan natija: commit haqida xabar.

Sinab ko'ramiz

Natijani taxmin qiling

try/catch yozilgan. Savol: ekranda nima chiqadi — va «Dastur davom etdi» chiqadimi?

taxmin.php
<?php echo "Boshlandi", PHP_EOL; try { echo 10 / 0; } catch (Exception $e) { echo "Tutildi: ", $e->getMessage(), PHP_EOL; } echo "Dastur davom etdi", PHP_EOL;
Javobni ko'rish
Boshlandi PHP Fatal error: Uncaught DivisionByZeroError: Division by zero in taxmin.php:4

«Dastur davom etdi» chiqmaydi. try/catch yozilgan bo'lsa ham dastur to'xtadi — go'yo catch yo'q kabi.

Sabab: 10 / 0 DivisionByZeroError otadi, u esa Error avlodi. catch (Exception $e) faqat Exception va uning avlodlarini tutadi. Error va Exception — aka-uka, biri ikkinchisining avlodi emas. Shuning uchun mos kelmadi va xato tutilmasdan o'tib ketdi.

Uch yechim, uch xil ma'no:

catch (Throwable $e) → hammasini tutadi catch (DivisionByZeroError $e) → aynan shuni tutadi if ($bolinuvchi !== 0) { ... } → xatoni umuman chiqarmaydi ← ENG YAXSHISI

Eng muhim xulosa: Error odatda dasturchi xatosi — uni tutish emas, tuzatish kerak. Nolga bo'lishni oldini olish catch qilishdan yaxshiroq. try/catch esa kutilgan muammolar uchun: foydalanuvchi kirtigi, fayl, tarmoq.

SAVOL 1 try ichida xato otilsa, blokning qolgan qatorlari nima bo'ladi?

Xato otilgan zahoti try bloki to'xtaydi va boshqaruv mos catch ga o'tadi. Undan keyin dastur normal davom etadi.

SAVOL 2 catch (Exception $e) TypeError ni tutadimi?

Error va Exception — aka-uka klasslar. Ikkisining ham otasi Throwable. Hammasini tutish uchun catch (Throwable $e) yoziladi.

SAVOL 3 Bir nechta catch bo'lsa, tartib qanday bo'lishi kerak?

PHP birinchi mos kelgan catch ni ishlatadi. catch (Exception) yuqorida tursa, o'zidan pastdagi aniq bloklar hech qachon ishlamaydi.

Eslab ayting

Avval o'zingiz javob bering, keyin ochib tekshiring. Oxirgi ikkitasi — 10-darsni takrorlash.

Nega exception darsi 4-darsda emas, shu yerda?

Chunki xato — obyekt. DivisionByZeroError — klass nomi. Uni tur bo'yicha tutish uchun klass, meros va ierarxiya kerak — ya'ni 7–10-darslardagi bilim.

Error va Exception munosabati qanday?

Aka-uka — biri ikkinchisining avlodi emas. Ikkisining otasi Throwable. Exception = kutilgan muammo, Error = dasturchi xatosi. Hammasini tutish → Throwable.

Nega o'z exception klassini yozish kerak?

Nom uchun. catch (MaoshXatosi $e) deb aynan shu muammoni ajratib hal qilasiz, va kodni o'qigan odam nomdan tushunadi. Tanasi bo'sh bo'lsa ham yetadi: class MaoshXatosi extends Exception {}.

↩︎ Takrorlash: metod ustunligi tartibi qanday?

O'z klassi > trait > ota klass. Trait otani yengadi, chunki uning kodi klass ichiga ko'chiriladi.

↩︎ Takrorlash: interface va trait farqi?

interface — «nima qila oladi» (shartnoma, kod yo'q, tip beradi). trait — «qanday qiladi» (kod bor, tip bermaydi). Bugungi Throwable — aslida interface.

Cho'ntak xulosasi
  • throw new Xato("xabar") — obyekt yasab, otadi; funksiya darhol to'xtaydi.
  • try { } catch (Tur $e) { } — tutib oladi, dastur davom etadi.
  • $e->getMessage() · getFile() · getLine() — 4-darsdagi «to'rt bo'lak» kod orqali.
  • catch avlodlarni ham tutadi — catch (Exception) barcha Exception avlodlarini oladi.
  • 🔑 Error ≠ Exception — aka-uka. Hammasi uchun Throwable.
  • Bir necha catch: aniqdan umumiyga. Birinchi mos kelgani ishlaydi.
  • finally — har holda ishlaydi (tozalash uchun).
  • class MaoshXatosi extends Exception {} — bo'sh tanasi bilan ham foydali: nom beradi.
  • Xatoni jimgina yutmang. Hal qiling, logga yozing yoki qayta oting.
🌱 Kelasi darslar uchun urug'

Modul A ning oxiriga yaqinlashdik va fayllaringiz ko'paydi: 21-xabar.php, 23-interface.php, 25-exception.php... Har birini require qilish kerak, va klasslar 50 taga chiqsa bu chidab bo'lmas bo'ladi. Bundan tashqari ikki xil kutubxonada bir xil nomli klass bo'lsa — to'qnashuv.

Keyingi dars ikkisini ham yechadi: namespace (nomlarni ajratish) va Composer bilan autoload — «kerak bo'lgan klassni PHP o'zi topib oladi». require yozish tugaydi. Va shu bilan Composer — Laravel o'rnatiladigan asbob — qo'lingizga o'tadi.
