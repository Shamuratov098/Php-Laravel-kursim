Baza bilan test: bog'langan ma'lumot

37- va 38-darsdagi testlarda ma'lumotni qo'lda yasadik. Ammo IshTop'da bog'lanishlar bor: vakansiyaning kompaniyasi, ko'nikmalari, egasi. Bugun ularni bir qatorda yasashni o'rganamiz — va yo'lda o'zbekcha nomlar tufayli chiqadigan aniq bir tuzoqni ochamiz.

📱 O'qish ≈ 16 daqiqa 💻 Amaliyot ≈ 25 daqiqa Kerak: Dars 38

Bu darsda nimalar bor

  2. for() — «kimga tegishli» belongsTo tomoni. Vakansiya::factory()->for($kompaniya, 'kompaniya').
  3. has() — «nimalari bor» hasMany tomoni. Bitta qatorda kompaniya va uning to'rtta vakansiyasi.
  4. ⚠️ O'zbekcha nom tuzog'i Nomsiz has() ishlamaydi: Call to undefined method ...::konikma(). Laravel qanday taxmin qilishi ochib beriladi.
  5. hasAttached() — pivot bilan 27-darsdagi ko'pga-ko'p bog'lanish va daraja pivot ustuni — bitta chaqiruvda.
  6. ⚠️ Factory zanjiri Uchta vakansiya yasasangiz bazada uchta kompaniya paydo bo'ladi. Nega — va qanday to'xtatiladi.
  7. recycle() Bitta bog'liq modelni qayta ishlatish — for() ga muqobil, ayniqsa chuqur zanjirlarda.
  8. sequence() Navbatma-navbat qiymatlar: ikkita Toshkent, ikkita Buxoro — filtr testlari uchun.
  9. Holatlarni zanjirlash 28-darsdagi yopiq() va boy() birga: ->yopiq()->boy().
  10. Baza tekshiruvlari assertDatabaseCount · assertModelExists · assertModelMissing.
  11. 🔍 Jadval nomini yozmaslik assertDatabaseHas(Vakansiya::class, …) — o'zbekcha jadval nomlarida ancha xavfsiz.
  12. Har xil holatlar (7 ta) Nomsiz has() · factory zanjiri · factory fayli yo'qligi · jadval nomi · recycle · sequence · birinchi testning sekinligi.
Bitta vakansiya — beshta chaqiruv

«Kompaniyasi va uchta ko'nikmasi bor vakansiya» kerak deylik. Qo'lda shunday bo'ladi:

$kompaniya = Kompaniya::create(['nom' => 'Softex Lab', ...]); $vakansiya = Vakansiya::create([ 'nom' => 'Backend dasturchi', 'maosh' => 9000000, 'kompaniya_id' => $kompaniya->id, ]); $php = Konikma::create(['nom' => 'PHP']); $sql = Konikma::create(['nom' => 'SQL']); $git = Konikma::create(['nom' => 'Git']); $vakansiya->konikmalar()->attach([ $php->id => ['daraja' => 'yuqori'], $sql->id => ['daraja' => 'yuqori'], $git->id => ['daraja' => 'yuqori'], ]);

Yigirma qator — va bu bitta test uchun. Ikkinchi testda hammasi qaytadan yoziladi.

Muammo faqat uzunlikda emas. Bu kodda test nima haqida ekani ko'rinmay qoladi: yigirma qator tayyorgarlik ichida bitta muhim tekshiruv yashirinib yotadi.

28-darsdagi factory shu ish uchun yaratilgan. Bugun uning bog'lanishlar bilan ishlaydigan qismini o'rganamiz.

for() — «kimga tegishli»

26-darsdagi belongsTo tomoni. Vakansiya kompaniyaga tegishli:

tests/Feature/BogliqlikTest.php $kompaniya = Kompaniya::factory()->create(['nom' => 'Softex Lab']); $vakansiya = Vakansiya::factory()->for($kompaniya, 'kompaniya')->create(); expect($vakansiya->kompaniya->nom)->toBe('Softex Lab');

Ikkinchi argument — bog'lanish metodining nomi. Uni yozmasangiz Laravel taxmin qiladi, va bizning holatda taxmin to'g'ri chiqadi:

for($kompaniya) → ishlaydi ✅ for($kompaniya, 'kompaniya') → ishlaydi ✅ (aniq yozilgan)

🔍 Nega ishlaydi? for() uchun taxmin birlikda: Kompaniya → kompaniya. Bizdagi metod ham aynan shunday nomlangan. Ko'plik yasalmaydi — shuning uchun muammo yo'q.

has() — «nimalari bor»

tests/Feature/BogliqlikTest.php $kompaniya = Kompaniya::factory() ->has(Vakansiya::factory()->count(4), 'vakansiyalar') ->create(['nom' => 'Softex Lab']); expect($kompaniya->vakansiyalar)->toHaveCount(4);

Bitta chaqiruvda kompaniya va uning to'rtta vakansiyasi. Har biriga kompaniya_id avtomatik qo'yiladi.

⚠️ Nomni yozmasangiz — o'zbekcha nomda ishlamaydi

Ikkinchi argumentni tashlab ko'ramiz:

Vakansiya::factory()->has(Konikma::factory()->count(3))->create(); BadMethodCallException Call to undefined method App\Models\Vakansiya::konikma()

Xato xabari konikma() deydi — birlikda. Nega shunday? Sehr yo'q, mexanizm ikki qadamli:

1) ko'plik yasaladi: Konikma → Konikmas → konikmas Vakansiya'da konikmas() metodi bormi? → YO'Q 2) birlikka qaytiladi: Konikma → konikma Vakansiya'da konikma() metodi bormi? → YO'Q → XATO

Bizdagi metod esa konikmalar() deb ataladi — o'zbekcha ko'plik. Laravel'ning inglizcha ko'plik yasovchisi uni hech qachon topa olmaydi.

Str::plural('Konikma') → Konikmas Str::plural('Vakansiya') → Vakansiyas Str::plural('Kompaniya') → Kompaniyas

🔑 Qoida (ADR 0004 ning davomi): o'zbekcha nomli modellarda has() va hasAttached() ga bog'lanish nomini har doim aniq bering. for() da esa shart emas — u ko'plik yasamaydi.

🔍 Bu qoida kursda uchinchi marta uchraydi: jadval nomi ($table), factory has() va shu yer. Umumiy sabab bitta — ko'plik yasalgan joyda taxmin buziladi.

hasAttached() — pivot bilan birga

27-darsdagi konikmalar() — ko'pga-ko'p bog'lanish, va uning pivot jadvalida daraja ustuni bor. Factory buni ham biladi:

tests/Feature/BogliqlikTest.php $vakansiya = Vakansiya::factory() ->hasAttached( Konikma::factory()->count(3), // nimani biriktiramiz ['daraja' => 'yuqori'], // pivot ustunlari 'konikmalar' // bog'lanish nomi (majburiy!) ) ->create(); expect($vakansiya->konikmalar)->toHaveCount(3); expect($vakansiya->konikmalar->first()->pivot->daraja)->toBe('yuqori');

O'lchangan: uchta ko'nikma yaratildi, pivot jadvalga uchta qator yozildi, har birida daraja = yuqori.

$this->assertDatabaseCount('konikma_vakansiya', 3); → ✅

Pivot jadval nomi — konikma_vakansiya (alifbo tartibida, 27-darsdagi kelishuv).

⚠️ Factory zanjiri: uchta vakansiya — uchta kompaniya

Endi kutilmagan narsa. Uchta vakansiya yasaymiz va bazani sanaymiz:

Vakansiya::factory()->count(3)->create(); vakansiyalar = 3 kompaniyalar = 3 ← ⚠️ uchta!

Sababi VakansiyaFactory ning o'zida (28-dars):

'kompaniya_id' => Kompaniya::factory(),

Ya'ni har bir vakansiya o'ziga kompaniya yasab oladi. Bu ko'pincha aynan kerak narsa — test ma'lumoti to'liq va mustaqil bo'ladi.

Lekin «bitta kompaniyaning uchta vakansiyasi» kerak bo'lsa, zanjirni to'xtatish kerak. Ikki usul bor:

// 1) for() bilan $k = Kompaniya::factory()->create(); Vakansiya::factory()->count(3)->for($k, 'kompaniya')->create(); → vakansiyalar = 3, kompaniyalar = 1 ✅ // 2) recycle() bilan $k = Kompaniya::factory()->create(); Vakansiya::factory()->count(3)->recycle($k)->create(); → vakansiyalar = 3, kompaniyalar = 1 ✅
for() yoki recycle()

for() — aniq bog'lanish uchun: «shu vakansiyalar shu kompaniyaga tegishli».

recycle() — kengroq: «shu modelni qayerda kerak bo'lsa qayta ishlat». Chuqur zanjirlarda foydali: vakansiya ham, uning egasi ham, ko'nikmalari ham bitta kompaniyaga bog'liq bo'lsa, recycle() hammasiga tarqaladi.

Boshlanish uchun for() yetadi — u nima bo'layotganini aniqroq ko'rsatadi.

sequence() — navbatma-navbat qiymatlar

Filtr testi uchun «ikkita Toshkent, ikkita Buxoro» kerak bo'lsa:

tests/Feature/BogliqlikTest.php Vakansiya::factory() ->count(4) ->sequence( ['shahar' => 'Toshkent'], ['shahar' => 'Buxoro'], ) ->create();
Toshkent = 2 Buxoro = 2

Ro'yxat aylanma: 1-yozuv Toshkent, 2-yozuv Buxoro, 3-yozuv yana Toshkent… Shuning uchun count(4) va ikkita variant — teng ikkiga bo'linadi.

Holatlarni zanjirlash

28-darsda VakansiyaFactory ga ikkita holat (state) yozgan edik. Ular birga ishlaydi:

$v = Vakansiya::factory()->yopiq()->boy()->create(); faol = false ← yopiq() dan maosh = 3033 ← boy() dan (3000–8000 oralig'ida)

Har bir holat oldingisining ustiga qo'shiladi. Bir xil maydonni o'zgartirsa — oxirgisi g'olib.

Bazani tekshirish

$this->assertDatabaseCount('vakansiyalar', 4); // nechta qator bor $this->assertDatabaseHas('vakansiyalar', [...]); // shunday qator bormi $this->assertDatabaseMissing('vakansiyalar', [...]); // yo'qmi $this->assertModelExists($vakansiya); // shu yozuv bazadami $this->assertModelMissing($vakansiya); // o'chirilganmi

assertModelExists va assertModelMissing — obyekt bilan ishlaydi, shart yozish shart emas. O'chirishni tekshirishda eng qulayi:

tests/Feature/BogliqlikTest.php test('o\'chirilgan vakansiya bazadan yo\'qoladi', function () { $vakansiya = Vakansiya::factory()->create(); $this->assertModelExists($vakansiya); $vakansiya->delete(); $this->assertModelMissing($vakansiya); $this->assertDatabaseCount('vakansiyalar', 0); });
🔍 Jadval nomini yozmaslik

Birinchi argument sifatida model klassini ham berish mumkin:

$this->assertDatabaseHas('vakansiyalar', ['nom' => 'Backend dasturchi']); $this->assertDatabaseHas(Vakansiya::class, ['nom' => 'Backend dasturchi']); // ✅

Ikkalasi ham ishlaydi (o'lchandi). Lekin ikkinchisi xavfsizroq: jadval nomini Laravel modeldagi $table dan oladi va siz uni qo'lda yozmaysiz.

Bu ayniqsa bizda muhim, chunki jadval nomlari o'zbekcha va taxminga mos kelmaydi. Xato yozilsa natija shunday bo'ladi:

assertDatabaseHas('vakansiyas', [...]) QueryException: no such table: vakansiyas (Connection: sqlite, Database: :memory:)

🔍 Xato xabarining oxiriga qarang: Database: :memory: — 37-darsda aytilgan xotira bazasi shu yerda o'z nomini ko'rsatib turibdi.

Har xil holatlar

Yetti holat. Bu bo'lim ma'lumotnoma — hozir bir marta o'qib chiqing, keyin kerak bo'lganda qaytib qarang.

HOLAT 1

Nomsiz has()

Vakansiya::factory()->has(Konikma::factory()->count(3))->create(); BadMethodCallException Call to undefined method App\Models\Vakansiya::konikma()

Laravel avval ko'plik (konikmas), keyin birlik (konikma) nomli metod qidiradi. Bizdagi konikmalar() ikkalasiga ham mos emas.

✅ Yechim bitta: nomni aniq bering.

->has(Konikma::factory()->count(3), 'konikmalar')

🔍 Xato xabari birlikni ko'rsatgani chalg'itishi mumkin — siz konikma() nomli metod yozishga urinishingiz mumkin. Aslida metod bor, faqat nomi boshqacha.

HOLAT 2

Kutilmagan factory zanjiri

Vakansiya::factory()->count(3)->create(); → vakansiyalar = 3, kompaniyalar = 3

Testda assertDatabaseCount('kompaniyalar', 1) yozgan bo'lsangiz — yiqiladi, va sabab birinchi qarashda ko'rinmaydi.

✅ Factory faylini oching va definition() ichida boshqa ::factory() chaqiruvlari bor-yo'qligini ko'ring. Bizda: 'kompaniya_id' => Kompaniya::factory().

✅ To'xtatish: ->for($k, 'kompaniya') yoki ->recycle($k).

HOLAT 3

Factory fayli yo'q

Konikma::factory()->create(); Error: Class "Database\Factories\KonikmaFactory" not found

Modelda use HasFactory; bor, lekin factory fayli yozilmagan. Xato aniq va nom ham to'liq ko'rsatilgan.

✅ php artisan make:factory KonikmaFactory va definition() ni to'ldiring.

🔍 Bu yerda taxmin ishlaydi: App\Models\Konikma → Database\Factories\KonikmaFactory. Ko'plik yasalmaydi, shuning uchun o'zbekcha nom xalaqit bermaydi — 33-darsdagi policy topilishi bilan bir xil naqsh.

HOLAT 4

Jadval nomi o'rniga model klassi

assertDatabaseHas('vakansiyalar', [...]) // ishlaydi assertDatabaseHas(Vakansiya::class, [...]) // ✅ afzal assertDatabaseHas('vakansiyas', [...]) → QueryException: no such table: vakansiyas

Model klassi berilganda jadval nomi $table dan olinadi — siz uni qo'lda yozmaysiz va xato yozib qo'yish imkoni yo'qoladi.

🔍 Bizning loyihada bu ayniqsa qimmatli: jadval nomlari o'zbekcha (vakansiyalar, kompaniyalar, konikmalar) va ularni yoddan yozganda xato qilish oson.

HOLAT 5

recycle() qachon for() dan afzal

// zanjir chuqur bo'lsa: Vakansiya::factory() ->count(3) ->recycle($kompaniya) // butun daraxtga tarqaladi ->create();

for() bitta bog'lanishga ta'sir qiladi. recycle() esa berilgan modelni qayerda kerak bo'lsa ishlatadi — ichma-ich yasalayotgan modellarda ham.

✅ Oddiy holatda for() ni tanlang: u nima bo'layotganini aniqroq ko'rsatadi. recycle() — uch va undan ko'p daraja bog'langan ma'lumot uchun.

HOLAT 6

sequence() va son mosligi

->count(4)->sequence(['shahar' => 'Toshkent'], ['shahar' => 'Buxoro']) → Toshkent = 2, Buxoro = 2 ✅ ->count(3)->sequence(['shahar' => 'Toshkent'], ['shahar' => 'Buxoro']) → Toshkent = 2, Buxoro = 1 ⚠️ teng emas

Ro'yxat aylanma bo'lgani uchun count variantlar soniga bo'linmasa taqsimot teng bo'lmaydi.

✅ Testda aniq son kerak bo'lsa, count ni variantlar soniga karrali qiling — yoki ikki alohida create() yozing, bu ancha o'qiladigan bo'ladi.

Sinab ko'ramiz

Natijani taxmin qiling

KonikmaFactory shunday yozilgan — o'nta variantdan takrorlanmas qiymat tanlaydi:

database/factories/KonikmaFactory.php
public function definition(): array { return [ 'nom' => fake()->unique()->randomElement([ 'PHP', 'Laravel', 'MySQL', 'JavaScript', 'Vue', 'Git', 'Docker', 'Redis', 'Linux', 'SQL', ]), ]; }

Dasturchi «ko'p ko'nikmali vakansiya» testini yozdi va count(15) so'radi. Nima bo'ladi — o'nta ko'nikma yasaladimi, yoki takrorlanadimi, yoki?

Javobni ko'rish
OverflowException Maximum retries of 10000 reached without finding a unique value

Na o'nta, na takrorlangan — istisno. unique() yangi qiymat topilmagach 10 000 marta qayta urinadi, keyin taslim bo'ladi.

⚠️ Xato xabari sababni aytmaydi: unda na Konikma, na randomElement, na «ro'yxat tugadi» degan gap bor. Siz esa count(15) ni ayblab o'ylamaysiz — chunki 15 ta yozuv so'rash mutlaqo oddiy narsa.

🔑 Tashxis qoidasi: Maximum retries so'zini ko'rsangiz, factory'da unique() ni izlang va uning manba ro'yxati qanchaligini sanang.

Uch yechim bor, va tanlov testning maqsadiga bog'liq:

// 1) chegarada qolish — ro'yxat 10 ta, demak ko'pi bilan 10 ->count(10) // 2) ro'yxatni kengaytirish 'nom' => fake()->unique()->word() // 3) takrorlanmaslikni son bilan ta'minlash 'nom' => 'Ko\'nikma ' . fake()->unique()->numberBetween(1, 9999)

🔍 Uchinchisi testlarda ko'pincha eng ma'qul: qiymat chiroyli emas, lekin hech qachon tugamaydi va test nechta yozuv so'rasa ham ishlaydi. Testda ma'lumotning chiroyli bo'lishi shart emas — ishonchli bo'lishi kerak.

🔑 Va umumiy saboq: unique() yozgan har bir joyda savol bering — «manba nechta qiymat bera oladi?»

SAVOL 1 O'zbekcha nomli bog'lanishda has() qanday ishlatiladi?

Laravel avval ko'plik (konikmas), keyin birlik (konikma) nomli metod qidiradi. Bizdagi konikmalar() ikkalasiga ham mos emas → Call to undefined method ...::konikma(). 🔍 for() da esa shart emas — u ko'plik yasamaydi.

SAVOL 2 Vakansiya::factory()->count(3)->create() bazada nima qoldiradi?

VakansiyaFactory ichida 'kompaniya_id' => Kompaniya::factory() turibdi — har bir vakansiya o'ziga kompaniya yasaydi. Zanjirni to'xtatish uchun ->for($k, 'kompaniya') yoki ->recycle($k).

SAVOL 3 assertDatabaseHas ga nimani berish afzal?

assertDatabaseHas(Vakansiya::class, [...]) jadval nomini modeldagi $table dan oladi. Bizda jadval nomlari o'zbekcha va taxminga mos kelmaydi, shuning uchun qo'lda yozish xatoga ochiq: no such table: vakansiyas.

Eslab ayting

Avval o'zingiz javob bering, keyin ochib tekshiring. Oxirgi ikkitasi — 38-darsni takrorlash.

for() va has() farqi nimada?

for() — belongsTo tomoni («kimga tegishli»), has() — hasMany tomoni («nimalari bor»). hasAttached() esa ko'pga-ko'p uchun, pivot ustunlari bilan.

Nega has() da nom majburiy, for() da yo'q?

has() taxminda ko'plik yasaydi (Konikma → konikmas) va o'zbekcha konikmalar() ga yetib bormaydi. for() esa birlik ishlatadi — kompaniya aynan mos keladi.

Factory zanjirini qanday to'xtatasiz?

->for($model, 'nom') — aniq bir bog'lanish uchun, yoki ->recycle($model) — butun daraxtga tarqaladi. Aks holda har yozuv o'ziga bog'liq modellarni yasaydi.

↩︎ Takrorlash: nega from() kerak?

Testda Referer yo'q, shuning uchun back() sayt ildiziga qaytaradi. Orqaga qaytaradigan har bir so'rovda ->from('/qayerdan') yozing.

↩︎ Takrorlash: assertSee apostrof bilan qanday ishlaydi?

Ishlaydi — chunki assertSee izlanayotgan matnni ham ekranlaydi. Ikkinchi argument false qo'ysangiz yiqiladi: HTML'da Qo&#039;shildi turadi.

Cho'ntak xulosasi
  • for($model, 'nom') — belongsTo tomoni («kimga tegishli»). Nom ixtiyoriy: taxmin birlikda va o'zbekcha nomga mos keladi.
  • has($factory->count(4), 'vakansiyalar') — hasMany tomoni. ⚠️ Nom majburiy.
  • ⚠️ Nega majburiy: taxmin avval ko'plik (Konikma → konikmas), keyin birlik (konikma). O'zbekcha konikmalar() ikkalasiga ham mos emas → Call to undefined method ...::konikma().
  • hasAttached($factory->count(3), ['daraja' => 'yuqori'], 'konikmalar') — ko'pga-ko'p va pivot ustunlari bitta chaqiruvda.
  • ⚠️ Factory zanjiri: Vakansiya::factory()->count(3) bazada 3 kompaniya ham qoldiradi — sababi definition() ichidagi Kompaniya::factory().
  • Zanjirni to'xtatish: ->for($k, 'kompaniya') (aniq bog'lanish) yoki ->recycle($k) (butun daraxtga).
  • sequence([...], [...]) — navbatma-navbat qiymatlar. ⚠️ count variantlar soniga bo'linmasa taqsimot teng bo'lmaydi.
  • Holatlar zanjirlanadi: ->yopiq()->boy(). Bir xil maydonni o'zgartirsa — oxirgisi g'olib.
  • assertDatabaseCount('vakansiyalar', 4) · assertModelExists($v) · assertModelMissing($v).
  • 🔍 Jadval nomini yozmang: assertDatabaseHas(Vakansiya::class, [...]) — nom $table dan olinadi. Xato yozilsa: no such table: vakansiyas.
  • ⚠️ Factory fayli yo'q bo'lsa: Class "Database\Factories\KonikmaFactory" not found. 🔍 Bu yerda taxmin ishlaydi — ko'plik yasalmaydi.
  • ⚠️ unique() manbasi tugasa: OverflowException: Maximum retries of 10000 reached. Har unique() uchun savol: manba nechta qiymat beradi?
  • Izolyatsiya o'lchandi: 0 → 5 → 0. Testlar bir-biriga iz qoldirmaydi.
  • 🔍 Birinchi Feature test ~0.11 s, qolganlari ~0.01 s — migratsiyalar bir marta bajariladi, keyin har test tranzaksiya ichida ishlaydi.
  • Natija: 15 test, 40 tekshiruv — 26–29-darsdagi bog'lanishlar va scope ham qulflandi.
