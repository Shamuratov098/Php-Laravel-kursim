DARS 25 · MODUL C — MA'LUMOTLAR

Eloquent: Vakansiya::find(3)

Uch darsda SQL'ni o'z qo'lingiz bilan yozdingiz. Endi Laravel'ning Eloquent qismi bilan tanishamiz: har jadvalga bitta klass, va o'sha SQL sizning nomingizdan yoziladi. Bu sehr emas — darsning o'rtasida Eloquent yozgan SQL'ni o'z ko'zingiz bilan ko'rasiz.

📱 O'qish ≈ 13 daqiqa 💻 Amaliyot ≈ 20 daqiqa Kerak: Dars 24

Bu darsda nimalar bor
  1. Model — jadvalni ifodalovchi klass make:model; bo'sh klass nima uchun allaqachon ishlaydi (meros).
  2. ⚠️ $table majburiy Laravel Vakansiya → vakansiyas deb taxmin qiladi (inglizcha ko'plik).
  3. getTable() Modeldan «sen qaysi jadvalni izlayapsan?» deb so'rash usuli.
  4. 🔒 $fillable Mass assignment himoyasi; ro'yxatda yo'q maydon jimgina tashlanadi.
  5. O'qish metodlari all · find · findOrFail · where · orderBy · count · value.
  6. Yozish metodlari create · save · delete; created_at 🎁 avtomatik.
  7. find va findOrFail Biri NULL, ikkinchisi 404 — controllerda qaysi biri.
  8. 🔍 toSql() Eloquent yozgan SQL'ni ko'rish; ? parametrlari — injection himoyasi o'z-o'zidan.
Nega bu muhim

24-darsdagi show metodiga qarang: 14 qator, yarmi SQL. Va u faqat bitta jadval, bitta amal. IshTop'da kompaniya, ariza, ko'nikma ham bo'ladi — har biri uchun SELECT, INSERT, UPDATE, DELETE ni qo'lda yozish minglab qator degani.

Eloquent — Laravel'ning ORM'i (object-relational mapper): jadvalni klass, qatorni obyekt qilib ko'rsatadi (7-dars!). O'sha 14 qator uch qatorga tushadi.

Va bu bilim ish uchun majburiy: Laravel vakansiyalarida «Eloquent» deyarli har doim talab sifatida yoziladi. Lekin siz uni SQL'dan keyin o'rganyapsiz — demak nima sodir bo'layotganini bilib ishlatasiz. Aynan shu farq junior'ni «faqat Eloquent biladigan» junior'dan ajratadi.

Model — jadvalni ifodalovchi klass

terminal
php artisan make:model Vakansiya
app/Models/Vakansiya.php — yaratilgani
<?php namespace App\Models; use Illuminate\Database\Eloquent\Model; class Vakansiya extends Model { // }

Bo'sh. Hech qanday metod yozilmagan, lekin Vakansiya::find(3) allaqachon ishlaydi. Nega? Chunki extends Model — 9-darsdagi meros. Barcha metodlar ota klassdan keladi.

⚠️ O'zbekcha nomlar bilan birinchi tuzoq: jadval nomi

Model qaysi jadvalga qarashini o'zi taxmin qiladi — klass nomini inglizcha qoida bo'yicha ko'plikka aylantirib:

Vakansiya → vakansiyas ❌ Kompaniya → kompaniyas ❌ User → users ✅ (inglizcha so'z)

Bizning jadval esa vakansiyalar. Natijada:

SQLSTATE[HY000]: General error: 1 no such table: vakansiyas

Yechim — jadval nomini o'zingiz aytish. O'zbekcha nomli loyihada bu har model uchun kerak bo'ladi:

protected $table = 'vakansiyalar';

Bu «sehr yo'q»ning yana bir ko'rinishi: Laravel taxmin qiladi, taxmin esa inglizcha til qoidasiga asoslangan. Xato chiqsa — no such table xabaridagi nomga qarang, u sizga nimani taxmin qilganini aytadi.

app/Models/Vakansiya.php — to'ldirilgani
<?php namespace App\Models; use Illuminate\Database\Eloquent\Model; class Vakansiya extends Model { protected $table = 'vakansiyalar'; protected $fillable = ['nom', 'maosh', 'shahar', 'faol', 'kompaniya_id']; }

$fillable — «formadan kelgan ma'lumot bilan to'ldirishga ruxsat berilgan ustunlar». Bu 20-darsda boshlagan gapning davomi: u yerda validate() faqat qoidadagi maydonlarni qaytarardi, bu esa ikkinchi qatlam. id va created_at ro'yxatda yo'q — ularni tashqaridan o'zgartirishga ruxsat bermaymiz.

O'qish

Vakansiya::find(3)Bitta, id bo'yicha. Topilmasa — NULL

Zanjir — metodlar ketma-ket ulanadi (23-darsdagi $table->string(...)->nullable() kabi):

misol
Vakansiya::where('faol', 1) ->where('maosh', '>', 700) ->orderBy('maosh', 'desc') ->get();

Ikki where — SQL'dagi AND (22-dars). ->get() — «endi bajar». Undan oldin hech qanday so'rov yuborilmaydi; siz shunchaki so'rovni yig'yapsiz.

find() obyekt, get() to'plam qaytaradi

Vakansiya::find(3) → bitta obyekt (App\Models\Vakansiya), ustunlar esa uning xossalari: $v->nom, $v->maosh.

->get() → Collection. Massivga o'xshaydi (@foreach ishlaydi, count() bor), lekin ancha ko'p imkoniyati bor. Uni Modul G da alohida ko'ramiz — hozircha massiv deb o'ylash yetarli.

Yozish

EloquentNima qiladi
Vakansiya::create([...])INSERT + obyektni qaytaradi. $fillable ga bo'ysunadi
$v->maosh = 1400; $v->save();UPDATE ... WHERE id = ?
$v->delete()DELETE ... WHERE id = ?
$v->toArray()Obyektni massivga aylantirish (tekshirish uchun qulay)
🎁 Bepul keladigan narsa: created_at

24-darsda created_at ni qo'lda to'ldirdik:

DB::insert( 'INSERT INTO vakansiyalar (nom, maosh, created_at, updated_at) VALUES (?, ?, ?, ?)', [$t['nom'], $t['maosh'], now(), now()] );

Eloquent'da esa:

Vakansiya::create($tekshirilgan);

created_at va updated_at avtomatik to'ldiriladi — 23-darsda migration'ga $table->timestamps() yozganimiz uchun. Yozuvni o'zgartirsangiz updated_at o'zi yangilanadi. Bu kelishuvning foydasi: nom to'g'ri bo'lsa, ish o'zi bajariladi.

🔍 Sehr yo'q: toSql()

Eloquent nima yozayotganini ko'rsatib beradi. get() o'rniga toSql() chaqiring:

tekshirish
Vakansiya::where('maosh', '>', 700)->orderBy('maosh', 'desc')->toSql()
select * from "vakansiyalar" where "maosh" > ? order by "maosh" desc

Aynan 21 va 22-darslarda qo'lda yozgan SQL. Va eng muhim tafsilot — ?. Eloquent qiymatni SQL satriga qo'shmaydi, parametr qilib beradi. Ya'ni u SQL injection'dan o'zi himoya qiladi (21-dars).

Shuning uchun tartib shunday edi: SQL avval, Eloquent keyin. Endi toSql() ni o'qiy olasiz — va bu Modul H dagi sekin so'rovlarni tuzatish darsida asosiy quroliga aylanadi.

Yonma-yon: xom SQL va Eloquent

24-dars — xom SQL
public function show(string $id): View { $qatorlar = DB::select(' SELECT v.*, k.nom AS kompaniya FROM vakansiyalar v LEFT JOIN kompaniyalar k ON k.id = v.kompaniya_id WHERE v.id = ? ', [$id]); if ($qatorlar === []) { abort(404); } return view('vakansiyalar.show', ['v' => $qatorlar[0]]); }
25-dars — Eloquent
public function show(string $id): View { $v = Vakansiya::findOrFail($id); return view('vakansiyalar.show', ['v' => $v]); }

findOrFail ichida ikkita ish bor: topish va topilmasa abort(404). Ya'ni if ham yo'qoldi. Xato tashlanganda ModelNotFoundException otiladi, Laravel esa uni 404 ga aylantiradi (17-darsdagi withExceptions).

Bitta narsa yo'qoladi: JOIN

Xom SQL'da bitta so'rovda kompaniya nomini ham olardik. Vakansiya::findOrFail($id) esa faqat vakansiyani oladi — kompaniya nomi yo'q.

Hozircha uni alohida olamiz: Kompaniya::find($v->kompaniya_id). Bu to'g'ri, lekin qo'pol. 26-darsda Eloquent'ning haqiqiy kuchi ochiladi: $v->kompaniya->nom deb yozish. Shu sababdan ro'yxat sahifasidan kompaniya ustunini vaqtincha olib qo'yamiz — keyingi darsda chiroyli shaklda qaytadi.

Sinab ko'ramiz

Natijani taxmin qiling

Modelda $fillable shunday:

protected $fillable = ['nom', 'maosh', 'shahar', 'faol', 'kompaniya_id'];

Diqqat: masofadan ustuni ro'yxatda yo'q (u 23-darsda migration bilan qo'shilgan va standart qiymati 0). Endi:

sinov
$v = Vakansiya::create([ 'nom' => 'Rust dasturchi', 'maosh' => 1600, 'masofadan' => 1, // $fillable da YO'Q ]); echo $v->nom, ' ', $v->maosh, ' ', Vakansiya::find($v->id)->masofadan;

Nima chiqadi — xato otiladimi, yoki masofadan 1 bo'ladimi?

Javobni ko'rish
Rust dasturchi 1600 0

Xato yo'q, lekin masofadan ham yozilmadi — u 0, ya'ni migration'dagi standart qiymatda qoldi. Eloquent $fillable da bo'lmagan maydonni jimgina tashlab yubordi.

🔒 Nega shunday? Aynan shu — mass assignment himoyasi. Tasavvur qiling, User modelida admin ustuni bor. Foydalanuvchi ro'yxatdan o'tish formasiga yashirincha admin=1 qo'shib yuborsa-chi? $fillable bo'lmasa, u o'zini admin qilib qo'yardi. Shu sababdan Eloquent «ruxsat berilmagan» maydonni o'tkazmaydi.

⚠️ Va agar $fillable ni butunlay yozmasangiz? Unda Eloquent hech nimaga ishonmaydi va exception otadi:

Illuminate\Database\Eloquent\MassAssignmentException Add [nom] to fillable property to allow mass assignment on [Vakansiya].

Ya'ni ikki holat bor: ro'yxat yo'q → xato (ovoz chiqaradi); ro'yxat bor, maydon unda yo'q → jimgina tashlanadi. Ikkinchisi chalg'ituvchi bo'lishi mumkin: «nega saqlanmadi?» degan savolda birinchi qaraydigan joy — $fillable.

SAVOL 1 Vakansiya modeli $table yozilmasa qaysi jadvalni izlaydi?

Laravel klass nomini inglizcha qoida bilan ko'plikka aylantiradi. O'zbekcha nomlarda bu deyarli har doim xato bo'ladi, shuning uchun protected $table yozish kerak. Tekshirish usuli — (new Vakansiya)->getTable().

SAVOL 2 $fillable da bo'lmagan maydon create() ga berilsa nima bo'ladi?

Maydon shunchaki o'tkazilmaydi — bu mass assignment himoyasi. MassAssignmentException esa boshqa holatda otiladi: $fillable umuman yozilmaganda.

SAVOL 3 findOrFail() ning find() dan farqi nimada?

find() topilmasa NULL beradi va keyingi qator xato bilan yiqiladi (500). findOrFail() ModelNotFoundException otadi, Laravel uni 404 ga aylantiradi — ya'ni abort(404) yozish shart emas.

Eslab ayting

Avval o'zingiz javob bering, keyin ochib tekshiring. Oxirgi ikkitasi — 24-darsni takrorlash.

Model bo'sh bo'lsa ham nega ishlaydi?

extends Model — meros (9-dars). find, where, create kabi barcha metodlar ota klassdan keladi.

Eloquent yozgan SQL'ni qanday ko'rish mumkin?

get() o'rniga toSql(): Vakansiya::where(...)->toSql(). Qiymatlar o'rnida ? turadi — ya'ni parametr, demak injection'dan himoyalangan.

created_at kim to'ldiradi?

Eloquent o'zi — migration'da $table->timestamps() bo'lgani uchun. Xom SQL'da esa now() bilan qo'lda yozgandik (24-dars).

↩︎ Takrorlash: route'lar qanday tartibda tekshiriladi?

Yozilgan tartibda, birinchi mos kelganida to'xtaydi. Shuning uchun /vakansiyalar/create /vakansiyalar/{id} dan oldin turishi kerak.

↩︎ Takrorlash: nega route('vakansiyalar.show', 3)?

Manzil bitta joyda (routes faylida) yozilishi uchun. Manzil o'zgarsa, qolgan hamma joy o'zi to'g'ri ishlaydi. Xato nom yozilsa — Route [...] not defined deb darhol aytadi.

Cho'ntak xulosasi
  • php artisan make:model Vakansiya — app/Models/ ga bo'sh klass. Metodlar extends Model dan keladi (meros).
  • ⚠️ O'zbekcha nomda $table majburiy: Laravel Vakansiya → vakansiyas deb taxmin qiladi. Xato: no such table: vakansiyas. Tekshirish: (new Vakansiya)->getTable().
  • 🔒 $fillable — formadan to'ldirishga ruxsat berilgan ustunlar. Ro'yxatda yo'q maydon jimgina tashlanadi; ro'yxat butunlay yo'q bo'lsa — MassAssignmentException.
  • O'qish: all() · find($id) · findOrFail($id) · where(...)->get() · orderBy(...) · first() · count() · value('nom').
  • find() topilmasa NULL, findOrFail() esa 404. Controllerda — findOrFail.
  • Yozish: create([...]) · $v->save() · $v->delete().
  • 🎁 created_at va updated_at — avtomatik (migration'dagi timestamps() tufayli).
  • 🔍 toSql() — Eloquent yozgan SQL. Qiymatlar ? bilan, ya'ni parametr — SQL injection'dan himoya o'z-o'zidan keladi.
  • find() obyekt, get() Collection qaytaradi (massivga o'xshaydi; Modul G da chuqur).
🌱 Keyingi dars

Bugun kod qisqardi, lekin bitta narsa qo'polroq bo'ldi: kompaniya nomini olish uchun ikkinchi so'rov yozdik va ro'yxatdan uni butunlay olib qo'ydik. Xom SQL'da bu bitta JOIN edi.

26-darsda Eloquent'ning haqiqiy kuchi ochiladi — bog'lanishlar. Modelga bir marta shunday yozasiz:

public function kompaniya() { return $this->belongsTo(Kompaniya::class); }

Shundan keyin butun ilovada $v->kompaniya->nom deb yozish kifoya. Va teskarisi ham ishlaydi: $kompaniya->vakansiyalar — o'sha kompaniyaning barcha vakansiyalari. 22-darsdagi JOIN shu yerda kodga aylanadi.
