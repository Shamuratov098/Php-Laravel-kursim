DARS 06 · MODUL A — POYDEVOR

Funksiya: mantiqqa nom berish

Bu darsdan keyin qayta ishlatiladigan funksiya yozasiz va uning tiplarini belgilaysiz. Ikkita katta narsa ochiladi: type hint o'zi kafolat bermaydi (va uni kafolatga aylantirish yo'li bor), hamda 4-darsda va'da qilgan stack trace endi to'liq ma'noga ega bo'ladi.

📱 O'qish ≈ 9 daqiqa 💻 Amaliyot ≈ 13 daqiqa Kerak: Dars 05

Nega bu muhim

Funksiya — bu mantiqqa nom berish. «Maoshni formatla», «arizani tekshir», «foydalanuvchini top» — har biri bitta funksiya. Foydasi uch tomonlama: kod takrorlanmaydi, o'qiladigan bo'ladi (nomning o'zi nima qilishini aytadi) va alohida sinash mumkin bo'ladi.

Laravel'da siz yozadigan deyarli hamma narsa funksiya bo'ladi — controller metodi, policy, job, validatsiya qoidasi. Ular klass ichida yashaydi va metod deb ataladi, lekin qoidalari aynan bugungi qoidalar. Ya'ni bu dars 7–10-darslardagi OOP uchun to'g'ridan-to'g'ri poydevor.

Funksiyaning tuzilishi

tushuncha
function maoshniFormatla(int $maosh, string $valyuta = "$"): string { return "{$maosh} {$valyuta}"; } echo maoshniFormatla(800); // 800 $ echo maoshniFormatla(9500000, "so'm"); // 9500000 so'm

Eng ko'p adashtiradigan joy: return ≠ echo

echo — matnni javobga yozadi (1-darsni eslang). return esa hech narsa chiqarmaydi — u qiymatni chaqirgan joyga qaytaradi, va siz u bilan xohlagan ishni qilasiz: o'zgaruvchiga solasiz, boshqa funksiyaga berasiz yoki echo qilasiz.

Qoida: funksiya hisoblab qaytarsin, chiqarishni chaqiruvchi hal qilsin. Shunda funksiyani boshqa joyda ham ishlatasiz — masalan HTML sahifada ham, JSON API'da ham. Laravel'da bu ayirma juda muhim.

Standart qiymat va parametr tartibi

string $valyuta = "$" — bu parametrni berish majburiy emas. Muhim qoida: standart qiymatli parametrlar oxirida turishi kerak, chunki PHP argumentlarni tartib bo'yicha o'qiydi.

O'zgaruvchi doirasi (scope): funksiya — yopiq xona

tushuncha
function hisobla(): int { $ichki = 42; // faqat shu funksiya ichida yashaydi return $ichki; } echo hisobla(); // 42 — to'g'ri echo $ichki; // Warning: Undefined variable $ichki

Funksiya ichida yaratilgan o'zgaruvchi tashqarida mavjud emas — va bu yaxshi: shuning uchun funksiya yozganda «bu nom boshqa joyda ishlatilganmi?» deb o'ylash kerak bo'lmaydi. Tashqaridan ma'lumot faqat parametr orqali kiradi, natija faqat return orqali chiqadi. Ikki teshikli qutiga o'xshaydi.

🔑 Type hint o'zi kafolat bermaydi

Bu darsning eng muhim qismi. int $son deb yozganingiz — «bu yerga son kelishi kerak» degani. Lekin PHP standart holatda buni majburlamaydi — 2 va 3-darsdagi qoida yana ishlaydi: tipni o'zgartirib yuboradi.

strict_types YO'Q
function ikkilantir(int $son): int { return $son * 2; } var_dump(ikkilantir(5)); // int(10) var_dump(ikkilantir("5")); // int(10) ← matn berdik, xato yo'q!

Ya'ni "5" matnini berdik, PHP uni jimgina 5 ga aylantirdi. Type hint yozgansiz, lekin himoya olmadingiz.

Buni haqiqiy kafolatga aylantirish uchun fayl boshiga bitta qator yoziladi:

strict_types BOR
<?php declare(strict_types=1); function ikkilantir(int $son): int { return $son * 2; } var_dump(ikkilantir(5)); // int(10) var_dump(ikkilantir("5")); // TypeError — dastur to'xtaydi

declare(strict_types=1); — «bu faylda tiplar qat'iy» degani. U <?php dan keyin, eng birinchi ko'rsatma bo'lishi shart.

Nega bu yaxshi xabar

Chunki xato ertaroq chiqadi. Qat'iy tip bo'lmasa, noto'g'ri tip kod ichiga kirib ketadi va muammo ancha keyin, butunlay boshqa joyda ko'rinadi — sababini topish qiyin bo'ladi. Qat'iy tipda esa PHP darhol «bu yerda noto'g'ri tip berildi» deb manzilini aytadi. Zamonaviy professional PHP kodida bu qator deyarli har faylda bo'ladi.

🎯 4-darsning qarzi: stack trace endi ma'noli

4-darsda stack trace #0 {main} dan iborat edi, chunki funksiya yo'q edi. Endi funksiya funksiyani chaqirsa, PHP butun zanjirni ko'rsatadi:

PHP Fatal error: Uncaught DivisionByZeroError: Division by zero in t2.php:4 Stack trace: #0 t2.php(8): bazadanOl() #1 t2.php(11): arizaniOqi() #2 {main} thrown in t2.php on line 4

Buni pastdan yuqoriga o'qiysiz — bu «qanday yo'l bilan kelindi» tarixi:

  1. #2 {main} — asosiy kod ishga tushdi
  2. #1 ... arizaniOqi() — 11-qatorda arizaniOqi() chaqirildi
  3. #0 ... bazadanOl() — 8-qatorda (ya'ni arizaniOqi ichida) bazadanOl() chaqirildi
  4. in t2.php:4 — va 4-qatorda xato yuz berdi

Ya'ni: tepadagi qator — xato joyi, pastdagilar — unga qanday kelib qolganingiz. Laravel'da bu ro'yxat 30-40 qatorli bo'ladi (framework ichidagi chaqiruvlar bilan), lekin sizga kerak bo'ladigani odatda o'z faylingiz nomi ko'ringan qatorlar — qolganini o'tkazib yuborishni o'rganasiz.

Funksiya + massiv: array_map va array_filter

5-darsda aytgan «keyingi darsda» shu yerda. Bu ikki funksiya boshqa funksiyani qabul qiladi va uni massivning har bir elementiga qo'llaydi:

tushuncha
function kattaHarf(string $s): string { return strtoupper($s); } $konikmalar = ["php", "laravel", "sql"]; $kattalar = array_map("kattaHarf", $konikmalar); // natija: ["PHP", "LARAVEL", "SQL"]
  • array_map — har bir elementni o'zgartiradi, yangi massiv qaytaradi (asl massiv tegilmaydi).
  • array_filter — shartga mos kelganlarni tanlaydi. Berilgan funksiya true qaytarsa element qoladi.
  • strtoupper — PHP'ning ichida kelgan funksiya: matnni katta harfga o'giradi. Bunday tayyor funksiyalar minglab.

Diqqat: funksiya nomi matn sifatida ("kattaHarf") beriladi. Bu «funksiyani qiymat kabi uzatish» degan g'oyaning eng oddiy shakli — Laravel'da buning ancha chiroyli ko'rinishi bor va biz unga keyinroq qaytamiz.

💻 Amaliy qism kompyuterda

Amaliyotda uchta fayl yozasiz: 14-funksiya.php (standart qiymatli parametr), 15-strict.php (declare(strict_types=1) bilan TypeError ni chiqarasiz va uning stack trace'ini o'qiysiz) va 16-massiv-funksiya.php (array_map). Oxirida scope'ni sinaysiz — funksiya ichidagi o'zgaruvchi tashqarida yo'qligini tasdiqlaysiz.

Amaliyot

  1. Papkaga o'ting

    cd ~/Projects/Learn/php-poydevor

    Kutilgan natija: jimlik.

  2. Birinchi funksiyangizni yozing

    Standart qiymat foydasi shu yerda ko'rinadi: bitta funksiya, ikki xil ishlatish.

    cat > 14-funksiya.php <<'EOF' <?php function maoshniFormatla(int $maosh, string $valyuta = "$"): string { return "{$maosh} {$valyuta}"; } echo maoshniFormatla(800), PHP_EOL; echo maoshniFormatla(9500000, "so'm"), PHP_EOL; EOF php 14-funksiya.php 800 $ 9500000 so'm

    Kutilgan natija: ikki qator. Birinchisida valyuta berilmagan — standart $ ishlatildi.

  3. Qat'iy tipni yoqing va TypeError ni chiqaring

    Bu darsning yuragi. Va bir vaqtda 4-darsdagi ko'nikmani ishlatasiz — xatoni o'qish.

    cat > 15-strict.php <<'EOF' <?php declare(strict_types=1); function ikkilantir(int $son): int { return $son * 2; } var_dump(ikkilantir(5)); var_dump(ikkilantir("5")); EOF php 15-strict.php int(10) PHP Fatal error: Uncaught TypeError: ikkilantir(): Argument #1 ($son) must be of type int, string given, called in 15-strict.php on line 8 and defined in 15-strict.php:3 Stack trace: #0 15-strict.php(8): ikkilantir() #1 {main} thrown in 15-strict.php on line 3

    Kutilgan natija: birinchi chaqiruv ishladi (int(10)), ikkinchisi to'xtatdi. Xabarni o'qib ko'ring — u ikkita joyni aytadi: called in ... line 8 (qaerdan chaqirilgan) va defined in ...:3 (funksiya qayerda yozilgan). Bu juda foydali: muammo chaqiruvda ekanini darrov bilasiz.

  4. Qat'iy tipni o'chirib solishtiring

    Farqni o'z ko'zingiz bilan ko'rish — «type hint o'zi kafolat bermaydi» degan gapni yodlashdan ko'ra ishonchli.

    Faylning 2-qatorini (declare(strict_types=1);) o'chirib tashlang va qayta bajaring. Tez usul — o'chirilgan nusxa yasash:

    grep -v 'strict_types' 15-strict.php > 15-bosh.php php 15-bosh.php int(10) int(10)

    Kutilgan natija: ikkita int(10) — xato yo'q. Ya'ni "5" jimgina 5 ga aylandi. Bitta qator bor-yo'qligi butun xatti-harakatni o'zgartirdi.

  5. Funksiyani massivga qo'llang

    cat > 16-massiv-funksiya.php <<'EOF' <?php function kattaHarf(string $s): string { return strtoupper($s); } $konikmalar = ["php", "laravel", "sql"]; $kattalar = array_map("kattaHarf", $konikmalar); foreach ($kattalar as $k) { echo "- {$k}", PHP_EOL; } EOF php 16-massiv-funksiya.php - PHP - LARAVEL - SQL

    Kutilgan natija: uchta katta harfli qator. array_map yangi massiv qaytardi — $konikmalar o'zgarmadi (xohlasangiz var_dump($konikmalar) bilan tekshiring).

  6. Scope'ni sinab ko'ring

    Funksiya yopiq xona ekanini isbotlash.

    php -r 'function f(): int { $ichki = 42; return $ichki; } echo f(), PHP_EOL; echo $ichki;' 42 PHP Warning: Undefined variable $ichki in Command line code on line 1

    Kutilgan natija: 42 chiqdi (funksiya ichidan return bilan), lekin $ichki tashqarida yo'q. Xato turi — Warning, ya'ni to'xtatmaydi.

  7. Ishni saqlang

    git add -A git commit -m "06-dars: funksiya va tiplar"

    Kutilgan natija: commit haqida xabar.

Sinab ko'ramiz

Natijani taxmin qiling

Ikki fayl bir xil — farqi faqat declare(strict_types=1); qatorida. Har birida ikkilantir("5") chaqirilgan. Ikkalasi nima qaytaradi?

A varianti — declare YO'Q
<?php function ikkilantir(int $son): int { return $son * 2; } var_dump(ikkilantir("5"));
B varianti — declare BOR
<?php declare(strict_types=1); function ikkilantir(int $son): int { return $son * 2; } var_dump(ikkilantir("5"));
Javobni ko'rish

A varianti — jimgina ishlaydi:

int(10)

B varianti — to'xtaydi:

PHP Fatal error: Uncaught TypeError: ikkilantir(): Argument #1 ($son) must be of type int, string given

Xulosa: int $son yozganingiz o'zi hech narsani kafolatlamaydi. U hujjat — «bu yerga son kutilyapti». Uni qoidaga aylantiradigan narsa — declare(strict_types=1); qatori, va u har faylda alohida yozilishi kerak.

Diqqat: bu qoida fayl bo'yicha ishlaydi — chaqirilgan funksiya qaysi faylda yozilganiga qarab emas, chaqiruv qaysi faylda turganiga qarab. Shuning uchun professional loyihalarda uni hamma faylga yozish odat qilingan.

SAVOL 1 return nima qiladi?

return hech narsa chiqarmaydi — qiymatni qaytaradi va funksiyani tugatadi. Chiqarish echo ning ishi. Shuning uchun funksiya hisoblab qaytarsin, chiqarishni chaqiruvchi hal qilsin.

SAVOL 2 int $son deb yozsangiz, matn berilishi mumkinmi?

Standart holatda PHP tipni o'zgartiradi — "5" jimgina 5 bo'ladi. declare(strict_types=1); yozilsagina TypeError chiqadi.

SAVOL 3 Stack trace'da xato joyi qayerda ko'rsatiladi?

Tepadagi in fayl.php:4 — xato joyi. Pastdagi #0, #1, #2 {main} — unga qanday kelib qolinganini ko'rsatadigan chaqiruvlar zanjiri.

Eslab ayting

Avval o'zingiz javob bering, keyin ochib tekshiring. Oxirgi ikkitasi — 5-darsni takrorlash.

return va echo farqi nima?

echo javobga yozadi. return qiymat qaytaradi va funksiyani tugatadi — chiqarishni chaqiruvchi hal qiladi. Shuning uchun bir funksiyani ham HTML sahifada, ham JSON API'da ishlatish mumkin.

Type hint'ni kafolatga aylantiradigan narsa nima?

declare(strict_types=1); — fayl boshida, <?php dan keyingi birinchi ko'rsatma. Usiz PHP tipni jimgina o'zgartiradi.

Stack trace'ni qaysi tomondan o'qiysiz?

Tepadagi qator — xato joyi. Undan pastdagilar (#0, #1, #2 {main}) — chaqiruvlar zanjiri, ya'ni «bu yergacha qanday kelindi».

↩︎ Takrorlash: PHP massivi ro'yxatmi yoki xarita?

Xarita — har doim «kalit → qiymat». Shuning uchun kalitlar uzluksiz bo'lmasligi mumkin va foreach tavsiya qilinadi.

↩︎ Takrorlash: $a = ["a","b"]; $a[5]="c"; $a[]="d"; — oxirgi kalit?

6 — chunki $a[] = «eng katta son kalit + 1» ni oladi, count ga qaramaydi.

Cho'ntak xulosasi
  • function nom(tip $param): tip { return ...; } — mantiqqa nom berish.
  • return qaytaradi, echo chiqaradi. Funksiya hisoblasin, chiqarishni chaqiruvchi hal qilsin.
  • Standart qiymatli parametrlar oxirida turadi.
  • Scope: funksiya ichidagi o'zgaruvchi tashqarida yo'q. Kirish — parametr, chiqish — return.
  • 🔑 Type hint o'zi kafolat emas. Kafolat — declare(strict_types=1);, har faylda alohida.
  • Stack trace: tepasi — xato joyi, pastdagilar — chaqiruvlar zanjiri.
  • array_map har elementni o'zgartiradi · array_filter shartga mos kelganini tanlaydi.
🌱 Kelasi darslar uchun urug'

Endi funksiya yozishni bilasiz. Lekin bitta muammo bor: bog'liq funksiyalar va ular ishlatadigan ma'lumot alohida-alohida yotadi. Masalan vakansiya ma'lumoti bir massivda, uni formatlaydigan funksiya boshqa joyda — ularni birga tutib turadigan narsa yo'q.

Keyingi dars shuni yechadi: ma'lumot va u bilan ishlaydigan funksiyalarni bitta qutiga solish — klass va obyekt. Klass ichidagi funksiya metod deb ataladi, lekin qoidalari bugungi qoidalar. Laravel butunlay shu tushuncha ustiga qurilgan.
