Laravel modelni o'zi topdi — KompaniyaFactory nomidan. Bizga faqat definition() ni to'ldirish qoldi: u bitta yozuvning maydonlarini qaytaradi.

⚠️ Birinchi to'siq: HasFactory trait'i

Factory yozilgan, lekin Kompaniya::factory() chaqirsangiz:

BadMethodCallException Call to undefined method App\Models\Kompaniya::factory()

Sababi: factory() metodi modelda yo'q — u trait orqali keladi (10-dars!). Modelga bitta qator qo'shish kerak:

use Illuminate\Database\Eloquent\Factories\HasFactory; class Kompaniya extends Model { use HasFactory; // ← shu ... }

Bu xato ovoz chiqaradi va xabari aniq, shuning uchun qo'rqmang — lekin birinchi marta uchraganda chalkashtiradi. Laravel'ning User modelida bu trait allaqachon bor (16-darsda ko'rgan skeletonda), shuning uchun ko'p o'quvchi uni umuman sezmaydi.

State — «shu holatdagi» yozuv

Ba'zan aynan yopiq yoki aynan yuqori maoshli vakansiya kerak bo'ladi. Buni har joyda create(['faol' => false]) deb yozish o'rniga, factory'ga nom berilgan holat qo'shiladi:

database/factories/VakansiyaFactory.php
public function yopiq(): static { return $this->state(['faol' => false]); } public function boy(): static { return $this->state(fn (array $atr) => ['maosh' => fake()->numberBetween(3000, 8000)]); }
Vakansiya::factory()->yopiq()->create() → faol=false Vakansiya::factory()->boy()->create() → maosh=6589 Vakansiya::factory()->yopiq()->boy()->create() → faol=false, maosh=3081 Vakansiya::factory(10)->yopiq()->create() → 10 ta yopiq vakansiya

State'lar zanjirlanadi — xuddi 25-darsdagi where lar kabi. Ikki shakl bor: oddiy massiv, yoki fn (array $atr) => [...] (closure — har yozuv uchun alohida hisoblanadi).

Seeder — bazani to'ldirishning rejasi

Factory bitta yozuvni biladi. «Bazada nima bo'lishi kerak» degan butun rasm esa seeder'da yoziladi:

database/seeders/DatabaseSeeder.php
public function run(): void { // 1) Ko'nikmalar — belgilangan ro'yxat, tasodifiy emas $konikmalar = collect(['PHP', 'Laravel', 'SQL', 'Git', 'Docker', 'JavaScript', 'Linux', 'Redis']) ->map(fn (string $nom) => Konikma::firstOrCreate(['nom' => $nom])); // 2) 5 kompaniya, har birida 4 vakansiya Kompaniya::factory(5) ->has(Vakansiya::factory(4), 'vakansiyalar') ->create(); // 3) Har vakansiyaga 1-3 tasodifiy ko'nikma Vakansiya::all()->each( fn (Vakansiya $v) => $v->konikmalar()->sync( $konikmalar->random(fake()->numberBetween(1, 3))->pluck('id')->all() ) ); }

Uch qadamning har biri ongli qaror:

  • Ko'nikmalar — factory emas. «PHP», «Laravel» — bular belgilangan qiymatlar, tasodifiy so'z bo'lmasligi kerak. Shuning uchun oddiy ro'yxat va firstOrCreate («bo'lsa top, bo'lmasa yarat»).
  • Kompaniya + vakansiya — birga. has() ikkisini bir chaqiruvda yasaydi va bog'lanishni to'g'ri qo'yadi.
  • Ko'nikmalar keyin biriktiriladi. Chunki ular allaqachon mavjud — 27-darsdagi sync() shu yerda o'z joyida ishlatilgan.

Har xil holatlar

Yetti holat. Bu bo'lim ma'lumotnoma — hozir bir marta o'qib chiqing, keyin kerak bo'lganda qaytib qarang.

HOLAT 1

Belgilangan ma'lumot — factory kerak emas

Ko'nikma nomlari («PHP», «SQL»), viloyatlar ro'yxati, to'lov turlari — bular tasodifiy bo'lmasligi kerak. Ularga factory yozish xato:

❌ Konikma::factory(8)->create(); → "laudantium", "voluptas" kabi ma'nosiz nomlar ✅ foreach (['PHP', 'Laravel', 'SQL'] as $nom) { Konikma::firstOrCreate(['nom' => $nom]); }

firstOrCreate — «bo'lsa top, bo'lmasa yarat». Shuning uchun seeder ikki marta ishga tushsa ham takroriy qator paydo bo'lmaydi.

🔑 Qoida: factory — hajm uchun; belgilangan ma'lumot — ro'yxat + firstOrCreate.

HOLAT 2

HasFactory trait'i yo'q

Call to undefined method App\Models\Kompaniya::factory()

Xato aniq va darhol chiqadi. Yechim — modelga use HasFactory; qo'shish (va yuqoriga use Illuminate\Database\Eloquent\Factories\HasFactory;).

Nima uchun bu chalkashtiradi: Laravel'ning User modelida bu trait allaqachon bor, shuning uchun hujjatlardagi misollar «ishlaydi», o'z modelingizda esa yo'q.

HOLAT 3

Bog'lanish nomi taxmin qilinmaydi

Kompaniya::factory()->has(Vakansiya::factory(2))->create(); → Call to undefined method App\Models\Kompaniya::vakansiya() Vakansiya::factory()->hasAttached($konikmalar)->create(); → Call to undefined method App\Models\Vakansiya::konikmas()

Laravel inglizcha ko'plik yasashga urinadi (Konikma → konikmas). Ikki xato ham ovoz chiqaradi, ya'ni jimgina buzilish emas — bu yaxshi.

✅ Nomni har doim yozing:

->has(Vakansiya::factory(2), 'vakansiyalar') ->hasAttached($konikmalar, [], 'konikmalar') ->for($kompaniya, 'kompaniya')

hasAttached da pivot ma'lumoti bo'lmasa ham bo'sh massiv ([]) berish kerak — chunki nom uchinchi argument.

HOLAT 4

O'zbekcha fake() — jimgina inglizcha

fake('uz_UZ')->city() → "Hahnfurt" ← xato yo'q, lekin inglizcha

Faker'da o'zbek tili yo'q va u jimgina standart tilga qaytadi. Bu 26 va 27-darslardagi «jimgina buzilish»larning uchinchi ko'rinishi.

✅ Uch yechim, foydalilik tartibida:

1) O'z ro'yxatingiz (eng oddiy va ishonchli) fake()->randomElement(['Toshkent', 'Samarqand', 'Buxoro']) 2) Ikki ro'yxatni qo'shish (ko'p variant kerak bo'lsa) randomElement([...]) . ' ' . randomElement([...]) → 6 × 3 = 18 xil 3) Tuzilmasi muhim bo'lgan joyda inglizcha qoldirish 'email' => fake()->unique()->safeEmail() ← email shakli tildan qat'i nazar bir xil
HOLAT 5

State: massiv yoki closure

// Massiv — qiymat har doim bir xil public function yopiq(): static { return $this->state(['faol' => false]); } // Closure — har yozuv uchun ALOHIDA hisoblanadi public function boy(): static { return $this->state(fn (array $atr) => ['maosh' => fake()->numberBetween(3000, 8000)]); }

Farqi muhim: state(['maosh' => fake()->numberBetween(...)]) yozsangiz, fake() bir marta chaqiriladi va 10 ta yozuvda bir xil maosh bo'ladi. Closure ichida esa har yozuv uchun qaytadan chaqiriladi.

$atr — shu yozuvning boshqa maydonlari, ya'ni bir maydonni ikkinchisiga qarab hisoblash mumkin.

HOLAT 6

Hajm va tezlik — ichma-ich factory qimmat

200 vakansiya yasashning ikki usuli o'lchandi:

factory(200)->create() 1579 ms 400 so'rov (har vakansiya O'ZIGA kompaniya yasadi) factory(200)->for($k, 'kompaniya')->create() 562 ms 200 so'rov (hammasi bitta kompaniyaga)

Sababi aniq: kompaniya_id => Kompaniya::factory() qatori har vakansiya uchun yana bitta INSERT qiladi.

⚠️ Raqamlarni qanday o'qish kerak: so'rovlar soni barqaror — har doim 400 va 200. Millisekundlar esa har ishga tushirishda o'zgaradi (bizda 1579/562 va 1113/730 chiqdi) va kompyuterga bog'liq. Shuning uchun tezlikni so'rovlar soni bilan o'lchash ishonchliroq.

🔑 Qoida: ko'p yozuv kerak bo'lsa, «ota» yozuvlarni oldin yasab, keyin for() bilan ulang:

$kompaniyalar = Kompaniya::factory(10)->create(); foreach ($kompaniyalar as $k) { Vakansiya::factory(50)->for($k, 'kompaniya')->create(); } // 10 kompaniya + 500 vakansiya = 510 INSERT, 5000 emas
HOLAT 7

Seeder'ni ikki marta ishga tushirish

db:seed mavjud ma'lumotni o'chirmaydi — qo'shadi. Ikki marta chaqirsangiz ma'lumot ikki barobar bo'ladi:

php artisan db:seed → 5 kompaniya php artisan db:seed → 10 kompaniya (yana 5 qo'shildi)

Ko'nikmalar esa takrorlanmaydi — firstOrCreate tufayli. Ya'ni seeder'ning bir qismi idempotent, bir qismi yo'q.

✅ Ikki yo'l bor:

1) migrate:fresh --seed ← toza holatdan (ishlab chiqishda odatiy yo'l) 2) Seeder boshida tozalash: Vakansiya::query()->delete(); Kompaniya::query()->delete();

⚠️ Real serverda ikkalasi ham xavfli — u yerda seeder faqat belgilangan ma'lumot uchun ishlatiladi (viloyatlar ro'yxati kabi), tasodifiy ma'lumot uchun emas.

Sinab ko'ramiz

Natijani taxmin qiling

VakansiyaFactory da 'kompaniya_id' => Kompaniya::factory() qatori bor. Baza bo'sh. Endi:

kod
Vakansiya::factory(200)->create(); echo Vakansiya::count(), ' vakansiya', PHP_EOL; echo Kompaniya::count(), ' kompaniya', PHP_EOL;

Ikki savol: (a) kompaniyalar jadvalida nechta qator bo'ladi? (b) bazaga nechta INSERT yuboriladi?

Javobni ko'rish
(a) 200 kompaniya (b) 400 so'rov (1579 ms)

Ko'pchilik 1 kompaniya deb o'ylaydi — «hammasi bir kompaniyaga tegishli bo'lsa kerak». Aslida Kompaniya::factory() qatori har vakansiya uchun qaytadan bajariladi, ya'ni har biriga o'z kompaniyasi yasaladi.

Bu ba'zan aynan kerak (testda «har birining o'z kompaniyasi bo'lsin»), lekin katta hajmda ikki muammo beradi:

  • Tezlik: 400 INSERT o'rniga 200 bo'lardi. Ikki o'lchovda 1579/562 ms va 1113/730 ms chiqdi — vaqt o'zgaradi, lekin so'rovlar soni har doim ikki barobar kam.
  • Realistik emas: haqiqiy bozorda 200 kompaniyada bittadan vakansiya bo'lmaydi. Sahifalash yoki hisobotni sinaganda ma'lumot g'alati chiqadi.

✅ To'g'ri yo'l — «ota»larni oldin yasash:

$kompaniyalar = Kompaniya::factory(10)->create(); foreach ($kompaniyalar as $k) { Vakansiya::factory(20)->for($k, 'kompaniya')->create(); } // 10 + 200 = 210 INSERT, va ma'lumot realistik

Yoki has() bilan bitta chaqiruvda: Kompaniya::factory(10)->has(Vakansiya::factory(20), 'vakansiyalar')->create().

🔑 Umumiy qoida: ichma-ich factory qulay, lekin u «yashirin INSERT»: bitta yozuv so'rasangiz ikkitasi yasaladi. Hajm oshganda buni eslash kerak.

SAVOL 1 make() va create() farqi nimada?

make() faqat obyekt yasaydi — id si NULL bo'ladi. Testda yoki namuna ma'lumot kerak bo'lganda qulay; qolgan hollarda create().

SAVOL 2 fake('uz_UZ') nima qiladi?

Faker'da o'zbek tili yo'q va u ogohlantirmasdan standart tilga qaytadi. O'zbekcha ma'lumot uchun randomElement(['Toshkent', ...]) — o'z ro'yxatingiz.

SAVOL 3 Factory'da has() ga bog'lanish nomi nima uchun beriladi?

Laravel Vakansiya dan vakansiyas, keyin vakansiya deb sinaydi — bizning metod esa vakansiyalar. Shuning uchun nomni har doim yozamiz.

Eslab ayting

Avval o'zingiz javob bering, keyin ochib tekshiring. Oxirgi ikkitasi — 27-darsni takrorlash.

Factory va seeder farqi nimada?

Factory — bitta yozuvning retsepti (definition()). Seeder — bazada nima bo'lishi kerakligining butun rejasi: qaysi factory, nechta, qanday bog'lanish bilan.

Belgilangan ma'lumot (ko'nikma nomlari) uchun nima ishlatiladi?

Factory emas — oddiy ro'yxat va firstOrCreate. Aks holda «laudantium» kabi ma'nosiz nomlar chiqadi. Factory hajm uchun.

Ichma-ich factory (Kompaniya::factory()) nima qiladi?

Har yozuv uchun yana bitta yozuv yasaydi va uning id sini qo'yadi. Qulay, lekin «yashirin INSERT» — 200 vakansiya → 400 so'rov. Katta hajmda for() ishlatiladi.

↩︎ Takrorlash: sync() nima qiladi?

Ro'yxatni aynan moslashtiradi — ro'yxatda yo'qlarini o'chiradi. Faqat qo'shish uchun — syncWithoutDetaching.

↩︎ Takrorlash: pivot jadval nomi qanday taxmin qilinadi?

Ikki model nomi → kichik harf → alifbo tartibida → _ bilan: konikma_vakansiya. Ko'plik yasalmaydi.

Cho'ntak xulosasi
  • Factory — bitta yozuvning retsepti (make:factory → definition()). Seeder — bazani to'ldirishning butun rejasi.
  • ⚠️ Modelga use HasFactory; kerak, bo'lmasa Call to undefined method ...::factory().
  • make() bazaga yozmaydi (id=NULL), create() yozadi. factory(3) — uchta. create(['nom' => ...]) — aniq qiymat.
  • fake(): numberBetween · boolean(80) · randomElement([...]) · unique() · dateTimeBetween · sentence.
  • ⚠️ fake('uz_UZ') jimgina inglizcha qaytaradi — Faker'da o'zbek tili yo'q. Yechim: o'z ro'yxatingiz (randomElement), kerak bo'lsa ikki ro'yxatni qo'shib.
  • Bog'lanishlar: has(..., 'nom') · for($obyekt, 'nom') · hasAttached($lar, [pivot], 'nom').
  • 🔑 Bog'lanish nomini har doim yozing — Laravel taxmini o'zbekcha nomda ishlamaydi (vakansiyas / konikmas). Xato ovoz chiqaradi.
  • State: state([...]) yoki state(fn ($atr) => [...]). Zanjirlanadi: ->yopiq()->boy(). Closure — har yozuv uchun alohida hisoblanadi.
  • Belgilangan ma'lumot (ko'nikmalar) — factory emas, ro'yxat + firstOrCreate.
  • db:seed qo'shadi · migrate:fresh --seed noldan to'ldiradi (kunlik ish shakli) · --class= bittasini.
  • ⚡ Ichma-ich factory — «yashirin INSERT»: 200 vakansiya → 400 so'rov. for() bilan — 200. Tezlikni so'rovlar soni bilan o'lchang: millisekund har safar o'zgaradi.
