OOP 1 — klass va obyekt: ma'lumot va mantiq birga

Bu darsdan keyin o'z klassingizni yozasiz va undan obyekt yasaysiz. Shu bilan Laravel kodidagi eng ko'p uchraydigan belgi — -> — sizga tushunarli bo'ladi. $user->name, $request->input() — bugundan keyin bular sehr emas.

📱 O'qish ≈ 9 daqiqa 💻 Amaliyot ≈ 13 daqiqa Kerak: Dars 06

Bu darsda nimalar bor
  1. Klass — shakl, obyekt — nusxa class yozasiz, new bilan nusxa olasiz.
  2. Xossa va metod Ma'lumot va u bilan ishlaydigan mantiq birga.
  3. $this Metod ichida «shu obyekt» degani.
  4. Konstruktor Obyekt tug'ilgan paytda bajariladi.
  5. 🔍 Konstruktor xossalari (PHP 8) Uch marta takrorlash o'rniga bir marta.
  6. ⚠️ Obyekt — nusxa emas, havola 🔍 $b = $a yangi obyekt yaratmaydi; clone yaratadi.
  7. ⚠️ E'lon qilinmagan xossa 🔍 Deprecated: Creation of dynamic property.
  8. Tiplangan xossa 🔍 Qiymatsiz o'qilsa — must not be accessed before initialization.
  9. static — klassga tegishli 🔍 Hamma obyektlar uchun bitta qiymat.
  10. Obyekt ichini ko'rish var_dump tipni ham ko'rsatadi; #1 — obyekt raqami.
  11. Klass qachon kerak, qachon yo'q Sinov savoli: «bu ma'lumotning o'z qoidalari bormi?»
  12. Har xil holatlar (7 ta) Havola va clone · dinamik xossa · static · var_dump · klass chegarasi.
Nega bu muhim

6-dars oxirida muammoni aytgandim: vakansiya ma'lumoti bir massivda, uni formatlaydigan funksiya boshqa joyda — ularni birga tutib turadigan narsa yo'q. Loyiha o'sgani sari bu chalkashlikka aylanadi: qaysi funksiya qaysi massiv bilan ishlaydi — faqat siz bilasiz, kod aytmaydi.

Klass shu muammoni yechadi: ma'lumot va u bilan ishlaydigan funksiyalar bitta quti ichida yashaydi. Laravel butunlay shu tushuncha ustiga qurilgan — har bir Model, Controller, Request, Job — bu klass. Ya'ni bugungi dars Laravel'ga kirish eshigi.

Klass — chizma, obyekt — undan yasalgan narsa

Ikkisini adashtirmaslik kerak:

TushunchaNima
class (klass)Chizma. «Vakansiya degan narsada nom va maosh bo'ladi, va u o'zini ko'rsata oladi». Bitta marta yoziladi
object (obyekt)Chizmaga ko'ra yasalgan aniq narsa. «Backend dasturchi, 800$». Xohlagancha yasash mumkin
propertyObyekt ichidagi ma'lumot (o'zgaruvchi)
methodObyekt ichidagi funksiya. Qoidalari 6-darsdagidek

Metafora: klass — uy chizmasi, obyekt — qurilgan uy. Bitta chizmadan yuzta uy qurish mumkin, va har birining o'z manzili, o'z rangi bo'ladi.

Kod

tushuncha
class Vakansiya { public string $nom; // property — ma'lumot public int $maosh; public function __construct(string $nom, int $maosh) { $this->nom = $nom; // kelgan qiymatni obyektga saqlaydi $this->maosh = $maosh; } public function korinish(): string // method — mantiq { return "{$this->nom} — {$this->maosh} $"; } } $backend = new Vakansiya("Backend dasturchi", 800); echo $backend->korinish(); // Backend dasturchi — 800 $

To'rtta yangi narsa bor:

  • new Vakansiya(...) — obyekt yasaydi. Har new — yangi, mustaqil obyekt.
  • __construct — maxsus metod: obyekt yasalganda avtomatik ishlaydi. Odatda kelgan qiymatlarni obyektga saqlash uchun ishlatiladi. Oldidagi ikki tagchiziq (__) «bu PHP uchun maxsus ma'noga ega» degani.
  • $this — «aynan shu obyekt». Metod ichida obyektning o'z ma'lumotiga murojaat qilish uchun ishlatiladi.
  • -> — obyektga murojaat belgisi. $backend->nom = «shu obyektning nom xossasi», $backend->korinish() = «shu obyektning korinish metodini ishga tushir».
$this nima uchun kerak

Metod ichida $nom deb yozsangiz — bu metodning o'z lokal o'zgaruvchisi (6-darsdagi scope qoidasi!). Obyektning xossasiga murojaat qilish uchun $this->nom deb aytish shart. $this — «metod hozir qaysi obyekt ustida ishlayapti» degan javob. Bitta klassdan yuzta obyekt yasalsa ham, metod har chaqiruvda o'zining $this ini biladi.

Obyekt — yangi tip

5-darsda var_dump massivni array(3) deb ko'rsatgan edi. Obyektni esa shunday ko'rsatadi:

object(Vakansiya)#1 (2) { ["nom"]=> string(17) "Backend dasturchi" ["maosh"]=> int(800) }

Diqqat qiling: tip nomi — Vakansiya, ya'ni siz yozgan klass o'zi tipga aylandi. #1 — obyektning tartib raqami (ikkinchi obyekt #2 bo'ladi). Bu 6-darsdagi type hint bilan bog'lanadi: endi function f(Vakansiya $v) deb yozib, «bu yerga faqat vakansiya obyekti kelsin» deyish mumkin.

Bir klass — bir fayl

Amalda har klass o'z faylida yashaydi va faylda faqat klass turadi — hech qanday echo yo'q. Boshqa fayldan uni ishlatish uchun:

tushuncha
require '17-klass.php'; // shu faylni bu yerga qo'shadi $backend = new Vakansiya("Backend dasturchi", 800);

require — «shu faylni o'qib, shu yerga qo'sh». Klasslar ko'payganda har birini qo'lda require qilish zerikarli bo'ladi — 12-darsda Composer buni avtomatik qilishni ko'rsatamiz (autoload). Hozircha qo'lda.

Tipli property'ga qiymat berilmasa — Fatal error

public string $nom; deb e'lon qilib, unga qiymat bermasangiz va o'qishga urinsangiz:

PHP Fatal error: Uncaught Error: Typed property V::$nom must not be accessed before initialization

Ya'ni «tipi bor xossaga qiymat berilmagan». Bu foydali qattiqqo'llik — null jimgina tarqalib ketishining oldini oladi. Va aynan shu sababdan __construct muhim: u obyekt yasalgan zahoti hamma xossaga qiymat beradi.

💻 Amaliy qism kompyuterda

Amaliyotda ikkita fayl yozasiz: 17-klass.php — faqat Vakansiya klassi (chiqishsiz), va 18-obyektlar.php — undan ikkita obyekt yasab, ro'yxat qilib chiqarasiz. Oxirida eng muhim tajriba: $b = $a yozganda obyekt nusxalanmasligini o'z ko'zingiz bilan ko'rasiz — va massiv bilan solishtirasiz.

Amaliyot

  1. Papkaga o'ting

    cd ~/Projects/Learn/php-poydevor

    Kutilgan natija: jimlik.

  2. Klassni alohida faylga yozing

    Faylda faqat klass — chiqish yo'q. Bu professional tuzilma va 10-darsdagi autoload uchun tayyorgarlik.

    cat > 17-klass.php <<'EOF' <?php declare(strict_types=1); class Vakansiya { public string $nom; public int $maosh; public function __construct(string $nom, int $maosh) { $this->nom = $nom; $this->maosh = $maosh; } public function korinish(): string { return "{$this->nom} — {$this->maosh} $"; } } EOF php 17-klass.php

    Kutilgan natija: jimlik — va bu to'g'ri! Faylda faqat chizma bor, hech narsa yasalmagan. Klass e'lon qilinishi o'zi hech narsa chiqarmaydi.

  3. Obyektlar yasang

    Bitta chizmadan ikkita mustaqil narsa — OOP ning asosiy foydasi.

    cat > 18-obyektlar.php <<'EOF' <?php declare(strict_types=1); require '17-klass.php'; $backend = new Vakansiya("Backend dasturchi", 800); $frontend = new Vakansiya("Frontend dasturchi", 700); foreach ([$backend, $frontend] as $v) { echo "- ", $v->korinish(), PHP_EOL; } var_dump($backend); EOF php 18-obyektlar.php - Backend dasturchi — 800 $ - Frontend dasturchi — 700 $ object(Vakansiya)#1 (2) { ["nom"]=> string(17) "Backend dasturchi" ["maosh"]=> int(800) }

    Kutilgan natija: ikkita qator va bitta object(Vakansiya)#1. Diqqat: obyektlarni massivga solib foreach qildik — 5-darsdagi ko'nikma shu yerda ishga tushdi.

  4. Massiv nusxalanadi — tekshirib ko'ring

    Keyingi qadam bilan solishtirish uchun asos.

    php -r '$a = ["nom" => "Backend"]; $b = $a; $b["nom"] = "Frontend"; echo "a: {$a["nom"]} | b: {$b["nom"]}", PHP_EOL;' a: Backend | b: Frontend

    Kutilgan natija: $a o'zgarmadi. Massiv = bilan berilganda nusxalanadi — ikkisi mustaqil.

  5. Obyekt esa nusxalanmaydi — darsning eng muhim tajribasi

    Bu farqni bilmagan odam kelajakda tushunarsiz bug'ga duch keladi.

    php -r 'require "17-klass.php"; $a = new Vakansiya("Backend", 800); $b = $a; $b->nom = "Frontend"; echo "a: {$a->nom} | b: {$b->nom}", PHP_EOL;' a: Frontend | b: Frontend

    Kutilgan natija: $a ham o'zgardi! Ikkisi bitta obyekt — = obyektni nusxalamaydi, faqat «o'sha obyektga yana bitta yorliq» yasaydi. Buni yaxshi tushunish kerak.

  6. Haqiqiy nusxa kerak bo'lsa — clone

    php -r 'require "17-klass.php"; $a = new Vakansiya("Backend", 800); $b = clone $a; $b->nom = "Frontend"; echo "a: {$a->nom} | b: {$b->nom}", PHP_EOL;' a: Backend | b: Frontend

    Kutilgan natija: endi mustaqil. clone — «shu obyektning haqiqiy nusxasini yasa».

  7. Ishni saqlang

    git add -A git commit -m "07-dars: klass va obyekt"

    Kutilgan natija: commit haqida xabar.

Har xil holatlar

Yetti holat. Bu bo'lim ma'lumotnoma — hozir bir marta o'qing, keyin kerak bo'lganda qaytib qarang.

HOLAT 1

⚠️ Obyekt — nusxa emas, havola

class V { public $nom = "eski"; } function f(V $v) { $v->nom = "yangi"; } $a = new V; f($a); echo $a->nom; → yangi ⚠️ o'zgardi! $b = $a; $b->nom = "b orqali"; echo $a->nom; → b orqali ⚠️ $a ham o'zgardi $c = clone $a; $c->nom = "c orqali"; echo $a->nom; → b orqali ✅ clone — haqiqiy nusxa

🔑 Bu massiv bilan tubdan farq qiladi. 5-darsda massiv funksiyaga nusxa bo'lib o'tgandi; obyekt esa o'zi o'tadi.

⚠️ $b = $a yangi obyekt yaratmaydi — u o'sha obyektga ikkinchi yorliq qo'yadi.

✅ Haqiqiy nusxa kerak bo'lsa — clone.

HOLAT 2

⚠️ E'lon qilinmagan xossa

class V { public string $nom = "Ali"; } $v = new V; $v->yosh = 30; PHP Deprecated: Creation of dynamic property V::$yosh is deprecated echo $v->yoq; PHP Warning: Undefined property: V::$yoq

PHP 8.2 gacha obyektga istalgan xossani qo'shish mumkin edi. Endi bu eskirgan deb belgilangan va kelajakda xato bo'ladi.

🔑 Va bu yaxshi: $v->nom o'rniga $v->norn deb xato yozsangiz, PHP sizga aytadi — jimgina yangi xossa yaratmaydi.

✅ Klassda ishlatiladigan hamma xossani oldindan e'lon qiling.

HOLAT 3

Tiplangan xossa — boshlang'ich qiymatsiz

class V { public string $nom; } $v = new V; echo $v->nom; PHP Fatal error: Uncaught Error: Typed property V::$nom must not be accessed before initialization class V { public string $nom = ""; } var_dump($v->nom); → string(0) "" ✅

🔑 Bu null emas — «hali qiymat berilmagan» degan uchinchi holat.

✅ Uch yechim: boshlang'ich qiymat berish · konstruktorda to'ldirish · ?string qilib null ga ruxsat berish.

🔍 Amalda deyarli har doim ikkinchisi ishlatiladi — keyingi holatda ko'rasiz.

HOLAT 4

Konstruktor xossalari (PHP 8)

// ESKI shakl — uch marta takrorlash class Eski { public string $nom; public int $maosh; public function __construct(string $nom, int $maosh) { $this->nom = $nom; $this->maosh = $maosh; } } // YANGI shakl — bir marta class Yangi { public function __construct(public string $nom, public int $maosh) {} }

🔍 Ikkalasi ham bir xil ishlaydi: PHP 900.

🔑 Parametr oldiga public yozilsa, PHP o'zi xossa yaratadi va o'zi to'ldiradi.

✅ Yangi kodda doim shu shakl ishlatiladi. Kursning davomida uni juda ko'p ko'rasiz.

HOLAT 5

$this va static

class V { public static int $soni = 0; public function __construct(public string $nom) { self::$soni++; } public function ayt(): string { return "men " . $this->nom; } public static function nechta(): int { return self::$soni; } } $a = new V("a"); $b = new V("b"); $a->ayt() → men a ← OBYEKTGA tegishli V::nechta() → 2 ← KLASSGA tegishli

🔑 $this — «shu obyekt». static esa obyektga emas, klassga tegishli — hamma obyektlar uchun bitta.

⚠️ Aralashtirib bo'lmaydi:

V::ayt(); Fatal error: Uncaught Error: Non-static method V::ayt() cannot be called statically

✅ Boshlanishida static deyarli kerak emas. Uni hisoblagich yoki yordamchi funksiya kerak bo'lgandagina ishlating.

HOLAT 6

Obyekt ichini ko'rish

class V { public function __construct( public string $nom = "PHP", public ?int $maosh = null ) {} } var_dump(new V); object(V)#1 (2) { ["nom"] => string(3) "PHP" ["maosh"] => NULL } print_r(new V); V Object ( [nom] => PHP [maosh] => )

🔑 var_dump tipni ham ko'rsatadi (string(3), NULL) — shuning uchun tekshirish uchun u afzal.

🔍 #1 — obyektning ichki raqami. Ikkita o'zgaruvchi bir xil raqamni ko'rsatsa, demak ular bitta obyekt (HOLAT 1).

⚠️ print_r da null bo'sh ko'rinadi — "" dan farqi bilinmaydi.

HOLAT 7

Klass qachon kerak, qachon yo'q

✅ KLASS YAXSHI: ma'lumot va u bilan ishlaydigan mantiq BIRGA yursa (vakansiya + uning maoshini formatlash) bir xil shakldagi ko'p nusxa kerak bo'lsa (yuzlab vakansiya — har biri o'z nomi, maoshi bilan) ❌ KLASS ORTIQCHA: bitta funksiya yetadigan joyda faqat ma'lumot saqlanadigan joyda — massiv yetadi "shunchaki OOP ishlatish kerak" degan sabab bilan

🔑 Sinov savoli: «bu ma'lumotning o'z qoidalari bormi?» Vakansiyaning bor: maoshi manfiy bo'lmaydi, nomi bo'sh bo'lmaydi. Massiv bu qoidalarni bilmaydi, klass esa — biladi.

🔍 Keyingi darsda aynan shuni ko'ramiz: obyekt o'z ma'lumotini qanday himoya qiladi.

Sinab ko'ramiz

Natijani taxmin qiling

Ikkita kod bir xil tuzilishda: qiymat yasaladi → $b = $a → $b o'zgartiriladi → ikkisi chiqariladi. Faqat biri massiv, ikkinchisi obyekt. Natijalar bir xil bo'ladimi?

A — massiv bilan
$a = ["nom" => "Backend"]; $b = $a; $b["nom"] = "Frontend"; echo $a["nom"];
B — obyekt bilan
$a = new Vakansiya("Backend", 800); $b = $a; $b->nom = "Frontend"; echo $a->nom;
Javobni ko'rish

A (massiv) → Backend. B (obyekt) → Frontend.

Ya'ni bir xil ko'rinishdagi kod ikki xil ishlaydi:

  • Massiv = bilan nusxalanadi. $b — alohida massiv, o'zgartirsangiz $a ga ta'sir qilmaydi.
  • Obyekt nusxalanmaydi. $b = $a — «o'sha obyektga yana bitta yorliq» degani. Ikki nom, bitta obyekt. Shuning uchun $b ni o'zgartirsangiz, $a orqali ham o'zgargan holatni ko'rasiz.

Nega bu muhim: obyektni funksiyaga bersangiz, funksiya uni o'zgartira oladi — asl obyekt o'zgaradi. Massivda esa funksiya nusxa oladi. Bu Laravel'da doim uchraydi: model obyektini metodga berib, u yerda o'zgartirilsa — o'zgarish tashqarida ham ko'rinadi.

Haqiqiy nusxa kerak bo'lsa: $b = clone $a;

SAVOL 1 class va object farqi nima?

Klass bir marta yoziladi — u chizma. new esa har chaqirilganda shu chizmaga ko'ra yangi, mustaqil obyekt yasaydi.

SAVOL 2 Metod ichida $this nimani bildiradi?

$this — «metod hozir qaysi obyekt ustida ishlayapti». Usiz $nom deb yozsangiz, u metodning lokal o'zgaruvchisi bo'lib qoladi (6-darsdagi scope qoidasi).

SAVOL 3 $b = $a; — $a obyekt bo'lsa nima bo'ladi?

Obyekt = bilan nusxalanmaydi — $b o'sha obyektga yana bitta yorliq bo'ladi. Haqiqiy nusxa uchun clone kerak. Massiv esa nusxalanadi.

Eslab ayting

Avval o'zingiz javob bering, keyin ochib tekshiring. Oxirgi ikkitasi — 6-darsni takrorlash.

__construct qachon ishlaydi va nima uchun kerak?

Obyekt new bilan yasalgan zahoti avtomatik ishlaydi. Kerakligi: obyekt yasalgan paytda hamma xossaga qiymat berib qo'yadi — aks holda tipli xossani o'qishda Fatal error chiqadi.

property va method nima?

Property — obyekt ichidagi ma'lumot (o'zgaruvchi). Method — obyekt ichidagi funksiya. Ikkisiga ham -> bilan murojaat qilinadi.

Obyekt va massivning = dagi farqi?

Massiv nusxalanadi (mustaqil bo'ladi), obyekt nusxalanmaydi (ikki nom — bitta obyekt). Nusxa uchun clone.

↩︎ Takrorlash: type hint'ni kafolatga aylantiradigan narsa nima?

declare(strict_types=1); — fayl boshida, birinchi ko'rsatma, har faylda alohida. Usiz PHP tipni jimgina o'zgartiradi.

↩︎ Takrorlash: return va echo farqi?

echo javobga yozadi, return qiymatni qaytaradi va funksiyani tugatadi. Bugungi korinish() metodi ham return qiladi — chiqarishni chaqiruvchi hal qiladi.

Cho'ntak xulosasi
  • class = chizma (bir marta) · object = new bilan yasalgan narsa (xohlagancha).
  • property = obyekt ichidagi ma'lumot · method = obyekt ichidagi funksiya.
  • __construct — obyekt yasalganda avtomatik ishlaydi; xossalarga qiymat beradi.
  • $this — «aynan shu obyekt». Xossaga murojaat uchun shart.
  • -> — obyektga murojaat: $v->nom, $v->korinish().
  • Klass o'zi tipga aylanadi: object(Vakansiya)#1, va function f(Vakansiya $v) yozish mumkin.
  • 🔑 Obyekt = bilan nusxalanmaydi (massiv nusxalanadi). Nusxa — clone.
  • Bir klass — bir fayl, chiqishsiz. Ulash: require (12-darsda avtomatlashtiramiz).
🌱 Kelasi darslar uchun urug'

Diqqat qilgan bo'lsangiz, hamma xossani public deb yozdik — ya'ni istalgan joydan o'zgartirish mumkin: $backend->maosh = -500; ham ishlaydi. Bu xavfli: obyekt o'z ma'lumotini himoya qilmayapti.

Keyingi dars shuni yechadi: private, protected — «bu ichki ish, tashqaridan tegilmaydi». Shu bilan birga static, const va PHP 8 ning ancha qisqa yozuv usulini ko'ramiz — Laravel kodida aynan o'sha qisqa shakl ishlatiladi.
