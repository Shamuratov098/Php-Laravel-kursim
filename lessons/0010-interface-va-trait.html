DARS 10 · MODUL A — POYDEVOR

interface va trait: shartnoma va qayta ishlatish

Bu darsdan keyin klasslarni bir-biriga bog'lamasdan almashtiriladigan qilasiz. Bu kursning eng muhim g'oyalaridan biri: kod aniq klassga emas, shartnomaga tayanadi. Laravel'ning butun ichki tuzilishi shu ustiga qurilgan.

📱 O'qish ≈ 9 daqiqa 💻 Amaliyot ≈ 12 daqiqa Kerak: Dars 09

Bu darsda nimalar bor
  1. interface — shartnoma «Bu metodlar bo'lishi shart» degan e'lon, tanasiz.
  2. Kod shartnomaga tayanadi Klassga emas, interfeysga tayanish nimani ochadi.
  3. Bir nechta shartnoma Bitta klass bir necha interfeysni bajarishi mumkin.
  4. trait Qayta ishlatiladigan kod bo'lagi — merossiz.
  5. Qaysi birini qachon interface — nima qilishi, trait — qanday qilishi.
  6. Tuzoq: ustuvorlik tartibi O'z klassi > trait > ota klass.
Nega bu muhim

9-darsda merosning cheklovini aytgandim: PHP'da klass faqat bitta otadan meros oladi. Va yana bir muammo bor — meros klasslarni qattiq bog'laydi: EmailXabar majburan Xabar ning avlodi bo'lishi kerak.

Lekin ba'zan bunday oila kerak emas. Masalan xabar yuborish uchun uchta butunlay bog'liq bo'lmagan kanal bo'lishi mumkin — email kutubxonasi, Telegram API, SMS provayder. Ularni bitta ota ostiga majburan tiqishtirish noto'g'ri. Kerak bo'lgani faqat bitta narsa: ularning hammasi «yuborish»ni bilsin.

Aynan shu — interface. Va bu Laravel'da eng ko'p uchraydigan naqsh: kodingiz «qaysi klass?» degan savolga emas, «nima qila oladi?» degan savolga tayanadi.

interface — shartnoma

tushuncha
interface Yuboruvchi { public function yubor(string $matn): string; // faqat IMZO, tanasi yo'q } class EmailKanal implements Yuboruvchi { public function yubor(string $matn): string { return "EMAIL: {$matn}"; } } class TelegramKanal implements Yuboruvchi { public function yubor(string $matn): string { return "TELEGRAM: {$matn}"; } }

interface — bu ro'yxat: «bu shartnomani qabul qilgan klass mana shu metodlarni albatta yozadi». Ichida kod yo'q, faqat imzolar. implements — «men shu shartnomani qabul qilaman».

EmailKanal va TelegramKanal bir-biriga hech qanday aloqasi yo'q — umumiy otasi yo'q. Lekin ikkalasi ham Yuboruvchi.

Shartnoma buzilsa — 9-darsdagi aynan o'sha xato
PHP Fatal error: Class SmsKanal contains 1 abstract method and must therefore be declared abstract or implement the remaining methods (Yuboruvchi::yubor)

Xabar abstract so'zini ishlatdi — chunki interface aslida hammasi abstract bo'lgan klassga o'xshaydi. Farqi: interface'da hech qanday kod bo'lmaydi, va klass bir nechta interface'ni qabul qila oladi (otasi esa faqat bitta).

Asosiy foyda: kod shartnomaga tayanadi

tushuncha
function xabarBer(Yuboruvchi $kanal, string $matn): void { echo $kanal->yubor($matn); } xabarBer(new EmailKanal(), $matn); // ishlaydi xabarBer(new TelegramKanal(), $matn); // ham ishlaydi

Diqqat qiling: xabarBer funksiyasi EmailKanal haqida hech narsa bilmaydi. U faqat «menga yubor() ni biladigan narsa bering» deydi. Natijasi:

  • Yangi kanal qo'shsangiz — xabarBer ga tegmaysiz.
  • Testda haqiqiy email jo'natmaslik uchun soxta kanal yozib berishingiz mumkin — u ham Yuboruvchi bo'lsa yetadi. (E modulida aynan shuni qilamiz.)
  • Kod bo'laklari bir-biridan ajratilgan bo'ladi.
Bu Laravel'ni tushunishning kaliti

Laravel ichida yuzlab interface bor (u yerda ular contract deb ataladi). Masalan cache, mail, queue — hammasi interface orqali ishlatiladi, shuning uchun drayverni .env da bitta so'z bilan almashtirish mumkin: kod Redis yoki fayl haqida bilmaydi, u faqat shartnomani biladi. 15-darsda o'z container'ingizni yozganda, shu g'oya bilan yana uchrashasiz.

Bir nechta shartnoma

tushuncha
class Kanal implements Yuboruvchi, Loglanadigan { // ikkala shartnomaning metodlarini ham yozishi shart }

Bu merosda mumkin emas — extends faqat bitta. Interface esa xohlagancha.

trait — qayta ishlatiladigan kod bo'lagi

Interface «nima qila olishini» aytadi, lekin kod bermaydi. Ba'zan esa aynan kod kerak bo'ladi — va u bir-biriga bog'lanmagan bir necha klassga bir xil kerak.

tushuncha
trait Loglaydi { public function log(string $xabar): string { return "[" . static::class . "] {$xabar}"; } } class SmsKanal { use Loglaydi; // kod shu yerga KO'CHIRILADI } class Vakansiya { use Loglaydi; // bu klassga ham }

trait — «kodni PHP o'zi ko'chirib qo'yadigan» bo'lak. use Loglaydi; yozsangiz, o'sha metodlar klass ichiga ko'chiriladi — go'yo siz ularni qo'lda yozgan kabi.

static::class — «hozir men qaysi klass ichidaman» degan javob. Natija:

[SmsKanal] xabar yuborildi [Vakansiya] vakansiya saqlandi

Bitta trait, ikki xil klass nomi — chunki kod har klassga alohida ko'chirilgan. SmsKanal va Vakansiya o'zaro hech qanday aloqada emas.

Qaysi birini qachon?

Amaliy qoida: tip kerak bo'lsa — interface. Takrorlanadigan kodni yo'qotish kerak bo'lsa — trait. Ko'pincha ikkalasi birga ishlatiladi: interface shartnomani belgilaydi, trait esa uning standart bajarilishini beradi.

trait ni ko'p ishlatmang

trait qulay, lekin u kodni yashiradi: klassga qarab «bu metod qayerdan keldi?» deb tushunish qiyinlashadi. Va trait o'zi tip bermaydi, ya'ni function f(Loglaydi $x) deb yozib bo'lmaydi. Shuning uchun avval interface va oddiy klasslar bilan yechishga urinib ko'ring; trait — takrorlanish chindan bezor qilganda ishlatiladigan asbob.

💻 Amaliy qism kompyuterda

Amaliyotda 23-interface.php da Yuboruvchi shartnomasini va unga mos ikkita bog'liq bo'lmagan kanalni yozasiz, hamda shartnomaga tayanadigan funksiyani sinaysiz. 24-trait.php da esa bitta trait'ni ikki xil klassga ulaysiz. Oxirida shartnomani buzib, PHP nima deyishini ko'rasiz.

Amaliyot

  1. Papkaga o'ting

    cd ~/Projects/Learn/php-poydevor

    Kutilgan natija: jimlik.

  2. Shartnoma va ikkita mustaqil kanalni yozing

    Diqqat: ikki klassning umumiy otasi yo'q — ular faqat bir xil shartnomani qabul qilgan.

    cat > 23-interface.php <<'EOF' <?php declare(strict_types=1); interface Yuboruvchi { public function yubor(string $matn): string; } class EmailKanal implements Yuboruvchi { public function yubor(string $matn): string { return "EMAIL: {$matn}"; } } class TelegramKanal implements Yuboruvchi { public function yubor(string $matn): string { return "TELEGRAM: {$matn}"; } } function xabarBer(Yuboruvchi $kanal, string $matn): void { echo $kanal->yubor($matn), PHP_EOL; } $matn = "Arizangiz qabul qilindi"; xabarBer(new EmailKanal(), $matn); xabarBer(new TelegramKanal(), $matn); EOF php 23-interface.php EMAIL: Arizangiz qabul qilindi TELEGRAM: Arizangiz qabul qilindi

    Kutilgan natija: ikki qator. Muhimi: xabarBer ikkala klass haqida hech narsa bilmaydi — u faqat Yuboruvchi ni biladi.
    O'zingiz sinab ko'ring: uchinchi kanal (SmsKanal) qo'shib, xabarBer ga tegmasdan uni ishlatib ko'ring.

  3. Shartnomani buzib ko'ring

    PHP majburlashini tasdiqlash — va 9-darsdagi xato bilan solishtirish.

    php -r 'require "23-interface.php"; class SmsKanal implements Yuboruvchi {}' 2>&1 | tail -1 PHP Fatal error: Class SmsKanal contains 1 abstract method and must therefore be declared abstract or implement the remaining methods (Yuboruvchi::yubor) in Command line code on line 1

    Kutilgan natija: 9-darsdagi aynan o'sha xato — «contains 1 abstract method». Chunki interface metodlari ham abstract.
    Eslatma: 23-interface.php ichida echo bor, shuning uchun tail -1 bilan faqat oxirgi qatorni oldik.

  4. Trait yozing va ikki xil klassga ulang

    Ikki klass o'zaro bog'liq emas, lekin bir xil kodni oldi.

    cat > 24-trait.php <<'EOF' <?php declare(strict_types=1); trait Loglaydi { public function log(string $xabar): string { return "[" . static::class . "] {$xabar}"; } } class SmsKanal { use Loglaydi; } class Vakansiya { use Loglaydi; } echo (new SmsKanal())->log("xabar yuborildi"), PHP_EOL; echo (new Vakansiya())->log("vakansiya saqlandi"), PHP_EOL; EOF php 24-trait.php [SmsKanal] xabar yuborildi [Vakansiya] vakansiya saqlandi

    Kutilgan natija: qavs ichidagi nom har xil — chunki kod har klassga alohida ko'chirilgan va static::class o'sha klassning nomini beradi.
    (new SmsKanal())->log(...) — obyektni o'zgaruvchiga solmasdan darhol ishlatish usuli.

  5. Ishni saqlang

    git add -A git commit -m "10-dars: interface va trait"

    Kutilgan natija: commit haqida xabar.

Sinab ko'ramiz

Natijani taxmin qiling

Bitta metod nomi uch joyda bor: ota klassda, trait'da va (B klassida) o'zida. Qaysi biri yutadi?

taxmin.php
<?php class Ota { public function kim(): string { return "OTA"; } } trait Xususiyat { public function kim(): string { return "TRAIT"; } } class A extends Ota { use Xususiyat; } class B extends Ota { use Xususiyat; public function kim(): string { return "O'ZI"; } } echo (new A())->kim(), PHP_EOL; echo (new B())->kim(), PHP_EOL;
Javobni ko'rish
TRAIT O'ZI

Ustunlik tartibi shunday:

o'z klassi > trait > ota klass
  • A da o'z metodi yo'q → trait yutadi, otani yengib o'tadi. Ko'pchilik buni kutmaydi.
  • B da o'z metodi bor → o'zi yutadi, trait ham, ota ham chetda qoladi.

Nega trait otani yengadi? Chunki trait kodi klass ichiga ko'chiriladi — go'yo siz uni o'z qo'lingiz bilan yozgan kabi. Ota klass esa undan bir bosqich yuqorida turadi, va PHP har doim eng yaqin metodni oladi.

Amaliy xulosa: trait qo'shganingizda u ota klassdagi xatti-harakatni jimgina almashtirib qo'yishi mumkin — va kodga qarab buni sezish qiyin. Aynan shu sababdan trait'ni ehtiyot bilan ishlatish kerak.

SAVOL 1 interface ichida nima bo'ladi?

Interface — shartnoma: nima qilinishi kerakligini aytadi, qanday qilinishini emas. Kod beradigan narsa — trait yoki oddiy klass.

SAVOL 2 function f(Yuboruvchi $x) deb yozishning foydasi nima?

Funksiya aniq klassga emas, shartnomaga bog'lanadi. Shuning uchun yangi kanal qo'shilsa funksiyaga tegilmaydi, va testda soxta kanal berish mumkin.

SAVOL 3 trait ni tip sifatida ishlatish mumkinmi?

trait faqat kod beradi, tip bermaydi — function f(Loglaydi $x) deb yozib bo'lmaydi. Tip kerak bo'lsa interface ishlatiladi.

Eslab ayting

Avval o'zingiz javob bering, keyin ochib tekshiring. Oxirgi ikkitasi — 9-darsni takrorlash.

interface va trait — bir gapda farqi?

interface — «nima qila oladi» (shartnoma, kod yo'q, tip beradi). trait — «qanday qiladi» (kod bor, tip bermaydi).

Nega shartnomaga tayanish yaxshi?

Chunki kod aniq klassdan ajratiladi: yangi klass qo'shilsa funksiyaga tegilmaydi, testda soxta obyekt berish mumkin, va drayverni almashtirish oson bo'ladi (Laravel'da cache/mail/queue shunday).

Metod uch joyda bo'lsa (o'zi, trait, ota) — qaysi yutadi?

o'z klassi > trait > ota klass. Trait otani yengadi, chunki uning kodi klass ichiga ko'chiriladi.

↩︎ Takrorlash: abstract metod nima?

Tanasi yo'q, faqat imzo — «avlod buni o'zi yozishi shart». Interface metodlari ham aslida shunday, shuning uchun xato xabari ham bir xil.

↩︎ Takrorlash: avlodda konstruktor yozsangiz nimani unutmaslik kerak?

parent::__construct(...) ni chaqirishni. Aks holda otaning xossalari qiymatsiz qoladi va keyinroq Typed property ... must not be accessed before initialization chiqadi.

Cho'ntak xulosasi
  • interface — shartnoma: faqat imzolar, kod yo'q. implements bilan qabul qilinadi, bir nechtasi mumkin.
  • 🔑 Kod aniq klassga emas, shartnomaga tayansin — f(Yuboruvchi $x). Laravel'da bu «contract» deb ataladi.
  • Shartnoma buzilsa — contains 1 abstract method xatosi (abstract bilan bir xil).
  • trait — kodni klass ichiga ko'chiradi. use bilan ulanadi, tip bermaydi.
  • Ustunlik: o'z klassi > trait > ota klass.
  • Tip kerak → interface. Takrorlanadigan kod → trait. Ehtiyot bo'ling: trait kodni yashiradi.
🌱 Kelasi darslar uchun urug'

Fayllaringiz ko'payib boryapti: 21-xabar.php, 23-interface.php, 24-trait.php... va har birini require qilib yurish kerak. Klasslar 50 taga chiqsa nima bo'ladi? Bundan tashqari ikki xil kutubxonada bir xil nomli klass bo'lsa — to'qnashuv chiqadi.

12-dars ikkisini ham yechadi: namespace (nomlarni ajratish) va Composer bilan autoload — «kerak bo'lgan klassni PHP o'zi topib oladi». require yozish tugaydi. Va shu bilan composer — Laravel o'rnatiladigan asbob — qo'lingizga o'tadi.
