DARS 45 · MODUL F — API QATLAMI

apiResource: to'liq CRUD

API himoyalangan, javob shakli boshqariladi — lekin unda atigi uchta amal bor. Tahrirlash va o'chirish yo'q, marshrutlarni esa qo'lda bittalab yozyapmiz. Bugun Route::apiResource bilan beshtasini bir qatorda beramiz va yangi status bilan tanishamiz — 204 No Content.

📱 O'qish ≈ 16 daqiqa 💻 Amaliyot ≈ 26 daqiqa Kerak: Dars 44

Bu darsda nimalar bor
  1. apiResource va resource Beshta marshrut va yettita — farqi create/edit sahifalarida. O'lchandi.
  2. make:controller --api Aynan beshta metodli skelet: index · store · show · update · destroy.
  3. Route model binding string $id o'rniga Vakansiya $vakansiya — findOrFail ham kerak emas.
  4. ⚠️ O'zbekcha nom tuzog'i — uchinchi marta Parametr {vakansiyalar} bo'lib chiqadi va binding jimgina buziladi: 200, lekin ma'lumot null.
  5. ->parameters([...]) Bir qatorli yechim va nega u majburiy.
  6. ⚠️ Marshrut nomlari to'qnashuvi Darsning eng qimmat topilmasi: route('vakansiyalar.index') jimgina /api/... ga o'tib ketdi va web testlari buzildi.
  7. ->names('api.vakansiyalar') Yechim va 42-darsdagi tavsiyaning isboti.
  8. update — PUT va PATCH Ikkalasi bir metodga tushadi. Farqi ma'noda, kodda emas.
  9. destroy → 204 No Content response()->noContent() — javob tanasi butunlay bo'sh (0 bayt, o'lchandi).
  10. Form Request qayta ishlatiladi 35-darsdagi VakansiyaRequest store da ham, update da ham — va u policy'ni ham chaqiradi.
  11. only() va guruhlar Ochiq amallar (o'qish) va himoyalanganlari (yozish) alohida guruhda.
  12. Har xil holatlar (7 ta) Parametr nomi · nom to'qnashuvi · --api · 204 va tana · PUT/PATCH · only/except · 404 tartibi.
Uch amal — va qo'lda yozilgan marshrutlar

44-darsdan keyin routes/api.php shunday edi:

Route::get('/vakansiyalar', [VakansiyaController::class, 'index']); Route::get('/vakansiyalar/{id}', [VakansiyaController::class, 'show']); Route::post('/vakansiyalar', [VakansiyaController::class, 'store']);

Ikki muammo bor:

1) Tahrirlash va o'chirish YO'Q → API to'liq emas 2) Har marshrut qo'lda → nom, manzil, metod — hammasi qo'lda

Ikkinchisi 24-darsdagi Route::resource bilan hal qilingan edi. API uchun uning ukasi bor — apiResource.1

apiResource — besh marshrut bir qatorda

Route::apiResource('vakansiyalar', VakansiyaController::class);

O'lchangan natija:

GET|HEAD api/vakansiyalar vakansiyalar.index @index POST api/vakansiyalar vakansiyalar.store @store GET|HEAD api/vakansiyalar/{...} vakansiyalar.show @show PUT|PATCH api/vakansiyalar/{...} vakansiyalar.update @update DELETE api/vakansiyalar/{...} vakansiyalar.destroy @destroy Showing [5] routes

Endi Route::resource bilan solishtiring — xuddi shu chaqiruv web tomonda:

GET|HEAD sinov-web/create sinov-web.create ← QO'SHIMCHA GET|HEAD sinov-web/{...}/edit sinov-web.edit ← QO'SHIMCHA Showing [7] routes

🔑 Farq ikkita marshrutda: create va edit. Ular HTML forma sahifalari — «yangi vakansiya qo'shish» va «tahrirlash» oynalari. API'da forma yo'q, shuning uchun ular ham kerak emas.

Controller skeletini ham shunga moslab yasash mumkin:

php artisan make:controller Api/SinovController --api public function index() public function store(Request $request) public function show(string $id) public function update(Request $request, string $id) public function destroy(string $id)

Route model binding

Shu paytgacha show shunday edi:

public function show(string $id) { $vakansiya = Vakansiya::with('kompaniya')->findOrFail($id); ... }

Laravel buni o'zi qila oladi — tip belgisiga qarab:

public function show(Vakansiya $vakansiya) { return VakansiyaResource::make($vakansiya->load('kompaniya')); }

Sehr yo'q: Laravel marshrut parametrining nomini ({vakansiya}) metod argumentining nomi bilan solishtiradi. Mos kelsa — o'sha id bo'yicha modelni topadi, topolmasa 404 beradi.

⚠️ O'zbekcha nom tuzog'i — uchinchi marta

apiResource('vakansiyalar', ...) parametr nomini resurs nomidan yasaydi. Ingliz tilida jobs → {job} (birlikka o'giriladi). O'zbekchada esa:

Route::apiResource('vakansiyalar', ...) api/vakansiyalar/{vakansiyalar} ← ⚠️ KO'PLIKDA qoldi

Metod argumenti esa $vakansiya — nomlar mos kelmaydi, binding ishlamaydi. Va eng yomoni, xato chiqmaydi:

GET /api/vakansiyalar/5 status : 200 ← xato yo'qdek data.nom : NULL ← ⚠️ model bog'lanmagan PUT /api/vakansiyalar/5 status : 500 "Attempt to read property \"id\" on null"

show 200 qaytardi — chunki resource null ni o'radi. Mijoz «ma'lumot yo'q» deb o'ylaydi, siz esa bazani tekshira boshlaysiz.

✅ Yechim bir qator:

Route::apiResource('vakansiyalar', VakansiyaController::class) ->parameters(['vakansiyalar' => 'vakansiya']); api/vakansiyalar/{vakansiya} ← ✅ endi mos

🔑 Bu ADR 0004 qoidasining uchinchi ko'rinishi. Naqsh har safar bir xil: Laravel ko'plik yasagan joyda o'zbekcha nom taxminga tushmaydi.

$table → qo'lda yozildi (25-dars) factory has() → nom aniq berildi (39-dars) apiResource → parameters() bilan (45-dars)
⚠️ Marshrut nomlari to'qnashuvi

Binding tuzatilgach testlarni ishga tushirdik — va beshta web testi qizardi:

⨯ nomzod ro'yxatdan o'tadi va darhol kiradi ⨯ to'g'ri parol bilan kiriladi ⨯ chiqilgandan keyin mehmon bo'ladi ⨯ ish beruvchi vakansiya qo'sha oladi Failed asserting that two strings are equal.

API'ga tegishli hech nima o'zgarmagan edi. Sabab boshqa joyda:

route('vakansiyalar.index') → /api/vakansiyalar ⚠️ route('vakansiyalar.store') → /api/vakansiyalar ⚠️

apiResource marshrutlarga nom ham beradi: vakansiyalar.index, vakansiyalar.store… Va bu nomlar routes/web.php dagi nomlar bilan aynan bir xil.

Bir nom ikki marta ro'yxatdan o'tsa, oxirgisi g'olib chiqadi. API fayli keyin yuklangani uchun redirect()->route('vakansiyalar.index') endi API manziliga yo'naltirardi.

✅ Yechim — nomlarni ajratish:

Route::apiResource('vakansiyalar', VakansiyaController::class) ->parameters(['vakansiyalar' => 'vakansiya']) ->names('api.vakansiyalar'); route('vakansiyalar.index') → /vakansiyalar ✅ route('api.vakansiyalar.index') → /api/vakansiyalar ✅

🔑 42-darsda «nomlash uchun guruh ishlatish qulay» deb aytilgan edi. Endi u tavsiya emas, majburiyat: aks holda web ilovangiz jimgina buziladi.

🔍 Va yana bir saboq: testlar API o'zgarishini web tomonda tutdi. Testsiz bu xatoni foydalanuvchi topardi — «qo'shish tugmasi JSON qaytaryapti» degan shaklda.

To'liq CRUD controlleri

app/Http/Controllers/Api/VakansiyaController.php use App\Http\Requests\VakansiyaRequest; use App\Http\Resources\VakansiyaResource; use App\Models\Vakansiya; class VakansiyaController extends Controller { public function index() { $vakansiyalar = Vakansiya::query()->with('kompaniya')->latest('id')->take(10)->get(); return VakansiyaResource::collection($vakansiyalar); } public function show(Vakansiya $vakansiya) { return VakansiyaResource::make($vakansiya->load('kompaniya')); } public function store(VakansiyaRequest $request) { $vakansiya = Vakansiya::create( $request->validated() + ['user_id' => $request->user()->id] ); return VakansiyaResource::make($vakansiya->fresh()) ->response() ->setStatusCode(201); } public function update(VakansiyaRequest $request, Vakansiya $vakansiya) { $vakansiya->update($request->validated()); return VakansiyaResource::make($vakansiya->fresh()); } public function destroy(Request $request, Vakansiya $vakansiya) { $this->authorize('delete', $vakansiya); $vakansiya->delete(); return response()->noContent(); } }

update() ga alohida qarang — u uch qator. Validatsiya ham, huquq tekshiruvi ham yo'q. Ikkalasi ham VakansiyaRequest ichida.

35-darsdagi Form Request qayta ishlaydi

VakansiyaRequest ni eslang:

public function authorize(): bool { $user = $this->user(); if ($user === null) { return false; } $vakansiya = $this->route('vakansiya'); // ← shu yerda ish beradi return $vakansiya ? $user->can('update', $vakansiya) // tahrirlash : $user->can('create', Vakansiya::class); // yaratish }

35-darsda uni web controlleri uchun yozgan edik. Endi u API da ham ishlaydi — bitta qator o'zgartirmasdan.

Farq faqat javob shaklida, va uni Laravel Accept sarlavhasiga qarab o'zi tanlaydi:

web: validatsiya xatosi → 302 + $errors API: validatsiya xatosi → 422 + {"message":..., "errors":{...}} web: authorize() false → 403 sahifa API: authorize() false → 403 {"message":"This action is unauthorized."}

🔑 $this->route('vakansiya') ishlashi uchun parametr nomi aynan vakansiya bo'lishi kerak — yuqoridagi parameters() tuzatishi shu yerda ham asqotdi.

Marshrutlar: ochiq va himoyalangan

routes/api.php Route::apiResource('vakansiyalar', VakansiyaController::class) ->parameters(['vakansiyalar' => 'vakansiya']) ->names('api.vakansiyalar') ->only(['index', 'show']); // o'qish — ochiq Route::middleware('auth:sanctum')->group(function () { Route::apiResource('vakansiyalar', VakansiyaController::class) ->parameters(['vakansiyalar' => 'vakansiya']) ->names('api.vakansiyalar') ->only(['store', 'update', 'destroy']) // yozish — token bilan ->middleware('abilities:vakansiya:yozish'); Route::delete('/token', [TokenController::class, 'ochir']); Route::get('/user', fn (Request $request) => $request->user()); });

only([...]) — «faqat shu amallarni yasa». Teskarisi ham bor: except([...]).

🔍 Bir resursni ikki marta e'lon qilish g'alati ko'rinishi mumkin, lekin bu oddiy naqsh: o'qish hammaga ochiq, yozish esa token va huquq talab qiladi. 44-darsdagi abilities ham shu guruhga tegishli.

update: PUT va PATCH

PUT|PATCH api/vakansiyalar/{vakansiya} → update()

Ikkala fe'l bitta metodga tushadi. Farqi kodda emas, ma'noda:

PUT → yozuvni TO'LIQ almashtirish («mana yangi holati») PATCH → faqat berilgan maydonlarni yangilash («shu ikkitasini o'zgartir»)

O'lchangan: ikkalasi ham 200 qaytardi va yangilangan obyektni berdi. Amalda ko'p loyihalar ikkalasini ham bir xil ishlatadi — lekin fe'lni to'g'ri tanlash mijozga nima kutishini aytadi.

PUT /api/vakansiyalar/5 → 200 data.nom = "Yangilangan nom" PATCH /api/vakansiyalar/5 → 200 data.nom = "PATCH bilan nom"

destroy: 204 No Content

return response()->noContent();

O'lchangan:

DELETE /api/vakansiyalar/5 status : 204 javob tanasi uzunligi : 0 bayt

204 No Content — «ish bajarildi, qaytaradigan narsa yo'q». O'chirilgan yozuvni qaytarish mantiqsiz bo'lardi: u endi yo'q.

200 → ish bajarildi, mana natija 201 → yangi narsa yaratildi, mana u 204 → ish bajarildi, tana BO'SH

⚠️ 204 javobda tana bo'lmagani uchun mijoz response.json() qilsa xato oladi. To'g'ri kod avval statusni tekshiradi:

if (r.status === 204) { /* muvaffaqiyat, o'qiydigan narsa yo'q */ }

Har xil holatlar

Yetti holat. Bu bo'lim ma'lumotnoma — hozir bir marta o'qib chiqing, keyin kerak bo'lganda qaytib qarang.

HOLAT 1

Parametr nomi ko'plikda qolishi

api/vakansiyalar/{vakansiyalar} ⚠️ public function show(Vakansiya $vakansiya) ← nom mos emas GET → 200, lekin data NULL PUT → 500, "Attempt to read property \"id\" on null"

Eng xavfli tomoni — show 200 qaytaradi. Xato yo'qdek ko'rinadi, mijoz esa bo'sh ma'lumot oladi.

✅ ->parameters(['vakansiyalar' => 'vakansiya']).

🔍 Tashxis: php artisan route:list --path=api va parametr nomiga qarang. U metod argumentining nomi bilan aynan mos bo'lishi kerak.

HOLAT 2

Marshrut nomlari to'qnashuvi

route('vakansiyalar.index') → /api/vakansiyalar ⚠️ web emas!

Bir nom ikki marta ro'yxatdan o'tsa oxirgisi g'olib. api.php keyin yuklanadi — demak API g'olib chiqadi va web ilovangiz jimgina buziladi.

✅ ->names('api.vakansiyalar') yoki butun faylni Route::name('api.')->group(...) ichiga oling.

🔍 Tashxis: php artisan route:list --name=vakansiyalar — bir xil nom ikki marta chiqsa, muammo shu.
🔑 Bu xatoni web testlari tutdi, API testlari emas.

HOLAT 3

--api bayrog'i

make:controller X → bo'sh klass make:controller X --api → index, store, show, update, destroy make:controller X --resource → + create, edit (web uchun)

Skelet metodlarning nomini to'g'ri yozib beradi — va bu muhim: apiResource aynan shu nomlarni qidiradi.

⚠️ Metod nomini o'zgartirsangiz (masalan ochirish), apiResource uni topolmaydi — 33-darsdagi policy metod nomlari bilan bir xil kelishuv.

HOLAT 4

204 va bo'sh tana

status: 204 tana: 0 bayt // mijoz tomonda: const d = await r.json(); ⚠️ xato — o'qiydigan narsa yo'q if (r.status === 204) { ... } ✅

204 «muvaffaqiyat, lekin qaytaradigan narsa yo'q» degani.

🔍 Muqobil yondashuv ham bor: 200 qaytarib {"xabar": "O'chirildi"} berish. Ikkalasi ham to'g'ri — muhimi bir xil qilish va hujjatda yozish.

✅ assertNoContent() — testda 204 ni tekshirishning qisqa yo'li.

HOLAT 5

PUT va PATCH farqi

PUT|PATCH → ikkalasi ham update() ga tushadi

Laravel farq qilmaydi. Farq ma'noda: PUT — to'liq almashtirish, PATCH — qisman yangilash.

⚠️ Bizning VakansiyaRequest da nom va maosh ikkalasi ham required. Ya'ni amalda bizda faqat PUT mantiqi ishlaydi: PATCH yuborsangiz ham hamma maydonni berishingiz kerak.

✅ Haqiqiy PATCH kerak bo'lsa, qoidalarni sometimes bilan yumshating yoki alohida Form Request yozing.

HOLAT 6

only() va except()

->only(['index', 'show']) → faqat shu ikkitasi ->except(['destroy']) → o'chirishdan tashqari hammasi

Bir resursni ikki marta e'lon qilish normal: bir qismi ochiq, boshqasi himoyalangan.

⚠️ Ikkala e'londa ham parameters() va names() ni takrorlash kerak — ular guruhga emas, e'lonning o'ziga tegishli.

🔍 Shu takrorlanishdan qochish uchun ba'zilar hammasini bitta apiResource qilib, himoyani controller ichida (authorize) qo'yadi. Ikkala uslub ham uchraydi.

HOLAT 7

404 qachon chiqadi

GET /api/vakansiyalar/999999 → 404 PUT /api/vakansiyalar/999999 → 404 DELETE /api/vakansiyalar/999999 → 404

Route model binding modelni topolmasa 404 beradi — controller metodi umuman ishlamaydi.

🔑 Muhim tartib: 401 (token) → 403 (huquq) → 404 (yozuv) → 422 (ma'lumot). Tokensiz so'rov mavjud bo'lmagan yozuvga yuborilsa — 401 keladi, 404 emas.

🔍 Bu ataylab: mavjud bo'lmagan yozuv haqida ma'lumot berishdan oldin kim ekaningizni aniqlash kerak. 30-darsdagi user enumeration fikri bilan bir oiladan.

💻 Amaliy qism kompyuterda

Amaliyotda API'ni to'liq CRUD'ga aylantirasiz. Yo'lda ikkita jimgina buziladigan holatni ataylab ko'rasiz: ko'plik parametr (200 lekin bo'sh ma'lumot) va marshrut nomlari to'qnashuvi (web ilova buziladi).

Sinab ko'ramiz

Natijani taxmin qiling

Dasturchi API'ni apiResource ga o'tkazdi va API testlarini ishga tushirdi:

routes/api.php
Route::apiResource('vakansiyalar', VakansiyaController::class) ->parameters(['vakansiyalar' => 'vakansiya']);

U xursand bo'lib commit qildi. Ertasi kuni foydalanuvchi yozdi: «vakansiya qo'shsam, sahifa o'rniga JSON chiqyapti». Nima bo'ldi?

Javobni ko'rish
route('vakansiyalar.index') → /api/vakansiyalar ⚠️ // web controllerdagi: return redirect()->route('vakansiyalar.index'); → API manziliga!

apiResource marshrutlarga nom ham beradi: vakansiyalar.index, vakansiyalar.store… Bu nomlar routes/web.php dagilar bilan aynan bir xil.

⚠️ Bir nom ikki marta ro'yxatdan o'tsa oxirgisi g'olib chiqadi. api.php keyin yuklanadi — demak route() helperi endi API manzilini qaytaradi.

🔑 Nega API testlari tutmadi? Chunki ular API manzillarini to'g'ridan-to'g'ri yozadi ('/api/vakansiyalar'), route() helperini ishlatmaydi. Muammo web tomonda edi.

SAVOL 1 apiResource va resource farqi nimada?

Farq create va edit da — ular HTML forma sahifalari. API'da forma yo'q, shuning uchun ular ham kerak emas. 🔍 make:controller X --api ham aynan beshta metodli skelet beradi.

SAVOL 2 O'zbekcha resurs nomida parametr bilan nima bo'ladi?

{vakansiyalar} bo'lib qoladi va show(Vakansiya $vakansiya) bilan mos kelmaydi. ⚠️ Eng xavflisi — xato chiqmaydi: show 200 qaytaradi, lekin ma'lumot null. ✅ ->parameters(['vakansiyalar' => 'vakansiya']).

SAVOL 3 204 javobi nimani bildiradi?

«Ish bajarildi, qaytaradigan narsa yo'q». O'lchandi: tana 0 bayt. ⚠️ Mijoz r.json() qilsa xato oladi — avval statusni tekshirishi kerak. Testda assertNoContent().

Eslab ayting

Avval o'zingiz javob bering, keyin ochib tekshiring. Oxirgi ikkitasi — 44-darsni takrorlash.

Route model binding qanday ishlaydi?

Laravel marshrut parametrining nomini metod argumentining nomi bilan solishtiradi. Mos kelsa modelni topadi, topolmasa 404. Nomlar mos kelmasa — binding jimgina ishlamaydi.

Nega names() berish majburiy?

apiResource vakansiyalar.index kabi nom beradi va u web.php dagi nom bilan to'qnashadi. Oxirgisi g'olib — route() helperi API manzilini qaytara boshlaydi va web ilova buziladi.

Nega update() uch qator?

Validatsiya ham, huquq tekshiruvi ham 35-darsdagi VakansiyaRequest ichida. U $this->route('vakansiya') orqali yaratish va tahrirlashni ajratadi.

↩︎ Takrorlash: token bazada qanday saqlanadi?

Faqat hash('sha256', $sirli_qism). Ochiq token bazada yo'q — shuning uchun u bir marta ko'rsatiladi.

↩︎ Takrorlash: uchta himoya qatlami qaysilar?

401 Unauthenticated. — token yo'q · 403 Invalid ability provided. — token huquqi · 403 This action is unauthorized. — policy.

Cho'ntak xulosasi
  • Route::apiResource — beshta marshrut, Route::resource — yettita. Farq create/edit forma sahifalarida.
  • make:controller X --api — aynan beshta metodli skelet. ⚠️ Metod nomlari kelishuv, o'zgartirilmaydi.
  • Route model binding: string $id + findOrFail o'rniga Vakansiya $vakansiya. Topilmasa 404.
  • ⚠️ O'zbekcha nom tuzog'i (uchinchi marta): parametr {vakansiyalar} bo'lib qoladi va binding jimgina buziladi — show 200 beradi, ma'lumot esa null.
  • ✅ ->parameters(['vakansiyalar' => 'vakansiya']). Naqsh: $table (25) · factory has() (39) · apiResource (45).
  • ⚠️ Nom to'qnashuvi: apiResource vakansiyalar.index nomini beradi va u web nomi bilan to'qnashadi. Oxirgisi g'olib → route('vakansiyalar.index') API manzilini qaytaradi va web ilova buziladi.
  • ✅ ->names('api.vakansiyalar') yoki Route::name('api.')->group(...).
  • 🔑 Bu xatoni web testlari tutdi. --filter=Api bilan ishlatilganda to'plam yashil ko'rinardi — commit oldidan to'liq to'plam.
  • update: PUT to'liq almashtirish, PATCH qisman. Laravel ikkalasini bir metodga tushiradi; farq ma'noda.
  • ⚠️ Qoidalarda hamma maydon required bo'lsa, amalda faqat PUT mantiqi ishlaydi. Haqiqiy PATCH uchun sometimes.
  • destroy → response()->noContent() → 204, tana 0 bayt (o'lchandi). Testda assertNoContent().
  • Statuslar: 200 mana natija · 201 yaratildi · 204 bajarildi, tana yo'q.
  • 35-darsdagi VakansiyaRequest API'da ham ishlaydi — bitta qator o'zgartirmasdan. Javob shaklini Laravel Accept ga qarab tanlaydi.
  • only([...]) / except([...]) — bir resursni ikki guruhga bo'lish. ⚠️ parameters() va names() har ikkala e'londa takrorlanadi.
  • 🔑 To'siqlar tartibi: 401 token → 403 huquq → 404 yozuv → 422 ma'lumot.
  • Natija: 60 test, 184 tekshiruv — to'liq CRUD API qulflandi.
