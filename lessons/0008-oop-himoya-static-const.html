Nega bu muhim

7-darsda hamma xossani public deb yozdik. Natijasi shu:

$v->maosh = -500; // ishlaydi. Hech kim to'xtatmaydi. echo $v->maosh; // -500

Manfiy maosh — ma'nosiz ma'lumot, lekin obyekt uni qabul qildi. Loyiha o'sganda bunday qiymat bazaga tushadi, hisobotni buzadi, va sababini topish uchun butun kodni qarab chiqishga to'g'ri keladi — chunki uni har qanday joydan o'zgartirish mumkin edi.

Yechim: obyekt o'z ma'lumotini o'zi qo'riqlasin. Tashqaridan faqat siz ruxsat bergan yo'l bilan o'zgartirilsin. Bu enkapsulyatsiya deb ataladi va mid-level dasturchini junior'dan ajratib turadigan asosiy odatlardan biri.

Uch daraja: public, private, protected

Kalit so'zKim ko'ra oladi
publicHamma — klass ichi ham, tashqarisi ham. Standart holat
privateFaqat shu klass ichi. Tashqaridan murojaat — Fatal error
protectedShu klass va undan meros olgan klasslar. Meros — keyingi darsda
Amaliy qoida

Xossalarni private qilib boshlang. Keyin, aniq zarurat bo'lsa, ochasiz. Teskarisi — public dan boshlab keyin yopish — ancha qiyin, chunki kodning boshqa joylari o'sha xossaga bog'lanib qolgan bo'ladi.

private xossaga tashqaridan tegishga urinsangiz:

PHP Fatal error: Uncaught Error: Cannot access private property Vakansiya::$maosh in a.php:19

Bu yaxshi xabar — xato darhol, aniq manzil bilan chiqdi (4-darsdagi ko'nikma ishga tushdi). Aks holda muammo jimgina ichkariga kirib ketardi.

Ma'lumotga qanday murojaat qilinadi?

private qilgandan keyin ham ma'lumot kerak bo'ladi. Buning uchun metod yoziladi — va mana shu joyda kuch bor: metod shart qo'ya oladi.

tushuncha
private int $maosh; public function maosh(): int // o'qish uchun — «getter» { return $this->maosh; } public function maoshniOzgartir(int $yangi): void // yozish uchun — shart bilan { if ($yangi < 0) { return; // rad etadi — obyekt o'zini himoya qildi } $this->maosh = $yangi; }

Endi manfiy maoshni kiritish mumkin emas — qaysi fayldan urinsangiz ham. Qoida bitta joyda, klass ichida yashaydi. Muammo chiqsa, qarash kerak bo'lgan joy ham bitta.

void — yangi qaytish tipi: «bu metod hech narsa qaytarmaydi, faqat ish qiladi».

Har xossaga getter yozish shart emas

Boshlovchilar ko'p qiladigan xato — har bir private xossaga getter va setter yozib chiqish. Bunda hech qanday himoya qolmaydi, faqat kod uzayadi. Faqat tashqariga chindan kerak bo'lganini ochasiz. Ko'p hollarda esa korinish() kabi ma'noli metod yozish yaxshiroq — u ma'lumotni bermaydi, natijani beradi.

PHP 8: qisqa yozuv (constructor property promotion)

7-darsdagi konstruktorni eslang — xossa uch joyda takrorlanadi: e'londa, parametrda, tayinlashda. PHP 8 dan buni bitta joyda yozish mumkin:

eski shakl — 10 qator
class Vakansiya { private string $nom; private int $maosh; public function __construct(string $nom, int $maosh) { $this->nom = $nom; $this->maosh = $maosh; } }
yangi shakl — 4 qator, aynan bir xil natija
class Vakansiya { public function __construct( private string $nom, private int $maosh, ) {} }

Parametr oldiga private (yoki public) yozsangiz, PHP o'zi xossa yaratadi va qiymatni unga soladi. Konstruktor tanasi bo'sh qoladi: {}.

Nega buni bilish shart

Chunki Laravel kodi shu shaklda yozilgan. Har bir controller, service, job konstruktorida shuni ko'rasiz. Tanimasangiz — «xossalar qayerda e'lon qilingan?» deb izlab yurasiz. Endi bilasiz: konstruktor parametrining o'zida.

Diqqat: var_dump himoya darajasini ham ko'rsatadi:

object(Vakansiya)#1 (2) { ["nom":"Vakansiya":private]=> string(17) "Backend dasturchi" ...

const — o'zgarmas qiymat

Ba'zi qiymatlar hech qachon o'zgarmaydi: holat nomlari, soliq foizi, standart limit. Ular uchun const ishlatiladi:

tushuncha
class Vakansiya { public const HOLAT_FAOL = "faol"; public const HOLAT_YOPIQ = "yopiq"; } echo Vakansiya::HOLAT_FAOL; // faol — obyekt YASAMASDAN

Diqqat: -> emas, ::. Sababi oddiy — -> «obyektning», :: esa «klassning» degani. Konstanta obyektga tegishli emas, u klassga tegishli, shuning uchun obyekt yasashning hojati yo'q.

Nega shunchaki "faol" deb yozmaymiz? Chunki:

  • Bir joyda "faol", boshqa joyda "Faol" deb yozib qo'yish mumkin — va bu xato jimgina ishlamaydi (3-darsdagi === ni eslang).
  • Vakansiya::HOLAT_FOAL deb adashsangiz, PHP darhol xato beradi — bunday konstanta yo'q.
  • Nomni o'zgartirish kerak bo'lsa — bitta joyda o'zgartiriladi.

const ni o'zgartirishga urinsangiz kod umuman ishga tushmaydi:

PHP Parse error: syntax error, unexpected token "="

Ya'ni bu Parse error — 4-darsni eslang, bajarish bosqichi boshlanmaydi ham.

static — obyektga emas, klassga tegishli

Odatdagi xossa har obyektda alohida bo'ladi. static xossa esa butun klass uchun bitta — barcha obyektlar uni bo'lishadi:

tushuncha
private static int $soni = 0; // hamma obyekt uchun BITTA public function __construct(...) { self::$soni++; // har yasalganda oshadi } public static function soni(): int { return self::$soni; } echo Vakansiya::soni(); // 2

self:: — «shu klassning o'zi». $this-> obyektga, self:: klassga murojaat qiladi. static metod ichida $this mavjud emas — chunki u hech qanday obyektga bog'lanmagan.

static ni ehtiyot bilan ishlatish

static — qulay, lekin global holat yaratadi: qiymat butun dastur bo'ylab bitta. Bu testlashni qiyinlashtiradi (bir test qoldirgan qiymat keyingisiga ta'sir qiladi) va bog'liqlikni yashiradi. Shuning uchun professional kodda static kamdan-kam ishlatiladi — asosan yordamchi funksiyalar va fabrika metodlari uchun. Laravel'dagi Vakansiya::where(...) kabi yozuvlar static ga o'xshaydi, lekin ular boshqa mexanizm — unga G modulida (facade) qaytamiz.

💻 Amaliy qism kompyuterda

Amaliyotda ikkita fayl yozasiz: 19-himoya.php (private + qisqa konstruktor; manfiy maoshni obyekt o'zi rad etadi) va 20-const-static.php (const va static — yasalgan obyektlarni sanaydi). Oxirida private xossaga tashqaridan tegib, Fatal error ni chiqarasiz — himoya ishlayotganini isbotlaysiz.

Amaliyot

  1. Papkaga o'ting

    Kutilgan natija: jimlik.

  2. Himoyalangan klass yozing — qisqa shaklda

    Bir vaqtda ikki narsa: private himoya va PHP 8 ning qisqa konstruktori.

    cat > 19-himoya.php <<'EOF' <?php declare(strict_types=1); class Vakansiya { public function __construct( private string $nom, private int $maosh, ) {} public function maoshniOzgartir(int $yangi): void { if ($yangi < 0) { echo "[rad etildi: maosh manfiy bo'lolmaydi]", PHP_EOL; return; } $this->maosh = $yangi; } public function korinish(): string { return "{$this->nom} — {$this->maosh} $"; } } $v = new Vakansiya("Backend dasturchi", 800); echo $v->korinish(), PHP_EOL; $v->maoshniOzgartir(-500); echo $v->korinish(), PHP_EOL; $v->maoshniOzgartir(900); echo $v->korinish(), PHP_EOL; EOF php 19-himoya.php Backend dasturchi — 800 $ [rad etildi: maosh manfiy bo'lolmaydi] Backend dasturchi — 800 $ Backend dasturchi — 900 $

    Kutilgan natija: manfiy qiymat rad etildi va maosh 800 da qoldi; to'g'ri qiymat esa qabul qilindi. Xossalar qayerda e'lon qilinganini ko'ryapsizmi? — konstruktor parametrining o'zida.

  3. private himoyasini sinab ko'ring

    Himoya chindan ishlayotganini isbotlash. Va 4-darsdagi ko'nikma — xato xabarini o'qish.

    php -r 'class V { private int $maosh = 800; } $x = new V(); echo $x->maosh;' PHP Fatal error: Uncaught Error: Cannot access private property V::$maosh in Command line code:1

    Kutilgan natija: Fatal error — «private xossaga murojaat qilib bo'lmaydi». Ya'ni himoya chindan ishlaydi.
    Bu yerda kichik V klassi ishlatildi — shunda chiqish toza bo'ladi va faqat xato ko'rinadi.

  4. const va static ni yozing

    cat > 20-const-static.php <<'EOF' <?php declare(strict_types=1); class Vakansiya { public const HOLAT_FAOL = "faol"; public const HOLAT_YOPIQ = "yopiq"; private static int $soni = 0; public function __construct( private string $nom, private string $holat = self::HOLAT_FAOL, ) { self::$soni++; } public static function soni(): int { return self::$soni; } public function korinish(): string { return "{$this->nom} [{$this->holat}]"; } } echo Vakansiya::HOLAT_FAOL, PHP_EOL; $a = new Vakansiya("Backend dasturchi"); $b = new Vakansiya("Frontend dasturchi", Vakansiya::HOLAT_YOPIQ); echo $a->korinish(), PHP_EOL; echo $b->korinish(), PHP_EOL; echo "Yasalgan obyektlar: ", Vakansiya::soni(), PHP_EOL; EOF php 20-const-static.php faol Backend dasturchi [faol] Frontend dasturchi [yopiq] Yasalgan obyektlar: 2

    Kutilgan natija: to'rt qator. Diqqat: Vakansiya::HOLAT_FAOL obyekt yasamasdan ishladi (birinchi qator), va soni() ikkita obyektni sanadi — static xossa ikkisi uchun bitta.

Har xil holatlar

Yetti holat. Bu bo'lim ma'lumotnoma — hozir bir marta o'qing, keyin kerak bo'lganda qaytib qarang.

HOLAT 1

🔍 Uch daraja va ularning xatolari

class V { private int $maosh = 900; } $v->maosh; Fatal error: Uncaught Error: Cannot access private property V::$maosh class V { protected int $maosh = 900; } $v->maosh; Fatal error: Uncaught Error: Cannot access protected property V::$maosh

🔑 Uchtasi bir jumlada:

public → hamma joydan protected → shu klass VA undan meros olganlar private → faqat shu klass

✅ Amaliy qoida: hammasini private dan boshlang. Kerak bo'lganda ochasiz — teskarisi ancha qiyin.

🔍 protected ning ma'nosi keyingi darsda ochiladi — u yerda meros bilan tanishasiz.

HOLAT 2

var_dump darajani ko'rsatadi

class V { public $a = 1; protected $b = 2; private $c = 3; } var_dump(new V); object(V)#1 (3) { ["a"] => int(1) ["b":protected] => int(2) ["c":"V":private] => int(3) }

🔑 var_dump hammasini ko'rsatadi — hatto private ni ham. Bu himoyani buzish emas: var_dump nosozlik qidirish vositasi.

🔍 ["c":"V":private] — «c xossasi V klassiga tegishli va private». Meros bo'lganda bu ma'lumot foydali bo'ladi.

⚠️ Va 4-darsdagi qoida esda tursin: var_dump ni ishlab chiqarish kodida qoldirmang.

HOLAT 3

readonly — bir marta yoziladi

class V { public function __construct(public readonly int $maosh) {} } $v = new V(900); echo $v->maosh; → 900 ✅ o'qish mumkin $v->maosh = 1000; Fatal error: Uncaught Error: Cannot modify readonly property V::$maosh ✅

🔑 private dan farqi: readonly xossa tashqaridan o'qiladi, lekin hech qayerdan — hatto klass ichidan ham — ikkinchi marta yozilmaydi.

✅ Ideal holat: obyekt yaratilgach o'zgarmaydigan ma'lumot uchun — identifikator, yaratilgan vaqt, valyuta kodi.

🔍 Bu PHP 8.1 dan beri bor va zamonaviy kodda tez-tez uchraydi.

HOLAT 4

Nima uchun setter kerak — himoya shu yerda

class V { private int $maosh = 0; public function maoshBer(int $m): void { if ($m < 0) { throw new InvalidArgumentException("Maosh manfiy bo'lmaydi: $m"); } $this->maosh = $m; } public function maosh(): int { return $this->maosh; } } $v->maoshBer(900); → 900 $v->maoshBer(-5); → InvalidArgumentException: Maosh manfiy bo'lmaydi: -5

🔑 Mana shu — «obyekt o'z ma'lumotini himoya qiladi» degan gapning aniq ma'nosi.

⚠️ Xossa public bo'lganda bu imkonsiz: kim xohlasa $v->maosh = -5 deb yozadi va hech kim to'sa olmaydi.

✅ E'tibor bering: maoshBer() faqat saqlamaydi — u qaror qabul qiladi. Shuning uchun unga «setter» deyish ham to'liq to'g'ri emas.

HOLAT 5

private metod

class V { public function hisobla(): int { return $this->soliq(900); } private function soliq(int $m): int { return (int)($m * 0.12); } } $v->hisobla(); → 108 ✅ ichkaridan chaqirildi $v->soliq(900); Fatal error: Uncaught Error: Call to private method V::soliq() from global scope

🔑 private metod — «bu ichki ish, tashqi dunyoga aloqasi yo'q».

✅ Foydasi: uni istalgan payt o'zgartirsangiz ham, tashqarida hech narsa buzilmaydi — chunki uni hech kim chaqirmaydi.

🔍 Bu «ommaviy shartnoma» va «ichki tafsilot» ajratmasi. Klassning public qismi qanchalik kichik bo'lsa, uni o'zgartirish shuncha oson.

HOLAT 6

🔍 private — obyektga emas, KLASSGA tegishli

class V { public function __construct(private int $m) {} public function kattaroqmi(V $b): bool { return $this->m > $b->m; ← BOSHQA obyektning private xossasi } } (new V(900))->kattaroqmi(new V(500)) → true ✅ RUXSAT

Kutilmagan bo'lishi mumkin, lekin qoida aynan shunday: private obyektni emas, klassni himoya qiladi.

🔑 Ya'ni V klassining kodi har qanday V nusxasining ichini ko'ra oladi.

✅ Bu foydali: solishtirish, teng-ligini tekshirish, nusxa olish kabi metodlar shu tufayli yoziladi.

HOLAT 7

⚠️ __get — sehr va uning narxi

class V { private array $d = ["nom" => "PHP"]; public function __get($k) { return $this->d[$k] ?? null; } } $v->nom → PHP ← xossa YO'Q, lekin ishladi $v->yoq → NULL ⚠️ xato ham, ogohlantirish ham YO'Q

PHP mavjud bo'lmagan xossa so'ralganda __get() ni chaqiradi. Bu qulay ko'rinadi — lekin:

1) IDE nima borligini bilmaydi — avtomatik to'ldirish yo'q 2) Nom xato yozilsa — NULL qaytadi, xato YO'Q (2-darsdagi tuzoq) 3) O'qiganda "bu xossa qayerdan keldi?" degan savol tug'iladi

🔑 Kursimizning tamoyili — «sehr yo'q». Xossalarni ochiq e'lon qiling.

⚠️ Lekin buni bilish kerak: ba'zi kutubxonalar aynan shunday ishlaydi, va o'shanda «bu xossa qayerda e'lon qilingan?» degan savolga javob hech qayerda bo'ladi.

Sinab ko'ramiz

Natijani taxmin qiling

Klassda ikkita hisoblagich bor: bittasi oddiy xossa, ikkinchisi static. Ikkita obyekt yasab, har birida ikkisini oshiramiz. Oxirida nima chiqadi?

taxmin.php
class Hisoblagich { public int $oddiy = 0; public static int $umumiy = 0; public function oshir(): void { $this->oddiy++; self::$umumiy++; } } $a = new Hisoblagich(); $a->oshir(); $b = new Hisoblagich(); $b->oshir(); echo $a->oddiy, " ", $b->oddiy, " ", Hisoblagich::$umumiy;
Javobni ko'rish
1 1 2

Ya'ni:

  • $a->oddiy = 1 va $b->oddiy = 1 — oddiy xossa har obyektda alohida. Har biri o'z hisoblagichini bir marta oshirdi.
  • Hisoblagich::$umumiy = 2 — static xossa klass uchun bitta. Ikkita obyekt bitta qiymatni bo'lishdi va uni ikki marta oshirdilar.

Mana static ning ma'nosi: «bu ma'lumot obyektga emas, klassga tegishli». Shuning uchun unga $this-> emas, self:: bilan murojaat qilinadi, va tashqaridan Hisoblagich::$umumiy deb — obyekt yasamasdan.

Va mana xavfi ham shu: qiymat butun dastur bo'ylab bitta. Uni bir joyda o'zgartirsangiz, butunlay boshqa joydagi kod ta'sirlanadi — bu «global holat» muammosi. Shuning uchun static kamdan-kam ishlatiladi.

SAVOL 1 Xossani private qilish nima beradi?

private — «tashqaridan tegilmaydi». O'zgartirish mumkin, lekin faqat klass ichidagi metod orqali — va o'sha metod shart qo'ya oladi. O'zgarmas qiymat uchun const bor.

SAVOL 2 -> va :: farqi nima?

-> = «shu obyektning» ($v->nom). :: = «shu klassning» (Vakansiya::HOLAT_FAOL) — obyekt yasashning hojati yo'q.

SAVOL 3 Constructor property promotion nima qiladi?

Parametr oldiga private/public yozilsa, PHP xossani o'zi yaratadi va qiymat beradi. Laravel kodi shu shaklda yozilgan — shuning uchun uni tanish muhim.

Eslab ayting

Avval o'zingiz javob bering, keyin ochib tekshiring. Oxirgi ikkitasi — 7-darsni takrorlash.

Nega xossani private qilib boshlash tavsiya qilinadi?

Chunki keyin ochish oson, yopish qiyin. public xossaga kodning boshqa joylari bog'lanib qoladi va manfiy maosh kabi ma'nosiz ma'lumot har qanday joydan kirib kelishi mumkin.

static xossa oddiy xossadan nimasi bilan farq qiladi?

Oddiy xossa har obyektda alohida, static esa klass uchun bitta — barcha obyektlar bo'lishadi. Murojaat: self::$nom yoki Klass::$nom.

Nega "faol" o'rniga const ishlatiladi?

Chunki matnni adashib yozsangiz PHP jimgina ishlamaydi, konstanta nomini adashsangiz esa darhol xato beradi. Bundan tashqari o'zgartirish bitta joyda bo'ladi.

↩︎ Takrorlash: $b = $a — obyekt nusxalanadimi?

Yo'q. Ikki nom — bitta obyekt. Massiv esa nusxalanadi. Haqiqiy nusxa uchun clone.

↩︎ Takrorlash: $this nimani bildiradi?

«Metod hozir qaysi obyekt ustida ishlayapti». static metod ichida esa $this mavjud emas — u obyektga bog'lanmagan.

Cho'ntak xulosasi
  • public = hamma · private = faqat klass ichi · protected = klass + merosxo'rlar.
  • Qoida: private dan boshlang, kerak bo'lsa ochasiz.
  • Ma'lumotga murojaat — metod orqali, va metod shart qo'ya oladi (manfiy maoshni rad etish).
  • Har xossaga getter/setter yozish shart emas — ma'noli metod yaxshiroq.
  • 🔑 Qisqa konstruktor: parametr oldiga private → PHP xossani o'zi yaratadi. Laravel shu shaklda yozilgan.
  • const — o'zgarmas, klassga tegishli. Murojaat: Klass::NOM.
  • static — klass uchun bitta qiymat. self::$nom. Ehtiyot bilan: global holat yaratadi.
  • -> obyektga · :: klassga.
🌱 Kelasi darslar uchun urug'

Endi tasavvur qiling: Vakansiya va Ariza klasslari bor, va ikkalasida ham «yaratilgan vaqtni saqlash» kerak. Kodni ikki marta yozamizmi?

Keyingi dars shuni yechadi — extends bilan meros olish va abstract bilan «buni avlod o'zi bajarsin» deyish. Undan keyin interface va trait (10-dars), va 11-darsda 4-darsdan qolgan qarz to'lanadi: try/catch bilan xatoni tutib olish. Nega o'shanda? Chunki Exception — bu klass, va uni tutish uchun klasslar ierarxiyasini tushunish kerak.
