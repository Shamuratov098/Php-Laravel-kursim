DARS 12 · MODUL A — POYDEVOR

namespace, autoload va Composer

Bu darsdan keyin require yozish tugaydi — kerakli klassni PHP o'zi topib oladi. Va shu bilan Composer qo'lingizga o'tadi: Laravel ham aynan shu asbob bilan o'rnatiladi, ya'ni bugun B moduliga eshik ochiladi.

📱 O'qish ≈ 10 daqiqa 💻 Amaliyot ≈ 14 daqiqa Kerak: Dars 11

Nega bu muhim

Ikkita muammo to'planib qoldi:

1) require zanjiri. Har klass uchun bitta require. Klasslar 50 taga chiqsa — 50 qator, va tartibi ham muhim (biri ikkinchisiga tayansa). Bu qo'lda boshqariladigan ish emas.

2) Nom to'qnashuvi. Sizda Xabar klassi bor. Kutubxona o'rnatdingiz — unda ham Xabar bor. PHP'da bir xil nomli ikki klass bo'lishi mumkin emas — kod ishga tushmaydi.

Yechim ikkitasi ham bitta darsda: namespace nomlarni ajratadi, Composer esa fayllarni o'zi topadi. Va eng muhimi — Laravel loyihasi butunlay shu ikki narsaga qurilgan: siz Laravel'da ko'radigan har bir use App\Models\User; qatori bugungi darsning natijasi.

namespace — klass nomining bir qismi

src/Xabar.php
<?php declare(strict_types=1); namespace App; class Xabar { ... }

Endi bu klassning haqiqiy nomi — Xabar emas, App\Xabar. Bu shunchaki gap emas, var_dump buni ko'rsatadi:

object(App\Xabar)#2 (2) { ... }

Ya'ni namespace — nomning old qismi. Papkaga o'xshaydi: App\Xabar va Kutubxona\Xabar — ikki boshqa klass, to'qnashuv yo'q.

Ikkita qat'iy qoida

1. namespace — faylning eng birinchi ko'rsatmasi bo'lishi kerak (faqat declare undan oldin turishi mumkin). Buzsangiz:

PHP Fatal error: Namespace declaration statement has to be the very first statement or after any declare call in the script

2. Bir faylda bitta klass — va fayl nomi klass nomiga mos bo'lishi kerak (Xabar → Xabar.php). Bu Composer uchun shart, quyida sababini ko'rasiz.

use — qisqa nom bilan ishlash

Har joyda new App\Xabar(...) deb yozish zerikarli. use buni yechadi:

tushuncha
use App\Xabar; // «Xabar deganda App\Xabar ni tushun» $x = new Xabar(...); // endi qisqa nom ishlaydi

use — import, ya'ni «shu faylda bu qisqa nom nimani bildirishini aytib qo'yaman». Hech narsa yuklamaydi, faqat nom haqida.

Diqqat: use ning ikki xil ma'nosi bor

10-darsda use ni trait ulash uchun ko'rgandik (class C { use Loglaydi; }). Bugungisi boshqa: fayl boshida turgan use — namespace import qilish. Bir xil so'z, ikki xil vazifa — joyiga qarab ajratiladi: klass ichida = trait, klass tashqarisida = import.

Composer va autoload: PHP klassni o'zi topadi

Autoload — «klass kerak bo'lganda PHP uni o'zi qidirib topadi» degani. Buning uchun PHP'ga qoida aytish kerak: qaysi namespace qaysi papkada yashaydi. Bu qoida PSR-4 deb ataladi va composer.json da yoziladi:

composer.json
{ "name": "dostonbek/php-poydevor", "version": "1.0.0", "require": { "php": "^8.3" }, "autoload": { "psr-4": { "App\\": "src/" } } }

"App\\": "src/" — bu bitta gap: «App\ bilan boshlanadigan klassni src/ papkasidan izla». Shundan keyin:

App\Xabar → src/Xabar.php App\Kanal\Email → src/Kanal/Email.php

Ya'ni namespace = papka yo'li, klass nomi = fayl nomi. Mana nega fayl nomi klass nomiga mos bo'lishi shart edi — Composer faylni nom bo'yicha topadi. (\\ ikki marta yozilgan, chunki JSON'da \ maxsus belgi.)

Uch qadam

Shundan keyin new Xabar(...) yozganingizda PHP: «App\Xabar kerak → qoidaga ko'ra src/Xabar.php → faylni o'qiy» deb o'zi hal qiladi. Siz hech narsa qilmaysiz.

composer require — begona kodni olib kelish

Composer'ning ikkinchi vazifasi — paket menejeri. Dunyodagi minglab PHP kutubxonasini bitta buyruq bilan olib kelasiz:

terminal
composer require symfony/var-dumper

Bu paketni ataylab tanladim. U dump() funksiyasini beradi — va Laravel'dagi dd() aynan shu paketdan keladi. 2-darsda «var_dump ning Laravel'dagi ekvivalenti dd()» degandim; endi uning qayerdan kelganini ko'rasiz.

Farqni solishtiring:

=== var_dump === object(App\Xabar)#2 (2) { ["qabulQiluvchi":"App\Xabar":private]=> string(18) "doston@example.com" ["matn":"App\Xabar":private]=> string(23) "Arizangiz qabul qilindi" } === dump (symfony/var-dumper) === App\Xabar {#2 -qabulQiluvchi: "doston@example.com" -matn: "Arizangiz qabul qilindi" }

Bir xil ma'lumot, lekin dump() ancha o'qiladigan (- = private). Va e'tibor bering: bu kodni siz yozmadingiz — Composer olib keldi va autoload uni o'zi ulab qo'ydi.

Qaysi fayl Git'ga tushadi?

Shuning uchun boshqa kompyuterda loyihani ishga tushirish uchun bitta buyruq yetadi: composer install — u composer.lock ni o'qib, aynan o'sha versiyalarni tiklaydi. Laravel loyihasini klon qilganda birinchi qiladigan ishingiz ham shu bo'ladi.

Bu B moduliga eshik

Laravel Composer paketi. 16-darsda IshTop loyihasini yaratganda ichkarida aynan bugungi mexanizm ishlaydi: vendor/ ga Laravel yuklanadi, composer.json da "App\\": "app/" qoidasi turadi, va public/index.php ning birinchi qatorlaridan biri — require __DIR__.'/../vendor/autoload.php'; bo'ladi. Ya'ni siz bugun qo'lda yozgan narsa Laravel'da tayyor holda turadi.

💻 Amaliy qism kompyuterda

Amaliyotda composer.json yozasiz, src/ papkasida namespace'li klass yaratasiz, composer dump-autoload bilan autoload'ni yoqasiz va require zanjiridan xalos bo'lasiz. Keyin haqiqiy paket (symfony/var-dumper) o'rnatib, dump() ni var_dump bilan solishtirasiz.

Amaliyot

Eski fayllar joyida qoladi

01-*.php … 25-*.php fayllariga tegmaymiz — ular mashq va o'z ishini qilgan. Bugundan boshlab yangi klasslar src/ papkasida, namespace bilan yashaydi. Bu real loyihalardagi tuzilma.

  1. Papkaga o'ting va composer.json yozing

    Bu fayl — loyihaning «pasporti»: nomi, talablari va autoload qoidasi.

    cd ~/Projects/Learn/php-poydevor cat > composer.json <<'EOF' { "name": "dostonbek/php-poydevor", "version": "1.0.0", "require": { "php": "^8.3" }, "autoload": { "psr-4": { "App\\": "src/" } } } EOF

    Kutilgan natija: jimlik. cat composer.json bilan tekshirib ko'ring — "App\\": "src/" qatori turishi kerak.

  2. Namespace'li klass yarating

    Fayl nomi (Xabar.php) klass nomiga (Xabar) mos — Composer faylni shunday topadi.

    mkdir -p src cat > src/Xabar.php <<'EOF' <?php declare(strict_types=1); namespace App; class Xabar { public function __construct( private string $qabulQiluvchi, private string $matn, ) {} public function yubor(): string { return "→ {$this->qabulQiluvchi}: {$this->matn}"; } } EOF

    Kutilgan natija: jimlik. Diqqat: namespace App; declare dan keyin, lekin klassdan oldin turadi.

  3. Autoload'ni yasang

    Composer qoidani o'qib, klass qidiruvchi kodni o'zi yozib beradi.

    composer dump-autoload Generating autoload files Generated autoload files

    Kutilgan natija: ikki qator. Endi vendor/ papkasi paydo bo'ldi — ls vendor/ qilib ko'ring, ichida autoload.php bor.

  4. require zanjiridan xalos bo'ling

    Bu darsning g'alabasi: bitta require, va klasslar cheksiz bo'lishi mumkin.

    cat > 26-autoload.php <<'EOF' <?php declare(strict_types=1); require 'vendor/autoload.php'; use App\Xabar; $x = new Xabar("doston@example.com", "Arizangiz qabul qilindi"); echo $x->yubor(), PHP_EOL; EOF php 26-autoload.php → doston@example.com: Arizangiz qabul qilindi

    Kutilgan natija: xabar chiqdi. Diqqat qiling: src/Xabar.php ni hech qayerda require qilmadik — PHP uni o'zi topdi. 🎉

  5. Haqiqiy paket o'rnating

    Composer'ning ikkinchi vazifasi. Bu paket Laravel'dagi dd() ning manbasi.

    composer require symfony/var-dumper - Installing symfony/polyfill-mbstring (v1.38.2): Extracting archive - Installing symfony/deprecation-contracts (v3.7.1): Extracting archive - Installing symfony/var-dumper (v7.4.15): Extracting archive Generating autoload files

    Kutilgan natija: uchta paket o'rnatildi (bittasini so'radik, u o'zi ikkitasiga tayanadi — bu «bog'liqlik» deb ataladi). Versiyalar sizda boshqacha bo'lishi mumkin. Endi composer.lock fayli ham paydo bo'ldi.

  6. dump() ni var_dump bilan solishtiring

    cat > 27-paket.php <<'EOF' <?php declare(strict_types=1); require 'vendor/autoload.php'; use App\Xabar; $x = new Xabar("doston@example.com", "Arizangiz qabul qilindi"); echo "=== var_dump ===", PHP_EOL; var_dump($x); echo "=== dump ===", PHP_EOL; dump($x); EOF php 27-paket.php === var_dump === object(App\Xabar)#2 (2) { ["qabulQiluvchi":"App\Xabar":private]=> string(18) "doston@example.com" ... === dump === App\Xabar {#2 -qabulQiluvchi: "doston@example.com" -matn: "Arizangiz qabul qilindi" }

    Kutilgan natija: ikki xil ko'rinish. E'tibor bering: klass nomi App\Xabar — namespace nomning bir qismi. Va dump() funksiyasini siz yozmadingiz — paket berdi, autoload uladi.

  7. vendor/ Git'ga tushmasligini tekshiring

    vendor/ — yuklab olingan kod, u repoda saqlanmaydi.

    git status --short

    Kutilgan natija: ro'yxatda composer.json, composer.lock, src/ va yangi .php fayllar bo'ladi — lekin vendor/ bo'lmaydi. Sababi: u .gitignore da (papka yaratilganda yozib qo'yilgan).
    Aynan qaysi fayllar chiqishi sizda boshqacha bo'lishi mumkin — muhimi vendor/ yo'qligi. Tekshirish uchun: git check-ignore -v vendor/

  8. Ishni saqlang

    git add -A git commit -m "12-dars: namespace, autoload va Composer"

    Kutilgan natija: commit haqida xabar.

Sinab ko'ramiz

Natijani taxmin qiling

Uchta variant. Xabar klassi App namespace'ida. Autoload ulangan. Qaysilari ishlaydi?

A — use YO'Q, qisqa nom
require 'vendor/autoload.php'; $x = new Xabar("a", "b");
B — use YO'Q, to'liq nom
require 'vendor/autoload.php'; $x = new App\Xabar("a", "b");
C — use BOR, qisqa nom
require 'vendor/autoload.php'; use App\Xabar; $x = new Xabar("a", "b");
Javobni ko'rish

A — ISHLAMAYDI:

PHP Fatal error: Uncaught Error: Class "Xabar" not found

B va C — ikkalasi ishlaydi.

Sabab: klassning haqiqiy nomi — App\Xabar. Xabar degan klass umuman mavjud emas.

  • A da PHP Xabar ni hozirgi namespace'da (ya'ni global'da) izlaydi va topmaydi.
  • B da to'liq nom berilgan — to'g'ridan-to'g'ri topadi.
  • C da use «Xabar deganda App\Xabar ni tushun» deb aytib qo'ygan — shuning uchun qisqa nom ishlaydi.

Muhim tushuncha: use hech narsa yuklamaydi — u faqat nomni hal qiladi. Yuklashni autoload qiladi. Shuning uchun use yozib ham composer dump-autoload qilmasangiz, klass topilmaydi. Ikkisi boshqa-boshqa ish.

SAVOL 1 namespace App; yozilgan Xabar klassining haqiqiy nomi nima?

Namespace — nomning old qismi. var_dump ham shuni ko'rsatadi: object(App\Xabar). Shuning uchun App\Xabar va Boshqa\Xabar to'qnashmaydi.

SAVOL 2 PSR-4 qoidasi "App\\": "src/" nimani bildiradi?

Namespace → papka, klass nomi → fayl nomi. App\Kanal\Email → src/Kanal/Email.php. Fayllar hammasi emas, faqat kerak bo'lgani yuklanadi.

SAVOL 3 Qaysi fayl Git'ga tushmaydi?

vendor/ — yuklab olingan kod, composer install bilan qayta tiklanadi. composer.json (nima kerak) va composer.lock (aynan qaysi versiya) esa tushishi kerak.

Eslab ayting

Avval o'zingiz javob bering, keyin ochib tekshiring. Oxirgi ikkitasi — 11-darsni takrorlash.

namespace qanday muammoni yechadi?

Nom to'qnashuvini. App\Xabar va Kutubxona\Xabar — ikki boshqa klass. Namespace nomning old qismiga aylanadi.

use va autoload — qaysi biri klassni yuklaydi?

Autoload yuklaydi. use faqat nomni hal qiladi («qisqa nom nimani bildiradi»). Ikkisi boshqa-boshqa ish — shuning uchun use yozib, dump-autoload qilmasangiz klass topilmaydi.

PSR-4 qoidasi bir gapda nima?

Namespace = papka yo'li, klass nomi = fayl nomi. App\Kanal\Email → src/Kanal/Email.php.

↩︎ Takrorlash: catch (Exception) TypeError ni tutadimi?

Yo'q — TypeError bu Error avlodi, Exception emas. Ular aka-uka. Hammasi uchun Throwable.

↩︎ Takrorlash: nega o'z exception klassini yozadilar?

Nom uchun — aynan shu muammoni catch bilan ajratib hal qilish va kodni o'qigan odamga tushunarli bo'lishi uchun. Tanasi bo'sh bo'lsa ham yetadi.

Cho'ntak xulosasi
  • namespace App; — klass nomining old qismi. Haqiqiy nom: App\Xabar. Faylning birinchi ko'rsatmasi (declare dan keyin).
  • use App\Xabar; — import: qisqa nom nimani bildirishini aytadi. Yuklamaydi.
  • ⚠️ use klass ichida = trait · klass tashqarisida = import.
  • PSR-4: "App\\": "src/" → namespace = papka, klass = fayl nomi.
  • composer dump-autoload → vendor/autoload.php yasaydi. Skriptda bitta require yetadi.
  • composer require paket/nomi — begona kodni olib keladi.
  • Git'ga: composer.json ✅ · composer.lock ✅ · vendor/ ❌. Tiklash: composer install.
  • dump() — symfony/var-dumper dan; Laravel'dagi dd() ning manbasi.
🌱 Kelasi darslar uchun urug'

Modul A ning oxirgi uchta darsi qoldi va ular eng qimmatlisi. 13-darsda HTTP'ni qo'lda ko'ramiz: forma, $_POST, session — ya'ni brauzer bilan server qanday gaplashadi.

Keyin 14 va 15-darslarda hammasi birlashadi: siz o'z qo'lingiz bilan mini-framework yozasiz — bitta kirish nuqtasi, router va container. Bugungi namespace + autoload esa uning poydevori bo'ladi. Shundan keyin Laravel ochilganda «sehr» qolmaydi: har bir qismini o'zingiz yozib ko'rgan bo'lasiz.
