DARS 61 · MODUL I — ISHLAB CHIQARISHGA TAYYORGARLIK

SQLite'dan MySQL'ga ko'chish

21-darsdan beri SQLite bilan ishlab keldik — u bitta fayl, sozlash talab qilmaydi. 60-darsda esa rejalar bazadan bazaga farq qilishini aytdik. Bugun haqiqatan ko'chamiz — va ikkala bazada bir xil kod ishlatib, farqlarni o'lchaymiz. Bittasi juda yoqimsiz: xato yo'q, natija boshqacha.

📱 O'qish ≈ 18 daqiqa 💻 Amaliyot ≈ 35 daqiqa Kerak: Dars 60

Bu darsda nimalar bor
  1. Nega SQLite yetarli emas Bitta fayl, bitta yozuvchi, bo'sh tekshiruv.
  2. pdo_mysql va MySQL server Ikkitasi alohida narsa — chalkashtirish oson.
  3. DB_* sozlamalari Va migrate:fresh — 🔍 MySQL 1.47s, SQLite 0.42s.
  4. 🔍 To'rtta ulanish xatosi Har biri boshqacha aytadi: could not find driver, 1045, 1044, 2002.
  5. ⭐ Xato yo'q, natija boshqacha 🔍 Bir xil so'rov: SQLite 1 ta, MySQL 3 ta topdi.
  6. utf8mb4_0900_ai_ci Nomning har harfi ma'noli. 🔍 Café = Cafe bo'lib chiqdi.
  7. ⚠️ Qat'iy tip tekshiruvi 🔍 SQLite maosh ga 'salom' ni yozib qo'ydi.
  8. ⚠️ varchar(255) chegarasi 🔍 SQLite 305 belgini saqladi, MySQL 1406 xatosi.
  9. ⚠️ DDL tranzaksiya 🔍 Yarim bajarilgan migratsiya MySQL'da qaytarilmaydi.
  10. whereLike() — yechim 🔍 Laravel MySQL'da like binary, SQLite'da glob yozar ekan.
  11. ⚠️ phpunit.xml tuzoq Testlaringiz MySQL'ga umuman tegmaydi.
  12. Har xil holatlar (7 ta) Ma'lumot ko'chirish · utf8mb4 · strict · PostgreSQL · zaxira nusxa.
SQLite yomonmi? Yo'q. Lekin...

SQLite ajoyib baza — u telefoningizda ham, brauzeringizda ham ishlaydi. Muammo unda emas, bizning ishimizda:

1) BITTA FAYL → bir vaqtda bitta yozuvchi. Ikkinchisi kutadi 2) BO'SH TEKSHIRUV → son ustuniga matn yozsangiz — qabul qiladi 3) FOYDALANUVCHI YO'Q → parol, huquq, masofadan ulanish yo'q 4) BOSHQA XULQ → ba'zi so'rovlar BOSHQACHA javob beradi

Birinchi uchtasi ma'lum va kutilgan. Eng xavflisi — to'rtinchisi, chunki u indamay keladi.

Bugun ikkala bazani yonma-yon qo'yib, bir xil kodni ishlatamiz. Va farqlarni ko'ramiz — aytilgan farqlarni ham, aytilmaganlarini ham.

Ikki alohida narsa

Bu yerda yangi boshlovchilar eng ko'p chalkashadi:

MySQL SERVER → ma'lumotni saqlaydigan dastur (alohida ishlaydi) pdo_mysql → PHP ning MySQL bilan gaplashish drayveri

Ikkalasi ham kerak. Bittasi bo'lmasa, xato boshqacha bo'ladi — va aynan shu farq sizga nima yetishmayotganini aytadi.

sudo apt install mysql-server ← SERVER sudo apt install php8.3-mysql ← DRAYVER php -m | grep pdo_mysql ← tekshiruv
🔑 php -m nima ko'rsatadi

php -m — PHP'ga o'rnatilgan modullar ro'yxati. pdo_mysql u yerda bo'lmasa, Laravel MySQL bilan gaplasha olmaydi — server ishlab turgan bo'lsa ham.

⚠️ Drayverni o'rnatgandan keyin PHP-FPM yoki artisan serve ni qayta ishga tushiring.

.env sozlamalari

Kurs boshidan beri .env da bitta qator bor edi:

DB_CONNECTION=sqlite

MySQL uchun oltita:

.env
DB_CONNECTION=mysql DB_HOST=127.0.0.1 DB_PORT=3306 DB_DATABASE=ishtop DB_USERNAME=ishtop DB_PASSWORD=sirli-parol

Bazani va foydalanuvchini oldindan yaratish kerak — Laravel buni o'zi qilmaydi:

create database ishtop character set utf8mb4 collate utf8mb4_0900_ai_ci; create user 'ishtop'@'localhost' identified by 'sirli-parol'; grant all privileges on ishtop.* to 'ishtop'@'localhost'; flush privileges;

So'ng migratsiya:

php artisan migrate:fresh --seed Creating migration table ....................... 16.35ms DONE 0001_01_01_000000_create_users_table ........... 74.66ms DONE ... 2026_01_01_000002_create_vakansiyalar_table .... 105.66ms DONE jami: 1.47 s (SQLite'da o'sha migratsiyalar: 0.42 s)

MySQL uch barobar sekinroq migratsiya qiladi — bu normal. U diskka ishonchli yozadi, huquqlarni tekshiradi, indekslarni quradi.

To'rtta ulanish xatosi

47-darsda «xatoni o'qishni o'rganing» degandik. Bu yerda u to'liq ishlaydi — har xato boshqa narsani aytadi:

could not find driver → pdo_mysql O'RNATILMAGAN. Server bilan aloqasi yo'q. → sudo apt install php8.3-mysql SQLSTATE[HY000] [2002] Connection refused → Serverga YETIB BORMADI. Ishlamayapti yoki port boshqa. → systemctl status mysql · DB_PORT ni tekshiring SQLSTATE[HY000] [1045] Access denied for user 'ishtop'@'...' (using password: YES) → Serverga yetdi, PAROL noto'g'ri. → DB_USERNAME / DB_PASSWORD SQLSTATE[HY000] [1044] Access denied for user 'ishtop'@'%' to database 'yoq_baza' → Parol to'g'ri, BAZA yo'q yoki huquq berilmagan. → create database ... · grant ...
🔑 1045 va 1044 — bir harf farq, boshqa sabab

Ikkalasi ham «Access denied» deydi, lekin:

1045 → "for user ... (using password: YES)" → PAROL 1044 → "for user ... to database 'X'" → BAZA / HUQUQ

Xato raqamini o'qing — u sizga qayerga qarashni aytadi. Taxmin qilib bir soat yo'qotishdan ko'ra, bir qator o'qigan yaxshi.

⭐ Xato yo'q, natija boshqacha

Endi darsning eng muhim qismi. Ikkala bazaga bir xil uchta yozuv qo'yamiz:

'ZOND Dasturchi' 'ZOND dasturchi' 'ZOND DASTURCHI'

Va bir xil so'rovni yuboramiz:

Vakansiya::where('nom', 'ZOND Dasturchi')->count() SQLite: 1 ta MySQL: 3 ta ⚠️

Xato yo'q. Ogohlantirish yo'q. Testlar yashil. Faqat javob boshqacha.

⚠️ Nega bunday?

Sabab — kollatsiya (solishtirish qoidasi). MySQL 8 ning standarti:

utf8mb4_0900_ai_ci │ │ │ │ │ │ │ └─ ci = case-insensitive (KATTA harf = kichik harf) │ │ └──── ai = accent-insensitive (é = e) │ └───────── 0900 = Unicode 9.0 qoidalari └───────────────── utf8mb4 = to'liq Unicode (emoji ham)

SQLite'da esa standart — BINARY: bayt bo'yicha aniq solishtirish.

🔍 Va ai ni ham o'lchadik:

Bazada saqlangan: 'ZOND Café' where nom = 'ZOND Cafe' SQLite: 0 ta MySQL: 1 ta ⚠️

MySQL uchun é va e — bir xil harf.

Bu yaxshimi yoki yomonmi?

Ikkalasi ham emas — boshqacha. Ko'p hollarda MySQL'ning xulqi foydalanuvchi kutganidek: odam «dasturchi» deb qidirsa, «Dasturchi» ni topishi kerak.

Muammo — bilmaslik. Agar siz SQLite'da ishlab, MySQL'ga chiqsangiz:

"Nega bu foydalanuvchi ikki marta ro'yxatdan o'tibdi?" → email tekshiruvi: SQLite'da 'Ali@x.uz' va 'ali@x.uz' — BOSHQA → MySQL'da ular BIR XIL, unique indeks ikkinchisini rad etadi "Nega qidiruv keraksiz narsalarni topyapti?" → MySQL harf registrini e'tiborsiz qoldiradi

✅ Yechim: whereLike()

Laravel bu farqni o'zi silliqlaydi — agar to'g'ri metodni ishlatsangiz:

2 ta yozuv: 'ZOND Dasturchi' va 'ZOND dasturchi' whereLike('nom', '%dasturchi%') SQLite: 2 MySQL: 2 ✅ whereLike('nom', '%dasturchi%', caseSensitive: true) SQLite: 1 MySQL: 1 ✅ where('nom', '=', 'ZOND dasturchi') SQLite: 1 MySQL: 2 ⚠️

🔍 Laravel qanday qilyapti? Yaratilgan SQL'ga qarang:

caseSensitive: true bo'lganda — MySQL: where `nom` like binary ? SQLite: where "nom" glob ?

Har baza uchun o'sha bazaning vositasini tanlaydi. Bu — 49-darsdagi abstraksiya g'oyasining amaldagi ko'rinishi.

🔑 Umumiy qoida

Baza xulqiga bog'liq joyni o'zingiz yozmang — Laravel bergan vositani ishlating:

❌ where('nom', 'like', "%{$q}%") → xulqi bazaga bog'liq ✅ whereLike('nom', "%{$q}%") → Laravel moslaydi ❌ whereRaw("date(created_at) = ?") → SQL funksiyalari farq qiladi ✅ whereDate('created_at', $sana) → Laravel moslaydi

⚠️ Qat'iy tekshiruv: SQLite nimalarni o'tkazib yuboradi

1) Son ustuniga MATN yozish (maosh — integer): SQLite: [OK] saqlandi, qiymat: 'salom' ⚠️ MySQL: [XATO] 1366 Incorrect integer value: 'salom' for column 'maosh' at row 1 2) varchar(255) ga 300 belgi yozish: SQLite: [OK] saqlandi, uzunligi: 305 ⚠️ MySQL: [XATO] SQLSTATE[22001] 1406 Data too long for column 'nom' at row 1 3) Guruhlanmagan ustunni tanlash: select shahar, nom from vakansiyalar group by shahar SQLite: [OK] 5 qator qaytardi ⚠️ MySQL: [XATO] 1055 Expression #2 of SELECT list is not in GROUP BY clause ...

Uchala holatda ham SQLite indamay qabul qildi. Kod ishladi, test yashil bo'ldi. Va ishlab chiqarishga chiqqanda — uchta xato birdan chiqadi.

⚠️ SQLite ustun uzunligini SAQLAMAYDI ham

Bir xil migratsiyadan keyin ustun tiplarini solishtiring:

migratsiyada: $table->string('nom'); // varchar(255) MySQL'da: nom varchar(255) SQLite'da: nom varchar ← uzunlik YO'Q migratsiyada: $table->id(); MySQL'da: id bigint unsigned SQLite'da: id INTEGER

🔑 SQLite tipni «maslahat» deb qabul qiladi. U hech qachon «bu ustunga sig'maydi» demaydi.

Bularning hammasi bitta sozlamadan kelib chiqadi — MySQL'ning sql_mode i:

ONLY_FULL_GROUP_BY, STRICT_TRANS_TABLES, NO_ZERO_IN_DATE, NO_ZERO_DATE, ERROR_FOR_DIVISION_BY_ZERO, NO_ENGINE_SUBSTITUTION

STRICT_TRANS_TABLES — «sig'masa xato ber». ONLY_FULL_GROUP_BY — «guruhlashda aniq bo'l». Bular MySQL 8 da standart yoqilgan.

⚠️ Yarim bajarilgan migratsiya

Bu farq eng kam gapiriladi va eng ko'p og'riq keltiradi.

DB::transaction(function () { DB::statement('create table zond_jadval (id int)'); throw new RuntimeException('ataylab xato'); }); // tranzaksiya bekor qilindi. zond_jadval bormi? SQLite: YO'Q ← jadval ham qaytarildi ✅ MySQL: HA ← jadval QOLDI ⚠️

MySQL'da create table, alter table, drop table — tranzaksiyaga bo'ysunmaydi. Ular bajarilishi bilan yozib qo'yiladi.

⚠️ Amaliy oqibati

Bitta migratsiya faylida ikkita amal bor:

public function up(): void { Schema::create('a_jadval', ...); ← bajarildi Schema::create('b_jadval', ...); ← XATO berdi }

MySQL'da natija: a_jadval bor, b_jadval yo'q, va migrations jadvalida bu migratsiya yozilmagan.

Endi php artisan migrate ni qayta ishga tushirsangiz — «a_jadval already exists» xatosi. Migratsiya tiqilib qoldi.

✅ Shuning uchun: bitta migratsiya = bitta amal. Va ishlab chiqarishda migratsiyadan oldin zaxira nusxa.

⚠️ phpunit.xml tuzog'i

Bazani MySQL'ga o'tkazdingiz. Testlarni ishga tushirdingiz — 85 ta yashil. Ajoyib!

Faqat bitta muammo bor. phpunit.xml ga qarang:

phpunit.xml
<env name="DB_CONNECTION" value="sqlite"/> <env name="DB_DATABASE" value=":memory:"/>

Testlaringiz MySQL'ga umuman tegmadi. Ular hamon xotiradagi SQLite'da ishlaydi. Ya'ni yuqorida ko'rgan farqlarning hech biri testda tutilmaydi.

🔑 Ikki qarash — ikkisi ham to'g'ri
SQLite :memory: da test → 0.77s TEZ, lekin haqiqiy emas MySQL da test → 1.98s SEKIN, lekin haqiqiy

Ko'p jamoalar ikkalasini ishlatadi:

mahalliy ish → SQLite (tez qaytish uchun) CI → MySQL (haqiqatni tekshirish uchun)

Buning uchun ikkinchi konfiguratsiya fayli yetarli:

cp phpunit.xml phpunit.mysql.xml # ichida DB_CONNECTION ni mysql ga o'zgartiring va force="true" qo'ying php artisan test -c phpunit.mysql.xml

⚠️ force="true" muhim — usiz PHPUnit mavjud muhit o'zgaruvchisini bosib o'tmaydi.

🔍 Va natija ishonch beradi — ikkala bazada ham 85 ta test yashil:

SQLite: Tests: 85 passed (173 assertions) Duration: 0.77s MySQL: Tests: 85 passed (173 assertions) Duration: 1.98s

Ya'ni loyihamiz ko'chma. Yuqoridagi farqlar bizga tegmadi — chunki 46-darsda qidiruvni whereLike() bilan yozgan edik.

Har xil holatlar

Yetti holat. Bu bo'lim ma'lumotnoma — hozir bir marta o'qing, ko'chirish paytida qaytib qarang.

HOLAT 1

Mavjud ma'lumotni ko'chirish

1) SQLite'dan o'qing, MySQL'ga yozing — artisan buyrug'i bilan 2) yoki: sqlite3 baza.sqlite .dump > eksport.sql (SQL sintaksisi FARQ qiladi) 3) yoki: eng ishonchlisi — seeder qayta ishga tushirish (test ma'lumoti bo'lsa)

⚠️ .dump to'g'ridan-to'g'ri MySQL'ga tushmaydi: AUTOINCREMENT, qo'shtirnoq turi, tip nomlari boshqacha.

✅ Haqiqiy ma'lumot bo'lsa, eng xavfsizi — Laravel'ning o'zida ikkita ulanish ochib, chunkById bilan ko'chirish (60-dars).

HOLAT 2

utf8mb4 emas utf8

create database ishtop character set utf8; ❌ ESKI create database ishtop character set utf8mb4; ✅

MySQL'ning utf8 si aslida to'liq emas — u har belgi uchun 3 bayt ajratadi va 4 baytli belgilarni sig'dira olmaydi.

Nima sig'maydi? Emoji va ba'zi belgilar. Foydalanuvchi izohga 🎉 yozsa — xato yoki yo'qolgan matn.

✅ Har doim utf8mb4. Laravel'ning config/database.php da standarti ham shu.

HOLAT 3

Kollatsiyani ataylab tanlash

utf8mb4_0900_ai_ci → standart. Katta-kichik va urg'u FARQSIZ utf8mb4_0900_as_cs → aniq solishtirish (as = accent-sensitive) utf8mb4_bin → bayt bo'yicha, SQLite'ning BINARY iga eng yaqin

Ustunga alohida ham berish mumkin:

$table->string('token')->collation('utf8mb4_bin');

✅ Token, hash, kalit kabi ustunlarga _bin to'g'ri keladi — u yerda ABC va abc haqiqatan boshqa narsa.

🔑 Ismlar va qidiriladigan matnlar uchun esa _ci yaxshi.

HOLAT 4

SQLite'ni ham qat'iy qilish

// config/database.php → sqlite ulanishida 'busy_timeout' => 5000, 'journal_mode' => 'WAL', 'synchronous' => 'NORMAL',

Yangi SQLite versiyalarida STRICT jadvallar ham bor — ular tipni haqiqatan tekshiradi.

✅ Lekin eng oddiy yechim boshqa: testlaringizni MySQL'da ham ishlating. Sozlama emas, o'lchov ishonch beradi.

🔍 WAL rejimi SQLite'ning bir vaqtda o'qish-yozish muammosini ancha yumshatadi — lekin bitta yozuvchi cheklovi qoladi.

HOLAT 5

PostgreSQL — uchinchi yo'l

DB_CONNECTION=pgsql DB_PORT=5432 sudo apt install php8.3-pgsql

PostgreSQL har doim katta-kichik harfni farqlaydi (= ham, LIKE ham). Ya'ni bu jihatdan u SQLite'ga yaqinroq.

Kuchli tomonlari: jsonb, kuchli tip tizimi, tranzaksion DDL (migratsiya yarim qolmaydi!).

🔑 Laravel uchalasini ham qo'llab-quvvatlaydi. Migratsiya va Eloquent kodingiz o'zgarmaydi — faqat whereRaw yozgan joylaringiz.

HOLAT 6

migrate:fresh ni ishlab chiqarishda ishlatish

php artisan migrate:fresh → HAMMA JADVALNI O'CHIRADI ☠️ php artisan migrate → faqat yangilarini qo'shadi ✅

⚠️ fresh — «toza boshlash». Ishlab chiqarishda bu hamma ma'lumotni yo'qotish demakdir.

✅ Laravel himoya qo'ygan: ishlab chiqarish muhitida u tasdiq so'raydi. --force bilan bu himoya o'chadi — shuning uchun --force ni skriptga yozishdan oldin ikki marta o'ylang.

HOLAT 7

Ko'chishdan oldingi ro'yxat

1) ZAXIRA NUSXA → eski bazani saqlang. Har doim. 2) php -m | grep pdo_mysql → drayver bormi? 3) baza + foydalanuvchi + huquq yaratilganmi? 4) utf8mb4 mi? 5) migrate (fresh EMAS) — xatosiz o'tdimi? 6) testlarni MySQL'da ishlating 7) qidiruv/solishtirish joylarini qo'lda tekshiring ← eng muhimi 8) .env.example ni ham yangilang (jamoadoshlaringiz uchun)

🔑 7-qadam eng ko'p o'tkazib yuboriladi va eng ko'p muammo keltiradi — chunki u yerda xato chiqmaydi.

💻 Quyida amaliyot bor. Hozir o'qish rejimidasiz — kompyuter yoningizda bo'lganda 💻 Amaliyot rejimiga o'ting va shu bo'limdan davom eting.

Amaliyot

⚠️ Avval zaxira nusxa

SQLite bazangiz bitta fayl — uni nusxalash bir buyruq. Buni hozir qiling.

  1. Zaxira nusxa va hozirgi holat.
    cd ~/Projects/Learn/ishtop cp database/database.sqlite database/database.sqlite.zaxira cp .env .env.sqlite.zaxira php -m | grep -c pdo_mysql php artisan test 2>&1 | tail -3

    grep -c 0 qaytarsa — drayver yo'q.

  2. ⚠️ Drayversiz nima bo'lishini ko'ring.
    php artisan migrate --database=mysql 2>&1 | head -5

    could not find driver — bu PHP tomonidagi muammo, server bilan aloqasi yo'q.

  3. Server va drayverni o'rnating.
    sudo apt update sudo apt install -y mysql-server php8.3-mysql php -m | grep pdo_mysql sudo systemctl status mysql --no-pager | head -4

    pdo_mysql va active (running).

  4. Baza va foydalanuvchi yarating.
    sudo mysql -e "create database if not exists ishtop character set utf8mb4 collate utf8mb4_0900_ai_ci;" sudo mysql -e "create database if not exists ishtop_test character set utf8mb4 collate utf8mb4_0900_ai_ci;" sudo mysql -e "create user if not exists 'ishtop'@'localhost' identified by 'sirli';" sudo mysql -e "grant all privileges on ishtop.* to 'ishtop'@'localhost';" sudo mysql -e "grant all privileges on ishtop_test.* to 'ishtop'@'localhost';" sudo mysql -e "flush privileges;"
  5. .env ni yangilang. DB_CONNECTION=sqlite qatorini o'chirib, o'rniga:
    # .env DB_CONNECTION=mysql DB_HOST=127.0.0.1 DB_PORT=3306 DB_DATABASE=ishtop DB_USERNAME=ishtop DB_PASSWORD=sirli
    php artisan config:clear php artisan migrate:fresh --seed

    54-darsdagi config:clear — konfiguratsiya keshlangan bo'lsa, eski sozlama qoladi.

  6. ⚠️ Uchta xatoni ataylab chaqiring. Har birida .env ni buzib, php artisan migrate ni ishga tushiring va xato raqamini yozib qo'ying:
    # 1) DB_PASSWORD=notogri → ? # 2) DB_DATABASE=yoq_baza → ? # 3) DB_PORT=3999 → ? # Har birida: php artisan config:clear && php artisan migrate

    Menda: 1045, 1044, 2002. So'ng .env ni tiklang.

  7. ⭐ Farqni o'z ko'zingiz bilan ko'ring. farq.php yarating:
    cat > farq.php <<'PHPEOF' <?php require __DIR__.'/vendor/autoload.php'; $app = require __DIR__.'/bootstrap/app.php'; $app->make(Illuminate\Contracts\Console\Kernel::class)->bootstrap(); use Illuminate\Support\Facades\DB; echo '=== ', DB::connection()->getDriverName(), ' ===', PHP_EOL; DB::table('vakansiyalar')->where('nom', 'like', 'ZOND%')->delete(); $kid = DB::table('kompaniyalar')->value('id'); foreach (['ZOND Dasturchi', 'ZOND dasturchi', 'ZOND DASTURCHI'] as $n) { DB::table('vakansiyalar')->insert(['nom' => $n, 'shahar' => 'T', 'maosh' => 1, 'faol' => 1, 'kompaniya_id' => $kid, 'created_at' => now(), 'updated_at' => now()]); } $b = fn () => DB::table('vakansiyalar')->where('nom', 'like', 'ZOND%'); printf(" where(nom, 'ZOND Dasturchi') -> %d ta\n", (clone $b())->where('nom', 'ZOND Dasturchi')->count()); printf(" whereLike(nom, '%%dasturchi%%') -> %d ta\n", (clone $b())->whereLike('nom', '%dasturchi%')->count()); printf(" whereLike(..., caseSensitive: true) -> %d ta\n", (clone $b())->whereLike('nom', '%dasturchi%', true)->count()); try { DB::table('vakansiyalar')->insert(['nom' => 'ZOND4', 'shahar' => 'T', 'maosh' => 'salom', 'faol' => 1, 'kompaniya_id' => $kid, 'created_at' => now(), 'updated_at' => now()]); echo ' maosh = "salom" -> QABUL QILINDI: ', var_export(DB::table('vakansiyalar')->where('nom', 'ZOND4')->value('maosh'), true), PHP_EOL; } catch (\Throwable $e) { echo ' maosh = "salom" -> XATO: ', substr(explode(' (Connection:', $e->getMessage())[0], 0, 90), PHP_EOL; } DB::table('vakansiyalar')->where('nom', 'like', 'ZOND%')->delete(); PHPEOF php farq.php
  8. ⭐ Endi SQLite'da bir xil skriptni ishlating.
    cp .env .env.mysql.zaxira cp .env.sqlite.zaxira .env php artisan config:clear php farq.php cp .env.mysql.zaxira .env php artisan config:clear

    ⚠️ Menda uchta yozuv ustida:

    SQLite MySQL where(nom, 'ZOND Dasturchi') 1 3 <- FARQ whereLike(nom, '%dasturchi%') 3 3 <- bir xil whereLike(..., caseSensitive: true) 1 1 <- bir xil maosh = "salom" QABUL QILINDI XATO 1366
  9. Testlarni MySQL'da ishlating.
    cp phpunit.xml phpunit.mysql.xml

    phpunit.mysql.xml ichida DB_CONNECTION va DB_DATABASE qatorlarini almashtiring:

    # phpunit.mysql.xml <env name="DB_CONNECTION" value="mysql" force="true"/> <env name="DB_HOST" value="127.0.0.1" force="true"/> <env name="DB_PORT" value="3306" force="true"/> <env name="DB_DATABASE" value="ishtop_test" force="true"/> <env name="DB_USERNAME" value="ishtop" force="true"/> <env name="DB_PASSWORD" value="sirli" force="true"/>
    php artisan test -c phpunit.mysql.xml 2>&1 | tail -4

Sinab ko'ramiz

Natijani taxmin qiling

Jamoa loyihani SQLite'dan MySQL'ga ko'chirdi. Hammasi rejadagidek o'tdi: migratsiyalar bajarildi, testlar yashil, sayt ishlayapti.

Ro'yxatdan o'tish kodi shunday:

$bor = User::where('email', $request->email)->exists(); if ($bor) { return back()->withErrors(['email' => 'Bu email band']); } User::create([...]);

Bir hafta o'tib qo'llab-quvvatlash xizmatiga shikoyat keldi:

"Ro'yxatdan o'tolmayapman. 'Bu email band' deydi, lekin men hech qachon ro'yxatdan o'tmaganman."

Dasturchi bazani tekshirdi — foydalanuvchining emaili haqiqatan yo'q. Nima bo'lyapti?

Javobni ko'rish

Foydalanuvchi Ali@example.com deb yozdi. Bazada esa ali@example.com bor — boshqa odamning emaili.

MySQL'ning _ci kollatsiyasi uchun bu ikkalasi — bir xil. Shuning uchun exists() true qaytardi.

SQLite'da bu kod yillar davomida to'g'ri ishlagan edi — u Ali@ va ali@ ni boshqa deb bilgan.

🔑 Va endi eng qiziq savol: qaysi biri to'g'ri?

RFC bo'yicha: email ning domen qismi — registrsiz local qismi (@ dan oldin) — TEXNIK JIHATDAN registrli Amalda: deyarli hamma pochta xizmati registrni e'tiborsiz qoldiradi. Ali@gmail.com va ali@gmail.com — BIR ODAM

Ya'ni MySQL'ning xulqi to'g'riroq. SQLite'dagi «to'g'ri ishlagan» kod aslida xato edi — u bir odamga ikkita hisob ochish imkonini bergan.

⚠️ Muammo ko'chishda emas. Ko'chish faqat eski xatoni ko'rsatdi.

✅ To'g'ri yechim — bazaga tayanmaslik:

// saqlashdan OLDIN normallashtirish $email = Str::lower(trim($request->email)); $bor = User::where('email', $email)->exists(); User::create(['email' => $email, ...]);

🔑 Umumiy saboq: qoidani bazaga emas, kodga yozing. Shunda u ko'chganda ham o'zgarmaydi — va o'qigan odam ko'radi.

🔍 Va eski ma'lumotni ham tozalash kerak: bazada allaqachon Ali@ va ali@ bo'lsa, ular birlashtirilishi yoki hal qilinishi lozim. Aks holda unique indeks qo'yishning o'zi xato beradi.

SAVOL 1 maosh (integer) ustuniga 'salom' yozsangiz nima bo'ladi?

🔍 O'lchandi: SQLite 'salom' ni saqlab qo'ydi; MySQL — 1366 Incorrect integer value. Xuddi shunday varchar(255) ga 300 belgi: SQLite 305 belgini saqladi, MySQL — 1406 Data too long. 🔑 Sabab: MySQL 8 da STRICT_TRANS_TABLES standart yoqiq.

SAVOL 2 Bazada 'ZOND Dasturchi', 'ZOND dasturchi', 'ZOND DASTURCHI' bor. where('nom', 'ZOND Dasturchi') nechta topadi?

🔍 O'lchandi: SQLite 1, MySQL 3. Xato yo'q — javob boshqacha. Sabab: MySQL 8 standarti utf8mb4_0900_ai_ci — ci registrni, ai urg'uni e'tiborsiz qoldiradi (o'lchandi: Café = Cafe). SQLite'da esa BINARY.

SAVOL 3 Qidiruv ikkala bazada bir xil ishlashi uchun nima qilasiz?

🔍 O'lchandi: whereLike('nom', '%dasturchi%') → ikkalasida ham 2; caseSensitive: true bilan → ikkalasida ham 1. Laravel yozgan SQL: MySQL'da like binary, SQLite'da glob. 🔑 Baza xulqiga bog'liq joyni o'zingiz emas, Laravel hal qilsin.

Eslab ayting

Javobni ovoz chiqarib ayting, keyin ochib solishtiring.

MySQL'ga o'tish uchun nima kerak?
Ikki alohida narsa: mysql-server (ma'lumotni saqlaydi) va php8.3-mysql (PHP'ning drayveri). Tekshiruv: php -m | grep pdo_mysql. So'ng: baza + foydalanuvchi + huquq yaratish (utf8mb4 bilan), oltita DB_* qatori, config:clear, migrate. 🔍 migrate:fresh: MySQL 1.47s, SQLite 0.42s.
To'rtta ulanish xatosi nimani aytadi?
could not find driver → drayver o'rnatilmagan (serverga tegishi yo'q). 2002 Connection refused → serverga yetib bormadi (ishlamayapti / port). 1045 Access denied ... (using password: YES) → parol. 1044 Access denied ... to database 'X' → baza yo'q yoki huquq berilmagan. 🔑 Raqamni o'qing — u qayerga qarashni aytadi.
⭐ Qanday farq eng xavfli va nega?
Xato yo'q, natija boshqacha. 🔍 O'lchandi: uchta yozuv (ZOND Dasturchi / dasturchi / DASTURCHI), where('nom', 'ZOND Dasturchi') → SQLite 1, MySQL 3. Sabab: utf8mb4_0900_ai_ci — ci registrsiz, ai urg'usiz (Café = Cafe); SQLite'da BINARY. ⚠️ Xavfli, chunki test yashil qoladi va xato faqat foydalanuvchi shikoyatida ko'rinadi. ✅ Yechim: whereLike() — Laravel MySQL'da like binary, SQLite'da glob yozadi.
SQLite yana nimalarni o'tkazib yuboradi?
🔍 O'lchandi: 1) integer ustunga 'salom' — saqladi (MySQL: 1366). 2) varchar(255) ga 300 belgi — 305 saqladi (MySQL: 1406). 3) guruhlanmagan ustunli group by — ishladi (MySQL: 1055). 4) Ustun tipini ham saqlamaydi: varchar(255) → varchar. 5) ⚠️ DDL tranzaksiyasi: SQLite create table ni qaytardi, MySQL qaytarmadi — yarim bajarilgan migratsiya tiqilib qoladi.
Testlar MySQL'da ishlashini qanday ta'minlaysiz?
