Topib bo'lmaydigan klass

36-darsda shunday yozgandik:

Log::info("Fayl yuklandi: {$nom}");

Bu statik metod chaqiruvi ko'rinishida. Demak Log degan klass bo'lishi kerak va unda info() degan statik metod bo'lishi kerak.

Lekin 49-darsda boshqa narsa ham ko'rdik:

app('log') → Illuminate\Log\LogManager

Ikkalasi ham logga yozadi. Ikkalasi ham ishlaydi. Lekin biri statik, ikkinchisi obyekt. Qaysi biri haqiqiy?

Va yana bir savol: Log ni yozganimizda hech qachon use qilmaganmiz. PHP'da bu mumkin emas — namespace'siz nom faqat global fazoda qidiriladi.

Bugun ikkala savolga ham javob beramiz. Va javob hayratlanarli darajada oddiy.

Birinchi qadam: klassni topamiz

Sir: __callStatic

PHP'da agar mavjud bo'lmagan statik metod chaqirilsa, PHP xato bermasdan oldin klassdagi __callStatic metodini qidiradi. Bu — «sehrli metod», 09-darsdagi __construct va __toString ning qarindoshi.1

Facade klassida u shunday:

vendor/.../Illuminate/Support/Facades/Facade.php
public static function __callStatic($method, $args) { $instance = static::getFacadeRoot(); if (! $instance) { throw new RuntimeException('A facade root has not been set.'); } return $instance->$method(...$args); }

Uch qator ish qiladi:

1) obyektni topadi getFacadeRoot() 2) topilmasa — xato "A facade root has not been set." 3) metodni O'SHA obyektda chaqiradi $instance->$method(...$args)

Ya'ni Log::info('salom') aslida:

Log::info('salom') ↓ (PHP: bunday statik metod yo'q → __callStatic) Facade::__callStatic('info', ['salom']) ↓ $instance = getFacadeRoot() ↓ $instance->info('salom') ← oddiy obyekt metodi

Statik chaqiruv faqat yozilishida. Ish esa oddiy obyektda bajariladi.

Ildiz qayerdan keladi?

Facade.php
public static function getFacadeRoot() { return static::resolveFacadeInstance(static::getFacadeAccessor()); } protected static function resolveFacadeInstance($name) { if (isset(static::$resolvedInstance[$name])) { return static::$resolvedInstance[$name]; } if (static::$app) { if (static::$cached) { return static::$resolvedInstance[$name] = static::$app[$name]; } return static::$app[$name]; } }

static::$app[$name] — bu container. Application klassi ArrayAccess ni amalga oshiradi (49-darsda interfeyslar ro'yxatida ko'rgandik), shuning uchun $app['log'] — app()->make('log') ning qisqasi.

O'lchaymiz:

Log::getFacadeRoot() → Illuminate\Log\LogManager app('log') → Illuminate\Log\LogManager AYNAN bir obyektmi: HA Route uchun ham: HA (Route::getFacadeRoot() === app('router'))
🔑 Zanjir yopildi
49-dars: container obyektlarni yasaydi 50-dars: provider'lar container'ni to'ldiradi 51-dars: fasad — container'dan olishning CHIROYLI yozilishi

Ya'ni Log::info(...) — app('log')->info(...) ning qisqartmasi. Boshqa hech narsa emas.

🔍 $resolvedInstance — kesh: bir so'rovda Log:: ni yuz marta yozsangiz ham container bir marta so'raladi.

Nega use kerak emas?

Ikkinchi savol qoldi: Log ni namespace'siz yozganimizda PHP uni qanday topadi?

config('app.aliases') → 47 ta Log -> Illuminate\Support\Facades\Log Route -> Illuminate\Support\Facades\Route Auth -> Illuminate\Support\Facades\Auth Arr -> Illuminate\Support\Arr ← fasad emas, oddiy klass ...

Bu ro'yxat qayerdan? config/app.php da aliases kaliti yo'q — u framework faylida:

vendor/laravel/framework/config/app.php:186 'aliases' => Facade::defaultAliases()->merge([ // 'Example' => App\Facades\Example::class, ])->toArray(),

Ro'yxatni ishga soladigan joy — RegisterFacades, ilova yuklanishining bosqichlaridan biri (17-dars):

Illuminate/Foundation/Bootstrap/RegisterFacades.php
public function bootstrap(Application $app) { Facade::clearResolvedInstances(); Facade::setFacadeApplication($app); AliasLoader::getInstance(array_merge( $app->make('config')->get('app.aliases', []), $app->make(PackageManifest::class)->aliases() ))->register(); }

Uch qadam: keshni tozalash → container'ni fasadlarga berish → taxalluslarni ro'yxatdan o'tkazish.

Ikkinchi qadam eng muhimi: setFacadeApplication($app) — bu static::$app ni to'ldiradi. Usiz resolveFacadeInstance null qaytaradi.

AliasLoader — bu autoloader

Illuminate/Foundation/AliasLoader.php
public function register() { if (! $this->registered) { spl_autoload_register($this->load(...), true, true); $this->registered = true; } } public function load($alias) { if (static::$facadeNamespace && str_starts_with($alias, static::$facadeNamespace)) { $this->loadFacade($alias); return true; } if (isset($this->aliases[$alias])) { return class_alias($this->aliases[$alias], $alias); } }

Ya'ni Laravel PHP'ning avtoyuklash navbatiga o'z funksiyasini qo'yadi. PHP Log ni topa olmaganda uni chaqiradi, u esa class_alias('Illuminate\Support\Facades\Log', 'Log') qiladi — 12-darsdagi Composer autoload bilan bir mexanizm.

Bu yalqov ekanini o'lchash mumkin:

class_exists('Log', false) → false ← avtoyuklashsiz: yo'q class_exists('Log') → true ← avtoyuklash bilan: yasaldi class_exists('Log', false) → true ← endi bor

47 ta taxallus ro'yxatda turadi, lekin faqat ishlatilgani yaratiladi.
