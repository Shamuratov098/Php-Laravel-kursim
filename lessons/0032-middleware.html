DARS 32 · MODUL D — FOYDALANUVCHI VA HUQUQLAR

Middleware: qatlamlarni o'zimiz yozamiz

17-darsda middleware'ni piyoz qatlamlari sifatida ko'rgandik, 30-darsda esa middleware('auth') ni ishlatdik. Bugun o'zimiz yozamiz — va piyoz naqshini log faylida o'z ko'zimiz bilan ko'ramiz.

📱 O'qish ≈ 15 daqiqa 💻 Amaliyot ≈ 24 daqiqa Kerak: Dars 31

Bu darsda nimalar bor
  1. Middleware nima va qachon kerak Har so'rovda takrorlanadigan ish — tekshirish, o'lchash, til tanlash — controllerda emas, yo'lda bajariladi.
  2. make:middleware Yasalgan klassning yagona metodi: handle(Request $request, Closure $next).
  3. 🔍 Piyoz naqshi — jonli isbot $next($request) dan oldin va keyin kod. Ikki middleware bilan log tartibi o'lchanadi.
  4. ⚠️ Laravel 11+ da Kernel.php YO'Q Eski qo'llanmalar app/Http/Kernel.php haqida yozadi — u o'chirilgan. Endi hammasi bootstrap/app.php da (17-dars!).
  5. Ro'yxatdan o'tkazishning uch usuli alias (nom berish) · append/prepend (global) · guruhga qo'shish.
  6. Qo'llashning uch shakli Bitta route'ga · massiv bilan bir nechta · Route::middleware([...])->group().
  7. To'xtatuvchi middleware $next chaqirilmasa controller umuman ishlamaydi — auth aynan shunday ishlaydi.
  8. Parametrli middleware 'til:en' · 'throttle:5,1' — ikki nuqtadan keyingi qiymat metodga argument bo'lib boradi.
  9. Har xil holatlar (7 ta) Tartib · global middleware xavfi · $next ni unutish · javobni o'zgartirish · terminate() · route:list -v · guest middleware.
  10. IshTop'da natija Har so'rovning vaqti o'lchanadi va javob sarlavhasiga qo'shiladi; til ?til=en bilan almashadi va sessiyada eslab qolinadi.
Nega bu muhim

Ba'zi ishlar har so'rovda takrorlanadi: «kirganmi?», «huquqi bormi?», «qaysi til?», «bu so'rov qancha vaqt oldi?». Ularni har controllerda yozish — takrorlanish va unutish demak (bittasida yozmay qolsangiz, teshik ochiladi).

Middleware shu ishlarni yo'lga qo'yadi: so'rov controllerga yetib borgunicha va javob brauzerga qaytgunicha o'tadigan qatlam.

Siz uni allaqachon ishlatgansiz — middleware('auth') (30-dars). Bugun uni ichidan ko'ramiz. Va bu bilim keyingi darslar uchun ham kerak: huquqlar (33), rollar (34) — hammasi shu mexanizmga tayanadi.

make:middleware — bitta metod

terminal
php artisan make:middleware SoravniOlchash
app/Http/Middleware/SoravniOlchash.php — yasalgani
class SoravniOlchash { public function handle(Request $request, Closure $next): Response { return $next($request); } }

Butun mexanizm shu bitta qatorda. $next — closure (16-dars): «zanjirning qolgan qismi». Uni chaqirsangiz so'rov oldinga ketadi; chaqirmasangiz — to'xtaydi.

Va eng muhimi: $next($request) javobni qaytaradi. Ya'ni kod yozish uchun ikkita joy bor:

public function handle(Request $request, Closure $next): Response { // ── 1) BU YERDA: so'rov hali controllerga bormagan // $request ni o'qish, tekshirish, to'xtatish mumkin $javob = $next($request); ← controller shu yerda ishlaydi // ── 2) BU YERDA: javob tayyor // $javob ni o'zgartirish, sarlavha qo'shish, o'lchash mumkin return $javob; }

🔍 Piyoz naqshi — jonli isbot

17-darsda middleware'ni piyoz qatlamlari deb chizgandik. Endi buni o'lchaymiz. Ikkita middleware yozamiz va har biri kirish-chiqishini logga yozsin:

app/Http/Middleware/SoravniOlchash.php
public function handle(Request $request, Closure $next): Response { $boshlandi = microtime(true); Log::info('[olchash] KIRDI: ' . $request->method() . ' ' . $request->path()); $javob = $next($request); $sarflandi = round((microtime(true) - $boshlandi) * 1000, 1); Log::info('[olchash] CHIQDI: ' . $request->path() . ' — ' . $sarflandi . ' ms, status ' . $javob->getStatusCode()); $javob->headers->set('X-Sarflangan-Vaqt', $sarflandi . 'ms'); return $javob; }

Ikkalasini bitta route'ga qo'yib, log'ga qaraymiz:

Route::get('/vakansiyalar', ...)->middleware(['olchash', 'til']); ── storage/logs/laravel.log [olchash] KIRDI: GET vakansiyalar ← tashqi qatlam kirdi [til] kirdi — standart: uz ← ichki qatlam kirdi ← CONTROLLER shu yerda ishladi [til] chiqdi — locale: uz ← ichki qatlam chiqdi [olchash] CHIQDI: vakansiyalar — 31.8 ms ← tashqi qatlam chiqdi

🎯 Mana piyoz. Birinchi yozilgan middleware — eng tashqi qatlam: u birinchi kiradi va oxirgi chiqadi. Javob middleware'lardan teskari tartibda qaytadi.

Va javob sarlavhasida natija ko'rinadi:

$ curl -D - http://localhost:8000/vakansiyalar X-Sarflangan-Vaqt: 30.3ms

⚠️ Laravel 11+ da Kernel.php yo'q

Internetdagi ko'p qo'llanma «middleware'ni app/Http/Kernel.php ga qo'shing» deydi. Laravel 11 dan boshlab bu fayl umuman yo'q:

$ ls app/Http/Kernel.php ls: cannot access 'app/Http/Kernel.php': No such file or directory

Uning o'rniga — bootstrap/app.php. 17-darsda uni ochib ko'rgandik, va o'shanda bo'sh joy bor edi. Mana o'sha joy:

bootstrap/app.php
->withMiddleware(function (Middleware $middleware): void { $middleware->alias([ 'olchash' => \App\Http\Middleware\SoravniOlchash::class, 'til' => \App\Http\Middleware\TilniTanla::class, ]); })

🎯 17-darsda «bu bo'sh joy nima uchun?» degan savol tug'ilgandi — javobi shu.

Uch xil ro'yxatdan o'tkazish

UsulQachon
$middleware->alias([...])Nom beradi, keyin route'da middleware('olchash'). Eng ko'p ishlatiladigan
$middleware->append(Klass::class)Global: har so'rovda, oxirgi qatlam sifatida
$middleware->prepend(Klass::class)Global, birinchi qatlam sifatida
$middleware->web(append: [...])Faqat web guruhiga (sessiya, CSRF bor route'lar)

Qo'llashning uch shakli

routes/web.php
// 1) bitta route'ga Route::get('/vakansiyalar', ...)->middleware('olchash'); // 2) bir nechta — massiv bilan Route::get('/vakansiyalar', ...)->middleware(['olchash', 'til']); // 3) guruhga — ichidagi HAMMA route'ga qo'llanadi Route::middleware(['olchash', 'til'])->group(function () { Route::get('/vakansiyalar', ...)->name('vakansiyalar.index'); Route::get('/vakansiyalar/{id}', ...)->name('vakansiyalar.show'); });

Qaysi route'da qanday middleware borligini ko'rish — route:list -v (24-darsdagi buyruqning batafsil shakli):

GET|HEAD vakansiyalar vakansiyalar.index › VakansiyaController@index ⇂ web ⇂ olchash ⇂ til POST vakansiyalar vakansiyalar.store › VakansiyaController@store ⇂ web ⇂ auth

web — Laravel o'zi qo'yadigan guruh: sessiya, cookie, CSRF (19-dars). Ya'ni har web so'rovda allaqachon bir nechta middleware ishlab turibdi.

To'xtatuvchi middleware

$next($request) ni chaqirmasangiz, so'rov oldinga ketmaydi — controller umuman ishlamaydi. auth aynan shunday ishlaydi (30-dars).

app/Http/Middleware/FaqatIshVaqti.php
public function handle(Request $request, Closure $next, int $boshi = 9, int $oxiri = 18): Response { $soat = (int) now()->format('H'); if ($soat < $boshi || $soat >= $oxiri) { return redirect()->route('vakansiyalar.index') ->with('xabar', "Bu amal faqat {$boshi}:00–{$oxiri}:00 orasida mumkin."); } return $next($request); }
Route::post('/vakansiyalar', ...)->middleware(['auth', 'ishvaqti:0,1']); POST yuborilganda (soat 12 da): status: 302 → /vakansiyalar xabar: Bu amal faqat 0:00–1:00 orasida mumkin. Controller CHAQIRILMADI — vakansiya qo'shilmadi.

Parametrli middleware

Yuqoridagi misolda 'ishvaqti:0,1' yozildi. Ikki nuqtadan keyingi qiymatlar handle() ga qo'shimcha argument bo'lib boradi:

'ishvaqti:0,1' ↓ ↓ handle($request, $next, $boshi = 0, $oxiri = 1) 'til:en' → handle($request, $next, $standart = 'en') 'throttle:5,1' → Laravel'ning o'z middleware'i (31-darsdagi rate limiting)

Parametr bo'lmasa, metoddagi standart qiymat ishlatiladi. Shuning uchun 'til' va 'til:en' ikkalasi ham to'g'ri.

Har xil holatlar

Yetti holat. Bu bo'lim ma'lumotnoma — hozir bir marta o'qib chiqing, keyin kerak bo'lganda qaytib qarang.

HOLAT 1

Tartib muhim

Middleware'lar yozilgan tartibda kiradi va teskari tartibda chiqadi:

middleware(['olchash', 'til']) olchash KIRDI til KIRDI controller til CHIQDI olchash CHIQDI

Bu amalda muhim: olchash tashqarida bo'lgani uchun u til ning vaqtini ham o'lchaydi. Agar tartibni almashtirsangiz, o'lchov til ni hisobga olmaydi.

Xuddi shunday: auth dan oldin turgan middleware kirmagan foydalanuvchi uchun ham ishlaydi; keyin turgani esa faqat kirganlar uchun.

HOLAT 2

$next ni unutish

public function handle(Request $request, Closure $next): Response { Log::info('kirdi'); // return $next($request); ← UNUTILDI }

Natija: PHP null qaytaradi, Laravel esa Response kutadi:

TypeError: ...::handle(): Return value must be of type Symfony\Component\HttpFoundation\Response, none returned

Xato aniq va darhol chiqadi — bu yaxshi. Lekin return ni yozib, $next ni shartli chaqirsangiz (masalan if ichida) va shart bajarilmasa — sahifa jimgina to'xtaydi. Shuning uchun har tarmoqda nimadir qaytishi kerak.

HOLAT 3

Global middleware — ehtiyot bo'ling

$middleware->append(\App\Http\Middleware\SoravniOlchash::class);

Endi u har so'rovda ishlaydi — shu qatorda:

  • statik fayllar so'rovi;
  • /up (sog'liq tekshiruvi);
  • API so'rovlari;
  • xato sahifalari.

Agar middleware sekin bo'lsa yoki bazaga yozsa, bu har so'rovga qo'shiladi. Log yozadigan middleware global qilinsa, log fayli tez to'lib ketadi.

✅ Qoida: avval alias bilan aniq route'larga qo'ying. Global qilish — faqat haqiqatan hamma joyda kerak bo'lsa (masalan xavfsizlik sarlavhalari).

HOLAT 4

Javobni o'zgartirish

$next dan keyin javob obyekt — uni o'zgartirish mumkin:

$javob = $next($request); $javob->headers->set('X-Sarflangan-Vaqt', $sarflandi . 'ms'); // sarlavha qo'shish $javob->setStatusCode(200); // statusni almashtirish return $javob;

Bu naqsh real loyihalarda ko'p ishlatiladi: xavfsizlik sarlavhalari (X-Frame-Options), kesh sarlavhalari, so'rov identifikatori.

⚠️ Lekin javob allaqachon yuborilgan bo'lsa (masalan fayl oqimi), o'zgartirish ish bermaydi. Bunday hollarda terminate() ishlatiladi (keyingi holat).

HOLAT 5

terminate() — javob yuborilgandan keyin

public function terminate(Request $request, Response $response): void { // Javob foydalanuvchiga YUBORILGANDAN keyin ishlaydi Log::info('so\'rov tugadi'); }

Foydasi: og'ir ishni (statistika yozish, log yuborish) foydalanuvchi kutmaydi — sahifa allaqachon ochilgan bo'ladi.

⚠️ Bu faqat php artisan serve yoki FPM kabi muhitlarda kutilganidek ishlaydi. Sekin ishlar uchun to'g'riroq yechim — navbat (queue), Modul H da ko'ramiz.

HOLAT 6

guest middleware — auth ning teskarisi

Kirgan odam kirish sahifasini ko'rishi mantiqsiz. Laravel'da tayyor middleware bor:

Route::get('/kirish', ...)->name('login')->middleware('guest'); Route::get('/royxatdan-otish', ...)->middleware('guest'); Kirgan odam /kirish ga borsa → 302 → bosh sahifaga

31-darsdagi Breeze aynan shunday qiladi: barcha auth route'lari Route::middleware('guest')->group(...) ichida.

Qayerga yuborishni bootstrap/app.php dagi $middleware->redirectUsersTo('/vakansiyalar') belgilaydi.

HOLAT 7

Middleware'ni ko'rish va tekshirish

php artisan route:list -v ← har route ostida middleware ro'yxati php artisan route:list --path=vakansiyalar -v GET|HEAD vakansiyalar ⇂ web ← Laravel qo'ygan guruh (sessiya, CSRF) ⇂ olchash ← bizniki ⇂ til ← bizniki

Bu «nega bu sahifa 302 qaytaryapti?» degan savolga javob topishning eng tez yo'li: route'da auth bormi? Kutilmagan middleware bormi?

Log ham foydali: har middleware kirish-chiqishini yozsa, tartib storage/logs/laravel.log da ko'rinadi (bugungi amaliyotda shunday qilamiz).

Sinab ko'ramiz

Natijani taxmin qiling

Ikkita middleware, har biri kirish va chiqishini logga yozadi:

kod
// SoravniOlchash Log::info('A kirdi'); $javob = $next($request); Log::info('A chiqdi'); // TilniTanla Log::info('B kirdi'); $javob = $next($request); Log::info('B chiqdi'); // routes/web.php Route::get('/vakansiyalar', ...)->middleware(['olchash', 'til']);

Sahifa ochilganda log faylida qanday tartibda to'rt qator paydo bo'ladi?

Javobni ko'rish
A kirdi B kirdi ← controller shu yerda ishlaydi B chiqdi A chiqdi

Ko'pchilik «A kirdi, A chiqdi, B kirdi, B chiqdi» deb o'ylaydi — go'yo ular navbat bilan ishlaydigandek. Aslida ular bir-birining ichida.

Sabab $next($request) ning tabiatida: u «keyingi qadamni bajar va natijasini qaytar» degani. A ning $next i — butun qolgan zanjir (B + controller). Shuning uchun A ning ikkinchi qismi faqat hammasi tugagandan keyin ishlaydi.

🔑 Amaliy natija: birinchi yozilgan middleware — eng tashqi qatlam:

  • u birinchi ko'radi so'rovni (tekshirish uchun qulay);
  • u oxirgi ko'radi javobni (o'lchash va o'zgartirish uchun qulay);
  • uning vaqt o'lchovi ichkaridagilarni ham qamrab oladi.

Jonli o'lchandi (17-darsdagi «piyoz» chizmasining isboti):

[olchash] KIRDI: GET vakansiyalar [til] kirdi — standart: uz [til] chiqdi — locale: uz [olchash] CHIQDI: vakansiyalar — 31.8 ms, status 200

SAVOL 1 Laravel 11+ da middleware qayerda ro'yxatdan o'tkaziladi?

app/Http/Kernel.php Laravel 11 dan beri umuman yo'q — eski qo'llanmalar shu sababdan chalkashtiradi. 17-darsda ko'rgan withMiddleware bo'sh joyi aynan shu uchun edi.

SAVOL 2 $next($request) dan keyingi kod qachon ishlaydi?

$next($request) — «qolgan zanjirni bajar va javobni qaytar». Shuning uchun undan keyingi kod javob tayyor bo'lganda ishlaydi: o'lchash, sarlavha qo'shish uchun aynan shu joy.

SAVOL 3 Middleware $next ni chaqirmasa nima bo'ladi?

Aynan shu auth ning ishlash usuli: shart bajarilmasa redirect qaytariladi va so'rov oldinga ketmaydi. Lekin biror narsa qaytishi shart — aks holda TypeError.

Eslab ayting

Avval o'zingiz javob bering, keyin ochib tekshiring. Oxirgi ikkitasi — 31-darsni takrorlash.

Middleware'da kod yozish uchun nechta joy bor?

Ikkita: $next($request) dan oldin (so'rovni tekshirish, to'xtatish) va keyin (javobni o'zgartirish, o'lchash).

Birinchi yozilgan middleware qaysi qatlam bo'ladi?

Eng tashqi: birinchi kiradi, oxirgi chiqadi. Uning vaqt o'lchovi ichkaridagilarni ham qamrab oladi.

Parametr middleware'ga qanday uzatiladi?

Ikki nuqta bilan: 'til:en' → handle($request, $next, $standart = 'en'). Bir nechta parametr vergul bilan: 'ishvaqti:0,1'.

Cho'ntak xulosasi
  • php artisan make:middleware Nomi — yagona metod: handle(Request $request, Closure $next).
  • 🔑 Kod yozish uchun ikki joy: $next($request) dan oldin va keyin. $next javobni qaytaradi.
  • 🔍 Piyoz: birinchi middleware — eng tashqi qatlam, birinchi kiradi va oxirgi chiqadi. Logda o'lchandi.
  • ⚠️ Laravel 11+ da app/Http/Kernel.php YO'Q. Hammasi bootstrap/app.php dagi withMiddleware da.
  • Ro'yxatdan o'tkazish: alias([...]) (nom) · append/prepend (global) · web(append: [...]) (guruh).
  • Qo'llash: ->middleware('nom') · ->middleware(['a', 'b']) · Route::middleware([...])->group(...).
  • 🔒 $next chaqirilmasa — controller ishlamaydi. auth aynan shunday. Lekin biror narsa qaytishi shart.
  • Parametr: 'til:en' · 'ishvaqti:0,1' → handle(..., $a, $b). Berilmasa standart qiymat ishlaydi.
  • Javobni o'zgartirish: $javob->headers->set(...). Javob yuborilgandan keyin ishlash — terminate().
  • route:list -v — har route ostida middleware ro'yxati. «Nega 302?» savoliga eng tez javob.
  • ⚠️ Global middleware har so'rovda ishlaydi — avval alias bilan aniq route'larga qo'ying.
🌱 Keyingi dars

Endi «kirganmi?» degan savolga javob bera olamiz. Lekin tez orada boshqa savol keladi: «bu vakansiyani kim tahrirlashi mumkin?» Javob «kirgan har qanday odam» bo'lsa — bir foydalanuvchi boshqasining e'lonini o'chirib yuboradi.

Middleware bunga to'liq javob bera olmaydi: u route darajasida ishlaydi, savol esa aniq yozuv haqida («shu vakansiya shu odamniki-mi?»).

33-darsda Gate va Policy bilan tanishamiz — Laravel'ning huquq tekshirish mexanizmi. @can Blade direktivasi, controllerdagi authorize() va 403 javobi.
