Mail

49-darsda XabarYuboruvchi interfeysini yozib, va'da bergandik: «ertaga boshqa amalga oshiruvchi yozsangiz, controller o'zgarmaydi». Bugun o'sha va'dani bajaramiz — haqiqiy email bilan. Va yo'lda bitta test ikki marta qizaradi.

📱 O'qish ≈ 16 daqiqa 💻 Amaliyot ≈ 26 daqiqa Kerak: Dars 55

Bu darsda nimalar bor
  1. log drayveri — xavfsiz sinash Email hech kimga ketmaydi, laravel.log ga yoziladi. 🔍 Sarlavhalari bilan birga ko'rsatiladi.
  2. make:mail --markdown Mailable klass + Blade shablon. Uch metod: envelope, content, attachments.
  3. Markdown komponentlari x-mail::message · panel · button — tayyor dizayn, HTML yozish kerak emas.
  4. with: — shablonga ma'lumot Model avtomatik uzatiladi, hisoblangan qiymat esa with orqali.
  5. ⚠️ ShouldQueue xatda 🔍 O'lchandi: send() yozdik, lekin email ketmadi — navbatga tushdi.
  6. ⚠️ assertSent topa olmadi Test ikki marta qizardi. Laravel o'zi maslahat berdi: «Did you mean to use assertQueued() instead?»
  7. 49-darsdagi va'da bajarildi EmailXabar yozildi va .env dagi bitta qiymat bilan almashtirildi. Controller ham, tinglovchi ham tegilmadi.
  8. Config bilan drayver tanlash match bilan container'da: 49 + 50 + 54-darslar bir joyda ishlaydi.
  9. Mail::fake() assertQueued · assertNotSent · assertNothingSent · hasTo bilan shart.
  10. Shablonni alohida tekshirish render() — HTML satrini qaytaradi, hech narsa yuborilmaydi.
  11. Ishlab chiqarishga chiqish MAIL_MAILER drayverlari va nima uchun from manzil muhim.
  12. Har xil holatlar (7 ta) Ilova · nusxa · lokalizatsiya · spam · Mail::raw · Mailtrap.
Va'da qarzi

49-darsda shunday yozgandik:

interface XabarYuboruvchi { public function yubor(string $kimga, string $matn): string; }

Va sabab keltirgandik: «ertaga SmsXabar yozsangiz — controller o'zgarmaydi».

Bu va'da edi. Bugun uni tekshiramiz: haqiqiy email yuboruvchi yozamiz va ko'ramizki, controller, hodisa, tinglovchi — hech biri tegilmaydi.

Boshlashdan oldin bitta xavotir: sinab ko'rayotganda haqiqiy odamlarga email ketib qolmasinmi?

Laravel buni hal qilgan. .env ga qarang:

MAIL_MAILER=log

Bu — standart qiymat. Email hech qayerga ketmaydi, u storage/logs/laravel.log ga yoziladi. Ya'ni xatolar bilan sinash xavfsiz.

Mailable yozish

php artisan make:mail VakansiyaEloni --markdown=mail.vakansiya-eloni INFO Markdown view [resources/views/mail/vakansiya-eloni.blade.php] created successfully.

Ikki fayl yaratildi: klass (nima yuborilishi) va shablon (qanday ko'rinishi).

app/Mail/VakansiyaEloni.php
<?php namespace App\Mail; use App\Models\Vakansiya; use Illuminate\Bus\Queueable; use Illuminate\Contracts\Queue\ShouldQueue; use Illuminate\Mail\Mailable; use Illuminate\Mail\Mailables\Content; use Illuminate\Mail\Mailables\Envelope; use Illuminate\Queue\SerializesModels; class VakansiyaEloni extends Mailable implements ShouldQueue { use Queueable, SerializesModels; public function __construct(public Vakansiya $vakansiya) {} public function envelope(): Envelope { return new Envelope( subject: "Yangi vakansiya: {$this->vakansiya->nom}", ); } public function content(): Content { return new Content( markdown: 'mail.vakansiya-eloni', with: ['maoshMatni' => $this->vakansiya->maoshFormat()], ); } }
envelope() → konvert: mavzu, kimdan, javob manzili content() → ichi: qaysi shablon va unga qanday ma'lumot attachments() → ilovalar (bizda yo'q)

public Vakansiya $vakansiya — ommaviy xossa shablonga avtomatik uzatiladi. Hisoblangan qiymat esa (maoshFormat()) with: orqali.

ShouldQueue va SerializesModels — 55-darsdan tanish. Xat ham ish, va uning ham navbatda joyi bor.

🔑 Nega Markdown, oddiy HTML emas?

Email HTML'i — alohida dunyo. Gmail, Outlook va telefon ilovalari har xil qoidalarga ega: CSS'ning yarmi ishlamaydi, tugma uchun jadval kerak bo'ladi.

Markdown komponentlari sinovdan o'tgan HTML beradi. Va Laravel avtomatik matnli nusxa ham yasaydi — email mijozi HTML'ni ko'rsata olmasa, matn ko'rinadi.

🔍 Uslubni o'zgartirmoqchi bo'lsangiz: php artisan vendor:publish --tag=laravel-mail.

⚠️ ShouldQueue send() ni ham ushlaydi

Mailable ShouldQueue ni amalga oshirsa, send() ham queue() kabi ishlaydi: xat navbatga tushadi.

Bu foydali — xat yuborish sekin amal (SMTP serveriga ulanish), va u foydalanuvchini kutdirmasligi kerak.

⚠️ Lekin kutilmagan bo'lsa chalg'itadi: «men send() yozdim, nega ketmadi?»

Ishchini ishga tushiramiz:

php artisan queue:work --stop-when-empty App\Mail\VakansiyaEloni ...... RUNNING App\Mail\VakansiyaEloni ...... 75.63ms DONE

Endi logda xat bor — 146 qator:

multipart/alternative — ikkita nusxa: matn va HTML. Va 2 500 so'm — with: orqali uzatgan qiymatimiz (41-darsdagi Maosh::format).

Har xil holatlar

Yetti holat. Bu bo'lim ma'lumotnoma — hozir bir marta o'qib chiqing, keyin kerak bo'lganda qaytib qarang.

HOLAT 1

Bir necha qabul qiluvchi

Mail::to($user) ->cc('rahbar@ishtop.uz') ->bcc('arxiv@ishtop.uz') ->send(new VakansiyaEloni($v));

to() ga model ham berish mumkin — Laravel undagi email va name maydonlarini o'zi oladi.

⚠️ Mail::to([$u1, $u2]) — bitta xat, ikkala manzil ko'rinadi. Alohida yuborish uchun siklda Mail::to($u)->send(...).

HOLAT 2

Dasturchi ariza kelganda ish beruvchiga xat yuborishni yozdi:

Testda tekshirdi — ishladi. Ishlab chiqarishga chiqardi.

Bir hafta o'tib katta kompaniya (200 xodim) ro'yxatdan o'tdi. Endi har ariza kelganda sayt bir necha soniya qotib qoladi, ba'zan esa 502 beradi. Nima bo'lyapti?

Javobni ko'rish

Ikki narsa birga yiqilyapti.

1. Tinglovchida ShouldQueue yo'q (53-dars). Demak sikl foydalanuvchining so'rovi ichida aylanadi.

2. Mail::to()->send() 200 marta. Agar ArizaEloni da ShouldQueue bo'lsa — bu 200 ta navbat yozuvi, ya'ni 200 ta INSERT. Bo'lmasa — 200 ta SMTP ulanishi.

200 × SMTP ulanish × ~200 ms ≈ 40 soniya → nginx/php-fpm timeout → 502

⚠️ Va foydalanuvchi 502 ko'rgani bilan ariza saqlangan — 53-darsdagi «500, lekin yozuv bazada» holatining o'zi.

🔍 Nega testda ko'rinmadi? Uch sabab:

1) testda 1-2 xodim bor edi, 200 emas 2) Mail::fake() haqiqiy SMTP'ga bormaydi — tez 3) QUEUE_CONNECTION=sync — navbat foydasi ko'rinmaydi

✅ Yechim ikki bosqichli:

1) Tinglovchiga ShouldQueue → so'rov darrov tugaydi 2) Siklni ham navbatga bo'ling: foreach ($xodimlar as $xodim) { ArizaXatiIsh::dispatch($ariza, $xodim); // har biri alohida ish } → bittasi yiqilsa qolganlari ketaveradi

EmailXabar yozildi va container'dagi bog'lanish config('ishtop.xabar_drayveri') ga bog'landi. 🔍 O'lchandi: log → LogXabar, email → EmailXabar. Controller, hodisa, tinglovchi va testlar — hech biri tegilmadi. 🔑 Uch dars birga ishladi: 49 (interfeys+container), 50 (provider), 54 (config).
Nega Markdown shablon, oddiy HTML emas?
Email HTML'i alohida dunyo — Gmail, Outlook va telefon ilovalari har xil qoidalarga ega, CSS'ning yarmi ishlamaydi. x-mail::message, panel, button — sinovdan o'tgan HTML beradi va Laravel avtomatik matnli nusxa ham yasaydi (multipart/alternative).
Testda haqiqiy xat ketib qolmasligi uchun nima qilasiz?
Ikki qatlam: 1) phpunit.xml da <env name="MAIL_MAILER" value="array"/> — to'r: kimdir fake() ni unutsa ham xat ketmaydi. 2) Har testda Mail::fake(). 🔑 54-darsdagi qoida: muhim sozlamalar phpunit.xml da, chunki u .env dan ustun.
