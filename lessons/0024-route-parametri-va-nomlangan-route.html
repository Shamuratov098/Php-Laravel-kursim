Manzildagi raqam: /vakansiyalar/3

Bazada 5 ta vakansiya bor, lekin sahifa hali ham 19-darsda qo'lda yozilgan massivni ko'rsatadi. Bugun ikkisini ulaymiz — va har vakansiyaga o'z manzili beramiz. Yo'lda chiroyli bog'lanish chiqadi: manzildagi {id} to'g'ri WHERE id = ? ga aylanadi.

📱 O'qish ≈ 12 daqiqa 💻 Amaliyot ≈ 22 daqiqa Kerak: Dars 23

Bu darsda nimalar bor
  1. Route parametri {id} Manzilning o'zgaruvchi qismi controller metodiga argument bo'lib boradi.
  2. 🔑 Route parametri → SQL parametri URL'ni istalgan odam o'zgartiradi, shuning uchun WHERE id = ? majburiy.
  3. abort(404) Topilmasa nima qilish kerak; bo'sh sahifa va 500 nima uchun xato yechim.
  4. Nomlangan route ->name() + route() — manzil bitta joyda yoziladi.
  5. route() ning xatolari «Missing required parameter» va «Route not defined» — xato ovoz chiqaradi.
  6. 🔑 Route tartibi Aniq yo'llar parametrlilardan oldin: /create va /{id} tuzog'i.
  7. Route::resource Bitta qatordan 7 route, standart nomlar bilan.
  8. 🎯 Sahifa bazaga ulanadi Qo'lda yozilgan massiv ketadi; forma haqiqatan saqlaydi.
Nega bu muhim

Har vakansiya o'z manziliga ega bo'lishi kerak. Sababi shunchaki qulaylik emas:

  • Havolani do'stingizga yuborish mumkin bo'ladi.
  • Google uni alohida sahifa sifatida indekslaydi.
  • Brauzerning «ortga» tugmasi to'g'ri ishlaydi.

Ikkinchi muammo esa havolalarni qo'lda yozish. Bugun 5 joyda href="/vakansiyalar/{{ $v->id }}" yozasiz. Ertaga manzilni /ishlar/… ga o'zgartirsangiz — 5 joyni topib tuzatish kerak, va bittasi albatta qolib ketadi. Nomlangan route shu muammoni yechadi: manzil bitta joyda yoziladi, qolgan joylarda uning nomi ishlatiladi.

Route parametri: manzilning o'zgaruvchi qismi

routes/web.php
Route::get('/vakansiyalar/{id}', [VakansiyaController::class, 'show']);

Jingalak qavs — «bu yerda istalgan qiymat bo'lishi mumkin». Laravel uni ushlab olib controller metodiga argument sifatida beradi:

app/Http/Controllers/VakansiyaController.php
public function show(string $id): View { $qatorlar = DB::select(' SELECT v.*, k.nom AS kompaniya FROM vakansiyalar v LEFT JOIN kompaniyalar k ON k.id = v.kompaniya_id WHERE v.id = ? ', [$id]); if ($qatorlar === []) { abort(404); } return view('vakansiyalar.show', ['v' => $qatorlar[0]]); }
🔑 Route parametri → SQL parametri

Diqqat qiling: URL'dan kelgan qiymat SQL satriga qo'shilmaydi, ? orqali beriladi. Bu 21-darsdagi qoidaning aynan o'zi — va bu yerda u ayniqsa muhim, chunki {id} ni istalgan odam o'zgartira oladi: manzil qatoriga nima yozsa, shu keladi.

Agar SQL'ga qo'shib yozganingizda, kimdir manzilga SQL bo'lagini yozib butun bazani o'qib olishi mumkin edi. Parametr esa qiymatni ma'lumot deb ishlaydi — u qanday ko'rinishda bo'lishidan qat'i nazar.

Topilmasa — abort(404)

/vakansiyalar/999 — bunday yozuv yo'q. DB::select bo'sh massiv qaytaradi, va bu holatni siz hal qilishingiz kerak:

YechimNatija
abort(404)✅ To'g'ri: brauzer 404 Not Found oladi
Hech narsa qilmaslik❌ $qatorlar[0] xato beradi — 500, ya'ni «bizning aybimiz»
Bo'sh sahifa ko'rsatish❌ Brauzer «sahifa bor» deb o'ylaydi, Google ham

abort(404) — 11-darsdagi throw ning Laravel shakli: funksiyani darhol to'xtatadi va javobni Laravel'ning o'zi yasaydi (<title>Not Found</title>). return yozish shart emas.

Nomlangan route va route()

routes/web.php
Route::get('/vakansiyalar', [VakansiyaController::class, 'index'])->name('vakansiyalar.index'); Route::post('/vakansiyalar', [VakansiyaController::class, 'store'])->name('vakansiyalar.store'); Route::get('/vakansiyalar/{id}', [VakansiyaController::class, 'show'])->name('vakansiyalar.show');

Nom berilgach, manzilni hech qayerda qo'lda yozmaysiz:

QayerdaKod
Blade'da havola<a href="{{ route('vakansiyalar.show', $v->id) }}">
Blade'da forma<form action="{{ route('vakansiyalar.store') }}">
Controller'da redirectredirect()->route('vakansiyalar.index')

Nom qolipi — resurs.amal: vakansiyalar.index, vakansiyalar.show. Bu Laravel'ning kelishuvi, va keyingi bo'limda nima uchun aynan shunday ekani ochiladi.

route('vakansiyalar.index') → http://localhost:8000/vakansiyalar route('vakansiyalar.show', 3) → http://localhost:8000/vakansiyalar/3

route() to'liq manzil qaytaradi (domen bilan) — bu email va bildirishnomalarda ham to'g'ri ishlashi uchun.

XatoXabar

Ikkalasi ham darhol va aniq aytadi — qo'lda yozilgan havola esa jimgina buzuq qoladi. Bu nomlangan route'ning yashirin foydasi: xato ovoz chiqaradi.

Route::resource — yetti route bitta qatorda

Har resurs (vakansiya, kompaniya, ariza) uchun bir xil yettita amal kerak bo'ladi. Laravel ularni bitta qatorda yasaydi:

routes/web.php
Route::resource('vakansiyalar', VakansiyaController::class);
GET|HEAD vakansiyalar vakansiyalar.index › index POST vakansiyalar vakansiyalar.store › store GET|HEAD vakansiyalar/create vakansiyalar.create › create GET|HEAD vakansiyalar/{vakansiyalar} vakansiyalar.show › show PUT|PATCH vakansiyalar/{vakansiyalar} vakansiyalar.update › update DELETE vakansiyalar/{vakansiyalar} vakansiyalar.destroy › destroy GET|HEAD vakansiyalar/{vakansiyalar}/edit vakansiyalar.edit › edit Showing [7] routes
  • Nomlar o'sha qolipda — endi vakansiyalar.index nomini o'zimiz o'ylab topmaganimiz ma'lum bo'ldi.
  • create — forma sahifasi, store — saqlash; edit — tahrir formasi, update — saqlash; destroy — o'chirish. @method (19-dars) shu yerda kerak bo'ladi.
  • Faqat bir qismi kerak bo'lsa: Route::resource(...)->only(['index', 'show', 'store']).
Hozircha uni ishlatmaymiz

Bizda hali create, edit, update, destroy metodlari yo'q — resource yozsak, bor bo'lmagan metodlarga ishora qiluvchi route'lar paydo bo'ladi. Shuning uchun bugun uni faqat ko'rib chiqamiz, keyin uch route'ni qo'lda qoldiramiz. To'liq CRUD tayyor bo'lganda unga o'tamiz.

Sinab ko'ramiz

Natijani taxmin qiling

«Yangi vakansiya» uchun alohida sahifa kerak bo'ldi va route oxiriga qo'shildi:

routes/web.php
Route::get('/vakansiyalar', [VakansiyaController::class, 'index'])->name('vakansiyalar.index'); Route::post('/vakansiyalar', [VakansiyaController::class, 'store'])->name('vakansiyalar.store'); Route::get('/vakansiyalar/{id}', [VakansiyaController::class, 'show'])->name('vakansiyalar.show'); Route::get('/vakansiyalar/create', function () { return 'YANGI VAKANSIYA FORMASI'; })->name('vakansiyalar.create');

/vakansiyalar/create ni ochsangiz nima ko'rasiz?

Javobni ko'rish
404 Not Found

Forma umuman ko'rinmaydi. Sababi: Laravel route'larni yozilgan tartibda tekshiradi va birinchi mos kelganida to'xtaydi.

/vakansiyalar/{id} yuqorida turadi va {id} «istalgan qiymat» degani — demak create so'zi ham unga mos keladi. So'rov show metodiga tushadi, u WHERE id = 'create' ni bajaradi, hech narsa topmaydi va abort(404) qiladi.

🔑 Yechim — tartibni almashtirish: aniq (qat'iy) yo'llar parametrli yo'llardan oldin turishi kerak:

Route::get('/vakansiyalar/create', ...); ← aniq, oldin Route::get('/vakansiyalar/{id}', ...); ← parametrli, keyin → /vakansiyalar/create ochiladi, /vakansiyalar/3 ham ishlaydi

Aynan shu sababdan Route::resource create ni {vakansiyalar} dan oldin qo'yadi — yuqoridagi ro'yxatga qaytib qarang. U bu tuzoqni siz uchun hal qilgan.

Xato juda chalg'ituvchi: kod to'g'ri, route bor, lekin 404. Endi buni bir ko'rishda taniysiz.

SAVOL 1 Nega route('vakansiyalar.show', 3) yoziladi, /vakansiyalar/3 emas?

Manzil faqat routes/web.php da yoziladi; qolgan hamma joyda uning nomi ishlatiladi. Bundan tashqari xato yozilsa Route [...] not defined deb darhol aytadi.

SAVOL 2 /vakansiyalar/create route'i {id} dan keyin yozilsa nima bo'ladi?

Route'lar tartib bilan tekshiriladi va birinchi mos kelgani ishlaydi. {id} «create» so'ziga ham mos keladi. Aniq yo'llar parametrlilardan oldin turishi kerak.

SAVOL 3 Bazada topilmagan id uchun nima qilinadi?

Bo'sh sahifa brauzerga va Google'ga «bu sahifa bor» deb aytadi — bu noto'g'ri. Hech narsa qilmaslik esa 500 beradi, ya'ni «serverda xato» — foydalanuvchining aybini o'zimizga olamiz.

Eslab ayting

Avval o'zingiz javob bering, keyin ochib tekshiring. Oxirgi ikkitasi — 23-darsni takrorlash.

URL'dagi {id} controllerga qanday yetib boradi?

Laravel uni argument sifatida metodga uzatadi: show(string $id). Undan keyin u SQL'ga parametr bo'lib boradi — WHERE id = ?, hech qachon satrga qo'shib emas.

abort(404) dan keyin return kerakmi?

Yo'q. U exception otadi va funksiyani darhol to'xtatadi (11-dars). Javobni Laravel o'zi yasaydi.

Route'lar qanday tartibda tekshiriladi?

Yozilgan tartibda, va birinchi mos kelganida to'xtaydi. Shuning uchun aniq yo'llar (/create) parametrli yo'llardan (/{id}) oldin turishi kerak.

↩︎ Takrorlash: migrate --pretend nima qiladi?

Migration'ni bajarmaydi — faqat u yuboradigan SQL'ni ko'rsatadi.

↩︎ Takrorlash: bajarilgan migration tahrirlansa nima bo'ladi?

Hech narsa — Laravel migrations jadvalidagi fayl nomiga qaraydi. Yangi migration kerak (yoki o'z kompyuteringizda migrate:fresh).

Cho'ntak xulosasi
  • Route::get('/vakansiyalar/{id}', ...) — jingalak qavs «istalgan qiymat»; controller metodi uni argument sifatida oladi.
  • 🔑 Route parametri → SQL parametri: WHERE id = ?, [$id]. URL'ni istalgan odam o'zgartiradi — qo'shib yozish injection teshigi.
  • abort(404) — topilmasa. return shart emas. Bo'sh sahifa ❌, hech narsa qilmaslik → 500 ❌.
  • ->name('vakansiyalar.show') + route('...', $id) — manzil bitta joyda. Nom qolipi: resurs.amal.
  • route() to'liq manzil qaytaradi; xato bo'lsa Missing required parameter yoki Route [...] not defined deb darhol aytadi.
  • 🔑 Route'lar tartib bilan tekshiriladi: aniq yo'llar parametrlilardan oldin.
  • Route::resource — 7 route bir qatorda, to'g'ri tartibda va standart nomlar bilan. Cheklash — ->only([...]).
  • DB::select obyekt qaytaradi: $v->nom, $v['nom'] emas.
  • Xom SQL bilan created_at ni o'zingiz to'ldirasiz (now()).
🌱 Keyingi dars

Endi controllerga qarang: show metodi 14 qator, ularning yarmi SQL. Har jadval uchun shunday yozish kerakmi? Har WHERE id = ? ni qo'lda, har created_at ni qo'lda?

25-darsda Eloquent bilan tanishamiz — har jadvalga bitta klass (7-darsdagi klass!). O'sha 14 qator uch qatorga tushadi va topilmasa 404 ni o'zi qaytaradi. Va u ham sehr emas: toSql() chaqirsangiz, Eloquent yozgan SQL'ni o'z ko'zingiz bilan ko'rasiz — 21-darsdagi ? parametrlari bilan birga.
