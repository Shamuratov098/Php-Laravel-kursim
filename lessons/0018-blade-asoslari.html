DARS 18 · MODUL B — LARAVEL

Blade: HTML'ni ma'lumot bilan to'ldirish

Bu darsdan keyin controller HTML qaytarishni to'xtatadi — uning o'rniga view keladi. Va 13-darsda va'da qilgan narsani nihoyat isbotlaymiz: {{ }} XSS'dan o'zi himoyalaydi — va nega, buni kompilyatsiya qilingan faylni ochib ko'rasiz.

📱 O'qish ≈ 11 daqiqa 💻 Amaliyot ≈ 16 daqiqa Kerak: Dars 17

Nega bu muhim

16-darsda controller shunday yozdik:

return '<h1>Vakansiyalar</h1><p>IshTop — birinchi sahifam</p>';

Bu ikki sabab bilan yaroqsiz. Birinchi: haqiqiy sahifada yuzlab qator HTML bo'ladi — uni PHP satri ichida yozib bo'lmaydi. Ikkinchi va muhimrog'i: ma'lumot va ko'rinish aralashib ketadi. Dizaynni o'zgartirish uchun controllerga tegishga majbur bo'lasiz.

View shu ikkisini ajratadi: controller ma'lumot yig'adi, view uni ko'rsatadi. Bu 6-darsdagi qoidaning davomi — «funksiya hisoblasin, chiqarishni chaqiruvchi hal qilsin».

Controller ma'lumot beradi, view ko'rsatadi

app/Http/Controllers/VakansiyaController.php
public function index(): View { $vakansiyalar = [ ['nom' => 'Backend dasturchi', 'maosh' => 800], ['nom' => 'Frontend dasturchi', 'maosh' => 700], ]; return view('vakansiyalar.index', [ 'vakansiyalar' => $vakansiyalar, ]); }

Ikki narsa:

  • view('vakansiyalar.index') — resources/views/vakansiyalar/index.blade.php faylini bildiradi. Nuqta = papka ajratuvchi.
  • Ikkinchi argument — massiv (5-dars). Uning kalitlari view ichida o'zgaruvchi bo'lib paydo bo'ladi: 'vakansiyalar' => ... → view'da $vakansiyalar.

Diqqat: ma'lumot hozircha qo'lda yozilgan massiv. C modulida uning o'rniga bazadan keladigan ma'lumot turadi — lekin shakli aynan bir xil bo'ladi (5-darsdagi «ichma-ich massiv = yozuvlar ro'yxati»). Shuning uchun view'ga tegilmaydi.

@forelse qulay: ro'yxat bo'sh bo'lsa @empty qismi ishlaydi. Sof PHP'da buni if (count(...) === 0) bilan alohida yozish kerak bo'lardi.

🔒 {{ }} — 13-darsdagi va'daning bajarilishi

13-darsda aytgandim: «Blade {{ }} htmlspecialchars ni o'zi qiladi». Bugun buni isbotlaymiz. Bir xil qiymatni ikki xil chiqaramiz:

view ichida
<p>Himoyalangan: {{ $xavfli }}</p> <p>Himoyasiz: {!! $xavfli !!}</p>

$xavfli ichida <script>alert(1)</script> bo'lsa, natija:

<p>Himoyalangan: &lt;script&gt;alert(1)&lt;/script&gt;</p> <p>Himoyasiz: <script>alert(1)</script></p>

Birinchisi zararsiz matn, ikkinchisi haqiqiy teg — brauzer uni bajaradi. Farq faqat qavslar shaklida.

🔍 Sehr yo'q: Blade oddiy PHP'ga aylanadi

Bu darsning eng qimmatli qismi. Blade — yangi til emas: Laravel uni oddiy PHP fayliga kompilyatsiya qiladi va shu faylni ishga tushiradi. Kompilyatsiya natijasi storage/framework/views/ da saqlanadi — ya'ni siz uni ochib ko'rishingiz mumkin.

Yuqoridagi view shunday PHP'ga aylanadi:

<h1>Vakansiyalar</h1> <p>Jami: <?php echo e(count($vakansiyalar)); ?> ta</p> <?php foreach($vakansiyalar as $v): ?> <p><?php echo e($v['nom']); ?> — <?php echo e($v['maosh']); ?> $</p> <?php endforeach; ?> <p>Himoyalangan: <?php echo e($xavfli); ?></p> <p>Himoyasiz: <?php echo $xavfli; ?></p>

Endi hammasi ravshan:

{!! $x !!}<?php echo $x; ?>Oddiy echo — himoya yo'q
@foreach<?php foreach(...): ?>5-darsdagi sikl
@endforeach<?php endforeach; ?>3-darsdagi qavssiz shakl
Va e() nima? — Aynan htmlspecialchars

Laravel'ning e() yordamchisi ichida htmlspecialchars turadi. Amaliyotda buni o'zingiz tekshirasiz: ikkisining natijasi === bilan solishtirilganda true chiqadi.

Ya'ni zanjir to'liq: 13-dars (htmlspecialchars) → bugun ({{ }}) → kompilyatsiya (echo e()) → e() = htmlspecialchars. Hech qanday sehr yo'q, faqat qulay yozuv.

Layout: takrorlanishni yo'qotish

Har sahifada bir xil narsa bo'ladi: <head>, menyu, footer. Ularni har faylda takrorlash — 9-darsdagi muammo. Yechim ham o'sha: umumiy qismni bitta joyga chiqarish.

resources/views/layouts/asosiy.blade.php
<!doctype html> <html lang="uz"> <head> <meta charset="utf-8"> <title>@yield('sarlavha', 'IshTop')</title> </head> <body> <nav><a href="/vakansiyalar">Vakansiyalar</a></nav> <main> @yield('mazmun') </main> <footer>IshTop &copy; 2026</footer> </body> </html>
resources/views/vakansiyalar/index.blade.php
@extends('layouts.asosiy') @section('sarlavha', 'Vakansiyalar — IshTop') @section('mazmun') <h1>Vakansiyalar</h1> ... @endsection
  • @yield('nom') — layout'da bo'sh joy qoldiradi. Ikkinchi argument — standart qiymat (6-darsdagi standart parametr g'oyasi).
  • @extends — «shu layout ichida yashayman». 9-darsdagi extends so'zi — bir xil g'oya: umumiy qism yuqorida, farq pastda.
  • @section('nom', 'qiymat') — qisqa shakl (bir qatorli mazmun uchun), @section ... @endsection — blok shakli.
💻 Amaliy qism kompyuterda

Amaliyotda controller'ni view qaytaradigan qilib o'zgartirasiz, vakansiyalar ro'yxatini chiqarasiz, XSS himoyasini {{ }} va {!! !!} bilan solishtirasiz — va eng qizig'i: kompilyatsiya qilingan PHP faylni ochib Blade'ning ichini ko'rasiz. Oxirida layout qo'shib takrorlanishni yo'qotasiz.

Amaliyot

  1. IshTop'ga o'ting va serverni ko'taring

    cd ~/Projects/Learn/ishtop php artisan serve

    Kutilgan natija: server ishlaydi. Keyingi qadamlar uchun yangi terminal oynasi oching.

  2. Controller'ni view qaytaradigan qiling

    Controller endi HTML yozmaydi — faqat ma'lumot yig'adi.

    cat > app/Http/Controllers/VakansiyaController.php <<'EOF' <?php namespace App\Http\Controllers; use Illuminate\View\View; class VakansiyaController extends Controller { public function index(): View { return view('vakansiyalar.index', [ 'vakansiyalar' => [ ['nom' => 'Backend dasturchi', 'maosh' => 800], ['nom' => 'Frontend dasturchi', 'maosh' => 700], ], 'xavfli' => '<script>alert(1)</script>', ]); } } EOF

    Kutilgan natija: jimlik. : View — qaytish tipi (6-dars). 'xavfli' ni ataylab qo'shdik — XSS'ni sinash uchun.

  3. View faylini yarating

    mkdir -p resources/views/vakansiyalar cat > resources/views/vakansiyalar/index.blade.php <<'EOF' <h1>Vakansiyalar</h1> <p>Jami: {{ count($vakansiyalar) }} ta</p> @forelse ($vakansiyalar as $v) <p>{{ $v['nom'] }} — {{ $v['maosh'] }} $</p> @empty <p>Hozircha vakansiya yo'q.</p> @endforelse <p>Himoyalangan: {{ $xavfli }}</p> <p>Himoyasiz: {!! $xavfli !!}</p> EOF curl -s http://localhost:8000/vakansiyalar <h1>Vakansiyalar</h1> <p>Jami: 2 ta</p> <p>Backend dasturchi — 800 $</p> <p>Frontend dasturchi — 700 $</p> <p>Himoyalangan: &lt;script&gt;alert(1)&lt;/script&gt;</p> <p>Himoyasiz: <script>alert(1)</script></p>

    Kutilgan natija: ro'yxat chiqdi. Va oxirgi ikki qatorga diqqat: bir xil qiymat, ikki xil natija. 🔒 {{ }} teglarni zararsizlantirdi, {!! !!} esa xom holda o'tkazdi.
    Brauzerda ham ochib ko'ring — «Himoyasiz» qatoridan oyna chiqadi.

  4. 🔍 Kompilyatsiya qilingan faylni ochib ko'ring

    Bu darsning eng muhim tajribasi: Blade'ning ichida sehr yo'q, oddiy PHP bor.

    cat $(grep -l 'Vakansiyalar' storage/framework/views/*.php | head -1) <h1>Vakansiyalar</h1> <p>Jami: <?php echo e(count($vakansiyalar)); ?> ta</p> <?php ... foreach($__currentLoopData as $v): ... ?> <p><?php echo e($v['nom']); ?> — ... <p>Himoyalangan: <?php echo e($xavfli); ?></p> <p>Himoyasiz: <?php echo $xavfli; ?></p>

    Kutilgan natija: 🎉 Oddiy PHP fayl! {{ }} → echo e(...), {!! !!} → oddiy echo, @foreach → foreach(...).
    foreach atrofidagi qo'shimcha kod — Blade'ning $loop o'zgaruvchisi uchun (nechanchi aylanish, oxirgisimi va boshqalar). Yadro esa oddiy foreach.

  5. 🔒 e() aynan nima ekanini tekshiring

    13-darsdagi bilim bilan bugungi {{ }} ni bir-biriga ulaydigan oxirgi bo'g'in.

    php -r ' require "vendor/autoload.php"; $app = require_once "bootstrap/app.php"; $x = "<script>alert(1)</script>"; echo e($x), PHP_EOL; var_dump(e($x) === htmlspecialchars($x, ENT_QUOTES, "UTF-8", true)); ' &lt;script&gt;alert(1)&lt;/script&gt; bool(true)

    Kutilgan natija: bool(true) — ya'ni e() va htmlspecialchars aynan bir xil natija beradi. Zanjir yopildi: {{ }} → e() → htmlspecialchars (13-dars). 🎉

  6. Layout yarating

    mkdir -p resources/views/layouts cat > resources/views/layouts/asosiy.blade.php <<'EOF' <!doctype html> <html lang="uz"> <head> <meta charset="utf-8"> <title>@yield('sarlavha', 'IshTop')</title> </head> <body> <nav><a href="/vakansiyalar">Vakansiyalar</a></nav> <main> @yield('mazmun') </main> <footer>IshTop &copy; 2026</footer> </body> </html> EOF

    Kutilgan natija: jimlik.

  7. View'ni layout ichiga soling

    cat > resources/views/vakansiyalar/index.blade.php <<'EOF' @extends('layouts.asosiy') @section('sarlavha', 'Vakansiyalar — IshTop') @section('mazmun') <h1>Vakansiyalar</h1> @forelse ($vakansiyalar as $v) <p>{{ $v['nom'] }} — {{ $v['maosh'] }} $</p> @empty <p>Hozircha vakansiya yo'q.</p> @endforelse @if (count($vakansiyalar) > 1) <p><b>Bir nechta vakansiya bor.</b></p> @endif @endsection EOF curl -s http://localhost:8000/vakansiyalar | head -8 <!doctype html> <html lang="uz"> <head> <meta charset="utf-8"> <title>Vakansiyalar — IshTop</title> </head>

    Kutilgan natija: endi to'liq HTML sahifa — menyu, footer va <title> bilan. <title> ichida @section('sarlavha', ...) dan kelgan matn turadi.
    O'zingiz sinab ko'ring: @section('sarlavha', ...) qatorini o'chirib qayta so'rang — sarlavha IshTop ga (standart qiymatga) qaytadi.

  8. Ishni saqlang

    git add -A git commit -m "18-dars: Blade asoslari va layout"

    Kutilgan natija: commit haqida xabar. Diqqat: storage/framework/views/ Git'ga tushmaydi — u kesh, kerak bo'lganda qayta yasaladi.

Sinab ko'ramiz

Natijani taxmin qiling

Foydalanuvchi o'z ismini <b>Doston</b> deb kiritgan (teglar bilan). View'da ikki xil chiqarilgan. Brauzerda nima ko'rinadi?

view
<p>A: {{ $ism }}</p> <p>B: {!! $ism !!}</p>
Javobni ko'rish

Brauzerda:

A: <b>Doston</b> ← teglar MATN sifatida ko'rinadi B: Doston ← qalin harflar bilan (teg BAJARILDI)

A da foydalanuvchi yozgan narsa xuddi shundayligicha ko'rinadi — chunki < belgisi &lt; ga aylantirilgan. B da esa teg ishlagan.

Nega A to'g'ri: foydalanuvchi HTML yozishi kutilmaydi — u ism yozadi. Agar teglarga ruxsat bersangiz, <b> bilan cheklanmaydi: <script> ham ishlaydi, ya'ni XSS.

Qoida: {!! !!} ni faqat siz o'zingiz yasagan, ishonchli HTML uchun ishlating (masalan Markdown'dan tayyorlangan matn). Foydalanuvchidan kelgan narsa uchun hech qachon. Va kod ko'rib chiqishda (code review) {!! !!} ko'rinsa — birinchi savol «bu qiymat qayerdan keldi?» bo'ladi.

SAVOL 1 {{ $x }} nimaga kompilyatsiya qilinadi?

{{ }} → <?php echo e($x); ?>, va e() ichida htmlspecialchars turadi. {!! !!} esa oddiy echo — himoyasiz.

SAVOL 2 view('vakansiyalar.index') qaysi faylni bildiradi?

View'lar resources/views/ da yashaydi, va nuqta papka ajratuvchi vazifasini bajaradi. Kengaytma — .blade.php.

SAVOL 3 Blade fayllari qanday ishlatiladi?

Laravel Blade'ni oddiy PHP fayliga aylantiradi va natijani storage/framework/views/ da saqlaydi. Shuning uchun Blade tezlikka salbiy ta'sir qilmaydi.

Eslab ayting

Avval o'zingiz javob bering, keyin ochib tekshiring. Oxirgi ikkitasi — 17-darsni takrorlash.

Controller va view mas'uliyati qanday bo'linadi?

Controller ma'lumot yig'adi va uni massivda uzatadi; view uni ko'rsatadi. Dizayn o'zgarsa controllerga tegilmaydi.

{{ }} nima uchun xavfsiz?

Chunki u echo e($x) ga kompilyatsiya qilinadi, va e() — bu htmlspecialchars. Ya'ni 13-darsdagi himoya avtomatik qo'llanadi.

@extends va @yield munosabati?

Layout'da @yield('nom') bo'sh joy qoldiradi; sahifa @extends bilan layout'ni oladi va @section('nom') bilan o'sha joyni to'ldiradi.

↩︎ Takrorlash: middleware controllerdan oldin ham, keyin ham ishlaydimi?

Ha. $next($request) dan oldingi kod — controllerdan oldin, keyingi kod — keyin. Middleware controllerni o'rab oladi.

↩︎ Takrorlash: bootstrap/app.php nima qaytaradi?

Application obyektini — Laravel'ning container'i. Sizning new Container() qatoringizning o'rni.

Cho'ntak xulosasi
  • view('papka.fayl', ['kalit' => $qiymat]) — nuqta = papka. Kalitlar view'da o'zgaruvchi bo'ladi.
  • 🔒 {{ $x }} — himoyalab chiqaradi · {!! $x !!} — xom holda (ehtiyot bo'ling!).
  • Blade oddiy PHP'ga kompilyatsiya qilinadi: {{ }} → echo e(), @foreach → foreach. Natija storage/framework/views/ da.
  • e() = htmlspecialchars (13-dars). Zanjir to'liq.
  • @if · @foreach · @forelse ... @empty (bo'sh ro'yxat uchun).
  • Layout: @yield('nom', 'standart') + @extends + @section.
  • storage/framework/views/ — kesh, Git'ga tushmaydi.
🌱 Keyingi dars

Layout takrorlanishning katta qismini yechdi. Lekin kichik bo'laklar ham takrorlanadi: vakansiya kartasi, tugma, ogohlantirish qutisi. Ular uchun komponent bor — 10-darsdagi «takrorlanishni yo'qotish» g'oyasining Blade'dagi shakli.

Va eng muhimi: forma yozamiz. U yerda yangi narsa bor — @csrf. 13-darsda cookie va session'ni o'rganganingizda «CSRF nima?» degan savol paydo bo'lgan bo'lsa, keyingi dars unga javob beradi. Va isbot ham bo'ladi: @csrf ni olib tashlab, Laravel 419 xatosi bilan formani rad etishini ko'rasiz.
