DARS 09 · MODUL A — POYDEVOR

Meros va abstract: umumiy kodni bir joyda tutish

Bu darsdan keyin bog'liq klasslar kodni takrorlamasdan bo'lishadi. Bundan tashqari abstract bilan «bu qismni har bir avlod o'zi bajarishi shart» deb aytishni o'rganasiz — Laravel'ning ko'p joyi aynan shu naqsh ustida qurilgan.

📱 O'qish ≈ 9 daqiqa 💻 Amaliyot ≈ 12 daqiqa Kerak: Dars 08

Bu darsda nimalar bor
  1. Meros — umumiy kodni bir joyga extends bilan otaning hamma narsasi bolaga o'tadi.
  2. 🔍 protected ning ma'nosi O'lchandi: private bolaga ko'rinmaydi, protected — ko'rinadi.
  3. parent:: Otaning metodini chaqirish.
  4. ⚠️ parent::__construct() ni unutish 🔍 Typed property must not be accessed before initialization.
  5. abstract klass «Umumiy shakl, lekin o'zi ishlamaydi».
  6. 🔍 abstract ning ikki qoidasi Cannot instantiate va must therefore be declared abstract.
  7. Metodni qayta yozish (override) 🔍 Shartnomani buzsangiz — must be compatible with.
  8. final 🔍 Cannot override final method · cannot extend final class.
  9. instanceof 🔍 Bola ham otadir — merosning asosiy foydasi.
  10. new static() 🔍 Bola::yasa() → Bola, self bo'lsa — Ota.
  11. Meros qachon ortiqcha Ko'p instanceof — signal.
  12. Har xil holatlar (7 ta) protected · parent · abstract · final · kech statik bog'lanish.
Nega bu muhim

IshTop loyihasida nomzodga xabar yuborish kerak — email bilan ham, SMS bilan ham. Ikkisida umumiy narsa ko'p: qabul qiluvchi, matn, matnni qisqartirish. Farqi esa faqat yuborish usulida.

Merossiz yo'l — ikkita klass yozib, umumiy qismni ikki marta takrorlash. Uchinchi kanal (Telegram) qo'shilsa — uch marta. Keyin matnni qisqartirish qoidasi o'zgarsa — uch joyni tuzatish kerak, va bittasini esdan chiqarish deyarli kafolatlangan.

Meros shuni yechadi: umumiy qism bitta joyda, farq qiladigan qism avlodlarda. Laravel'da siz bu naqshni doim ko'rasiz — masalan har bir controller extends Controller, har bir model extends Model.

Meros: extends

tushuncha
class Xabar // ota klass (parent) { public function yubor(): string { ... } } class EmailXabar extends Xabar // avlod (child) { // Xabar dagi hamma narsa bu yerda ham BOR }

extends — «bu klass o'sha klassning hamma narsasini oladi». Avlod otasining xossalari va metodlariga egalik qiladi, ustiga o'zining qismini qo'shadi.

Endi 8-darsdagi protected ma'noga to'ldi:

DarajaAvlod ko'radimi?
publicHa — va tashqaridan ham
protectedHa — lekin tashqaridan yo'q. Meros uchun aynan shu kerak
privateYo'q — faqat o'sha klassning o'zi

Shuning uchun ota klassda avlodlar ishlatadigan narsalar protected qilinadi: tashqaridan yopiq, lekin «oila ichida» ochiq.

parent:: — otaning versiyasini chaqirish

tushuncha
class EmailXabar extends Xabar { public function __construct(string $qabulQiluvchi, private string $mavzu) { parent::__construct($qabulQiluvchi); // otaning konstruktorini ishlat } public function yubor(): string { return parent::yubor() . " [mavzu: {$this->mavzu}]"; // ustiga qo'sh } }

Avlod otaning metodini o'zining versiyasi bilan almashtira oladi — bu override deb ataladi. parent:: esa «otaning versiyasini ham ishlatmoqchiman» degani.

Avlod o'z konstruktorini yozsa — parent::__construct() shart

Aks holda otaning konstruktori umuman ishlamaydi va uning xossalari qiymatsiz qoladi → 7-darsdagi Typed property ... must not be accessed before initialization xatosi chiqadi. PHP buni o'zi qilib bermaydi, siz aytishingiz kerak.

abstract: «buni avlod o'zi bajarsin»

Bizning holatda Xabar ning o'zidan obyekt yasashning ma'nosi yo'q — «umuman xabar» degan narsa yuborilmaydi, faqat email yoki SMS yuboriladi. Va yubor() metodini ota klassda yozib ham bo'lmaydi — chunki har kanalda boshqacha.

abstract aynan shu holat uchun:

tushuncha
abstract class Xabar // obyekt yasab bo'lmaydi { public function __construct( protected string $qabulQiluvchi, protected string $matn, ) {} abstract public function yubor(): string; // tanasi YO'Q — avlod yozadi protected function qisqaMatn(): string // umumiy kod — bir joyda { return mb_substr($this->matn, 0, 20) . "..."; } }

Ikki narsa e'lon qilindi:

  • abstract class — bu klassdan obyekt yasab bo'lmaydi. U faqat asos bo'lish uchun. Urinsangiz: Fatal error: Cannot instantiate abstract class.
  • abstract public function yubor(): string; — tanasi yo'q, faqat imzo va nuqtali vergul. Ma'nosi: «har bir avlod buni o'zi yozishi shart».
Nega bu kuchli

Chunki PHP majburlaydi. Avlodda yubor() ni yozishni esdan chiqarsangiz, kod umuman ishga tushmaydi:

PHP Fatal error: Class Y contains 1 abstract method and must therefore be declared abstract or implement the remaining methods (X::f)

Ya'ni xato ishlatishda emas, e'lon qilishda chiqadi — bu eng yaxshi vaqt. Xabar hatto nima qilish kerakligini ham aytadi.

Foydasi: bitta sikl, har xil obyektlar

tushuncha
$xabarlar = [ new EmailXabar("doston@example.com", $matn), new SmsXabar("+998901234567", $matn), ]; foreach ($xabarlar as $x) { echo $x->yubor(); // har biri O'ZINING usulini ishlatadi }

Diqqat qiling: foreach ichida hech qanday if yo'q — «bu emailmi yoki SMSmi?» deb tekshirmadik. Har obyekt o'zining yubor() ini biladi. Bu polimorfizm deb ataladi: bir xil murojaat, har xil xatti-harakat.

Foydasi kelajakda ko'rinadi: Telegram kanali qo'shsangiz, bu foreach ga tegmaysiz ham — u yangi klassni ham xuddi shunday ishlatadi.

instanceof — «bu obyekt qaysi turdan?»

$e = new EmailXabar(...); $e instanceof EmailXabar → true $e instanceof Xabar → true ← ota tipiga ham MOS

Avlod ikkala tipga ham mos keladi. Shuning uchun function yubor(Xabar $x) deb yozsangiz — unga EmailXabar ham, SmsXabar ham, kelajakdagi TelegramXabar ham beriladi. 6-darsdagi type hint endi ancha kuchli asbobga aylandi.

💻 Amaliy qism kompyuterda

Amaliyotda 21-xabar.php da abstract class Xabar va undan meros olgan ikkita klass yozasiz, 22-yuborish.php da esa ularni bitta siklda ishlatasiz. Keyin ikkita chekni sinaysiz: abstract klassdan obyekt yasashga urinish va abstract metodni bajarmaslik — ikkalasi ham PHP tomonidan taqiqlanadi.

Amaliyot

  1. Papkaga o'ting

    cd ~/Projects/Learn/php-poydevor

    Kutilgan natija: jimlik.

  2. Abstract ota klass va ikki avlodni yozing

    Umumiy kod (qisqaMatn) bir joyda, farq qiladigan qism (yubor) avlodlarda.

    cat > 21-xabar.php <<'EOF' <?php declare(strict_types=1); abstract class Xabar { public function __construct( protected string $qabulQiluvchi, protected string $matn, ) {} abstract public function yubor(): string; protected function qisqaMatn(): string { return mb_substr($this->matn, 0, 20) . "..."; } } class EmailXabar extends Xabar { public function yubor(): string { return "EMAIL → {$this->qabulQiluvchi}: {$this->qisqaMatn()}"; } } class SmsXabar extends Xabar { public function yubor(): string { return "SMS → {$this->qabulQiluvchi}: {$this->qisqaMatn()}"; } } EOF php 21-xabar.php

    Kutilgan natija: jimlik — faylda faqat klasslar bor. Diqqat: qisqaMatn protected — tashqaridan yopiq, lekin avlodlar ishlatadi.

  3. Ikki xil xabarni bitta siklda yuboring

    Bu polimorfizm — siklda hech qanday if yo'q.

    cat > 22-yuborish.php <<'EOF' <?php declare(strict_types=1); require '21-xabar.php'; $matn = "Arizangiz ko'rib chiqildi va suhbatga chaqirildingiz"; $xabarlar = [ new EmailXabar("doston@example.com", $matn), new SmsXabar("+998901234567", $matn), ]; foreach ($xabarlar as $x) { echo $x->yubor(), PHP_EOL; echo " Xabar turi: ", get_class($x), PHP_EOL; echo " Xabar avlodimi: ", var_export($x instanceof Xabar, true), PHP_EOL; } EOF php 22-yuborish.php EMAIL → doston@example.com: Arizangiz ko'rib chi... Xabar turi: EmailXabar Xabar avlodimi: true SMS → +998901234567: Arizangiz ko'rib chi... Xabar turi: SmsXabar Xabar avlodimi: true

    Kutilgan natija: har xabar o'z usulida yuborildi, lekin qisqaMatn ikkisida ham bir xil ishladi — umumiy kod bir joyda. Ikkisi ham Xabar avlodi (true).
    get_class($x) — obyektning klass nomini beradi, var_export(..., true) — true/false ni matn qilib qaytaradi.

  4. Birinchi chek: abstract klassdan obyekt yasashga urinish

    PHP taqiqlashini o'z ko'zingiz bilan ko'rasiz.

    php -r 'require "21-xabar.php"; new Xabar("test", "matn");' 2>&1 | head -1 PHP Fatal error: Uncaught Error: Cannot instantiate abstract class Xabar in Command line code:1

    Kutilgan natija: «abstract klassdan obyekt yasab bo'lmaydi». To'g'ri — «umuman xabar» degan narsa yo'q.

  5. Ikkinchi chek: abstract metodni bajarmaslik

    Xato e'lon qilishda chiqadi — ishlatishni kutmaydi.

    php -r 'require "21-xabar.php"; class TelegramXabar extends Xabar {}' 2>&1 | head -1 PHP Fatal error: Class TelegramXabar contains 1 abstract method and must therefore be declared abstract or implement the remaining methods (Xabar::yubor) in Command line code on line 1

    Kutilgan natija: PHP aynan nima yetishmayotganini aytdi — Xabar::yubor. Endi o'zingiz sinab ko'ring: shu buyruqqa yubor() metodini qo'shib, xato yo'qolishini tekshiring.

    git add -A git commit -m "09-dars: meros va abstract"

    Kutilgan natija: commit haqida xabar.

Har xil holatlar

Yetti holat. Bu bo'lim ma'lumotnoma — hozir bir marta o'qing, keyin kerak bo'lganda qaytib qarang.

HOLAT 1

🔍 protected ning ma'nosi ochildi

class Ota { private $a = 1; protected $b = 2; public $c = 3; } class Bola extends Ota { /* $this->a, $this->b, $this->c */ } natija: b=2 c=3 a=KO'RINMAYDI

8-darsda uch daraja bilan tanishgandik, lekin protected ning ma'nosi o'sha yerda to'liq ochilmagan edi. Mana javob:

private → faqat O'SHA klass protected → o'sha klass VA undan meros olganlar ← farq shu public → hamma joydan

🔑 Ya'ni protected — «bolalarimga ishonaman, begonaga yo'q».

✅ Amaliy qoida o'zgarmaydi: private dan boshlang. Meros kerak bo'lganda protected ga ko'taring.

HOLAT 2

⚠️ parent::__construct() ni unutish

class Ota { public function __construct(public string $nom) {} } // ✅ TO'G'RI class Bola extends Ota { public function __construct(string $nom, public int $yosh) { parent::__construct($nom); } } new Bola("Ali", 30) → Ali 30 // ⚠️ NOTO'G'RI — parent chaqirilmadi class Bola extends Ota { public function __construct(public int $yosh) {} } $b->nom → Fatal error: Uncaught Error: Typed property Ota::$nom must not be accessed before initialization

🔑 Bola konstruktori otanikini almashtiradi, to'ldirmaydi. Otaning ishi bajarilishi kerak bo'lsa — o'zingiz chaqirasiz.

🔍 Va e'tibor bering: xato 7-darsdagi o'sha xabar — «tiplangan xossa hali to'ldirilmagan».

HOLAT 3

abstract — ikkita qoida

abstract class Shakl { abstract public function yuza(): float; } new Shakl(); Fatal error: Uncaught Error: Cannot instantiate abstract class Shakl ← 1-qoida class Kvadrat extends Shakl {} Fatal error: Class Kvadrat contains 1 abstract method and must therefore be declared abstract or implement the remaining methods ← 2-qoida

🔑 Ikki qoida bir jumlada: abstract klassdan obyekt yasab bo'lmaydi, va abstract metodni bola bajarishi shart.

✅ Foydasi: «har shaklning albatta yuzasi bo'ladi, lekin uni qanday hisoblash — har shaklning o'z ishi».

🔍 Ikkinchi xato matnini eslab qoling — keyingi darsda interface bilan xuddi shu xabarni ko'rasiz.

HOLAT 4

Metodni qayta yozish (override)

class Ota { public function ayt(): string { return "ota"; } } class Bola extends Ota { public function ayt(): string { return "bola (" . parent::ayt() . ")"; } } (new Bola)->ayt() → bola (ota) ✅ // ⚠️ tipni o'zgartirsangiz: class Bola extends Ota { public function ayt(): int { return 1; } } Fatal error: Declaration of Bola::ayt(): int must be compatible with Ota::ayt(): string

🔑 Bola metodni almashtira oladi, lekin shartnomani buza olmaydi: parametrlar va qaytish tipi mos bo'lishi kerak.

✅ parent::ayt() — «avval otaniki bajarilsin, keyin men qo'shaman». Bu juda ko'p uchraydigan naqsh.

🔍 «Shartnoma» so'zi bejiz emas — keyingi darsda u asosiy mavzu bo'ladi.

HOLAT 5

final — «bu yerda to'xtang»

class Ota { final public function ayt() { return "ota"; } } class Bola extends Ota { public function ayt() { return "bola"; } } Fatal error: Cannot override final method Ota::ayt() final class Ota {} class Bola extends Ota {} Fatal error: Class Bola cannot extend final class Ota

🔑 final — «bu metodni (yoki klassni) o'zgartirmang».

✅ Qachon kerak? Klass ichida muhim qoida bo'lsa va uni bola buzib qo'yishi mumkin bo'lsa. Masalan parolni tekshirish metodi.

🔍 Ko'p tajribali dasturchilar standart holda final yozishni tavsiya qiladi — meros kerak bo'lganda ochiladi.

HOLAT 6

instanceof — «bu kim?»

class Ota {} class Bola extends Ota {} $b = new Bola; $b instanceof Bola → true $b instanceof Ota → true ← bola HAM otadir get_class($b) → "Bola" $b::class → "Bola" ← PHP 8 dagi qisqa shakl

🔑 instanceof merosni hisobga oladi: Bola ayni paytda Ota hamdir.

✅ Bu merosdan foydalanishning asosiy sababi: Ota kutayotgan joyga Bola ni berish mumkin.

⚠️ Lekin kodda instanceof ko'p bo'lsa — bu signal: ehtimol if o'rniga metodni qayta yozish kerak.

HOLAT 7

new static() — bola o'zini yasaydi

class Ota { public static function yasa(): static { return new static(); } } class Bola extends Ota {} Ota::yasa() → Ota Bola::yasa() → Bola ✅ o'z klassini yasadi

🔑 new self() bo'lganda ikkalasi ham Ota qaytarardi. static esa chaqirilgan klassni oladi.

✅ Bu «kech statik bog'lanish» (late static binding) deb ataladi va zamonaviy PHP kutubxonalarida juda ko'p ishlatiladi.

🔍 Kursning davomida Model::find() kabi chaqiruvlarni ko'rasiz — ular ichida aynan shu mexanizm turadi.

Sinab ko'ramiz

Natijani taxmin qiling

Avlod klass o'z konstruktorini yozgan, lekin parent::__construct() ni chaqirmagan. Nima bo'ladi?

taxmin.php
<?php class Xabar { public function __construct(protected string $qabulQiluvchi) {} } class EmailXabar extends Xabar { public function __construct(private string $mavzu) { // parent::__construct(...) YO'Q } public function korinish(): string { return "{$this->qabulQiluvchi} — {$this->mavzu}"; } } $e = new EmailXabar("Ariza holati"); echo "Obyekt yasaldi", PHP_EOL; echo $e->korinish();
Javobni ko'rish
Obyekt yasaldi PHP Fatal error: Uncaught Error: Typed property Xabar::$qabulQiluvchi must not be accessed before initialization

Diqqat qiling — obyekt yasaldi, xato faqat korinish() ni chaqirganda chiqdi. Ya'ni muammo yaratilishda emas, keyinroq ko'rindi — aynan shunday xatolarni topish qiyin bo'ladi.

Sabab: avlod o'z konstruktorini yozganda, otaning konstruktori avtomatik ishlamaydi. Demak $qabulQiluvchi ga hech kim qiymat bermadi va u qiymatsiz qoldi. 7-darsdagi «Typed property ... must not be accessed before initialization» xatosi shu.

Yechim: avlod konstruktorining birinchi qatorida:

parent::__construct($qabulQiluvchi);

Qoida: avlodda konstruktor yozsangiz — parent::__construct() ni chaqirishni unutmang. PHP buni o'zi qilmaydi. Bu Laravel'da ham uchraydi: masalan o'z Request klassingizni yozganda.

SAVOL 1 abstract class ning asosiy xususiyati nima?

abstract class faqat asos bo'lish uchun. new qilishga urinsangiz: Cannot instantiate abstract class. Meros olish esa aynan uning maqsadi.

SAVOL 2 Ota klassdagi xossani avlod ko'rishi uchun u qanday bo'lishi kerak?

private — faqat o'sha klassning o'zi, avlod ham ko'rmaydi. protected — «oila ichida ochiq, tashqaridan yopiq», meros uchun aynan shu kerak.

SAVOL 3 abstract metodni avlodda yozmasangiz nima bo'ladi?

Xato ishlatishda emas, e'lon qilishda chiqadi — bu eng yaxshi vaqt. Va PHP nima yetishmayotganini aniq aytadi (Xabar::yubor). Otada tanasi yo'q, shuning uchun «ishlatib ketish» imkoni ham yo'q.

Eslab ayting

Avval o'zingiz javob bering, keyin ochib tekshiring. Oxirgi ikkitasi — 8-darsni takrorlash.

Meros qanday muammoni yechadi?

Takrorlanishni. Bog'liq klasslardagi umumiy kod bitta joyda (ota klassda) yashaydi, farq qiladigan qism avlodlarda. Qoida o'zgarsa — bitta joy tuzatiladi.

abstract metod nima va nega kuchli?

Tanasi yo'q, faqat imzo: «har avlod buni o'zi yozishi shart». Kuchli, chunki PHP majburlaydi — yozmasangiz kod e'lon qilishda xato beradi, ya'ni muammo eng erta payt topiladi.

Polimorfizm nima — bir gapda?

Bir xil murojaat, har xil xatti-harakat. $x->yubor() deb yozasiz, obyekt esa o'zining usulini ishlatadi — siklda if yozish kerak bo'lmaydi.

↩︎ Takrorlash: -> va :: farqi?

-> = obyektning, :: = klassning. Bugun yana bittasi qo'shildi: parent:: — «ota klassning».

↩︎ Takrorlash: qisqa konstruktor (promotion) nima qiladi?

Parametr oldiga private/protected yozilsa, PHP xossani o'zi yaratadi. Bugun ota klassda protected string $qabulQiluvchi aynan shu shaklda yozildi.

Cho'ntak xulosasi
  • class B extends A — B, A ning hamma narsasini oladi.
  • protected = «oila ichida ochiq, tashqaridan yopiq» — meros uchun aynan shu.
  • parent::metod() — otaning versiyasini chaqirish. Avlodda konstruktor yozsangiz parent::__construct() shart.
  • abstract class — obyekt yasab bo'lmaydi, faqat asos.
  • abstract function f(); — tanasi yo'q, avlod yozishi shart; aks holda e'lon qilishda xato.
  • Polimorfizm: bitta siklda har xil obyektlar, if yo'q.
  • instanceof — avlod ikkala tipga ham mos keladi.
🌱 Kelasi darslar uchun urug'

Meros kuchli, lekin bitta cheklovi bor: PHP'da klass faqat bitta otadan meros oladi. Unda nima qilamiz, agar EmailXabar ga «logga yozish» qobiliyati ham kerak bo'lsa — va u qobiliyat Xabar bilan hech qanday aloqasi yo'q boshqa klasslarga ham kerak bo'lsa?

Keyingi dars ikki yechimni beradi: interface — «bu klass shu ishni qila oladi» degan shartnoma, va trait — «mana qanday qiladi» degan qayta ishlatiladigan kod bo'lagi. Laravel'ning ichida ikkisi ham juda ko'p ishlatiladi.
