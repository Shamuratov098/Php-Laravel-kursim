API Resource: javob shaklini boshqarish

42-darsda API ishladi, lekin bitta muammoni ataylab ochiq qoldirdik: javob bazangizning ko'zgusi edi. user_id, created_at — hammasi mijozga ketdi, va bazaga ustun qo'shsangiz API o'z-o'zidan o'zgarardi. Bugun javob shaklini alohida faylga ko'chiramiz.

📱 O'qish ≈ 16 daqiqa 💻 Amaliyot ≈ 25 daqiqa Kerak: Dars 42

Bu darsda nimalar bor
  1. Baza ichki, API tashqi Nega javob shakli shartnoma va u bazadan mustaqil bo'lishi kerak.
  2. make:resource Yasalgan skelet va uning yagona metodi — toArray().
  3. Shaklni o'zingiz yozasiz Yetti maydon tanladik — qolgan beshtasi javobdan butunlay yo'qoldi. O'lchandi.
  4. ⚠️ data o'rami Resource javobni data ichiga o'raydi — ro'yxatni ham, bitta obyektni ham. Eski testlar buziladi.
  5. whenLoaded() Bog'lanish yuklanmagan bo'lsa kalit umuman chiqmaydi — null ham emas. HTTP orqali o'lchandi.
  6. Ichma-ich resource KompaniyaResource ichkarida: kompaniyaning ham faqat kerakli maydonlari.
  7. 🔍 Hisoblangan maydon maosh_matni — 41-darsdagi maoshFormat() javobga qo'shiladi. Bazada bunday ustun yo'q.
  8. ⚠️ Scope va ustun nomi to'qnashuvi Darsning eng qiziq topilmasi: ArgumentCountError va u faqat store da chiqadi.
  9. whenHas() va fresh() Ikki yechim, ikki xil maqsad — ikkalasi ham o'lchandi.
  10. Sahifalash bilan paginate() + collection() → data, links, meta.
  11. Testlarni yangilash assertJsonPath('data.nom', ...) va «ichki maydonlar chiqmasin» testi.
  12. Har xil holatlar (7 ta) data o'rami · scope to'qnashuvi · whenLoaded · whenHas · withoutWrapping tuzog'i · N+1 · shartnoma buzilishi.
Baza — ichki, API — tashqi shartnoma

42-darsdagi javobga yana bir marta qarang:

{"id":31,"nom":"...","maosh":7000000,"shahar":null,"faol":1, "kompaniya_id":null,"created_at":"...","updated_at":"...", "masofadan":0,"user_id":null,"kompaniya":null}

O'n bitta maydon — va ularning hech biri ataylab tanlanmagan. Ular shunchaki vakansiyalar jadvalidagi ustunlar.

Bu ikki muammo tug'diradi:

1) Ichki narsa tashqariga chiqadi user_id, kompaniya_id — mijozga kerak emas, lekin ko'rinadi 2) Baza o'zgarsa API ham o'zgaradi ustun qo'shdingiz → javobga yangi kalit tushdi ustun nomini o'zgartirdingiz → mijozning kodi BUZILDI

Ikkinchisi jiddiyroq. Mijoz — mobil ilova bo'lishi mumkin, va uning yangi versiyasi oylab tarqaladi. Siz esa bazangizni o'zgartirishdan qo'rqib qolasiz.

🔑 Yechim — ajratish: baza o'zingizniki, javob shakli esa mijoz bilan tuzilgan shartnoma. Ikkalasi alohida yashasin.

make:resource — shartnoma fayli

php artisan make:resource VakansiyaResource php artisan make:resource KompaniyaResource INFO Resource [app/Http/Resources/VakansiyaResource.php] created successfully.
app/Http/Resources/VakansiyaResource.php — yasalgan holicha class VakansiyaResource extends JsonResource { public function toArray(Request $request): array { return parent::toArray($request); // ← «modeldagi hamma narsa» } }

parent::toArray() aynan 42-darsdagi xulqni beradi — modelni butunlay. Uni o'z ro'yxatimiz bilan almashtiramiz:

app/Http/Resources/VakansiyaResource.php class VakansiyaResource extends JsonResource { public function toArray(Request $request): array { return [ 'id' => $this->id, 'nom' => $this->nom, 'maosh' => $this->maosh, 'maosh_matni' => $this->maoshFormat(), // ← 41-darsdan 'shahar' => $this->shahar, 'faol' => $this->whenHas('faol', fn () => (bool) $this->faol), 'kompaniya' => KompaniyaResource::make($this->whenLoaded('kompaniya')), ]; } }
app/Http/Resources/KompaniyaResource.php class KompaniyaResource extends JsonResource { public function toArray(Request $request): array { return [ 'id' => $this->id, 'nom' => $this->nom, ]; } }

$this->id — bu resource'ning emas, o'ralgan modelning maydoni. JsonResource o'ziga tushmagan murojaatlarni modelga uzatadi. Sehr yo'q: bu PHP'ning __get mexanizmi.

Controllerda

app/Http/Controllers/Api/VakansiyaController.php use App\Http\Resources\VakansiyaResource; public function index() { $vakansiyalar = Vakansiya::query()->with('kompaniya')->latest('id')->take(10)->get(); return VakansiyaResource::collection($vakansiyalar); // ko'plik } public function show(string $id) { $vakansiya = Vakansiya::with('kompaniya')->findOrFail($id); return VakansiyaResource::make($vakansiya); // bitta } public function store(Request $request) { $tekshirilgan = $request->validate([ /* ... */ ]); $vakansiya = Vakansiya::create($tekshirilgan); return VakansiyaResource::make($vakansiya->fresh()) ->response() ->setStatusCode(201); }

JsonResponse tip belgisi olib tashlandi: resource o'zi javobga aylanadi. 201 kerak bo'lganda esa ->response()->setStatusCode(201) bilan javobga o'tamiz.

Natija — o'lchangan

OLDIN (42-dars): {"id":31,"nom":"...","maosh":7000000,"shahar":null,"faol":1, "kompaniya_id":null,"created_at":"...","updated_at":"...", "masofadan":0,"user_id":null,"kompaniya":null} KEYIN: {"data":{"id":2,"nom":"Full-stack mutaxassis","maosh":1081, "maosh_matni":"1 081 so'm","shahar":"Toshkent","faol":true, "kompaniya":{"id":1,"nom":"Uzum Group"}}}

Uch narsa o'zgardi:

1) user_id · kompaniya_id · created_at · updated_at · masofadan → YO'QOLDI 2) maosh_matni → QO'SHILDI (bazada bunday ustun YO'Q) 3) faol: 1 → faol: true (haqiqiy mantiqiy qiymat)

🔍 maosh_matni ga alohida qarang: u 41-darsda TDD bilan qurgan maoshFormat() metodidan keladi. Mijoz endi sonni o'zi formatlamaydi — server tayyor matn beradi va formatlash bir joyda qoladi.

⚠️ data o'rami — eski testlar buziladi

Javobning eng yuqori qavatiga qarang: {"data": ...}. Resource javobni o'raydi — va bu ro'yxatga ham, bitta obyektga ham tegishli:

ro'yxat: {"data": [ {...}, {...} ]} bitta: {"data": {...}}

42-darsdagi testlarni ishga tushirsak:

⨯ ro'yxat JSON qaytaradi Failed asserting that actual size 1 matches expected size 3. ⨯ bitta vakansiya JSON qaytaradi Failed asserting that null is identical to 'Backend dasturchi'.

Birinchisi: assertJsonCount(3) endi yuqori qavatni sanaydi — u yerda bitta kalit bor (data). Ikkinchisi: assertJsonPath('nom', ...) yo'li endi data.nom.

assertJsonCount(3) → assertJsonCount(3, 'data') assertJsonPath('nom', ...) → assertJsonPath('data.nom', ...) assertJsonStructure(['*' => ...])→ assertJsonStructure(['data' => ['*' => ...]])

🔑 Bu yaxshi narsa: testlar javob shakli o'zgarganini darhol aytdi. Agar ular bo'lmaganda, mijoz buni sizdan oldin bilardi.

🔍 Nega o'rash umuman kerak? Chunki javobga qo'shimcha ma'lumot kerak bo'ladi — sahifalash, meta, xatolar. Ular data yonida yashaydi.

whenLoaded() — yuklangan bo'lsa qo'sh

'kompaniya' => KompaniyaResource::make($this->whenLoaded('kompaniya')),

Ikki holatni HTTP orqali o'lchadik:

with('kompaniya') BILAN kalitlar: id, nom, maosh, maosh_matni, shahar, faol, kompaniya kompaniya: {"id": 1, "nom": "Uzum Group"} with('kompaniya') SIZ kalitlar: id, nom, maosh, maosh_matni, shahar, faol kompaniya kaliti bormi: YO'Q

🔑 E'tibor bering: kalit null emas — umuman yo'q. Bu muhim farq: null «kompaniyasi yo'q» degani, kalitning yo'qligi esa «bu javobda so'ralmagan» degani.

Sehr yo'q: MissingValue

whenLoaded() bog'lanish yuklanmagan bo'lsa MissingValue nomli maxsus obyekt qaytaradi. U toArray() natijasida hali turadi — biz buni sinab ko'rdik:

$resource->toArray($request) natijasi: kalitlar: id, nom, maosh, maosh_matni, shahar, faol, kompaniya kompaniya kaliti bormi: HA ← hali bor!

Filtrlash javob yasalganda bo'ladi: Laravel massivni ko'rib chiqadi va MissingValue bo'lgan kalitlarni tashlaydi.

🔍 Amaliy xulosa: resource'ni tekshirayotganda toArray() ga emas, haqiqiy javobga qarang — $this->getJson(...) bilan.

⚠️ Va nega umuman whenLoaded? Chunki $this->kompaniya deb yozsangiz, yuklanmagan holatda Eloquent yangi so'rov yuboradi — 29-darsdagi N+1 muammosi qaytadi. whenLoaded so'rov yubormaydi.

⚠️ Scope va ustun nomi to'qnashuvi

Resource yozilgach uchta test yashil, bittasi esa 500 berdi — va faqat store da:

ArgumentCountError Too few arguments to function App\Models\Vakansiya::faol(), 0 passed at app/Models/Vakansiya.php:22 #[Scope] protected function faol(Builder $so_rov): void ← 29-darsdagi scope

Nima bo'ldi? Zanjirni bosqichma-bosqich ochamiz:

1) Vakansiya::create(['nom' => ..., 'maosh' => ...]) → modelda faqat SHU ikki atribut bor 2) Resource $this->faol ni so'radi 3) Eloquent: «faol nomli atribut yo'q» → «unda faol() nomli METOD bormi?» → BOR — bu 29-darsdagi scope → uni 0 argument bilan chaqiradi → 💥

🔑 Sabab: ustun ham, scope ham bir xil nomlangan. Modelda atribut mavjud bo'lganda muammo yo'q — Eloquent metodgacha bormaydi. Shuning uchun xato faqat yangi yaratilgan modelda chiqdi.

🔍 Solishtiring: shahar atributi ham yo'q edi, lekin u xato bermadi — chunki shahar() nomli metod yo'q. U shunchaki null bo'ldi.

atribut yo'q + metod yo'q → null (xavfsiz) atribut yo'q + metod BOR → metod chaqiriladi 💥

Ikki yechim

// 1) Resource tomonda — mudofaa 'faol' => $this->whenHas('faol', fn () => (bool) $this->faol), → atribut yo'q bo'lsa kalit CHIQMAYDI, xato ham yo'q // 2) Controller tomonda — to'liq javob return VakansiyaResource::make($vakansiya->fresh()) → bazadan qayta o'qiydi, standart qiymatlar bilan birga

fresh() nega kerak — o'lchandik:

create() dan keyin faol atributi bormi: false fresh() dan keyin faol: 1

🔑 Ustunning standart qiymati bazada yashaydi (default '1'), PHP modelida emas. create() qaytargan obyekt siz bergan maydonlarni biladi, baza qo'ygan qiymatlarni bilmaydi.

Amalda ikkalasi ham qilinadi: fresh() javobni to'liq qiladi, whenHas esa kelajakdagi shunday to'qnashuvlardan himoyalaydi.

🔍 Uchinchi yechim ham bor va u eng chuquri: scope nomini ustun nomidan farqli qilish (masalan faqatFaol). Lekin bu 29-darsdagi kodni o'zgartirishni talab qiladi va mavjud chaqiruvlarni ham.

Sahifalash bilan birga

29-darsdagi paginate() resource bilan birga ishlaydi va javobga ikkita yangi qavat qo'shadi:

$vakansiyalar = Vakansiya::with('kompaniya')->paginate(3); return VakansiyaResource::collection($vakansiyalar);
yuqori kalitlar: data, links, meta links: first, last, prev, next meta: current_page, from, last_page, links, path, per_page, to, total meta.total = 29 meta.per_page = 3

🔑 Endi data o'ramining sababi ko'rinadi: links va meta ga joy kerak. Agar javob to'g'ridan-to'g'ri massiv bo'lganda, ularni qo'yadigan yer bo'lmasdi.

Mijoz uchun bu tayyor shartnoma: u meta.total dan umumiy sonni, links.next dan keyingi sahifa manzilini oladi — va buni o'zi hisoblamaydi.

Har xil holatlar

Yetti holat. Bu bo'lim ma'lumotnoma — hozir bir marta o'qib chiqing, keyin kerak bo'lganda qaytib qarang.

HOLAT 1

data o'rami unutilishi

assertJsonPath('nom', 'Backend dasturchi') → Failed asserting that null is identical to 'Backend dasturchi'

Resource qo'shilgach javobning butun yo'llari bir qavat pastga tushadi. Xato xabari null deydi va bu chalg'itadi — go'yo maydon yo'q.

✅ Yo'l boshiga data. qo'shing. assertJsonCount da esa ikkinchi argument: assertJsonCount(3, 'data').

🔍 Tashxis: dump($javob->json()) — javobning haqiqiy shaklini bir marta ko'rish yetadi.

HOLAT 2

Scope va ustun bir xil nomlanishi

ArgumentCountError: Too few arguments to function ...::faol(), 0 passed

Atribut mavjud bo'lmaganda Eloquent metod qidiradi va scope'ni topib, uni argumentsiz chaqiradi.

⚠️ Xato tanlab chiqadi: bazadan o'qilgan modellarda atribut bor, shuning uchun index va show ishlaydi. Faqat yangi yaratilgan modelda ko'rinadi — va buni sinovda o'tkazib yuborish oson.

✅ whenHas() ishlating, yoki fresh() bilan modelni to'ldiring, yoki scope nomini o'zgartiring.

HOLAT 3

whenLoaded — kalit yo'qoladi, null emas

yuklangan: "kompaniya": {"id": 1, "nom": "Uzum Group"} yuklanmagan: (kalit umuman YO'Q) bog'lanish bo'sh: "kompaniya": null

Uch xil holat, uch xil ma'no. Mijoz kodini shunga qarab yozadi: kalit yo'q — «so'ralmagan», null — «yo'q».

⚠️ Ba'zi mijozlar kalit yo'qligiga tayyor bo'lmaydi. Shunday hollarda whenLoaded o'rniga har doim yuklab, null qaytarish qulayroq bo'lishi mumkin — lekin unda with() ni hech qachon unutmaslik kerak.

🔍 toArray() ni to'g'ridan-to'g'ri chaqirib tekshirmang — u yerda kalit hali turadi (MissingValue). Haqiqiy javobga qarang.

HOLAT 4

Shartli maydonlar oilasi

whenLoaded('kompaniya') → bog'lanish yuklangan bo'lsa whenHas('faol') → atribut modelda bor bo'lsa when($shart, $qiymat) → ixtiyoriy shart whenNotNull($qiymat) → null bo'lmasa whenNull($qiymat) → null bo'lsa whenCounted('konikmalar') → withCount() bilan yuklangan bo'lsa whenPivotLoaded('konikma_vakansiya', ...) → 27-darsdagi pivot uchun

Hammasi bir xil ishlaydi: shart bajarilmasa MissingValue qaytadi va kalit javobdan tushib qoladi.

🔍 Foydali naqsh — huquqqa qarab maydon berish:

'user_id' => $this->when($request->user()?->can('update', $this->resource), $this->user_id),

Bu 33-darsdagi policy'ni javob shakliga olib kiradi: egasi ko'proq maydon ko'radi.

HOLAT 5

withoutWrapping() tuzog'i

JsonResource::withoutWrapping(); oddiy ro'yxat → [ {...}, {...} ] ← data YO'Q ✅ sahifalangan → {"data": ..., "links": ..., "meta": ...} ⚠️ data BOR

«data yoqmadi» deb uni o'chirsangiz, natija nomuvofiq API bo'ladi: bir endpoint o'ralgan, boshqasi yo'q.

Sabab oddiy: sahifalashda links va meta ga joy kerak, shuning uchun o'ram majburan qoladi.

✅ Tavsiya: data ni qoldiring. U bir kun kelib kerak bo'ladi, va mijozlar unga tayangan bo'ladi.

HOLAT 6

Resource ichida N+1

'kompaniya' => KompaniyaResource::make($this->kompaniya), // ⚠️ whenLoaded YO'Q

Ro'yxatda 10 ta vakansiya bo'lsa, bu 10 ta qo'shimcha so'rov yuboradi — 29-darsdagi N+1 muammosi aynan qaytadi.

Xavfli tomoni: kod ishlaydi va javob to'g'ri chiqadi. Faqat sekin.

✅ whenLoaded so'rov yubormaydi — yuklanmagan bo'lsa shunchaki kalitni tashlaydi. Va controllerda with() yozilganini tekshiring.

🔍 Tashxis: DB::listen yoki debug paneli bilan so'rovlar sonini sanang — ro'yxat uchun ikkita so'rov bo'lishi kerak (vakansiyalar + kompaniyalar).

HOLAT 7

Shartnomani buzmaslik

'maosh' => $this->maosh → 'oylik' => $this->maosh ⚠️ MIJOZ BUZILADI 'maosh' => $this->maosh → + 'oylik' => $this->maosh ✅ qo'shish xavfsiz

API — shartnoma. Kalit qo'shish odatda xavfsiz (eski mijoz uni e'tiborsiz qoldiradi), o'chirish va nomini o'zgartirish esa buzuvchi o'zgarish.

✅ Buzuvchi o'zgarish kerak bo'lsa — versiyalash: /api/v1/vakansiyalar va /api/v2/.... Eski versiya bir muddat ishlab turadi.

🔑 Endi resource fayli aynan shu shartnomaning yozma ko'rinishi. Uni o'zgartirayotganda «mijozning kodi buziladimi?» degan savolni bering — bazani o'zgartirayotganda esa bermasangiz ham bo'ladi.

Sinab ko'ramiz

Natijani taxmin qiling

Dasturchi ro'yxat endpoint'ini tezlashtirmoqchi. U with('kompaniya') ni olib tashladi — «baribir whenLoaded bor, o'zi hal qiladi» deb:

app/Http/Controllers/Api/VakansiyaController.php
public function index() { $vakansiyalar = Vakansiya::query() ->latest('id') // with('kompaniya') OLIB TASHLANDI ->take(10) ->get(); return VakansiyaResource::collection($vakansiyalar); }

Endpoint tezlashadimi? Va mijoz uchun nima o'zgaradi?

Javobni ko'rish
Tezlashadi — LEKIN javob SHAKLI o'zgaradi: {"data":[{"id":31,"nom":"...","maosh":7000000,"maosh_matni":"...", "shahar":null,"faol":true}]} ← "kompaniya" kaliti YO'Q

Ha, so'rov soni kamaydi — whenLoaded yuklanmagan bog'lanish uchun so'rov yubormaydi. Lekin natijada kompaniya kaliti javobdan butunlay chiqib ketdi.

⚠️ Mijozning kodi buziladi: vakansiya.kompaniya.nom deb yozgan mobil ilova undefined oladi. Va bu jimgina bo'ladi — server 200 qaytaradi, hech qanday xato yo'q.

🔑 whenLoaded — xavfsizlik kamari, tezlik vositasi emas. U N+1 dan himoyalaydi, lekin with() ning o'rnini bosmaydi.

with() BOR + whenLoaded → 2 so'rov, kalit BOR ✅ with() YO'Q + whenLoaded → 1 so'rov, kalit YO'Q ⚠️ shartnoma buzildi with() YO'Q + $this->kompaniya → 11 so'rov, kalit BOR ⚠️ N+1

🔍 Va eng yomoni: bu o'zgarishni test tutmaydi, agar testda faqat assertOk() bo'lsa. Shuning uchun assertJsonStructure da kompaniya ni aniq yozganimiz muhim:

$javob->assertJsonStructure([ 'data' => ['*' => ['id', 'nom', 'maosh', 'maosh_matni', 'kompaniya' => ['id', 'nom']]], ← shu qator tutadi ]);

Umumiy saboq: javob shakli — shartnoma, va uni test qo'riqlashi kerak. Tezlashtirish uchun qilingan o'zgarish shartnomani buzmasligi shart.

SAVOL 1 Resource javob shakliga nima qo'shadi?

O'ram ikkalasiga ham tegishli: ro'yxat {"data": [...]}, bitta obyekt {"data": {...}}. Shuning uchun testlarda yo'l data.nom bo'ladi va assertJsonCount(3, 'data') yoziladi. 🔑 O'ram kerak, chunki sahifalashda links va meta ga joy kerak.

SAVOL 2 whenLoaded('kompaniya') bog'lanish yuklanmagan bo'lsa nima qiladi?

Kalit butunlay yo'qoladi — null ham emas. Uch xil holat, uch xil ma'no: kalit yo'q — «so'ralmagan», null — «yo'q», obyekt — «bor». 🔍 Filtrlash toArray() da emas, javob yasalganda bo'ladi — u yergacha MissingValue turadi.

SAVOL 3 Ustun va scope bir xil nomlanganda nima bo'ladi?

Atribut topilmasa Eloquent metod qidiradi va scope'ni argumentsiz chaqiradi → ArgumentCountError. ⚠️ Xato tanlab chiqadi: bazadan o'qilgan modellarda atribut bor, faqat yangi yaratilganida yo'q. Yechim: whenHas(), fresh() yoki scope nomini o'zgartirish.

Eslab ayting

Avval o'zingiz javob bering, keyin ochib tekshiring. Oxirgi ikkitasi — 42-darsni takrorlash.

Nega javob shakli bazadan ajratiladi?

Baza — ichki narsa, API — mijoz bilan shartnoma. Ular yopishib qolsa: ustun qo'shsangiz javob o'zgaradi, ustun nomini o'zgartirsangiz mijozning kodi buziladi.

whenHas va whenLoaded farqi?

whenHas — atribut modelda bormi (masalan create() dan keyin yo'q bo'lishi mumkin). whenLoaded — bog'lanish yuklanganmi. Ikkalasi ham shart bajarilmasa kalitni javobdan olib tashlaydi.

fresh() nega kerak bo'ldi?

Ustunning standart qiymati bazada yashaydi. create() qaytargan obyekt siz bergan maydonlarni biladi, baza qo'ygan qiymatlarni (masalan faol = 1) bilmaydi. fresh() uni bazadan qayta o'qiydi.

↩︎ Takrorlash: Accept sarlavhasi nega muhim?

Usiz Laravel so'rovni brauzerdan kelgan deb hisoblaydi: validatsiya xatosi 302 + HTML, 404 esa HTML sahifa. Mijoz SyntaxError: Unexpected token '<' ko'radi.

↩︎ Takrorlash: 201 va 422 nimani bildiradi?

201 — yangi narsa yaratildi (javobda obyekt va id). 422 — so'rov to'g'ri o'qildi, lekin ma'lumot qoidaga mos emas. 400 dan farqli — u so'rovning o'zi buzuq.

  • php artisan make:resource VakansiyaResource → app/Http/Resources/. Yagona metod — toArray().

  • Controllerda: Resource::collection($ro'yxat) · Resource::make($bitta) · ->response()->setStatusCode(201).
  • ⚠️ data o'rami — ro'yxatga ham, bitta obyektga ham. Testlarda: assertJsonCount(3, 'data'), assertJsonPath('data.nom', ...), assertJsonStructure(['data' => [...]]).
