Har so'rovda 30 000 yozuv

52-darsdagi statistika controlleri shunday boshlanadi:

$vakansiyalar = Vakansiya::with('kompaniya')->get();

Bu hamma vakansiyani xotiraga oladi. Bazada 30 000 yozuv bo'lsa, har so'rov shuni takrorlaydi:

GET /api/v1/statistika (uch marta) 0.929s 0.720s 0.936s

Va bu bitta foydalanuvchi. Sahifa mashhur bo'lsa, baza faqat shu so'rov bilan band bo'lib qoladi.

Muhimi shundaki, javob deyarli o'zgarmaydi: statistika har soniyada emas, har o'n daqiqada yangilansa yetarli.

Aynan shu holat uchun kesh bor: bir marta hisoblab, natijani tez joyga qo'yib qo'yish.

Cache::remember

app/Http/Controllers/Api/StatistikaController.php
use Illuminate\Support\Facades\Cache; public function __invoke() { return Cache::remember('statistika', now()->addMinutes(10), fn () => $this->hisobla()); } private function hisobla(): array { $vakansiyalar = Vakansiya::with('kompaniya')->get(); // ... 52-darsdagi kod o'zgarmadi }

remember uch narsani oladi:

'statistika' → kalit now()->addMinutes(10) → qancha yashaydi fn () => ... → keshda bo'lmasa NIMA qilish

Mantiq oddiy: keshda bo'lsa — darrov qaytaradi; bo'lmasa — closure'ni ishlatadi, natijani saqlaydi va qaytaradi.

Hisoblash kodini hisobla() ga ko'chirdik — __invoke endi bir qator.

O'lchov

CACHE_STORE=database 0.739s ← birinchi so'rov (kesh bo'sh, hisoblandi) 0.011s ← ikkinchi 0.010s 0.0099s

67 barobar tez. Va e'tibor bering: birinchi so'rov ham oldingidan tez emas — kesh hisoblashni tezlashtirmaydi, u faqat takrorlanishini oldini oladi.

Redis bilan

Redis — xotirada ishlaydigan ma'lumotlar ombori. Kesh uchun eng ko'p ishlatiladigan tanlov.

# .env CACHE_STORE=redis REDIS_CLIENT=phpredis REDIS_HOST=127.0.0.1 REDIS_PORT=6379
CACHE_STORE=redis 0.892s ← birinchi 0.0060s ← ikkinchi 0.0054s 0.0049s
database kesh redis kesh birinchi so'rov 0.739s 0.892s keyingilari ~0.010s ~0.005s ← ikki barobar tez

Farq kichik ko'rinadi (5 millisekund), lekin sekundiga yuzlab so'rovda bu sezilarli. Va asosiysi: Redis bazani umuman bezovta qilmaydi.

Redis ichiga qaraymiz

redis-cli -n 1 --scan laravel-database-laravel-cache-statistika TTL=566 laravel-database-laravel-cache-a75f3f17... TTL=25 ← 48-darsdagi cheklov laravel-database-laravel-cache-a75f3f17...:timer TTL=25

Uch narsa ko'rinadi. Birinchidan, kalit -n 1 — Redis ning 1-bazasida (config/database.php da shunday yozilgan).

Ikkinchidan, prefiks: laravel-database-laravel-cache-. Bitta Redis serverini bir necha ilova baham ko'rishi mumkin — prefiks ularni ajratadi.

Uchinchidan, TTL=566 — bizning 600 soniyamizdan qolgan vaqt. Va yonida 48-darsdagi rate limiter kalitlari ham turibdi: kesh va cheklov bir omborni ishlatadi.

⚠️ Redis:: fasadi ishlamaydi
Redis::set('sinov', 'salom'); Error: Non-static method Redis::set() cannot be called statically.

Sabab: PHP'ning phpredis kengaytmasida global Redis klassi bor, va u Laravel fasadidan ustun keladi.

✅ To'liq nom bilan yozing:

\Illuminate\Support\Facades\Redis::set('sinov', 'salom'); // yoki faylning boshida: use Illuminate\Support\Facades\Redis;

🔑 51-darsdagi taxalluslar ro'yxatida Redis yo'q edi — endi sababi ma'lum.

Kesh — kelishuv

Kesh bepul emas. Uning narxi — eski ma'lumot:

2 ta vakansiya yaratildi GET /statistika → jami: 2 (keshlandi) yana 5 ta yaratildi GET /statistika → jami: 2 ⚠️ hamon 2 Vakansiya::count() → 7

Bu xato emas — kesh aynan shunday ishlaydi. Savol boshqacha: qancha eskilik joiz?

statistika sahifasi → 10 daqiqa eskilik — muammo emas foydalanuvchi profili → eskilik SEZILADI — keshlamang yoki qisqa bank balansi → eskilik MUMKIN EMAS

Ikki yo'l bor va ikkalasi ham kerak:

1) TTL → vaqt o'tsa o'zi eskiradi 2) forget() → ma'lumot o'zgarganda darrov tashlash

Bizda ikkalasi ham bor: 10 daqiqa TTL va hodisa bo'yicha tozalash.

Teglar

Bir guruh kalitni birdan tozalash kerak bo'lganda:

Cache::tags(['statistika', 'vakansiya'])->put('shahar-jami', 42, 600); teg bilan o'qish: 42 tegsiz o'qish: NULL ← teg kalitning bir qismi Cache::tags(['vakansiya'])->flush(); flush dan keyin: NULL ✅ bitta teg yetarli

Foydali holat: vakansiya o'zgarsa, unga tegishli hamma keshni tashlash — ro'yxat, statistika, qidiruv natijasi.

⚠️ Teglar hamma drayverda yo'q
CACHE_STORE=database Cache::tags(['a'])->put('k', 1, 60); BadMethodCallException: This cache store does not support tagging.

Teglar faqat redis va memcached da ishlaydi. file va database da yo'q.

🔑 Ya'ni teglarga tayangan kod drayver almashtirilganda yiqiladi. Loyihani file keshda boshlab, keyin teg yozsangiz — ishlab chiqarishda kutilmagan xato chiqadi.

✅ Muqobil: kalit nomiga versiya qo'shish ("vakansiya:{$v->id}:v{$v->updated_at}") — hamma drayverda ishlaydi.

Boshqa foydali metodlar

Cache::put('kalit', $qiymat, 600) → saqlash Cache::get('kalit', 'standart') → o'qish Cache::has('kalit') → bormi Cache::forget('kalit') → o'chirish Cache::flush() → ⚠️ HAMMASINI Cache::increment('son', 5) → 15 (o'lchandi) Cache::add('son', 99, 60) → false ← mavjud bo'lsa YOZMAYDI Cache::add('yangi', 1, 60) → true Cache::rememberForever('kalit', fn () => ...) → TTL'siz Cache::flexible('kalit', [60, 600], fn () => ...) → eskisini berib, fonda yangilaydi
🔑 add() — oddiy qulf

add qiymat yo'q bo'lsagina yozadi va true/false qaytaradi. Bu atomar amal.

if (Cache::add("eksport:{$user->id}", true, 300)) { EksportIsh::dispatch($user); // faqat bitta ish ketadi }

🔍 Jiddiyroq qulf uchun Cache::lock('nom', 10)->get(fn () => ...) — u 58-darsdagi withoutOverlapping() ichida ishlatiladigan mexanizm.

Har xil holatlar

Yetti holat. Bu bo'lim ma'lumotnoma — hozir bir marta o'qib chiqing, keyin kerak bo'lganda qaytib qarang.

HOLAT 1

Kalitni nomlash

❌ 'data' · 'x' · 'natija' ✅ 'statistika' ✅ "vakansiya:{$id}" ✅ "vakansiya:{$id}:konikmalar" ✅ "qidiruv:{$shahar}:{$sahifa}"

Kalit — global nom. Ikki joyda bir xil kalit ishlatilsa, biri ikkinchisining ma'lumotini o'qiydi.

🔑 Ikki nuqta bilan bo'lish odat: tur:id:qism. Redis vositalarida ular daraxt bo'lib ko'rinadi.

⚠️ Kalitga foydalanuvchi kiritgan matnni to'g'ridan-to'g'ri qo'ymang — md5() yoki tozalash kerak.

HOLAT 2

Nimani keshlamaslik kerak

❌ foydalanuvchiga xos ma'lumot — umumiy kalit bilan Cache::remember('profil', 600, fn () => auth()->user()->profil()) → BIRINCHI kirgan odamning profili HAMMAGA ko'rinadi ⚠️ ✅ Cache::remember("profil:{$user->id}", 600, ...)

Bu eng xavfli kesh xatosi: xato emas, ma'lumot sizishi.

⚠️ Yana: tez o'zgaradigan narsalar (balans, ariza holati), va hisoblash arzon bo'lgan narsalar — kesh ham vaqt oladi.

🔑 Qoida: kalitda kimga tegishli ekani ko'rinsin.

HOLAT 3

Drayverlar

array → xotirada, so'rov tugasa yo'qoladi (TESTLAR) file → storage/framework/cache — sozlash shart emas, sekin database → cache jadvali — bir necha server ko'radi redis → eng tez, teglar bor, ishlab chiqarish uchun memcached → redis kabi, lekin imkoniyati kamroq

⚠️ file keshi bir necha serverda alohida bo'ladi — 48-darsdagi rate limiting ham shundan buziladi.

🔑 Yo'l: mahalliy ishda file yoki database, ishlab chiqarishda redis. Kod o'zgarmaydi — 54-darsdagi config qatlami tufayli.

HOLAT 4

Cache::lock — haqiqiy qulf

$qulf = Cache::lock('hisobot', 120); if ($qulf->get()) { try { // faqat bitta jarayon bu yerga kiradi } finally { $qulf->release(); } } // yoki qisqasi: Cache::lock('hisobot', 120)->get(fn () => ...);

58-darsdagi withoutOverlapping() aynan shu mexanizmni ishlatadi.

⚠️ finally muhim: xato bo'lsa ham qulf ochilsin. Aks holda vazifa abadiy bloklanadi.

🔍 block(10) — qulf bo'shashini 10 soniya kutish.

HOLAT 5

Kesh bosqinchiligi (stampede)

⚠️ kesh eskirdi + 100 ta so'rov bir vaqtda keldi → 100 tasi ham "keshda yo'q" deb ko'radi → 100 marta hisoblash boshlanadi → baza yiqiladi

✅ Laravel 11+ da tayyor yechim bor:

Cache::flexible('statistika', [300, 600], fn () => $this->hisobla());

Ikki son: 300 soniyagacha kesh «yangi»; 300–600 orasida eski qiymat darrov beriladi, yangilash esa fonda bajariladi; 600 dan keyin oddiy remember kabi.

🔑 Muqobil: Cache::lock bilan faqat bitta jarayon hisoblasin.

HOLAT 6

Testda kesh

phpunit.xml: <env name="CACHE_STORE" value="array"/>

48-darsda buni ko'rgandik: array keshi har test uchun yangi, ya'ni testlar bir-birining keshini merosga olmaydi.

⚠️ Oqibati: teglar testda ishlaydi (array ularni qo'llab-quvvatlaydi), lekin database drayverida ishlab chiqarishda yiqiladi.

🔑 Ya'ni test drayveri ishlab chiqarishnikiga yaqin bo'lishi kerak — aks holda 54 va 55-darslardagi kabi «testda ishladi» tuzog'i qaytadi.

HOLAT 7

Redis nafaqat kesh

CACHE_STORE=redis → kesh QUEUE_CONNECTION=redis → navbat (55-dars) — database'dan tez SESSION_DRIVER=redis → sessiya — bir necha serverda majburiy + rate limiting (48-dars) ham kesh omborini ishlatadi

🔍 O'lchandi: Redis'ning 1-bazasida statistika kaliti yonida 48-darsdagi cheklov kalitlari ham turibdi.

⚠️ Shuning uchun Cache::flush() xavfli: u cheklov hisoblarini ham tozalaydi.

🔑 Aniq kalitni forget() qiling yoki teg ishlating.
