DARS 19 · MODUL B — LARAVEL

Komponent va forma: @csrf nima uchun kerak

Bu darsdan keyin takrorlanadigan HTML bo'laklarini komponentga aylantirasiz va IshTop'ga birinchi formani qo'shasiz. Va 13-darsda qolgan savolga javob olasiz: CSRF nima? — nazariya emas, hujumning o'zi tushuntiriladi va himoyani olib tashlab sinab ko'rasiz.

📱 O'qish ≈ 11 daqiqa 💻 Amaliyot ≈ 16 daqiqa Kerak: Dars 18

Bu darsda nimalar bor
  1. @include Eng oddiy qayta ishlatish — va uning cheklovi.
  2. Komponent <x-nom /> va @props — «HTML tegi» kabi ishlatish.
  3. Parametr uzatish :nom="$ifoda" — ikki nuqtaning ma'nosi.
  4. Forma va @csrf Yashirin _token maydoni qanday paydo bo'ladi.
  5. 🔒 CSRF hujumi Nazariya emas — hujumning o'zi: brauzer cookie'ni avtomatik yuboradi.
  6. 419 Page Expired Tokensiz POST qanday rad etiladi (jonli isbot).
  7. @method HTML forma faqat GET/POST ni biladi — method spoofing.
Nega bu muhim

18-darsdagi layout katta takrorlanishni yechdi — <head>, menyu, footer. Lekin kichik bo'laklar qoladi: vakansiya kartasi, tugma, ogohlantirish qutisi. Ular sahifalar bo'ylab takrorlanadi.

Va ikkinchi mavzu — forma. Bu ilovaning eng muhim qismi: foydalanuvchi ma'lumot kiritadi. Lekin Laravel'da forma yozganda darhol @csrf ga duch kelasiz — va uni «shunchaki yozib qo'yish kerak» deb o'tkazib yuborish xato bo'ladi. Bu himoya chorasi, va nimadan himoya qilishini bilish kerak.

@include — eng oddiy qayta ishlatish

tushuncha
@include('sinov.qism', ['nom' => 'IshTop'])

«Shu view faylini shu yerga qo'sh». 7-darsdagi require ning Blade varianti. Ma'lumot ikkinchi argumentda uzatiladi.

Oddiy, lekin bitta kamchiligi bor: qanday ma'lumot kutilayotgani ko'rinmaydi. Fayl ichini ochib qarash kerak, va nimani uzatish kerakligini eslab qolish kerak.

Komponent — «HTML tegi» kabi

resources/views/components/vakansiya-karta.blade.php
@props(['nom', 'maosh']) <div class="karta"> <b>{{ $nom }}</b> — {{ $maosh }} $ </div>
ishlatilishi
@foreach ($vakansiyalar as $v) <x-vakansiya-karta :nom="$v['nom']" :maosh="$v['maosh']" /> @endforeach

Uchta qoida:

  • Fayl resources/views/components/ da yashaydi, va nomi <x-fayl-nomi /> ga aylanadi. x- — Laravel'ning komponent belgisi.
  • @props(['nom', 'maosh']) — qanday ma'lumot kutilayotganini e'lon qiladi. Bu 6-darsdagi funksiya parametrlariga o'xshaydi: shartnoma ko'rinadi.
  • :nom="$v['nom']" — ikki nuqta muhim. Ikki nuqta bilan — qiymat PHP ifodasi; ikki nuqtasiz (nom="Backend") — oddiy matn.

Amaliy qoida: parametr bo'lsa — komponent. Parametrsiz oddiy bo'lak bo'lsa — @include ham yetadi.

Forma va @csrf

resources/views/vakansiyalar/index.blade.php
<form method="POST" action="/vakansiyalar"> @csrf <input type="text" name="nom" placeholder="Vakansiya nomi"> <button type="submit">Saqlash</button> </form>

13-darsdan bilasiz: POST — o'zgartirish uchun, va ma'lumot $_POST ga tushadi. Laravel'da uni $request->input('nom') bilan olasiz (17-dars).

Yangi narsa — @csrf. U nimaga aylanadi? Yashirin inputga:

<input type="hidden" name="_token" value="ABptdBrT1KOnxl7mya8Qf5arbLr3hWXZ95ZhQu8w" autocomplete="off">

Ya'ni sehr yo'q: tasodifiy token formaga yashirin qo'shiladi. Xuddi shu token sizning sessiyangizda ham saqlanadi (13-dars!). Forma yuborilganda Laravel ikkisini solishtiradi — mos kelmasa rad etadi.

🔒 CSRF hujumi — nimadan himoyalanamiz

Buni tushunish uchun 13-darsdagi bitta faktni eslash kerak: brauzer cookie'ni avtomatik yuboradi. Har so'rovda, kim so'raganidan qat'i nazar.

1 · Siz kirgansiz

ishtop.uz
Brauzerda sessiya cookie'si turadi

2 · Boshqa saytga kirasiz

yomon-sayt.uz
Unda yashirin forma bor — action="ishtop.uz/..."

3 · Forma o'zi yuboriladi

JS bilan
Brauzer cookie'ni ham qo'shadi — avtomatik

4 · Server ishonadi

«bu o'sha odam»
Va amalni bajaradi — sizning nomingizdan

Bu CSRF (cross-site request forgery) — «boshqa saytdan so'rovni qalbakilashtirish». Hujumchi sizning parolingizni bilmaydi, cookie'ni ham o'qiy olmaydi — lekin brauzerni sizning nomingizdan so'rov yuborishga majburlashi mumkin.

Token nega yechim bo'ladi

Hujumchi boshqa saytda turadi, va brauzerning xavfsizlik qoidasi unga ishtop.uz sahifasining mazmunini o'qishga ruxsat bermaydi. Ya'ni u cookie'ni «qo'shtirishga» majburlay oladi, lekin tokenni bilib olmaydi.

Token esa formada bo'lishi shart. Yo'q bo'lsa — Laravel rad etadi. Shunday qilib: cookie yetarli emas, sahifani ko'rgan bo'lish ham talab qilinadi.

@csrf ni olib tashlasangiz nima bo'ladi? Amaliyotda sinaysiz:

419 | Page Expired

419 — Laravel'ning «CSRF tokeni yo'q yoki mos kelmadi» degan javobi. Bu xatoni bilib qo'yish foydali: ish joyida forma ishlamasa, birinchi tekshiriladigan narsa — @csrf bor-yo'qligi.

Nega bu faqat POST'da kerak

13-darsdagi qoida: GET — o'qish, POST — o'zgartirish. CSRF himoyasi o'zgartiradigan so'rovlarga qo'llanadi: POST, PUT, PATCH, DELETE. GET ga kerak emas, chunki u (to'g'ri yozilgan bo'lsa) hech narsani o'zgartirmaydi.

Mana nega o'sha qoida shunchalik muhim edi: agar o'chirish amalini GET qilib qo'ysangiz, CSRF himoyasi umuman ishlamaydi.

@method — HTML formaning cheklovi

REST bo'yicha tahrirlash PUT, o'chirish DELETE bo'lishi kerak. Lekin HTML forma faqat ikkitasini biladi: GET va POST. Yechim:

tushuncha
<form method="POST" action="/vakansiyalar/12"> @csrf @method('PUT') ... </form>

Va bu ham yashirin inputga aylanadi — sehr yo'q:

<input type="hidden" name="_method" value="PUT">

Laravel _method maydonini ko'rsa, so'rovni PUT deb hisoblaydi va Route::put(...) ga yuboradi. Bu method spoofing deb ataladi. Brauzer POST yuboradi, Laravel esa PUT deb tushunadi.

💻 Amaliy qism kompyuterda

Amaliyotda vakansiya kartasini komponentga aylantirasiz, keyin IshTop'ga forma qo'shasiz va uni POST route'ga ulaysiz. Eng muhim tajriba oxirida: @csrf ni olib tashlab, Laravel formani 419 bilan rad etishini ko'rasiz — keyin qaytarib qo'yasiz.

Amaliyot

  1. IshTop'ga o'ting va serverni ko'taring

    cd ~/Projects/Learn/ishtop php artisan serve

    Kutilgan natija: server ishlaydi. Yangi oyna oching.

  2. Komponent yarating

    @props bilan «qanday ma'lumot kutilayotgani» ko'rinadigan bo'ladi.

    mkdir -p resources/views/components cat > resources/views/components/vakansiya-karta.blade.php <<'EOF' @props(['nom', 'maosh']) <div style="border:1px solid #ccc; padding:8px; margin:6px 0"> <b>{{ $nom }}</b> — {{ $maosh }} $ </div> EOF

    Kutilgan natija: jimlik. Fayl nomi vakansiya-karta → teg <x-vakansiya-karta />.

  3. View'ni komponent va forma bilan yangilang

    cat > resources/views/vakansiyalar/index.blade.php <<'EOF' @extends('layouts.asosiy') @section('sarlavha', 'Vakansiyalar — IshTop') @section('mazmun') <h1>Vakansiyalar</h1> @foreach ($vakansiyalar as $v) <x-vakansiya-karta :nom="$v['nom']" :maosh="$v['maosh']" /> @endforeach <h2>Yangi vakansiya</h2> <form method="POST" action="/vakansiyalar"> @csrf <input type="text" name="nom" placeholder="Vakansiya nomi"> <button type="submit">Saqlash</button> </form> @endsection EOF

    Kutilgan natija: jimlik.

  4. Controller'ga store metodi qo'shing

    Forma qabul qiluvchi. Hozircha faqat qaytarib beradi — bazaga yozish C modulida.

    cat > app/Http/Controllers/VakansiyaController.php <<'EOF' <?php namespace App\Http\Controllers; use Illuminate\Http\Request; use Illuminate\View\View; class VakansiyaController extends Controller { public function index(): View { return view('vakansiyalar.index', [ 'vakansiyalar' => [ ['nom' => 'Backend dasturchi', 'maosh' => 800], ['nom' => 'Frontend dasturchi', 'maosh' => 700], ], ]); } public function store(Request $request): string { return 'Qabul qilindi: ' . e($request->input('nom')); } } EOF

    Kutilgan natija: jimlik. Diqqat: e(...) — 18-darsda o'rgangan himoya. Controller matn qaytarganda {{ }} yo'q, shuning uchun qo'lda himoyalash kerak.

  5. POST route'ni qo'shing

    cat > routes/web.php <<'EOF' <?php use App\Http\Controllers\VakansiyaController; use Illuminate\Support\Facades\Route; Route::get('/vakansiyalar', [VakansiyaController::class, 'index']); Route::post('/vakansiyalar', [VakansiyaController::class, 'store']); EOF php artisan route:list --path=vakansiyalar GET|HEAD vakansiyalar .. VakansiyaController@index POST vakansiyalar .. VakansiyaController@store

    Kutilgan natija: ikkita route — bir xil manzil, ikki xil metod. 14-darsdagi qoida amalda: route jadvali metod + yo'l bo'yicha kalitlangan.

  6. Komponent va @csrf chiqishini ko'ring

    curl -s http://localhost:8000/vakansiyalar | grep -E 'border|_token' | head -4 <div style="border:1px solid #ccc; padding:8px; margin:6px 0"> <div style="border:1px solid #ccc; padding:8px; margin:6px 0"> <input type="hidden" name="_token" value="ABptdBrT..." autocomplete="off">

    Kutilgan natija: ikkita karta (komponent ikki marta ishladi) va @csrf dan kelgan yashirin input. Token sizda boshqacha bo'ladi — u har sessiyada yangi.

  7. Formani brauzerda yuborib ko'ring

    xdg-open http://localhost:8000/vakansiyalar

    Kutilgan natija: vakansiya nomini yozib «Saqlash» bosganingizda: Qabul qilindi: ... chiqadi. 🎉 Forma ishlaydi.

  8. 🔒 @csrf ni olib tashlab sinang

    Bu darsning eng muhim tajribasi. Himoya chindan ishlayotganini ko'rasiz.

    View'dagi @csrf qatorini o'chirib (yoki {{-- @csrf --}} qilib izohga aylantirib) saqlang, keyin brauzerda sahifani yangilab formani qayta yuboring.

    grep -c '@csrf' resources/views/vakansiyalar/index.blade.php 0

    Kutilgan natija: brauzerda katta xato sahifasi:

    419 | Page Expired

    Laravel formani rad etdi — controller umuman ishlamadi. Bu 17-darsdagi middleware mexanizmi: CSRF tekshiruvi middleware sifatida ishlaydi va $next() ni chaqirmaydi.

  9. @csrf ni qaytarib qo'ying

    grep -n 'form method' resources/views/vakansiyalar/index.blade.php

    Kutilgan natija: qator raqami ko'rinadi. Muharrirda <form ...> dan keyingi qatorga @csrf ni qaytarib yozing va formani qayta yuborib ishlashini tasdiqlang.

  10. @method nimaga aylanishini ko'ring

    Sehr yo'q — yana yashirin input.

    mkdir -p resources/views/sinov printf '<form method="POST">\n @csrf\n @method("PUT")\n</form>\n' > resources/views/sinov/m.blade.php php artisan tinker --execute="echo view('sinov.m')->render();" 2>/dev/null | grep -oE '<input[^>]*>' <input type="hidden" name="_token" value="" autocomplete="off"> <input type="hidden" name="_method" value="PUT">

    Kutilgan natija: ikkita yashirin input. @method('PUT') → _method maydoni. Laravel shuni ko'rib so'rovni PUT deb hisoblaydi — chunki HTML forma faqat GET va POST'ni biladi.
    💡 Diqqat: _token qiymati bu yerda bo'sh — chunki tinker terminalda ishlaydi va sessiya yo'q (13-dars: sessiya cookie orqali yashaydi). Brauzerda esa u to'ldirilgan bo'ladi — yuqoridagi qadamda ko'rdingiz.
    Sinovdan keyin tozalash: rm -rf resources/views/sinov

  11. Ishni saqlang

    rm -rf resources/views/sinov git add -A git commit -m "19-dars: Blade komponent, forma va CSRF"

    Kutilgan natija: commit haqida xabar.

Sinab ko'ramiz

Natijani taxmin qiling

Hujumchi yomon-sayt.uz da shunday forma yashirgan, va siz ishtop.uz ga kirgan holdasiz:

yomon-sayt.uz sahifasida
<form method="POST" action="https://ishtop.uz/vakansiyalar/12/ochirish" id="f"> </form> <script>document.getElementById('f').submit();</script>

Ikki savol: (a) brauzer sessiya cookie'ngizni yuboradimi? (b) vakansiya o'chiriladimi?

Javobni ko'rish

(a) HA — cookie yuboriladi. Bu 13-darsdagi fakt: brauzer cookie'ni avtomatik qo'shadi, so'rovni kim boshlaganidan qat'i nazar. Server nuqtai nazaridan bu «kirgan foydalanuvchi»ning so'rovi.

(b) YO'Q — o'chirilmaydi, chunki formada CSRF tokeni yo'q. Laravel 419 qaytaradi va controller ishlamaydi.

Nega hujumchi tokenni qo'sha olmaydi: token ishtop.uz sahifasida turadi. Hujumchining sahifasi boshqa domenda, va brauzer unga boshqa domendagi sahifaning mazmunini o'qishga ruxsat bermaydi. Ya'ni u cookie'ni «qo'shtirishga» majburlay oladi, lekin tokenni ko'ra olmaydi.

Asosiy xulosa: cookie «kim ekanligingizni» isbotlaydi, token esa «haqiqatan siz xohlaganingizni» isbotlaydi. Ikkisi boshqa-boshqa savol — shuning uchun ikkisi ham kerak.

SAVOL 1 @csrf nimaga aylanadi?

<input type="hidden" name="_token" value="..."> — oddiy yashirin maydon. Xuddi shu token sessiyada ham saqlanadi va ikkisi solishtiriladi.

SAVOL 2 Nega hujumchi CSRF tokenini qo'sha olmaydi?

Brauzerning xavfsizlik qoidasi boshqa domendagi sahifa mazmunini o'qishni taqiqlaydi. Cookie avtomatik ketadi, lekin token ko'rinmaydi.

SAVOL 3 Nega @method('PUT') kerak?

HTML forma PUT/DELETE ni yubora olmaydi. Yechim: POST yuborib, _method yashirin maydonida haqiqiy metodni aytish — method spoofing.

Eslab ayting

Avval o'zingiz javob bering, keyin ochib tekshiring. Oxirgi ikkitasi — 18-darsni takrorlash.

Komponent va @include — qachon qaysi biri?

Parametr bo'lsa — komponent (@props bilan kutilayotgan ma'lumot ko'rinadi). Parametrsiz oddiy bo'lak bo'lsa @include ham yetadi.

CSRF hujumi qanday ishlaydi — bir gapda?

Brauzer cookie'ni avtomatik yuborgani uchun, boshqa saytdagi yashirin forma sizning nomingizdan so'rov yubora oladi. Token buni to'xtatadi, chunki hujumchi uni o'qiy olmaydi.

CSRF himoyasi qaysi metodlarga qo'llanadi?

O'zgartiradiganlarga: POST, PUT, PATCH, DELETE. GET ga kerak emas — shuning uchun o'zgartirishni hech qachon GET qilmaslik muhim (13-dars).

↩︎ Takrorlash: {{ }} nimaga kompilyatsiya qilinadi?

<?php echo e($x); ?> — va e() bu htmlspecialchars. Shuning uchun {{ }} XSS'dan himoyalaydi.

↩︎ Takrorlash: @yield va @section munosabati?

Layout'da @yield('nom') bo'sh joy qoldiradi; sahifa @section('nom') bilan uni to'ldiradi.

Cho'ntak xulosasi
  • @include('papka.fayl', [...]) — oddiy qayta ishlatish (require ning Blade varianti).
  • Komponent: resources/views/components/nom.blade.php → <x-nom />. @props([...]) bilan parametrlar e'lon qilinadi.
  • :nom="$ifoda" — ikki nuqta = PHP ifodasi; ikki nuqtasiz = oddiy matn.
  • Forma: method="POST" + @csrf. Ma'lumot $request->input('nom') bilan olinadi.
  • 🔒 @csrf → <input type="hidden" name="_token" ...>. Xuddi shu token sessiyada ham bor, ikkisi solishtiriladi.
  • CSRF hujumi: brauzer cookie'ni avtomatik yuboradi → boshqa sayt sizning nomingizdan so'rov yubora oladi. Token buni to'xtatadi, chunki hujumchi uni o'qiy olmaydi.
  • @csrf yo'q → 419 Page Expired. Forma ishlamasa — birinchi shuni tekshiring.
  • @method('PUT') → _method yashirin maydoni (HTML forma faqat GET/POST biladi).
🌱 Keyingi dars — Modul B ning oxirgisi

Forma ishlaydi, lekin bitta jiddiy kamchiligi bor: hech narsa tekshirilmaydi. Foydalanuvchi bo'sh nom yuborsa ham, 500 belgili matn yuborsa ham — hammasi qabul qilinadi.

20-darsda validation keladi: qoidalarni e'lon qilasiz, Laravel tekshiradi, xato bo'lsa foydalanuvchini formaga qaytaradi — xato xabarlari va oldin kiritilgan qiymatlar bilan (old()). Bu 13-darsdagi «POST → redirect → GET» naqshining Laravel'dagi to'liq shakli. Shundan keyin Modul B tugaydi va bazaga o'tamiz.
