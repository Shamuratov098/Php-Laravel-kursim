DARS 16 · MODUL B — LARAVEL

Laravel o'rnatish: IshTop tug'iladi

Modul B boshlandi. Bugun IshTop loyihasini yaratamiz — bu kursning oxirigacha o'sib boradigan va oxirida portfoliongizga aylanadigan ilova. Va papkalarni ochib qarasangiz, ko'p narsani allaqachon tanigan bo'lasiz.

📱 O'qish ≈ 10 daqiqa 💻 Amaliyot ≈ 20 daqiqa Kerak: Dars 15

Bu dars nima uchun oson bo'ladi

15 dars davomida poydevor qo'ydik va oxirida mini-framework yozdik. Bugun Laravel ochilganda quyidagilarni ko'rasiz:

  • public/index.php — front controller (14-dars)
  • routes/web.php — route jadvali (14-dars)
  • app/Http/Controllers/ — controllerlar (14-dars)
  • vendor/autoload.php — autoload (12-dars)
  • Konstruktorga yozilgan tiplar — container va DI (15-dars)

Ya'ni Laravel — siz yozgan narsaning professional, to'liq versiyasi. Bugungi maqsad: ilovani ishga tushirish va har papkaning nima uchun borligini bilish.

O'rnatish: bitta buyruq

terminal
composer create-project laravel/laravel ishtop

12-darsda ko'rgan Composer — mana uning eng katta ishi. Bu buyruq ~1 daqiqada quyidagilarni o'zi qiladi:

  1. 79 ta paketni yuklab oladi (vendor/ ga) — Laravel'ning o'zi va uning bog'liqliklari
  2. .env faylini yaratadi va ilova kalitini generatsiya qiladi (APP_KEY — shifrlash uchun)
  3. database/database.sqlite faylini yaratadi
  4. Migration'larni ishga tushiradi — bazada users, cache, jobs jadvallari paydo bo'ladi
Nega SQLite — va nega bu yaxshi xabar

Laravel 11 dan boshlab standart baza — SQLite. Ya'ni server o'rnatish, parol, port, foydalanuvchi yaratish — hech narsa kerak emas. Baza shunchaki bitta fayl: database/database.sqlite.

Bu bizning rejaga aynan mos: C modulida Eloquent'ni o'rganganda diqqat ma'lumotda bo'ladi, baza sozlashda emas. MySQL'ga Modul H da ko'chamiz — va o'sha ko'chishning o'zi alohida dars bo'ladi.

Bu faylda baza paroli, API kalitlari va APP_KEY bo'ladi. Laravel uni .gitignore ga o'zi qo'shib qo'yadi — tekshirib ko'rasiz. Uning o'rniga .env.example repoda turadi: «qanday kalitlar kerak» ro'yxati, qiymatlarsiz.

Route yozishning ikki shakli

Laravel o'rnatilganda routes/web.php shunday bo'ladi:

routes/web.php — standart holat
Route::get('/', function () { return view('welcome'); });

Ajratilgan qism — nomsiz funksiya (closure yoki anonim funksiya). 6-darsda funksiyalarni o'rgandik, lekin ularga har doim nom berdik. Bu esa nomsiz: funksiya darhol, joyida beriladi.

Ma'nosi: «/ so'ralganda mana shu kodni bajar». Kichik sahifalar uchun qulay. Lekin loyiha o'sganda routes/web.php uzun bo'lib ketadi, shuning uchun ikkinchi shakl bor — controller:

routes/web.php — controller bilan
Route::get('/vakansiyalar', [VakansiyaController::class, 'index']);

Bu sizning $router->add('GET', '/vakansiyalar', Vakansiyalar::class) qatoringizning aynan o'zi — faqat bitta qo'shimcha bilan: metod nomi ham beriladi ('index'). Shuning uchun bitta controllerda bir nechta sahifa bo'lishi mumkin — sizda esa har controllerda faqat bitta handle() bor edi.

Qaysi shaklni ishlatish

Bu kursda controller shaklini ishlatamiz — chunki real loyihada shunday yoziladi va u testlash uchun ham qulay. Closure'li shakl esa juda kichik sahifalar yoki tez sinov uchun qoladi.

💻 Amaliy qism kompyuterda

Amaliyotda IshTop loyihasini yaratasiz (bir buyruq, ~1 daqiqa), papkalarni ochib ko'rasiz, .env ni tekshirasiz, serverni ko'tarib brauzerda Laravel'ning kutib olish sahifasini ko'rasiz. Keyin birinchi controller va route'ingizni yozib, route:list da paydo bo'lganini tasdiqlaysiz.

Amaliyot

  1. IshTop loyihasini yarating

    Loyiha Learn/ papkasida, kurs sayti va php-poydevor yonida turadi — rejada shunday belgilangan.

    cd ~/Projects/Learn composer create-project laravel/laravel ishtop Creating a "laravel/laravel" project at "./ishtop" ... INFO Application key set successfully. INFO Preparing database. Creating migration table .. DONE INFO Running migrations. 0001_01_01_000000_create_users_table .. DONE 0001_01_01_000001_create_cache_table .. DONE 0001_01_01_000002_create_jobs_table .. DONE

    Kutilgan natija: ~1 daqiqa kutiladi, oxirida migration'lar bajarilgani ko'rinadi. Diqqat: siz hech narsa sozlamadingiz — baza fayli yaratildi va jadvallar tushdi.
    Agar tarmoq sekin bo'lsa uzoqroq davom etadi — bu normal.

  2. Versiyani va tuzilmani ko'ring

    cd ishtop php artisan --version ls Laravel Framework 13.25.0 app artisan bootstrap composer.json composer.lock config database package.json phpunit.xml public README.md resources routes storage tests vendor vite.config.js

    Kutilgan natija: versiya raqami (sizda kattaroq bo'lishi mumkin — Laravel tez-tez yangilanadi) va papkalar ro'yxati.

  3. Tanish fayllarni oching

    Bu darsning eng qiziq daqiqasi: siz yozgan narsani Laravel'da ko'rish.

    head -3 public/index.php echo '---' cat routes/web.php echo '---' ls app/Http/Controllers/ <?php use Illuminate\Foundation\Application; --- <?php use Illuminate\Support\Facades\Route; Route::get('/', function () { return view('welcome'); }); --- Controller.php

    Kutilgan natija: public/index.php, routes/web.php va app/Http/Controllers/ — uchtasi ham 14-darsda o'zingiz yasagan narsalar. 17-darsda index.php ni to'liq o'qib chiqamiz.

  4. .env ni tekshiring

    grep -E 'APP_NAME|APP_KEY|DB_CONNECTION|SESSION_DRIVER' .env echo '--- .env Git'ga tushadimi? ---' git check-ignore -v .env APP_NAME=Laravel APP_KEY=base64:... DB_CONNECTION=sqlite SESSION_DRIVER=database .gitignore:3:.env

    Kutilgan natija: APP_KEY to'ldirilgan (o'rnatishda generatsiya qilingan), baza — sqlite. Va oxirgi qator muhim: .env allaqachon .gitignore da — Laravel buni o'zi qilgan.
    APP_NAME ni IshTop ga o'zgartirib qo'yishingiz mumkin.

  5. Serverni ko'taring

    php artisan serve INFO Server running on [http://127.0.0.1:8000]. Press Ctrl+C to stop the server

    Kutilgan natija: brauzerda http://localhost:8000 ni ochsangiz — Laravel'ning kutib olish sahifasi. 🎉 Ilova ishlayapti.
    Terminal band bo'ladi — yangi oyna oching.

  6. Route'larni ko'ring

    Bu sizning $routes massivingizning ko'rinadigan shakli.

    php artisan route:list GET|HEAD / .. routes/web.php:5 GET|HEAD storage/{path} storage.local › ... GET|HEAD up ... Showing [4] routes

    Kutilgan natija: to'rtta route. Diqqat: GET|HEAD — Laravel HEAD ni ham o'zi qo'shadi (sizning router'ingizda bu yo'q edi). up — «ilova tirikmi?» tekshiruvi uchun maxsus route.
    Sinab ko'ring: curl -s -o /dev/null -w '%{http_code}\n' http://localhost:8000/up

  7. Birinchi controller'ingizni yarating

    Qo'lda yozish kerak emas — artisan shablonni o'zi beradi.

    php artisan make:controller VakansiyaController INFO Controller [app/Http/Controllers/VakansiyaController.php] created successfully.

    Kutilgan natija: fayl yaratilgani haqida xabar. cat app/Http/Controllers/VakansiyaController.php bilan ochib ko'ring — ichi hozircha bo'sh.

  8. Controller'ga metod yozing

    cat > app/Http/Controllers/VakansiyaController.php <<'EOF' <?php namespace App\Http\Controllers; class VakansiyaController extends Controller { public function index(): string { return '<h1>Vakansiyalar</h1><p>IshTop — birinchi sahifam</p>'; } } EOF

    Kutilgan natija: jimlik. Diqqat qiling: namespace App\Http\Controllers — 12-darsdagi PSR-4 qoidasi (App\ → app/). Va extends Controller — 9-darsdagi meros.

  9. Route'ni ulang

    cat > routes/web.php <<'EOF' <?php use App\Http\Controllers\VakansiyaController; use Illuminate\Support\Facades\Route; Route::get('/', function () { return view('welcome'); }); Route::get('/vakansiyalar', [VakansiyaController::class, 'index']); EOF curl -s http://localhost:8000/vakansiyalar; echo <h1>Vakansiyalar</h1><p>IshTop — birinchi sahifam</p>

    Kutilgan natija: sahifa ishlaydi. 🎉 Va e'tibor bering — serverni qayta ishga tushirmadik. Laravel har so'rovda fayllarni qaytadan o'qiydi (1-darsdagi «interpretator» xususiyati).

  10. Yangi route ro'yxatda paydo bo'lganini tekshiring

    php artisan route:list --path=vakansiyalar GET|HEAD vakansiyalar .. VakansiyaController@index Showing [1] routes

    Kutilgan natija: VakansiyaController@index — ya'ni «bu route shu controllerning shu metodiga boradi». --path= — faqat mos route'larni ko'rsatadi.

  11. tinker ni sinab ko'ring

    Bu ilova ichida kod sinash uchun — C modulida bazani tekshirishda juda ko'p ishlatiladi.

    php artisan tinker Psy Shell ... (PHP 8.3.32 — cli)

    Kutilgan natija: interaktiv rejim ochiladi. Sinab ko'ring: 2 + 2 → = 4. Chiqish uchun exit.
    Bu oddiy PHP emas — ilovangiz yuklangan holda ishlaydi, shuning uchun keyinchalik User::count() kabi narsalarni ham shu yerda sinaymiz.

  12. Git repo yarating va saqlang

    IshTop — alohida repo, chunki u portfolio ishingiz bo'ladi (rejada shunday belgilangan).

    git init -b main git add -A git commit -m "IshTop: Laravel 13 loyihasi yaratildi"

    Kutilgan natija: commit yaratildi. Diqqat: git status qilsangiz vendor/ va .env ro'yxatda yo'q — Laravel .gitignore ni to'g'ri sozlab qo'ygan (12-darsdagi qoida).

Sinab ko'ramiz

Natijani taxmin qiling

routes/web.php ga yangi route qo'shdingiz, lekin serverni qayta ishga tushirmadingiz. Va route:list ni ham ishlatmadingiz. Sahifa ishlaydimi?

routes/web.php ga qo'shildi
Route::get('/kompaniyalar', [KompaniyaController::class, 'index']);
Javobni ko'rish

Ha, darhol ishlaydi — server qayta ishga tushirilmasa ham.

Sabab: 1-darsdagi fakt — PHP interpretator. Har so'rovda fayllar qaytadan o'qiladi, ya'ni oxirgi holati ishlatiladi. Kompilyatsiya qilinadigan tillarda (Java, Go) esa qayta qurish va qayta ishga tushirish kerak bo'lardi.

route:list ham hech narsani «yoqmaydi» — u shunchaki ko'rsatadi. Ya'ni tekshirish uchun asbob, sozlash uchun emas.

⚠️ Bitta muhim istisno bor: agar php artisan route:cache ishlatilgan bo'lsa (ishlab chiqarish serverida tezlik uchun), route'lar keshlanadi va yangi route ko'rinmaydi — kesh tozalanmaguncha (route:clear). Ish joyida bu klassik chalkashlik: «kodni o'zgartirdim, lekin hech narsa o'zgarmadi». Kesh haqida Modul G da (config va kesh darsi) gaplashamiz.

SAVOL 1 Laravel'da standart baza qaysi?

Laravel 11 dan boshlab standart — SQLite, va create-project uni o'zi yaratib migration'larni ham bajaradi. MySQL'ga Modul H da ko'chamiz.

SAVOL 2 routes/web.php sizning mini-framework'ingizdagi nimaga to'g'ri keladi?

Route::get('/x', [C::class, 'index']) — bu $router->add('GET', '/x', C::class) ning aynan o'zi, faqat metod nomi ham beriladi.

SAVOL 3 .env fayli nima uchun Git'ga tushmaydi?

Baza paroli, API kalitlari, APP_KEY — bular maxfiy. Repoda uning o'rniga .env.example turadi: kalitlar ro'yxati, qiymatlarsiz.

Eslab ayting

Avval o'zingiz javob bering, keyin ochib tekshiring. Oxirgi ikkitasi — 15-darsni takrorlash.

composer create-project to'rtta nima qiladi?

1) Paketlarni yuklaydi (vendor/). 2) .env va APP_KEY yaratadi. 3) database/database.sqlite faylini yaratadi. 4) Migration'larni ishga tushiradi.

Closure (nomsiz funksiya) nima?

Nom berilmagan funksiya — joyida, darhol beriladi: Route::get('/', function () { ... }). Kichik sahifalar uchun qulay; real loyihada controller ishlatiladi.

Laravel'dagi qaysi uch narsa sizga 14-darsdan tanish?

public/index.php (front controller), routes/web.php (route jadvali), app/Http/Controllers/ (controllerlar).

↩︎ Takrorlash: container nima qiladi?

Obyekt yasaydi va kerakli bog'liqliklarni o'zi topib qo'yadi — konstruktor tiplarini Reflection bilan o'qib. Bu autowiring.

↩︎ Takrorlash: nega faqat public/ brauzerga ochiq?

Xavfsizlik: .env, vendor/, app/ — brauzer uchun mavjud emas. Laravel ham xuddi shu tuzilmani ishlatadi.

Cho'ntak xulosasi
  • composer create-project laravel/laravel ishtop — bitta buyruq: paketlar + APP_KEY + SQLite fayli + migration'lar.
  • Standart baza — SQLite, bitta fayl: database/database.sqlite. Sozlash kerak emas.
  • Tanish papkalar: public/index.php · routes/web.php · app/Http/Controllers/ · vendor/.
  • Yangi papkalar: app/Models · config · database · resources/views · storage · tests.
  • ⚠️ .env — Git'ga tushmaydi (parollar). Repoda .env.example.
  • artisan: serve · route:list · make:controller · tinker · migrate.
  • Route ikki shakli: closure (kichik) va controller (real loyiha — biz shuni ishlatamiz).
  • Kod o'zgarsa server qayta ishga tushirilmaydi — PHP har so'rovda faylni qayta o'qiydi.
🌱 Keyingi dars — eng katta bog'lanish

Bugun public/index.php ning faqat birinchi qatorlariga qaradik. 17-darsda uni to'liq o'qiymiz — va uning yonida o'zingizning public/index.php faylini qo'yamiz. Ular qator-baqator mos keladi:

sizda: require 'vendor/autoload.php'; → Laravel: require ... vendor/autoload.php sizda: new Container(); bind(...) → Laravel: bootstrap/app.php sizda: $router->dispatch($metod, $yol) → Laravel: $app->handleRequest(...)

Bundan tashqari bitta yangi tushuncha keladi — middleware. Uni jonli ko'rasiz: log yozadigan middleware yasab, u controllerdan oldin ham, keyin ham ishlashini o'z ko'zingiz bilan tasdiqlaysiz.
