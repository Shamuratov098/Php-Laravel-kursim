Migration: jadvalni qo'lda emas, kod bilan yaratish

21 va 22-darslarda jadvallarni qo'lda yasadik. Bugun ularni kodga ko'chiramiz — shunda jadval tuzilishi git'da yashaydi va istalgan kompyuterda bitta buyruq bilan qayta tiklanadi. Va bu ham sehr emas: Laravel sizga aynan o'sha CREATE TABLE ni ko'rsatib beradi.

  5. Ustun turlari id · string · integer · boolean · timestamps · nullable · default.

Nega qo'lda yozilgan SQL yetmaydi

Hozir sizning jadvallaringiz sql/01-jadval.php va sql/04-join.php ichida. Uchta savol:

  1. Hamkasbingiz loyihani yuklab oldi. Unda jadvallar qayerdan paydo bo'ladi? Unga «bu ikki faylni shu tartibda ishga tushir» deb yozasizmi?
  2. Serverga chiqarganda-chi? U yerda ham qo'lda ishga tushirasizmi?
  3. Bir oydan keyin jadvalga ustun qo'shdingiz. Hamkasbingiz qaysi o'zgarishlarni allaqachon qo'llagan-u qaysinisini qo'llamaganini qanday biladi?

Uchala savolning javobi bitta: migration. Bu — jadval tuzilishini kod qilib yozish. Kod git'da yashaydi (demak hamma bir xil nusxaga ega), va Laravel har bir kompyuterda qaysi o'zgarish qo'llanganini yozib boradi — shuning uchun php artisan migrate hamma joyda faqat yetishmaganini bajaradi.

Bu Git kursidagi g'oyaning davomi: tarix va takrorlanuvchanlik. Farqi — u yerda kod tarixi edi, bu yerda baza tuzilishi tarixi.

Birinchi migration

terminal
php artisan make:migration create_kompaniyalar_table

Fayl database/migrations/ ichida, oldida sana va vaqt bilan paydo bo'ladi: 2026_08_17_045931_create_kompaniyalar_table.php. Vaqt tasodifiy emas — tartibni belgilaydi: migration'lar shu nom bo'yicha ketma-ket bajariladi.

database/migrations/…_create_kompaniyalar_table.php
<?php use Illuminate\Database\Migrations\Migration; use Illuminate\Database\Schema\Blueprint; use Illuminate\Support\Facades\Schema; return new class extends Migration { public function up(): void { Schema::create('kompaniyalar', function (Blueprint $table) { $table->id(); $table->timestamps(); }); } public function down(): void { Schema::dropIfExists('kompaniyalar'); } };

Diqqat qiling — Laravel jadval nomini o'zi topdi: create_kompaniyalar_table → Schema::create('kompaniyalar', …). Shuning uchun nomni shu qolipda yozish kerak.

Ikkita yangi shakl

1) return new class extends Migration — nomsiz klass (anonim klass). 7-darsdagi oddiy klass, faqat nomi yo'q. Nega? Bu klass faqat shu faylda, bir marta ishlatiladi — nom berilsa, ikkita migration bir xil nom olib to'qnashishi mumkin edi. G'oyasi 16-darsdagi nomsiz funksiya (closure) bilan bir xil: bir martalik narsaga nom shart emas.

2) function (Blueprint $table) { … } — closure (16-dars). Laravel bo'sh «chizma»ni (Blueprint) yasab, uni sizning funksiyangizga beradi; siz unga ustunlarni qo'shasiz; keyin Laravel undan SQL tuzadi.

up() va down()

MetodVazifasi
up()Oldinga: o'zgarishni qo'llash (jadval yasash, ustun qo'shish)
down()Ortga: aynan shu o'zgarishni bekor qilish

down() — bu «undo» tugmasi. Yangi jadval yaratganda Laravel uni o'zi to'ldiradi (dropIfExists). Lekin mavjud jadvalni o'zgartirganda u bo'sh qoladi — chunki Laravel sizning niyatingizni bilmaydi. O'zingiz yozishingiz kerak: ustun qo'shdingizmi — down() da uni o'chiring.

Ustun turlari

KodNima yasaydi
$table->id()Birlamchi kalit — o'sib boruvchi id (21-dars)
$table->string('nom')Matn (qisqa). Uzun matn uchun — text()
$table->integer('maosh')Butun son
$table->boolean('faol')Ha/yo'q (SQLite'da 0/1)
$table->timestamps()Ikkita ustun: created_at va updated_at
->nullable()Bo'sh (NULL) bo'lishi mumkin
->default(true)Standart qiymat
->unique()Takrorlanmasin
$table->foreignId('kompaniya_id')->constrained('kompaniyalar')Tashqi kalit (22-dars) + baza darajasidagi tekshiruv

Bu metodlar zanjir bo'lib ulanadi: $table->string('shahar')->nullable(). Har biri o'zini qaytaradi — shuning uchun ketma-ket yozish mumkin.

🔍 Sehr yo'q: --pretend

«Laravel bu kod ortida nima qiladi?» degan savolga javobni o'zi beradi. --pretend flagi migration'ni bajarmaydi, faqat qanday SQL yuborishini ko'rsatadi:

terminal
php artisan migrate --pretend
2026_08_17_045931_create_kompaniyalar_table ⇂ create table "kompaniyalar" ("id" integer primary key autoincrement not null, "nom" varchar not null, "shahar" varchar, "created_at" datetime, "updated_at" datetime)

Bu aynan 21-darsda qo'lingiz bilan yozgan CREATE TABLE. $table->id() → integer primary key autoincrement, $table->string('nom') → varchar not null, ->nullable() → not null yo'q.

Migration — yangi til emas, SQL yozadigan qulay usul. Xuddi Blade oddiy PHP'ga aylangani (18-dars) va Eloquent keyinroq SQL yozishi kabi.

Bajarish, tarix va ortga qaytish

BuyruqNima qiladi
php artisan migrateHali bajarilmagan migration'larni ishga tushiradi
php artisan migrate:statusQaysi biri bajarilgan (Ran), qaysi biri kutyapti (Pending)
php artisan migrate:rollbackOxirgi to'plamni ortga qaytaradi (down() ni chaqiradi)
php artisan migrate:freshHamma jadvalni tashlab, hammasini qaytadan yasaydi. ⚠️ Ma'lumot yo'qoladi
php artisan migrate --pretendBajarmaydi — faqat SQL'ni ko'rsatadi

Laravel «qaysi biri bajarilgan»ni qayerda saqlaydi? Bazaning o'zida — migrations nomli jadvalda:

id | migration | batch 1 | 0001_01_01_000000_create_users_table | 1 2 | 0001_01_01_000001_create_cache_table | 1 3 | 0001_01_01_000002_create_jobs_table | 1 4 | 2026_08_17_045931_create_kompaniyalar_table | 1 5 | 2026_08_17_050016_create_vakansiyalar_table | 1

Bu oddiy jadval — 21-darsda o'rgangan SELECT bilan o'qiy olasiz. Sehr yo'q, ro'yxat bor.

batch — to'plam raqami

Bir migrate chaqiruvida bajarilgan hammasi bitta batch raqamini oladi. Keyinroq yangi migration qo'shib migrate qilsangiz — u batch 2 bo'ladi.

migrate:rollback aynan oxirgi to'plamni qaytaradi. Ya'ni «kecha qo'shgan 3 ta o'zgarishimni bekor qil» degani — hammasi birga qaytadi, bittalab emas.

⚠️ migrate:fresh — kuchli, lekin xavfli

U bazadagi barcha jadvalni tashlaydi va migration'larni noldan bajaradi. Ishlab chiqishda juda qulay («toza holatdan boshlay»), lekin real serverda hamma ma'lumot yo'qoladi. Qoida: fresh — faqat o'z kompyuteringizda.

Tashqi kalitni baza tekshiradi

migration ichida
$table->foreignId('kompaniya_id')->nullable()->constrained('kompaniyalar');

22-darsda kompaniya_id oddiy son edi — u yerga istalgan raqam yozish mumkin edi, hatto mavjud bo'lmagan kompaniyaniki ham. constrained() esa bazaga qoida qo'yadi:

INSERT INTO vakansiyalar (nom, kompaniya_id) VALUES ('Test', 999) SQLSTATE[23000]: Integrity constraint violation: 19 FOREIGN KEY constraint failed

Baza o'zi rad etdi. Bu 20-darsdagi validatsiyaning eng chuqur qatlami: formada tekshiramiz, lekin oxirgi himoya — bazada.

💻 Amaliy qism kompyuterda

Amaliyotda ikkita migration yozasiz va qo'lda yasagan jadvallaringizni ular bilan almashtirasiz. Yo'lda --pretend bilan Laravel yozadigan SQL'ni ko'rasiz, migrations jadvalini o'qiysiz, rollback qilib ortga qaytasiz va tashqi kalitni bazaning o'zi tekshirishini sinab ko'rasiz.

Amaliyot

  1. Ikkita migration yarating

    Tartib muhim: vakansiyalar kompaniyalar ga tayanadi, shuning uchun kompaniyalar oldin yaratilishi kerak.

    Kutilgan natija: ikkita yangi fayl. Ro'yxatda Laravel'ning o'z migration'lari ham bor (users, cache, jobs) — ular loyiha yaratilganda kelgan (16-dars).

  2. kompaniyalar migration'ini to'ldiring

    Muharrirda …_create_kompaniyalar_table.php ni oching va up() ichidagi Schema::create ni shunday qiling:

    Ya'ni: $table->id(); va $table->timestamps(); orasiga ikki qator qo'shasiz. down() ga tegmang — u allaqachon to'g'ri.

  3. vakansiyalar migration'ini to'ldiring

    Bu yerda 22-darsdagi tashqi kalit qoida bo'lib yoziladi.

  5. Endi haqiqatda bajaring

    Kutilgan natija: beshta migration bajariladi (uchtasi Laravel'niki + sizniki ikkita). Ma'lumot yo'qoldi — bu kutilgan, keyingi qadamda qaytaramiz.

Sinab ko'ramiz

Natijani taxmin qiling

kompaniyalar migration'i allaqachon bajarilgan (Ran). Endi unutilgan ustunni qo'shmoqchisiz — faylni ochib tahrirlaysiz va migrate qilasiz:

…_create_kompaniyalar_table.php
Schema::create('kompaniyalar', function (Blueprint $table) { $table->id(); $table->string('nom'); $table->string('veb_sayt')->nullable(); // ← yangi qator $table->string('shahar')->nullable(); $table->timestamps(); });

php artisan migrate dan keyin veb_sayt ustuni bazada paydo bo'ladimi?

Javobni ko'rish
veb_sayt ustuni: YO'Q kompaniyalar ustunlari: id, nom, shahar, created_at, updated_at

Yo'q. Va bu — yangi boshlaganlarning eng ko'p aldanadigan joyi: «kodni o'zgartirdim, migrate qildim, lekin hech narsa o'zgarmadi».

Sabab yuqorida ko'rgan migrations jadvalida: Laravel u yerda fayl nomini saqlaydi. Fayl nomi o'zgarmagani uchun u hali ham «bajarilgan» holatda. Laravel fayl ichini tekshirmaydi — demak tahrir e'tiborsiz qoladi. migrate esa faqat Pending larni bajaradi.

Ikki to'g'ri yechim:
1) make:migration add_veb_sayt_to_kompaniyalar_table — yangi migration. Serverda ishlayotgan loyiha uchun yagona to'g'ri yo'l: eski migration allaqachon bajarilgan va uni o'zgartirish tarixni buzadi.
2) php artisan migrate:fresh — hammasini noldan. Faqat o'z kompyuteringizda, chunki ma'lumot yo'qoladi.

Amaliy qoida: migration commit qilinmagan bo'lsa (hali faqat sizda) — tahrirlab fresh qilish mumkin. Commit qilingan va boshqalarga ketgan bo'lsa — faqat yangi migration.

SAVOL 1 Migration nima uchun kerak?

Tuzilma kod bo'lgani uchun git'da yashaydi va istalgan kompyuterda bir xil tiklanadi. SQL yo'qolmaydi — --pretend aynan o'sha SQL'ni ko'rsatadi.

SAVOL 2 Bajarilgan migration fayli tahrirlanib migrate qilinsa nima bo'ladi?

Laravel migrations jadvalidagi fayl nomiga qaraydi, fayl ichiga emas. To'g'ri yo'l — yangi migration (yoki o'z kompyuteringizda migrate:fresh).

SAVOL 3 migrate:fresh nima qiladi?

Shuning uchun ma'lumot yo'qoladi — real serverda ishlatilmaydi. «Faqat yangilarini» — oddiy migrate; «oxirgi to'plamni ortga» — migrate:rollback.

Eslab ayting

Avval o'zingiz javob bering, keyin ochib tekshiring. Oxirgi ikkitasi — 22-darsni takrorlash.

up() va down() nima qiladi?

up() — o'zgarishni qo'llaydi, down() — aynan shu o'zgarishni bekor qiladi. Yangi jadval uchun Laravel down() ni o'zi yozadi; mavjud jadvalni o'zgartirganda esa siz yozasiz.

Laravel qaysi migration bajarilganini qayerdan biladi?

Bazadagi migrations jadvalidan — u yerda fayl nomi va batch raqami turadi. Oddiy jadval, SELECT bilan o'qish mumkin.

Migration'ning SQL'ini bajarmasdan qanday ko'rish mumkin?

php artisan migrate --pretend — u bajarmaydi, faqat yuboradigan SQL'ni chiqaradi.

↩︎ Takrorlash: JOIN va LEFT JOIN farqi?

JOIN juftligi topilmagan qatorni tushiradi, LEFT JOIN esa uni qoldiradi va o'ng tomonni NULL qiladi.

↩︎ Takrorlash: UPDATE da WHERE unutilsa?

Butun jadval o'zgaradi va SQL bunga xato bermaydi.

Cho'ntak xulosasi
  • php artisan make:migration create_nom_table — jadval nomi fayl nomidan topiladi.
  • up() qo'llaydi, down() bekor qiladi. Jadvalni o'zgartirganda down() ni o'zingiz yozasiz.
  • Ustunlar: id() · string() · integer() · boolean() · timestamps(), ustiga ->nullable() · ->default() · ->unique().
  • 🔑 migrate --pretend — SQL'ni ko'rsatadi, bajarmaydi. Migration yangi til emas, SQL yozadigan usul.
  • migrate faqat Pending larni bajaradi · migrate:status ro'yxat · migrate:rollback oxirgi to'plam · migrate:fresh hammasini noldan (⚠️ ma'lumot yo'qoladi).
  • Tarix — bazadagi oddiy migrations jadvalida (fayl nomi + batch).
  • 🔑 Bajarilgan migration'ni tahrirlash ish bermaydi — Laravel fayl nomiga qaraydi. Yechim: yangi migration (yoki o'z kompyuteringizda fresh).
  • foreignId(...)->constrained(...) — tashqi kalitni baza o'zi tekshiradi: mavjud bo'lmagan id ga FOREIGN KEY constraint failed.
  • Tuzilmaning egasi endi migration — jadvalni DROP qiladigan eski qo'lda yozilgan skriptlar ishlatilmaydi.
