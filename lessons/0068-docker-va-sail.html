compose.yaml ni o'qish

services: laravel.test: build: context: ./vendor/laravel/sail/runtimes/8.3 ← Dockerfile qayerda image: sail-8.3/app ports: - '${APP_PORT:-80}:80' ← host:konteyner environment: WWWUSER: '${WWWUSER}' volumes: - '.:/var/www/html' ← KODNI ULASH networks: [sail] depends_on: [mysql, redis, mailpit] mysql: image: 'mysql:8.4' ports: - '${FORWARD_DB_PORT:-3306}:3306' volumes: - 'sail-mysql:/var/lib/mysql' ← MA'LUMOT saqlanadi healthcheck: test: [CMD, mysqladmin, ping, '-p${DB_PASSWORD}']
🔑 Uchta muhim tushuncha
1) VOLUME: '.:/var/www/html' Kod konteynerga ULANADI (nusxalanmaydi). Faylni tahrirlaysiz → konteynerda DARROV o'zgaradi. 2) PORTS: '8080:80' host:konteyner. Konteyner ichida 80, tashqarida 8080. 3) NETWORKS: sail Bir tarmoqdagi konteynerlar bir-birini NOM bilan topadi.

🔍 ${APP_PORT:-80} — «.env da APP_PORT bo'lsa uni ol, bo'lmasa 80». Shuning uchun portlarni .env dan boshqarasiz.

⭐ Konteynerlar bir-birini qanday topadi

MySQL konteyneridan turib tekshirdik:

getent hosts redis → 172.19.0.2 redis getent hosts mailpit → 172.19.0.3 mailpit

Ya'ni DB_HOST=mysql yozganingizda — bu haqiqiy manzil. Docker o'z DNS serverini yuritadi va xizmat nomlarini IP'ga aylantiradi.

🔑 Va bu o'zgarmaydi: konteyner qayta ishga tushsa IP boshqacha bo'lishi mumkin, lekin nom o'sha.

🔍 Izolyatsiya — o'lchangan

Mening kompyuterimda Redis allaqachon ishlab turardi (59-darsdan). Konteynerda ham Redis bor. Ular bir xilmi?

redis-cli -p 6379 set zond hostdan ← host Redis redis-cli -p 16379 set zond konteynerdan ← konteyner Redis redis-cli -p 6379 get zond → hostdan ✅ redis-cli -p 16379 get zond → konteynerdan ✅

Bir xil kalit, ikki xil qiymat. Ular butunlay alohida — bu izolyatsiyaning butun ma'nosi.

⚠️ Birinchi xato: port band

Xizmatlarni ko'targanimizda:

Error response from daemon: failed to set up container networking: driver failed programming external connectivity on endpoint ishtop-redis-1: failed to bind host port 0.0.0.0:6379/tcp: address already in use

Sabab — hostda Redis ishlab turibdi:

ss -tlnp | grep 6379 LISTEN 0 511 127.0.0.1:6379 0.0.0.0:*
✅ Yechim: FORWARD_* o'zgaruvchilari
# .env FORWARD_DB_PORT=13306 FORWARD_REDIS_PORT=16379 FORWARD_MAILPIT_PORT=11025 FORWARD_MAILPIT_DASHBOARD_PORT=18025 APP_PORT=8080

Natija:

mysql 0.0.0.0:13306->3306/tcp redis 0.0.0.0:16379->6379/tcp mailpit 0.0.0.0:11025->1025/tcp, 0.0.0.0:18025->8025/tcp

🔑 Konteyner ichidagi port o'zgarmaydi (3306, 6379) — faqat hostdan ko'rinadigan port ko'chadi. Shuning uchun .env dagi DB_PORT hamon 3306.

🔍 Tekshirdik: mailpit paneli http://127.0.0.1:18025 → 200.

⚠️ Nega docker compose emas, sail?

docker compose ni to'g'ridan-to'g'ri ishlatganimizda:

warning: The "WWWUSER" variable is not set. Defaulting to a blank string. warning: The "WWWGROUP" variable is not set. Defaulting to a blank string.

Bu ikki o'zgaruvchini sail skripti o'zi qo'yadi:

export WWWUSER=${WWWUSER:-$UID} export WWWGROUP=${WWWGROUP:-$(id -g)} export APP_SERVICE=${APP_SERVICE:-"laravel.test"}

HOLAT 4

Tezlik: macOS va Windows

Linux → volume tez (yadro bir xil) macOS → fayl tizimi SEKIN (VM orqali) Windows → WSL2 ichida saqlansa tez, C:\ da sekin

⚠️ macOS'da composer install yoki npm install konteynerda bir necha barobar sekin bo'lishi mumkin.

✅ Yechimlar: :cached/:delegated volume bayroqlari, yoki vendor va node_modules ni nomlangan volume ga chiqarish.

🔑 Windows'da: loyihani WSL2 ichida saqlang (/home/...), Windows diskida emas.

Sinab ko'ramiz

Natijani taxmin qiling

Jamoa Sail'ga o'tdi. Hammasi ishladi: sail up, migratsiyalar, testlar — yashil.

Bir hafta o'tib yangi dasturchi qo'shildi. U ham hammasini bajardi:

git clone ... composer install cp .env.example .env php artisan key:generate sail up -d sail artisan migrate

Va xato oldi:

SQLSTATE[HY000] [2002] Connection refused (Connection: mysql, Host: 127.0.0.1, Port: 3306, Database: laravel)

Lekin sail ps — MySQL ishlab turibdi va healthy. Nima bo'lgan?

Javobni ko'rish

Xato matnida javob bor: Host: 127.0.0.1.

U .env.example dan nusxa oldi — va u yerda hamon eski qiymat turibdi:

.env.example: DB_HOST=127.0.0.1 ← ESKI .env (sizda): DB_HOST=mysql ← Sail o'zgartirgan

🔑 sail:install faqat .env ni o'zgartiradi. .env.example git'da yotgan eski holicha qoladi (66-darsdan: .env git'da yo'q).

Va nega 127.0.0.1 ishlamaydi? Chunki konteyner ichida 127.0.0.1 — bu o'sha konteynerning o'zi, host emas. MySQL esa boshqa konteynerda.

konteyner ichidan: 127.0.0.1 → laravel.test konteyneri (u yerda MySQL yo'q) ❌ mysql → mysql konteyneri ✅ host.docker.internal → HOST mashinasi (Sail buni qo'shgan)

✅ Ikki qismli tuzatish:

1) Yangi dasturchi uchun DARHOL: .env da DB_HOST=mysql, REDIS_HOST=redis, MAIL_HOST=mailpit 2) QAYTMASLIGI uchun — .env.example ni ham yangilang va COMMIT qiling

🔑 Umumiy saboq: .env.example — bu hujjat. U eskirsa, har yangi dasturchi bir soat yo'qotadi.

🔍 Va tekshirish oson: yangi papkaga git clone qilib, .env.example dan boshlab o'zingiz o'tib ko'ring. Bu onboarding testi.
