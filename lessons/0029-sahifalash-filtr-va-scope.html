paginate() — sahifalash

controller
$vakansiyalar = Vakansiya::orderByDesc('maosh')->paginate(5);

get() o'rniga paginate(5) — tamom. U LengthAwarePaginator qaytaradi: bu @foreach da massiv kabi ishlaydi, lekin ustiga sahifa haqidagi ma'lumot ham olib yuradi:

MetodNima beradi
total()Jami qatorlar soni (hamma sahifalarda)
count()Shu sahifadagi qatorlar soni
currentPage() · lastPage()Joriy va oxirgi sahifa raqami
firstItem() · lastItem()«20 tadan 6–10» yozuvi uchun
onFirstPage() · hasMorePages()Havolani o'chirib qo'yish uchun
previousPageUrl() · nextPageUrl()Tayyor manzillar (?page=2)
hasPages()Umuman sahifalash kerakmi (natija bitta sahifaga sig'sa — yo'q)

Sahifa raqami qayerdan olinadi? Manzildagi ?page= dan — o'zi. Siz hech narsa yozmaysiz.

🔍 Sehr yo'q: paginate ikki so'rov yuboradi

O'lchandi:

── paginate(5) → 2 so'rov select count(*) as "aggregate" from "vakansiyalar" select * from "vakansiyalar" limit 5 offset 0 ── simplePaginate(5) → 1 so'rov select * from "vakansiyalar" limit 6 offset 0

paginate ga «4 sahifadan 2-si» deb yozish uchun jami son kerak — shuning uchun COUNT so'rovi. simplePaginate esa faqat «keyingi sahifa bormi?» degan savolga javob beradi va buni ayyorona hal qiladi: limit 5 o'rniga limit 6 so'raydi — oltinchi qator kelsa, demak davomi bor.

Millionlab qatorli jadvalda COUNT qimmat bo'ladi, shuning uchun simplePaginate tezroq. Evaziga total() va lastPage() yo'q bo'ladi.

Filtr va qidiruv: when()

Foydalanuvchi ba'zan qidiradi, ba'zan shahar tanlaydi. Ya'ni shart bo'lishi ham, bo'lmasligi ham mumkin. Buni if bilan yozsa kod tez chalkashadi:

❌ $so_rov = Vakansiya::query(); if ($request->input('q')) { $so_rov->whereLike('nom', '%' . $request->input('q') . '%'); } if ($request->input('shahar')) { $so_rov->where('shahar', $request->input('shahar')); } ...

Laravel'ning when() metodi shuni zanjirda yozishga imkon beradi:

app/Http/Controllers/VakansiyaController.php
$vakansiyalar = Vakansiya::query() ->with('kompaniya') ->withCount('konikmalar') ->when($request->input('q'), fn ($so_rov, $matn) => $so_rov->whereLike('nom', "%{$matn}%")) ->when($request->input('shahar'), fn ($so_rov, $shahar) => $so_rov->where('shahar', $shahar)) ->when($request->boolean('faqat_faol'), fn ($so_rov) => $so_rov->faol()) ->orderByDesc('maosh') ->paginate(5) ->withQueryString();

when($shart, $closure): shart rost bo'lsa closure ishlaydi, aks holda hech narsa qo'shilmaydi. Va closure'ning ikkinchi argumenti — o'sha shartning qiymati, ya'ni uni qaytadan yozish shart emas.

shahar = null → select * from "vakansiyalar" shahar = 'Toshkent' → select * from "vakansiyalar" where "shahar" = ?

SQL'ning o'zi o'zgaradi — kerak bo'lmagan shart umuman qo'shilmaydi.

ShartMa'nosi
whereLike('nom', '%php%')Qidiruv. Standart holda katta-kichik harfga sezgir emas
whereLike('nom', '%PHP%', true)Uchinchi argument — sezgir qilish
where('nom', 'like', '%php%')Eski shakl — hamma versiyada ishlaydi
whereBetween('maosh', [1000, 2000])Oraliq
whereIn('shahar', ['Toshkent', 'Buxoro'])Ro'yxatdagilardan biri
distinct()->pluck('shahar')Takrorlanmas qiymatlar — filtr ro'yxatini yasash uchun
⚠️ withQueryString() — eng ko'p uchraydigan bug'

Foydalanuvchi «Toshkent» ni tanladi, 4 ta natija ko'rdi, «Keyingi» ni bosdi — va filtr yo'qoldi, yana hamma vakansiya chiqdi. Sabab:

withQueryString() SIZ → http://localhost:8000?page=2 withQueryString() BOR → http://localhost:8000?shahar=Toshkent&q=dasturchi&page=2

Paginator manzilni o'zi yasaydi va standart holda faqat page ni qo'yadi. withQueryString() unga «manzildagi qolgan parametrlarni ham olib qol» deydi.

Muqobili — appends(['shahar' => $shahar]): aniq qaysi parametrlarni saqlashni o'zingiz aytasiz. withQueryString() aksariyat holatda qulayroq.

Scope — shartga nom berish

where('faol', true) ni o'nta joyda yozgan bo'lsangiz va ertaga «faol» ning ta'rifi o'zgarsa (masalan «muddati o'tmagan» ham qo'shilsa) — o'nta joyni tuzatish kerak. Scope shu shartga nom beradi va uni modelga ko'chiradi:

app/Models/Vakansiya.php
use Illuminate\Database\Eloquent\Attributes\Scope; use Illuminate\Database\Eloquent\Builder; class Vakansiya extends Model { #[Scope] protected function faol(Builder $so_rov): void { $so_rov->where('faol', true); } #[Scope] protected function qimmat(Builder $so_rov, int $eng_kam = 2000): void { $so_rov->where('maosh', '>=', $eng_kam); } }
Vakansiya::faol()->count() → 16 Vakansiya::faol()->qimmat()->count() → 8 Vakansiya::faol()->qimmat(1500)->toSql() → select * from "vakansiyalar" where "faol" = ? and "maosh" >= ?

Uch foydasi: nom («faol» — kod o'qishga oson bo'ladi), bir joyda (ta'rif o'zgarsa bitta joyni tuzatasiz) va zanjirlanadi (boshqa shartlar bilan birga ishlaydi).

#[Scope] — atribut, PHP 8 ning imkoniyati: metodga «yorliq» osadi va Laravel uni shu yorliqdan taniydi. Metodning o'zi protected, lekin tashqarida Vakansiya::faol() deb chaqiriladi.

⚡ N+1 bilan rasmiy tanishuv

26-darsda muammoni o'lchagandik: sikl ichida bog'lanishga murojaat → 1 + N so'rov. Lekin u jimgina muammo: sahifa ishlaydi, faqat sekin. Kichik bazada esa sekinlik ham sezilmaydi — muammo real serverda, ma'lumot ko'payganda «portlaydi».

Laravel'da uni xatoga aylantiradigan bitta qator bor:

app/Providers/AppServiceProvider.php
use Illuminate\Database\Eloquent\Model; public function boot(): void { Model::preventLazyLoading(! app()->isProduction()); }

Endi with() ni unutsangiz sahifa ochilmaydi:

Illuminate\Database\LazyLoadingViolationException Attempted to lazy load [kompaniya] on model [App\Models\Vakansiya] but lazy loading is disabled. resources/views/vakansiyalar/index.blade.php:33

Xato qaysi bog'lanish va qaysi qator ekanini aytadi. Ya'ni muammoni yozayotgan paytingizda topasiz.

Nega ! app()->isProduction()

Real serverda bu o'chirilgan bo'lishi kerak: u yerda unutilgan with() sahifani butunlay buzadi, holbuki u shunchaki sekinroq ishlagan bo'lardi. Foydalanuvchi uchun «sekin» — «buzuq» dan yaxshiroq.

Ya'ni bu ishlab chiqish asbobi: qattiq qoida faqat sizning kompyuteringizda. Bu naqsh Laravel jamoasida keng tarqalgan.

⚠️ Bir nozik jihat o'lchandi: cheklov to'plamdagi modellarga qo'llanadi — ya'ni aynan N+1 holatiga. Yakka model (Vakansiya::first()->kompaniya) uchun u ogohlantirmaydi.

Har xil holatlar

Yetti holat. Bu bo'lim ma'lumotnoma — hozir bir marta o'qib chiqing, keyin kerak bo'lganda qaytib qarang.

HOLAT 1

Mavjud bo'lmagan sahifa so'ralsa

?page=999 — bunday sahifa yo'q. Laravel xato bermaydi:

?page=999 → bo'sh ro'yxat, 200 status → «Hech narsa topilmadi» → navigatsiyada: 999 / 4 ← g'alati ko'rinadi

Bu odatda yaxshi: qo'lda yozilgan yoki eskirgan havola sahifani buzmaydi. @forelse ning @empty qismi (18-dars) shu holatni chiroyli ko'rsatadi.

Lekin navigatsiyada 999 / 4 chiqadi — chunki currentPage() manzildan olingan raqamni qaytaradi. Ikki yechim:

// 1) 404 berish if ($vakansiyalar->currentPage() > $vakansiyalar->lastPage()) { abort(404); } // 2) oxirgi sahifaga yo'naltirish if ($vakansiyalar->currentPage() > $vakansiyalar->lastPage()) { return redirect()->route('vakansiyalar.index', ['page' => $vakansiyalar->lastPage()]); }

Kichik loyihada hech narsa qilmaslik ham mumkin — sahifa buzilmaydi.

HOLAT 2

Natija bitta sahifaga sig'sa

4 ta natija, sahifada 5 ta ko'rsatilyapti — «Oldingi/Keyingi» kerak emas. hasPages() aynan shuni tekshiradi:

?shahar=Toshkent → 4 tadan 1–4 (Oldingi/Keyingi ko'rsatilmaydi) ⚠️ Sizdagi son boshqacha bo'ladi — ma'lumot tasodifiy yasalgan (28-dars). Muhimi: natija bitta sahifaga sig'sa, navigatsiya ko'rinmaydi.

Lekin «4 tadan 1–4» yozuvi hasPages() dan tashqarida turishi kerak — foydalanuvchi natijalar sonini har doim ko'rishi kerak. Shuning uchun bizning qismimizda ikkita alohida @if bor.

HOLAT 3

Filtr + sahifa: withQueryString() unutilsa

?shahar=Toshkent → 4 ta natija ✅ «Keyingi» bosildi → ?page=2 ← shahar YO'QOLDI → yana hamma vakansiya

Foydalanuvchi buni «sayt buzuq» deb qabul qiladi. Va kod jihatidan hech qanday xato yo'q — shuning uchun uni sinovda topish qiyin.

✅ ->withQueryString() — paginate'dan keyin:

->paginate(5) ->withQueryString(); «Oldingi» havolasi: ?q=dasturchi&faqat_faol=1&page=1 ✅
HOLAT 4

links() ni ishlatmoqchi bo'lsangiz

Loyihada Tailwind yoki Bootstrap bo'lsa, tayyor havolalar chiroyli chiqadi:

{{ $vakansiyalar->links() }} ← Tailwind (standart) {{ $vakansiyalar->links('pagination::bootstrap-5') }} ← Bootstrap 5

Yoki AppServiceProvider'da bir marta: Paginator::useBootstrapFive();

Ko'rinishlarni o'zingizniki qilish ham mumkin — ular oddiy Blade fayllari (yana «sehr yo'q»):

php artisan vendor:publish --tag=laravel-pagination → resources/views/vendor/pagination/ (9 ta blade fayl)

Biz esa o'z qismimizni yozdik — chunki kursda CSS framework yo'q va paginator API'sini bilib olish foydaliroq.

HOLAT 5

Scope'ning ikki shakli

Internetdagi ko'p misollarda eski shakl uchraydi — u hali ham ishlaydi:

// ESKI (barcha versiyalarda): metod nomi "scope" bilan boshlanadi public function scopeFaol(Builder $so_rov): void { $so_rov->where('faol', true); } // YANGI (Laravel 12+): atribut #[Scope] protected function faol(Builder $so_rov): void { $so_rov->where('faol', true); }

Ikkalasi ham Vakansiya::faol() deb chaqiriladi va natijasi bir xil (o'lchandi: 16 va 16).

Yangi shakl afzal: metod nomi toza (faol, emas scopeFaol) va niyat atribut bilan ochiq ko'rsatilgan. Lekin eski kodni o'qiy olish uchun ikkalasini bilish kerak.

HOLAT 6

when() va 0 tuzog'i

when() shartni truthy deb tekshiradi (3-dars!). Demak 0, '0', bo'sh satr — yolg'on hisoblanadi:

?eng_kam_maosh=0 → when(0, ...) → shart QO'SHILMAYDI // Foydalanuvchi «0» dan katta maosh so'radi, lekin filtr ishlamadi

Odatda bu to'g'ri xatti-harakat (bo'sh maydon = filtr yo'q). Lekin 0 ma'noli qiymat bo'lgan joyda aniq tekshirish kerak:

->when($request->filled('eng_kam_maosh'), fn ($q) => $q->where('maosh', '>=', $request->integer('eng_kam_maosh')))

filled() — «maydon bor va bo'sh emas» (0 ham hisoblanadi). Bu 20-darsdagi required va truthy farqining davomi.

HOLAT 7

preventLazyLoading ni qayerga qo'yish

✅ app/Providers/AppServiceProvider.php → boot() Model::preventLazyLoading(! app()->isProduction()); ❌ Controllerda yoki modelda — u global sozlama, bir joyda bo'lishi kerak

Qo'shimcha imkoniyat: xato o'rniga logga yozish:

Model::handleLazyLoadingViolationUsing(function ($model, $relation) { logger()->warning("N+1: {$relation} on " . get_class($model)); });

Bu real serverda foydali: sahifa buzilmaydi, lekin muammolar logga tushadi va keyin ularni tuzatasiz. Modul H da bunga qaytamiz.

Sinab ko'ramiz

Natijani taxmin qiling

Controller shunday yozilgan — withQueryString() siz:

controller
$vakansiyalar = Vakansiya::query() ->when($request->input('shahar'), fn ($s, $sh) => $s->where('shahar', $sh)) ->paginate(5); // ← withQueryString() YO'Q

Foydalanuvchi «Toshkent» ni tanladi — 12 ta natija chiqdi, ya'ni 3 sahifa. Keyin «Keyingi» ni bosdi. Nima ko'radi?

Javobni ko'rish
Manzil: ?page=2 ← shahar YO'Q Natija: BARCHA vakansiyalarning 2-sahifasi (Toshkent emas) Xato: yo'q

Filtr jimgina yo'qoladi. Paginator manzilni o'zi yasaydi va standart holda faqat page parametrini qo'yadi — manzildagi qolgan parametrlarni bilmaydi.

Foydalanuvchi tomonidan bu shunday ko'rinadi: «filtrladim, keyingi sahifaga o'tdim va hammasi buzildi». Va bu eng ko'p uchraydigan sahifalash bug'i — chunki dasturchi odatda birinchi sahifada sinab, ishlayapti deb o'ylaydi.

✅ Yechim bitta metod:

->paginate(5) ->withQueryString(); → ?shahar=Toshkent&page=2 ✅

Tekshirish odati: filtrlagandan keyin «Keyingi» ni bosib, manzil qatoriga qarang. Filtr parametri bormi? Yo'q bo'lsa — withQueryString() unutilgan.

Muqobil: appends(['shahar' => $shahar]) — aniq parametrlarni sanab berish. Lekin filtrlar ko'payganda withQueryString() qulayroq.

SAVOL 1 paginate() va simplePaginate() farqi nimada?

O'lchandi: paginate — 2 so'rov (COUNT qo'shiladi), simplePaginate — 1 so'rov (limit 6 bilan «davomi bormi» ni biladi). Evaziga total() va lastPage() bo'lmaydi.

SAVOL 2 withQueryString() nima uchun kerak?

Usiz «Keyingi» havolasi faqat ?page=2 bo'ladi va filtr jimgina yo'qoladi. Tekshirish odati: filtrlagandan keyin manzil qatoriga qarang.

SAVOL 3 Model::preventLazyLoading() nima qiladi?

U bog'lanishni o'zi yuklamaydi — aksincha, with() unutilgan joyda LazyLoadingViolationException otadi va qaysi qatorda ekanini aytadi. Real serverda o'chirilgan bo'ladi (! app()->isProduction()).

Eslab ayting

Avval o'zingiz javob bering, keyin ochib tekshiring. Oxirgi ikkitasi — 28-darsni takrorlash.

Sahifa raqami qayerdan olinadi?

Manzildagi ?page= dan — paginator uni o'zi o'qiydi. Siz hech narsa yozmaysiz.

when() nima qiladi?

Shart rost bo'lsagina closure'ni ishlatadi — aks holda WHERE umuman qo'shilmaydi. Closure'ning ikkinchi argumenti — shartning qiymati.

Scope nima uchun kerak?

Takrorlanadigan shartga nom berish va uni bir joyda saqlash. Ta'rif o'zgarsa bitta joyni tuzatasiz. Zanjirlanadi: Vakansiya::faol()->qimmat().

↩︎ Takrorlash: fake('uz_UZ') nima qiladi?

Jimgina inglizcha ma'lumot qaytaradi — Faker'da o'zbek tili yo'q. Yechim: randomElement bilan o'z ro'yxatingiz.

↩︎ Takrorlash: factory'da bog'lanish nomi nima uchun yoziladi?

Laravel taxmini o'zbekcha nomda ishlamaydi (vakansiyas, konikmas). Shuning uchun has(..., 'vakansiyalar') deb aniq beriladi.

Cho'ntak xulosasi
  • get() o'rniga paginate(5) — sahifa raqami ?page= dan o'zi olinadi.
  • Paginator metodlari: total · currentPage · lastPage · firstItem/lastItem · hasPages · onFirstPage · previousPageUrl/nextPageUrl.
  • 🔍 paginate — 2 so'rov (COUNT bor); simplePaginate — 1 so'rov (limit 6 hiylasi), lekin total() yo'q.
  • ⚠️ withQueryString() — bo'lmasa sahifa almashganda filtr yo'qoladi. Eng ko'p uchraydigan sahifalash bug'i.
  • when($shart, $closure) — shart rost bo'lsagina qo'shiladi; ikkinchi argument — qiymat. ⚠️ 0 falsy, kerak bo'lsa filled().
  • whereLike (standart holda sezgir emas) · whereBetween · whereIn · distinct()->pluck().
  • Scope — shartga nom: #[Scope] (yangi) yoki scopeFaol() (eski). Zanjirlanadi, parametr qabul qiladi.
  • ⚡ Model::preventLazyLoading(! app()->isProduction()) — N+1 ni 500 xatosiga aylantiradi va qatorini ko'rsatadi. Real serverda o'chiq.
  • Blade: @selected(...) · @checked(...) · request('q') bilan formani to'ldirish.
  • Filtr formasi — method="GET": ma'lumot o'zgarmaydi, natijani havola qilib yuborish mumkin, @csrf kerak emas.
