Modul A–B — PHP, veb va Laravel

Darslarda uchragan atamalar: DARS 01 (so'rov–javob aylanasi) · DARS 02 (o'zgaruvchi va tiplar) · DARS 03 (solishtirish va shart) · DARS 04 (xato turlari) · DARS 05 (massiv) · DARS 06 (funksiya va tiplar) · DARS 07 (klass va obyekt) · DARS 08 (himoya, static, const) · DARS 09 (meros va abstract) · DARS 10 (interface va trait) · DARS 11 (exception) · DARS 12 (namespace va Composer) · DARS 13 (HTTP, XSS, session) · DARS 14 (router) · DARS 15 (container va DI) · DARS 16 (Laravel o'rnatish) · DARS 17 (lifecycle va middleware) · DARS 18 (Blade va layout) · DARS 19 (komponent, forma, CSRF).

request (HTTP request) — so'rov
Brauzerning serverga yuborgan «menga shu manzilni ber» degan xati. Backend ishi shu xatdan boshlanadi. GET /02-sahifa.php
response (HTTP response) — javob
Serverning qaytargan xati: status kodi, sarlavhalar va tana (matn). PHP'ning butun vazifasi — shu tanani hosil qilish. 200 OK + <h1>Salom</h1>
interpreter — interpretator, bajaruvchi
Kodni oldindan mashina tiliga aylantirmasdan, o'qib turib bajaradigan dastur. PHP shunday ishlaydi: fayl har so'rovda qaytadan o'qiladi. php 01-salom.php → PHP faylni o'qib bajaradi
PHP tag — PHP teglari
<?php va ?> — kod hududining chegarasi. Ichi bajariladi, tashqarisi o'zgarmasdan javobga o'tadi. Faqat PHP'dan iborat faylda yopuvchi teg yozilmaydi. <?php echo "salom";
echo — javobga matn qo'shish
Ekranga chizmaydi — javobga yozadi. Terminalda bajarsangiz javob terminalga tushadi, brauzer so'rasa brauzerga. echo "Salom"; → javobda: Salom
web server — veb-server
So'rovni qabul qilib, kerakli faylni topadigan va .php bo'lsa PHP'ga uzatadigan dastur. O'rganish uchun PHP'ning ichkisi yetadi. php -S localhost:8000
CLI (command line interface) — buyruq qatori
PHP'ning terminal orqali ishlash rejimi — brauzer va server ishtirokisiz. php -v chiqishida shu so'z turadi. PHP 8.3.32 (cli)
variable — o'zgaruvchi
Qiymat saqlanadigan joyga qo'yilgan nom. PHP'da har doim $ bilan boshlanadi. = «teng» emas, «o'ngdagisini chapga sol» degani. $ism = "Doston";
dynamic typing — dinamik tiplash
Tip o'zgaruvchida emas, qiymatda yashaydi. Shu sababli bitta o'zgaruvchi hayoti davomida tipini o'zgartira oladi va kodga qarab tipni bilib bo'lmaydi — shuning uchun var_dump kerak. $x = 5; keyin $x = "besh";
type — tip, ma'lumot turi
Qiymatning turi. Asosiylari: string, int, float, bool, null va array. Xatolarning katta qismi «tipini boshqa deb o'ylash»dan chiqadi. "25" — string, 25 — int
null — «qiymat yo'q»
Alohida tip: nol ham, bo'sh matn ham emas — hech narsa yo'q. Bazadagi to'ldirilmagan maydon shunday keladi. echo uni ko'rsatmaydi, var_dump esa NULL deb aytadi. $kasb = null; → NULL
var_dump() — qiymat va tipni ko'rsatuvchi asbob
Qiymatni va tipini birga chiqaradi; matn uzunligini ham beradi. Tekshirishda echo o'rniga shu ishlatiladi, chunki echo true ni 1, null ni bo'shliq qilib chalg'itadi. Laravel'dagi ekvivalenti — dd(). var_dump($a, $b); → string(6) "Doston"
string interpolation — matn ichiga qiymat qo'yish
Qo'shtirnoq ichidagi o'zgaruvchi qiymatiga almashadi; bittalik tirnoq ichidagisi almashmaydi. Qavs chegarani aniqlaydi. "Salom, {$ism}!" → Salom, Doston!
concatenation — matnlarni ulash
PHP'da ulash belgisi — nuqta (.), + emas. Operator tipni o'zgartiradi: "5" + 5 → int(10), ammo "5" . 5 → string "55". "Salom, " . $ism
== va === — bo'sh va qat'iy solishtirish
== faqat qiymatni tekshiradi va kerak bo'lsa tipni o'zgartiradi; === qiymat va tipni tekshiradi. Qoida: doim ===. "25" == 25 → true · "25" === 25 → false
truthy / falsy — rost va yolg'on hisoblanadigan qiymatlar
if ichida yolg'on hisoblanadigan qiymatlar: false, 0, 0.0, "", "0", null, []. Qolgan hammasi rost — "false" va " " ham. (bool)"0" → false · (bool)"false" → true
match — qiymat qaytaradigan tanlov
if dan farqi: natijani qaytaradi (o'zgaruvchiga solinadi) va har doim === bilan solishtiradi. Mos variant topilmasa va default yozilmagan bo'lsa — UnhandledMatchError. Enum bilan ishlaganda bu foyda: yangi case qo'shsangiz match darhol xato berib, sizni to'ldirish kerak bo'lgan joyga olib boradi. $m = match($holat) { "yangi" => "...", default => "..." };
Parse error — sintaksis xatosi
PHP faylni o'qiy olmadi, shuning uchun ishga tushirmaydi ham — hatto to'g'ri yozilgan birinchi qator ham bajarilmaydi. Ko'rsatilgan qator PHP muammoni sezgan joy; topmasangiz bir qator yuqoriga qarang. unexpected token "echo", expecting ";"
Warning — ogohlantirish
Kod ishlaydi va davom etadi, lekin biror narsa g'alati. Xavfli tomoni: sayt «ishlab» turib noto'g'ri natija berishi mumkin. E'tiborsiz qoldirmang. Undefined variable $yosh
Fatal error — halokatli xato
Kod bajarilib borgan, lekin davom etish imkonsiz bo'lgan joyda to'xtagan. Ya'ni bir qismi bajarilgan, qolgani yo'q. Ostida ko'pincha stack trace chiqadi. Uncaught DivisionByZeroError: Division by zero
stack trace — chaqiruvlar zanjiri
«Bu yergacha qanday yo'l bilan kelindi» ro'yxati. #0 {main} = xato asosiy kodda. Funksiyalar ishtirok etsa ro'yxat uzayadi va xatoga olib kelgan zanjirni ko'rsatadi. #0 fayl.php(3): funksiyaNomi()
array — massiv
Bitta nomda ko'p qiymat. PHP'da massiv har doim «kalit → qiymat» xaritasi — «indeksli» massiv shunchaki kalitlari 0, 1, 2 bo'lgan massiv. Shu sababli kalitlar uzluksiz bo'lmasligi mumkin. ["PHP", "SQL"] · ["nom" => "Backend"]
foreach — massivni aylanib chiqish
Massiv uchun eng to'g'ri sikl: mavjud kalitlarni oladi, shuning uchun assotsiativ massivda ham, kalitlari uzluksiz bo'lmagan massivda ham ishlaydi (for ishlamaydi). foreach ($a as $k => $q) { ... }
function — funksiya
Nom berilgan, qayta ishlatiladigan mantiq bo'lagi. Tashqaridan ma'lumot parametr orqali kiradi, natija return orqali chiqadi. Klass ichida yashaganda metod deb ataladi. function salom(string $ism): string { ... }
return — qiymat qaytarish
Qiymatni chaqirgan joyga qaytaradi va funksiyani darhol tugatadi. echo dan farqi: hech narsa chiqarmaydi. Qoida — funksiya hisoblab qaytarsin, chiqarishni chaqiruvchi hal qilsin. return "{$maosh} $";
type hint — tip ko'rsatmasi
Parametr yoki qaytish qiymatining kutilgan tipi. ⚠️ O'zi kafolat bermaydi — standart holatda PHP tipni o'zgartirib yuboradi. Kafolat uchun strict_types kerak. function f(int $son): string
declare(strict_types=1) — qat'iy tip rejimi
Type hint ni haqiqiy qoidaga aylantiradi: noto'g'ri tip berilsa TypeError chiqadi. Fayl boshida, <?php dan keyingi birinchi ko'rsatma bo'lishi shart va har faylda alohida yoziladi. <?php declare(strict_types=1);
scope — o'zgaruvchi doirasi
Funksiya ichida yaratilgan o'zgaruvchi tashqarida mavjud emas (va aksincha). Bu foydali: nom to'qnashuvi bo'lmaydi. Kirish — parametr, chiqish — return. funksiya ichidagi $ichki tashqarida Warning beradi
class — klass, chizma
Ma'lumot va u bilan ishlaydigan metodlarni birga tutadigan chizma. Bir marta yoziladi. Klass o'zi tipga aylanadi: function f(Vakansiya $v) yozish mumkin. class Vakansiya { ... }
object — obyekt
Klassga ko'ra new bilan yasalgan aniq narsa. Har new — yangi, mustaqil obyekt. ⚠️ = bilan nusxalanmaydi (massivdan farqli) — ikki nom, bitta obyekt bo'ladi; nusxa uchun clone. $v = new Vakansiya("Backend", 800);
property — xossa
Obyekt ichidagi ma'lumot. Tipli xossaga qiymat berilmasa va o'qilsa — Fatal error: Typed property ... must not be accessed before initialization. private string $nom;
method — metod
Klass ichidagi funksiya. Qoidalari oddiy funksiyadek, farqi — u $this orqali obyektning ma'lumotiga yeta oladi. public function korinish(): string { ... }
$this — «aynan shu obyekt»
Metod hozir qaysi obyekt ustida ishlayotganini bildiradi. Xossaga murojaat uchun shart — usiz $nom metodning lokal o'zgaruvchisi bo'lib qoladi. static metod ichida mavjud emas. $this->nom = $nom;
__construct — konstruktor
Obyekt new bilan yasalgan zahoti avtomatik ishlaydigan maxsus metod. Odatda xossalarga boshlang'ich qiymat beradi. Ikki tagchiziq — «PHP uchun maxsus ma'noga ega» belgisi. public function __construct(string $nom) { ... }
clone — obyektning haqiqiy nusxasi
Obyektni chindan nusxalaydi — natijada ikki mustaqil obyekt bo'ladi. = esa nusxalamaydi. $b = clone $a;
visibility — ko'rinish darajasi
public = hamma · private = faqat shu klass ichi · protected = klass va merosxo'rlari. Qoida: private dan boshlang. Buzilsa — Fatal error: Cannot access private property. private int $maosh;
encapsulation — enkapsulyatsiya, ma'lumotni qo'riqlash
Obyekt o'z ma'lumotini o'zi himoya qilishi: tashqaridan faqat ruxsat berilgan yo'l bilan o'zgartiriladi va metod shart qo'ya oladi (masalan manfiy maoshni rad etadi). Shart bitta joyda yashaydi. if ($yangi < 0) { return; }
constructor property promotion — qisqa konstruktor
PHP 8: konstruktor parametri oldiga private/public yozilsa, PHP xossani o'zi yaratadi va qiymat beradi. Laravel kodi shu shaklda yozilgan — shuning uchun tanish bo'lishi muhim. __construct(private string $nom) {}
class constant — klass konstantasi
const bilan e'lon qilinadigan o'zgarmas qiymat. Klassga tegishli, shuning uchun obyekt yasamasdan Klass::NOM deb olinadi. Foydasi: adashib yozsangiz PHP darhol xato beradi, matn esa jimgina ishlamaydi. Vakansiya::HOLAT_FAOL
static — klassga tegishli (obyektga emas)
Oddiy xossa har obyektda alohida, static esa klass uchun bitta — barcha obyektlar bo'lishadi. Murojaat: self::$nom yoki Klass::$nom. ⚠️ Global holat yaratadi va testlashni qiyinlashtiradi — kamdan-kam ishlatiladi. private static int $soni = 0;
-> va :: — obyekt va klass operatorlari
-> = «shu obyektning» ($v->nom). :: = «shu klassning» (Vakansiya::HOLAT_FAOL, self::$soni) — obyekt yasashning hojati yo'q. $v->korinish() · Vakansiya::soni()
inheritance / extends — meros
class B extends A — B, A ning hamma narsasini oladi. Umumiy kod ota klassda, farq qiladigan qism avlodlarda. PHP'da klass faqat bitta otadan meros oladi. class EmailXabar extends Xabar
parent:: — ota klassning versiyasi
Otaning metodini chaqirish. ⚠️ Avlod o'z konstruktorini yozsa, parent::__construct() ni chaqirish shart — aks holda otaning xossalari qiymatsiz qoladi. parent::__construct($qabulQiluvchi);
abstract — chala, faqat asos
abstract class — undan obyekt yasab bo'lmaydi, faqat asos. abstract function f(); — tanasi yo'q, avlod yozishi shart; aks holda xato e'lon qilishda chiqadi. abstract public function yubor(): string;
polymorphism — polimorfizm
Bir xil murojaat, har xil xatti-harakat. Bitta siklda har xil obyektlar ishlatiladi va if yozish kerak bo'lmaydi — har obyekt o'zining metodini biladi. Yangi tur qo'shilsa sikl o'zgarmaydi. foreach ($xabarlar as $x) { $x->yubor(); }
instanceof — «bu obyekt shu turdanmi?»
Avlod ikkala tipga ham mos keladi — o'ziga ham, otasiga ham. Shuning uchun f(Xabar $x) ga barcha avlodlarni berish mumkin. $e instanceof Xabar → true
interface — shartnoma (Laravel'da: contract)
Faqat metod imzolari, kod yo'q: «bu shartnomani qabul qilgan klass shu metodlarni albatta yozadi». implements bilan qabul qilinadi, bir nechtasi mumkin. Tip sifatida ishlatiladi — kod aniq klassga emas, shartnomaga tayanadi. class EmailKanal implements Yuboruvchi
trait — qayta ishlatiladigan kod bo'lagi
Kodni klass ichiga ko'chiradi (use bilan). Bog'liq bo'lmagan klasslarga bir xil kod berish uchun. ⚠️ Tip bermaydi va kodni yashiradi — ehtiyot bilan ishlatiladi. Ustunlik: o'z klassi > trait > ota klass. trait Loglaydi { ... } → use Loglaydi;
exception — otiladigan xato obyekti
Xato ham obyekt: DivisionByZeroError — bu klass nomi. Shu sababli uni tur bo'yicha tutish mumkin. Exception = kutilgan muammo (validatsiya, fayl, tarmoq). throw new MaoshXatosi("Manfiy maosh");
throw — xatoni otish
Obyekt yasab, uni «otadi»: funksiya darhol to'xtaydi, return ga yetmaydi. 8-darsdagi «jimgina rad etish»dan farqi — chaqiruvchi muammoni biladi. throw new InvalidArgumentException("...");
try / catch / finally — tutib olish
try — urinib ko'r; xato otilsa blokning qolgani tashlanadi. catch (Tur $e) — shu turdagi xatoni hal qiladi (avlodlarni ham tutadi), keyin dastur davom etadi. finally — har holda ishlaydi. Bir necha catch bo'lsa: aniqdan umumiyga. try { ... } catch (Exception $e) { ... }
Throwable / Error — xatolar ierarxiyasi
Throwable — eng tepadagi interface. Ostida ikki aka-uka: Exception (kutilgan muammo) va Error (dasturchi xatosi — TypeError, DivisionByZeroError). ⚠️ catch (Exception) Error ni TUTMAYDI — hammasi uchun Throwable. catch (Throwable $e) → hammasini tutadi
namespace — nom hududi
Klass nomining old qismi: namespace App; yozilsa, haqiqiy nom App\Xabar bo'ladi. Nom to'qnashuvini yechadi. Faylning birinchi ko'rsatmasi bo'lishi kerak (declare dan keyin). object(App\Xabar) — var_dump ko'rsatadi
use (import) — qisqa nom e'loni
«Bu faylda Xabar deganda App\Xabar ni tushun». Hech narsa yuklamaydi — faqat nomni hal qiladi; yuklashni autoload qiladi. ⚠️ Klass ichida turgan use — bu trait ulash, boshqa narsa. use App\Xabar;
PSR-4 — namespace ↔ papka qoidasi
Namespace = papka yo'li, klass nomi = fayl nomi. "App\\": "src/" qoidasi bilan App\Kanal\Email → src/Kanal/Email.php. Shu sababli fayl nomi klass nomiga mos bo'lishi shart. composer.json → autoload → psr-4
autoload — klassni o'zi topib yuklash
Klass kerak bo'lganda PHP uni PSR-4 qoidasi bo'yicha o'zi qidirib topadi. composer dump-autoload buni yasaydi, va skriptda bitta qator yetadi — require zanjiri tugaydi. require 'vendor/autoload.php';
Composer — PHP paket menejeri
Ikki vazifasi: (1) autoload ni boshqarish, (2) begona kutubxonalarni olib kelish. Laravel ham shu asbob bilan o'rnatiladi. Git'ga: composer.json ✅ · composer.lock ✅ · vendor/ ❌ (u composer install bilan tiklanadi). composer require symfony/var-dumper
XSS (cross-site scripting) — begona kod kiritish hujumi
Tashqaridan kelgan matn HTML'ga xom holda chiqarilsa, undagi teglar brauzer tomonidan bajariladi — hujumchi sizning sahifangizda o'z kodini ishlatadi (cookie o'g'irlash). Himoya: chiqarishdan oldin htmlspecialchars. Blade {{ }} buni o'zi qiladi, {!! !!} esa o'chiradi. <script> → &lt;script&gt;
session — so'rovlar orasida saqlanadigan holat
Ma'lumot serverda, kaliti (session ID) brauzerdagi cookie'da. Cookie bo'lmasa server foydalanuvchini tanimaydi. session_start() har qanday chiqishdan oldin chaqirilishi kerak (sarlavha orqali yuboriladi). $_SESSION['tashrif'] = 1;
front controller — yagona kirish nuqtasi
Barcha so'rov bitta faylga (public/index.php) keladi. To'rt foydasi: sozlash takrorlanmaydi · markaziy nazorat (log, auth) · chiroyli manzil · xavfsizlik (faqat public/ brauzerga ochiq). php -S localhost:8000 public/index.php
router — yo'l jadvali
Metod + yo'l → controller moslashtiruvchi. Ichma-ich massiv: $routes['GET']['/vakansiyalar']. GET / va POST / — ikki boshqa route. Topilmasa 404. $router->add('GET', '/', BoshSahifa::class);
dependency injection — bog'liqlikni tashqaridan berish
Obyekt kerakli narsani o'zi yasamaydi, konstruktorda e'lon qiladi. Tip — interface, aniq klass emas. Natijada testda soxta obyekt berish va bajarilishni almashtirish oson bo'ladi. __construct(private VakansiyaRepo $repo) {}
container — obyekt yasovchi (Laravel: Service Container)
Ikki vazifasi: bind($interface, $klass) — interface uchun bajarilishni ko'rsatish; make($nom) — obyekt yasash va bog'liqliklarni o'zi topib qo'yish (rekursiv). Interface uchun bind() qilinmasa: «not instantiable» xatosi. $container->make(Vakansiyalar::class)
Reflection — PHP o'z kodiga qarashi
Dastur ishlab turganda klassni tekshirish: isInstantiable(), getConstructor(), getParameters(), getType(). Container shu bilan konstruktor tiplarini o'qiydi — «sehr»ning haqiqiy mexanizmi shu. new \ReflectionClass($klass)
autowiring — simlarni o'zi ulash
Container konstruktordagi type hint larni Reflection bilan o'qib, kerakli obyektlarni o'zi yasab beradi. Mana 6-darsdagi type hint nima uchun ham kerak edi: u hujjat emas, mashina o'qiydigan ma'lumot. Laravel: __construct(Request $request)
artisan — Laravel'ning buyruq qatori
php artisan serve (server) · route:list (route'lar) · make:controller · make:middleware · migrate · tinker (ilova ichida kod sinash) · list (barcha buyruqlar). php artisan route:list --path=vakansiyalar
.env — muhit sozlamalari
Baza, kalitlar, muhitga bog'liq qiymatlar. ⚠️ Git'ga tushmaydi (parollar bor) — repoda uning o'rniga .env.example turadi. Laravel uni .gitignore ga o'zi qo'shadi. DB_CONNECTION=sqlite · APP_KEY=base64:...
closure — nomsiz (anonim) funksiya
Nom berilmagan, joyida beriladigan funksiya. Laravel route'larining qisqa shaklida ishlatiladi. Real loyihada esa route ni controller ga ulash afzal. Route::get('/', function () { ... });
middleware — so'rov yo'lidagi qatlam
So'rov controllerga yetib borguncha o'tadigan qatlam. $next($request) dan oldin va keyin kod ishlaydi — ya'ni controllerni o'rab oladi. Bir necha middleware ichma-ich: A(B(CONTROLLER)), chiqish teskari tartibda. $next() chaqirilmasa so'rov to'xtaydi (auth shunday ishlaydi). ->middleware(IzniKuzat::class)
Request obyekti — so'rov bitta obyektda
Request::capture() metod, yo'l, $_GET, $_POST, sarlavhalar, cookie va fayllarni bitta obyektga yig'adi. Shu sababli Laravel'da $request->input('ism') yoziladi — ostida esa $_POST turadi. $app->handleRequest(Request::capture())
request lifecycle — so'rovning sayohati
Yetti qadam: public/index.php → autoload → bootstrap/app.php (container) → Request::capture() → middleware → router + controller → javob middleware'lardan teskari qaytadi. Intervyuda eng ko'p beriladigan savol. 7 qadamdan 5 tasi Modul A da yozilgan
view — ko'rinish (Blade shabloni)
Controller ma'lumot yig'adi, view uni ko'rsatadi. view('papka.fayl', ['kalit' => $qiymat]) — nuqta = papka ajratuvchi, kalitlar view ichida o'zgaruvchi bo'ladi. Fayllar resources/views/ da, kengaytmasi .blade.php. view('vakansiyalar.index', [...])
Blade — Laravel shablon tili
Yangi til emas: oddiy PHP fayliga kompilyatsiya qilinadi va natija storage/framework/views/ da saqlanadi. {{ }} → echo e(), @foreach → foreach. @if · @foreach · @forelse ... @empty
{{ }} va {!! !!} — himoyalab va xom chiqarish
🔒 {{ $x }} → echo e($x), va e() bu htmlspecialchars — ya'ni XSS himoyasi avtomatik. {!! $x !!} → oddiy echo, himoya yo'q. Ikkinchisini faqat o'zingiz yasagan ishonchli HTML uchun ishlating. {{ $ism }} — xavfsiz · {!! $html !!} — ehtiyot
layout — umumiy sahifa qolipi
Takrorlanadigan qismni (head, menyu, footer) bir joyga chiqarish. Layout'da @yield('nom', 'standart') bo'sh joy qoldiradi; sahifa @extends bilan uni oladi va @section bilan to'ldiradi. G'oya 9-darsdagi meros bilan bir xil. @extends('layouts.asosiy')
Blade komponent — qayta ishlatiladigan HTML bo'lagi
resources/views/components/nom.blade.php → <x-nom />. @props([...]) bilan kutilayotgan parametrlar e'lon qilinadi (@include da ko'rinmaydi). :nom="$ifoda" — ikki nuqta = PHP ifodasi; ikki nuqtasiz = oddiy matn. <x-vakansiya-karta :nom="$v['nom']" />
CSRF (cross-site request forgery) — so'rovni qalbakilashtirish
Brauzer cookie ni avtomatik yuborgani uchun, boshqa saytdagi yashirin forma sizning nomingizdan so'rov yubora oladi. @csrf formaga token qo'shadi (yashirin _token input); xuddi shu token sessiyada ham bor. Hujumchi tokenni o'qiy olmaydi (boshqa domen mazmuni yopiq). Yo'q bo'lsa — 419 Page Expired. Faqat o'zgartiruvchi metodlarga qo'llanadi. @csrf → <input type="hidden" name="_token" ...>
method spoofing — metodni almashtirib ko'rsatish
HTML forma faqat GET va POST ni biladi. Shuning uchun @method('PUT') yashirin _method maydonini qo'shadi — Laravel uni ko'rib so'rovni PUT deb hisoblaydi. @method('PUT') → <input name="_method" value="PUT">
display_errors — xatoni ekranda ko'rsatish sozlamasi
Ishlab chiqishda yoqilgan, haqiqiy serverda o'chirilgan bo'ladi (xato ichida maxfiy ma'lumot bo'lishi mumkin). O'chirilganda brauzerda bo'sh oq sahifa chiqadi — xato yo'qolmaydi, log faylga yoziladi. php -d display_errors=0 fayl.php
validatsiya (validation) — kirayotgan ma'lumotni tekshirish
$request->validate([...]) — bitta chaqiruv, butun tekshiruv. Qoidalar | bilan ajratiladi (required|string|min:5). U qiymat qaytaradi — va faqat qoidada sanab o'tilgan maydonlarni, shuning uchun bazaga yozishda $request->all() emas, shu qiymat ishlatiladi. Xato bo'lsa exception otadi va keyingi kod bajarilmaydi. Har doim serverda bajariladi; brauzerdagi tekshiruv faqat qulaylik. $t = $request->validate(['nom' => 'required|min:5']);
$errors — xato xabarlari to'plami
Laravel har bir view'ga avtomatik qo'shadi (controller uzatmaydi). $errors->any() — xato bormi; $errors->all() — barcha xabarlar. Bitta maydon uchun @error('nom') {{ $message }} @enderror. @if ($errors->any()) ... @endif
old() — oldin kiritilgan qiymat
Validatsiya xatosidan keyin foydalanuvchi kiritgan qiymatlar sessiyaga yoziladi; old('nom') ularni formaga qaytaradi. Yozilmasa foydalanuvchi hamma maydonni qaytadan to'ldiradi. value="{{ old('nom') }}"
flash xabar — bir martalik xabar
Sessiyada faqat keyingi so'rovgacha yashaydi. redirect()->with('xabar', '...') qo'yadi, view'da session('xabar') oladi. Sahifa yangilansa yo'qoladi — «saqlandi» degan tasdiq uchun ishlatiladi. return redirect('/vakansiyalar')->with('xabar', 'Qo\'shildi');

Modul C — ma'lumotlar bazasi

SQL Eloquent'dan oldin o'rganiladi — shunda ORM sehr emas, qulaylik bo'lib ko'rinadi.

SQL (structured query language) — bazaga so'rov tili
Bazadan ma'lumot so'rash va o'zgartirish tili. O'qishga oson — inglizcha gapga o'xshaydi. Tartib o'zgarmaydi: SELECT → FROM → WHERE → ORDER BY → LIMIT. Matn bittalik tirnoqda. SELECT nom FROM vakansiyalar WHERE maosh > 700
jadval (table) — qator va ustunlardan iborat saqlash joyi
Har qator (row) — bitta yozuv, har ustun (column) — bitta maydon. G'oyasi massivlar massiviga o'xshaydi, lekin diskda saqlanadi va qoidalari bor (NOT NULL, DEFAULT). CREATE TABLE vakansiyalar (id INTEGER PRIMARY KEY, nom TEXT NOT NULL)
birlamchi kalit (primary key) — qatorning takrorlanmas raqami
Har qatorni bir xilda ajratib turadigan ustun. AUTOINCREMENT bilan o'zi ortib boradi. Keyinroq boshqa jadval shu raqamga tayanib bog'lanadi (JOIN). id INTEGER PRIMARY KEY AUTOINCREMENT
NULL — «noma'lum», qiymatning yo'qligi
PHP'dagi null ning bazadagi ukasi, lekin xatarliroq: = NULL va != NULL hech qachon rost bo'lmaydi — IS NULL / IS NOT NULL kerak. Undan yomoni: WHERE shahar != 'Toshkent' NULL qatorni jimgina tashlab ketadi — hisobotdan qatorlar «g'oyib bo'ladigan» klassik bug'. WHERE shahar IS NULL OR shahar != 'Toshkent'
SQL injection — so'rovga begona SQL kiritish
Foydalanuvchi qiymatini SQL satriga qo'shib yozsangiz, u SQL sifatida bajariladi. Yechim — parametr: ? o'rniga qiymat ma'lumot sifatida qo'yiladi. XSS bilan bitta sababdan tug'iladi: tashqi ma'lumotni kod deb ishlatish. XSS — chiqishda, injection — so'rovda. DB::select('... WHERE nom = ?', [$nom]);
tashqi kalit (foreign key) — boshqa jadvalga ishora
Boshqa jadvaldagi qatorning id sini saqlaydigan ustun; nomi odatda <jadval>_id. Ma'lumot takrorlanmasligi uchun kerak: kompaniya nomi bir joyda turadi, vakansiyalar unga raqam bilan ishora qiladi. Migration'da foreignId(...)->constrained(...) yozilsa, mavjud bo'lmagan raqamni bazaning o'zi rad etadi. FOREIGN KEY constraint failed
JOIN — ikki jadvalni bitta qator qilib o'qish
ON sharti qanday bog'lashni aytadi. Oddiy JOIN juftligi topilmagan qatorni tushirib qoldiradi; LEFT JOIN esa uni qoldirib o'ng tomonni NULL qiladi. ⚠️ LEFT JOIN dan keyin WHERE da o'ng jadval ustunini ishlatsangiz, u jimgina oddiy JOIN ga aylanadi — shartni ON ga yozing. JOIN kompaniyalar k ON k.id = v.kompaniya_id
GROUP BY — guruhlab hisoblash
Qatorlarni guruhlarga bo'lib, har guruhni bitta qator qiladi. Guruh funksiyalari: COUNT, SUM, AVG, MIN, MAX. Guruhlarni filtrlash — HAVING (WHERE guruhlashdan oldin ishlaydi, shuning uchun unda COUNT(*) yozib bo'lmaydi). COUNT(*) qatorlarni, COUNT(ustun) esa NULL bo'lmaganlarni sanaydi. GROUP BY k.id HAVING COUNT(*) > 1
migration — jadval tuzilishi kod ko'rinishida
database/migrations/ dagi fayl: up() o'zgarishni qo'llaydi, down() bekor qiladi. Kod git'da yashaydi, shuning uchun istalgan kompyuterda php artisan migrate bilan bir xil tiklanadi. Laravel bajarilganlarni bazadagi migrations jadvalida fayl nomi va batch raqami bilan yozib boradi — shuning uchun bajarilgan faylni tahrirlash ish bermaydi. Sehr yo'q: --pretend u yuboradigan CREATE TABLE ni ko'rsatadi. php artisan make:migration create_kompaniyalar_table
anonim klass — nomsiz klass
Oddiy klass, faqat nomi yo'q — bir marta ishlatiladigan joyda nom shart emas. Har migration fayli aynan shunday boshlanadi (return new class extends Migration): nom berilsa, ikkita migration to'qnashishi mumkin edi. G'oyasi closure bilan bir xil. return new class extends Migration { ... };
route parametri — manzilning o'zgaruvchi qismi
/vakansiyalar/{id} — jingalak qavs «istalgan qiymat» degani; Laravel uni controller metodiga argument qilib beradi. U yerdan SQL'ga faqat parametr bo'lib boradi (WHERE id = ?) — manzilni istalgan odam o'zgartira olgani uchun bu majburiy (SQL injection). ⚠️ Route'lar yozilgan tartibda tekshiriladi: aniq yo'llar (/create) parametrlilardan oldin turishi kerak, aks holda {id} ularni ham «yeb qo'yadi». Route::get('/vakansiyalar/{id}', [Ctrl::class, 'show']);
nomlangan route (named route) — manzilga nom berish
->name('vakansiyalar.show') bilan nom beriladi, keyin hamma joyda route('vakansiyalar.show', $id) ishlatiladi. Foydasi: manzil bitta joyda yoziladi, va xato yozilsa Laravel darhol aytadi (Route [...] not defined). Nom qolipi — resurs.amal. route() to'liq manzil (domen bilan) qaytaradi. <a href="{{ route('vakansiyalar.show', $v->id) }}">
resource controller — yetti amalning standart to'plami
Route::resource('vakansiyalar', VakansiyaController::class) bitta qatordan 7 route yasaydi: index, create, store, show, edit, update, destroy — standart nomlar bilan va to'g'ri tartibda (create ni {id} dan oldin qo'yadi). Cheklash — ->only([...]). Route::resource('vakansiyalar', VakansiyaController::class);
abort(404) — so'rovni to'xtatib xato javob berish
throw ning Laravel shakli: funksiyani darhol to'xtatadi, javobni Laravel yasaydi. return yozish shart emas. Yozuv topilmasa 404 berish kerak — bo'sh sahifa brauzerga «sahifa bor» deb aytadi, hech narsa qilmaslik esa 500 beradi. if ($qatorlar === []) { abort(404); }
Eloquent — Laravel'ning ORM'i
ORM (object-relational mapper): jadvalni klass, qatorni obyekt qilib ko'rsatadi. Sehr emas — SQL yozadi, va toSql() uni ko'rsatadi (qiymatlar ? bilan, ya'ni parametr). O'qish: all · find · findOrFail · where(...)->get(). Yozish: create · save · delete. created_at/updated_at avtomatik to'ldiriladi. Vakansiya::where('maosh', '>', 700)->get()
$table — model qaysi jadvalga qarashi
Laravel klass nomini inglizcha qoida bilan ko'plikka aylantirib taxmin qiladi: Vakansiya → vakansiyas. O'zbekcha nomli loyihada bu deyarli har doim xato, shuning uchun protected $table yozish majburiy. Xato ko'rinishi: no such table: vakansiyas. Tekshirish: (new Vakansiya)->getTable(). protected $table = 'vakansiyalar';

bug tergovi — sakkiz qadam
⭐ 1) TAKRORLA — bug'ni o'z qo'lingizda ko'ring · 2) TORAYTIR (route:list --path=X, grep -rn) · 3) KUZAT (controller → service → model) · 4) O'LCHA (toSql, DB::listen, log, dd) · 5) TUSHUN — nega? · 6) TEST YOZ — qizarishi shart · 7) TUZAT · 8) KO'LAMNI TEKSHIR. ⚠️ 1-qadamni o'tkazib yubormang: «kodga qarab tushundim» — eng ko'p vaqt yo'qotadigan yo'l. ⚠️ Va eng ko'p qilinadigan xato — alomatni yamash (natijani filter qilish), sababni emas. 🔑 Ikki savol: «NEGA bunday bo'lyapti?» va «Yana QAYERDA shunday bo'lishi mumkin?» php artisan route:list --path=tavsiya
orWhere va qavs — AND, OR dan kuchliroq
⭐ SQL'da AND OR dan kuchliroq bog'lanadi — xuddi × va + kabi. 🔍 O'lchandi: where "faol" = ? and "nom" like ? or exists (...) aslida (faol AND nom) OR exists(...) — ikkinchi shoxda faol yo'q. Natija: 2 ta yopilgan vakansiya chiqdi. ✅ Eloquent'da qavs — where(function (Builder $s) { ... }): where "faol" = ? and ("nom" like ? or exists (...)). 🔑 Naqsh: filtr + qidiruv birga bo'lsa, qidiruv shoxlari doim qavsda bo'lsin. ⚠️ Tekshiruv: grep -rn 'orWhere' app/ — bitta bug ko'pincha yolg'iz emas. ->where(fn ($s) => $s->whereLike(...)->orWhereHas(...))
so'rovni ko'rish — toSql, toRawSql, DB::listen
$q->toSql() — ? belgilar bilan · $q->getBindings() — qiymatlar · $q->toRawSql() — ikkalasi birga (bazaga to'g'ridan-to'g'ri nusxalash uchun). Zanjir ichida: ->dump() (davom etadi) · ->dd() (to'xtaydi) · ->dumpRawSql(). Butun oqim uchun: DB::listen(fn ($q) => ...) — har so'rov vaqti bilan (🔍 menda [0.60 ms]). 🔑 dump va dd farqi: dump and die — siklda dump() ishlating. ⚠️ dd() ni commit qilmang. 🔍 Log kerak bo'ladigan joylar: navbatdagi job, rejalashtirilgan buyruq, ishlab chiqarish — php artisan pail bilan jonli kuzating. $q->toRawSql()
mass assignment — ommaviy to'ldirish va uning himoyasi
Massivdagi barcha maydonni birdan modelga yozish (create($massiv)). Xavfi: foydalanuvchi formaga yashirincha admin=1 qo'shsa, o'zini admin qilib qo'yishi mumkin. Shuning uchun $fillable — ruxsat berilgan ustunlar ro'yxati. Ro'yxatda yo'q maydon jimgina tashlanadi; $fillable butunlay yo'q bo'lsa — MassAssignmentException. Birinchi qatlam esa validatsiya (20-dars). protected $fillable = ['nom', 'maosh'];
bog'lanish (relationship) — modellar orasidagi aloqa
Bazadagi tashqi kalitning Eloquent dagi shakli. Modelga bir marta metod yoziladi, keyin butun ilovada ishlatiladi. Qaysi metod kerakligini bitta savol hal qiladi: _id ustuni qaysi jadvalda? — o'sha modelda belongsTo, ikkinchisida hasMany. $v->kompaniya->nom · $k->vakansiyalar
belongsTo — «kimga tegishli» (tashqi kalit shu modelda)
Bitta obyekt yoki NULL qaytaradi. Tashqi kalit nomini metod nomidan taxmin qiladi: kompaniya() → kompaniya_id. ⚠️ Metod nomi ustunga mos kelmasa — jimgina NULL, xato ham, so'rov ham yo'q. Tashxis: getForeignKeyName(); yechim — ikkinchi argument. return $this->belongsTo(Kompaniya::class, 'kompaniya_id');
hasMany — «kimlarga ega» (tashqi kalit boshqa jadvalda)
Collection qaytaradi (bo'sh bo'lishi mumkin). Tashqi kalitni klass nomidan taxmin qiladi: Kompaniya → kompaniya_id. 🔑 Qavssiz — natija, qavs bilan — so'rov: $k->vakansiyalar tayyor to'plam, $k->vakansiyalar() esa ustiga where, orderBy, hatto create qo'shiladigan so'rov. $k->vakansiyalar()->where('faol', 1)->get()
N+1 muammosi — sikl ichida bog'lanishga murojaat
Ro'yxat uchun 1 so'rov, keyin har qator uchun bittadan — jami 1 + N. 5 qatorda sezilmaydi, 500 qatorda sahifa sekinlashadi. Yechim — eager loading: with('bog\'lanish'), u kerakli id larni yig'ib bitta in (...) so'rovi yuboradi (o'lchandi: 5 → 2). Standart holat esa lazy loading deb ataladi. Sanash uchun — withCount (1 so'rov). Vakansiya::with('kompaniya')->get()
nullsafe operator — ?->, bo'sh qiymatni xatosiz o'qish
PHP 8: chapdagisi null bo'lsa, davom etmaydi va null qaytaradi. Bog'lanish bo'sh bo'lganda $v->kompaniya->nom «Attempt to read property on null» beradi, $v->kompaniya?->nom esa null. Odatda ?? bilan birga ishlatiladi. Muqobillari: @if va optional(). {{ $v->kompaniya?->nom ?? '—' }}
pivot jadval — bog'lanishni saqlaydigan uchinchi jadval
Ko'pdan-ko'pga (many to many) bog'lanish ikki tomonning hech biriga tegishli emas — u ikkisining orasidagi fakt, shuning uchun o'z jadvalida saqlanadi. Har qator = bitta juftlik. Boshqa nomlari: junction table, join table, oraliq jadval. Qo'shimcha ustun ham bo'lishi mumkin (daraja) — unga withPivot orqali yetiladi. Migration'da unique([...]) takroriy juftlikni taqiqlaydi. konikma_vakansiya (vakansiya_id, konikma_id, daraja)
belongsToMany — ko'pdan-ko'pga bog'lanish
belongsTo/hasMany juftligidan farqli — ikki tomon ham bir xil metodni ishlatadi. Pivot jadval nomini shunday taxmin qiladi: ikki model nomi → kichik harf → alifbo tartibida → _ bilan (Konikma+Vakansiya → konikma_vakansiya). Ko'plik yasamaydi. Nom mos kelmasa — to'rt argument beriladi va xato ovoz chiqaradi («no such table»). return $this->belongsToMany(Konikma::class)->withPivot('daraja');
attach / detach / sync — pivot juftliklarini boshqarish
attach($id) qo'shadi (mavjudini tekshirmaydi) · detach($id) olib tashlaydi, argumentsiz — hammasini · ⚠️ sync([...]) ro'yxatni aynan moslashtiradi, ya'ni ro'yxatda yo'qlarini o'chiradi (hisobot qaytaradi: attached/detached/updated) · syncWithoutDetaching([...]) faqat qo'shadi · toggle([...]) almashtiradi · updateExistingPivot($id, [...]) pivot ustunini o'zgartiradi. Hammasi qavs bilan chaqiriladi. $v->konikmalar()->syncWithoutDetaching([5]);
cascadeOnDelete — «ota» o'chsa, bog'liq qatorlar ham o'chadi
Migration'da tashqi kalitga qo'yiladigan qoida: vakansiya o'chirilsa, uning pivot qatorlari bazaning o'zi tomonidan o'chiriladi — «yetim» qatorlar qolmaydi. SQL'da on delete cascade bo'lib chiqadi (--pretend bilan ko'rish mumkin). $table->foreignId('vakansiya_id')->constrained('vakansiyalar')->cascadeOnDelete();
factory — bitta yozuvning «retsepti»
database/factories/ dagi klass: definition() metodi bitta yozuvning maydonlarini qaytaradi. Modelda use HasFactory; bo'lishi shart, aks holda Call to undefined method ...::factory(). make() bazaga yozmaydi, create() yozadi; factory(3) — uchta. Bog'lanishlar: has() · for() · hasAttached() — o'zbekcha nomda bog'lanish nomini aniq berish kerak. Vakansiya::factory(10)->for($k, 'kompaniya')->create()
fake() — soxta, lekin realistik ma'lumot (Faker)
numberBetween · boolean(80) · randomElement([...]) · unique() · dateTimeBetween · sentence. ⚠️ O'zbek tili yo'q: fake('uz_UZ') jimgina inglizchaga qaytadi (xato bermaydi). Shuning uchun o'zbekcha ma'lumot uchun randomElement bilan o'z ro'yxatingiz ishlatiladi. fake()->randomElement(['Toshkent', 'Samarqand'])
state — factory'ning nom berilgan holati
«Yopiq vakansiya», «yuqori maoshli vakansiya» kabi holatlarni factory'ga metod sifatida qo'shish. Zanjirlanadi: ->yopiq()->boy(). Massiv shakli qiymatni bir marta hisoblaydi, fn ($atr) => [...] shakli esa har yozuv uchun qaytadan — fake() ishlatilsa ikkinchisi kerak. return $this->state(['faol' => false]);
seeder — bazani to'ldirishning butun rejasi
Factory bitta yozuvni biladi, seeder esa «bazada nima bo'lishi kerak»ni: qaysi factory, nechta, qanday bog'lanish bilan. php artisan db:seed ma'lumot qo'shadi (ikki marta chaqirilsa ikki barobar bo'ladi), migrate:fresh --seed esa noldan to'ldiradi — ishlab chiqishdagi odatiy yo'l. 🔑 Belgilangan ma'lumot (ko'nikma nomlari) factory bilan emas, ro'yxat va firstOrCreate bilan solinadi. php artisan migrate:fresh --seed
sahifalash (pagination) — natijani sahifalarga bo'lish
